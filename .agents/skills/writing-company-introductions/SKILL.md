# 公司介绍写作

## 0. 目标与职责

让陌生读者形成具体认识：公司卖什么，谁使用、谁付钱，客户为什么需要，规模和盈利来自哪里，经营发生了什么变化，以及与题材、同行有什么真实联系。文章可以单独阅读。

公司介绍通常在每次正式推荐归档后写一次，已有有效介绍直接复用；值得为关键问题做必要的定向研究，不按高频批量摘要压缩工作。程序管事实、时点和确定性计算，AI 选择问题、补读原文并写解释；正文不由程序模板拼接。

它不参与选股，不是第六个视角或正式复盘。不给出股票推荐、短期走势、买入条件、仓位或目标价，不进入 Forward CSV、V4 trace、monitor snapshot 或复盘正文。运行和保存见 `ops/company-introduction-prompt.md`；原公司研究 Skill 不因介绍改变职责。

## 1. 先形成对生意的认识，再组织文章

写作前先用已有资料回答这些问题，并找出影响理解的缺口：

- **卖什么、为什么有人买**：把技术名称翻译成实际用途，说明使用者、付款者和交付内容。公司做材料、设备、项目服务还是股权投资，须分清。
- **生意如何运转**：选择影响收入、成本、交付或回款的关键环节。只有取得公司自身证据时，才把订单、产能、原料、项目结算等写成其经营特点；不照搬同行惯例。
- **规模和盈利由谁贡献**：识别收入主力与毛利主力是否相同，解释业务组合为什么值得读者注意。只披露一个业务时就讲清这一项。
- **近期变化意味着什么**：在同口径下连接收入、盈利和现金流变化，找到公司解释或可核对的变化证据；结构占比不能单独解释增长主因。
- **真实联系和差异在哪里**：用产品、应用、客户、交付阶段或会计关系说明主题联系；有帮助才比较同行的重叠环节。

“缺一张表”和“公司没有这项业务”不同。本地已有数据也可能只够列数字、不够解释；核心产品、收入来源、可比口径或重要事件仍不清楚时，按第 4 节主动补证。地址、员工数、完整股东名单等次要资料可以省略。

## 2. 以读者的理解顺序写，内容由证据决定

首段先给核心生意和公司身份，随后交代有助理解的控制关系。更名沿革、总部地址、家族成员名单不挤占开头；重要重组改变业务边界时要说清。

常用顺序如下，可合并或调整标题，不要求逐栏填写：

| 内容 | 写到什么程度 |
|---|---|
| 公司定位与生意 | 具体产品/服务、用途、客户类型和重要经营环节，让读者能复述公司靠什么赚钱 |
| 收入与盈利结构 | 选择同一口径的关键分部，必要时配一张表；文字解读最重要差异，不逐行复述 |
| 近期经营 | 用关键指标和有依据的解释说明变化，区分盈利、现金回收及一次性影响 |
| 业务联系与竞争特点 | 用实际产品/项目和商业阶段建立联系；同行只比较重叠环节，业务组合不同要交代 |
| 重要事项与市场定价 | 说明事项进展、规模和影响时段；估值有明确交易日与口径，不自动判断便宜或昂贵 |

不要用字数、回答问题的数量或表格数量验收。业务复杂就展开，集中就简写；简写仍要有公司的具体特点。删除公司名后若大部分文字适用于许多公司，应补足有来源的产品、客户、经营结构或项目细节，而非添加形容词。

表格每列有独立、清楚的表头，报告期和单位明确；不把整行表头塞进第一格。正文、表格、资料限制和来源说明构成同一篇文章，不能各说各话。

初次按本 Skill 写作，或初稿仍像数字摘要时，阅读 [写作对照](references/writing-examples.md)，学习解释方法，不复用其中的假设数据或公司专属结论。

## 3. 用事实解释，避免看似合理的跳步

优先把“关键事实”和“它对理解生意的意义”连起来，必要时交代边界；不逐段套三句模板或反复写免责声明。

- 区分披露事实、公司的归因、AI 的推断。公司归因用“公司解释/报告称”；推断写清依据和范围。找到更可靠原文后可修正初稿，不维护错误说法。
- 收入占比、毛利率和毛利份额回答结构问题；要说某业务推动本期增长，还需可比期间变化、增量计算或明确披露。毛利贡献不等于归母净利润贡献。
- 扣非归母接近归母，只说明非经常性损益的净影响较小，不能单独证明增长来自主营、可以持续或现金质量好；经常性损益还可能含投资收益等项目。
- 利润与现金流分别理解。现金流低基数、由负转正时优先给两期金额及原因，避免醒目的巨大百分比替代解释；经营现金流不能机械与归母利润做质量评分。
- ROE 区分期间指标和年化值；负债率是期末时点；毛利率按同公司、期间、币种及业务范围的收入与对应成本计算。指标名称相近、字段含 profit，并不意味着口径相同。
- 只用一套可核对分类算结构，不混加产品、地区、行业和汇总行。分母不明就给金额和限制，不补成 100%。同行采用原截止前适当的可比期间，不混年排名。
- 主营关系要分清自营/参股、在售/储备、意向/签约/履约/收入确认。参股公司的营业收入不直接并入上市公司主营，投资收益对利润的影响按真实会计处理核对。
- 核电小额外加剂合同不能写成核电主营已经放量；研发、专利或产品目录不能直接证明商业规模。合同总额不等于当期收入，收入不等于利润。
- 同一事项的预告、快报和正式报告按进展合并，不算多项独立利好。较早披露但仍影响公司的重组或长期合同不能被“最近公告”窗口自动排除。
- 有份额依据才写份额，没有统一排名仍可用具体产品、用途和同行业务差异说明位置，不能直接放弃认识公司的差异。

## 4. 本地不够时，主动取得关键官方证据

本地 facts-file 是起点，不是能力上限。已授权为本次公司介绍临时使用 WEB、公开官方接口和现有读取工具；无需逐次请用户确认搜索。关键问题未解决时不能因某字段缺失、接口不支持或一个 URL 失败就结束。

**先定位资料，再换取得方法。** 优先读原截止前最新可用定期报告的业务、管理层讨论、主要财务数据及相关附注；摘要能确认数字，但通常不能替代业务全文。按具体缺口补读合同、重组、控制关系或投资者关系原文，避免无目的扩大采集。

- 链接 404：核对公告身份和路径，从官方检索重新定位；可尝试同文档的静态文件入口、交易所披露或公司投资者关系页面。巨潮 `www` 页面与 `static` 文件入口不同，换入口后仍须核对文档，不能猜公告编号。
- 本地未收录/接口受限：用公司代码、名称、报告期或公告标题查官方网页、公开检索/API；需要时读取官方页面实际返回的下载链接。工具或网页解析失败，可换现有 HTTP 客户端或浏览器读取。
- PDF 无法提取：先确认取得的是 PDF 而非错误页面，再用已有解析器、页面查看或必要页 OCR；表格错列时回看页面，不能据乱码计算。
- 官网介绍或备料字段陈旧：用当时已公开的报告确认业务范围。主营和估值不能由当前网页回填历史。

不限制为“补读一次”，不机械穷举渠道或反复请求同一坏链接。有有效新线索且缺口重要就继续换方法；所需原文、版本和时间核实后停止该项。合理官方路径仍无结果、只剩重复失败或访问确需额外权限时，记录具体未知。公开检索失败不等于公司未披露。

网页/搜索摘要只帮助定位，事实回到已核对原文。核对代码、公司名称、报告期、公告标题/身份和版本；同一公告备料块可能混有别家公司，不能直接信任归属。仅有标题不能推断合同结果、金额或风险解除。

失败入口、已尝试方法及仍缺什么记在临时工作记录，便于继续；正文只写影响读者认识的实质未知。资料取得使用临时目录和现有工具，不建长期爬虫、下载平台或全文库，不把本次补读变成事实仓维护任务。

## 5. 原截止、来源与计算

- 逐字沿用原 `formation_date`、`action_date` 和带时区的 `as_of`；估值交易日不晚于 formation_date，事实在 as_of 可用。`generated_at` 记录实际写作时间，不倒填。
- 现在取得的官方文件可以用于历史介绍，但所依据的版本必须在原截止已经公开。来源的 `available_at` 按核实的历史公开时间填写，`retrieved_at` 是实际取得时间。日期证据不能确定是否早于当天截止时，不凭空填零点来通过校验；以后更正的版本不能覆盖此前未知。
- 本地来源保留 dataset、block_id、locator、available_at 和引用的关键原值 values，与原 facts-file 对应。
- 外部官方来源沿用 `official_document`，记录真实 URL、文档/页码/表格定位、公开时间依据 `availability_basis`、`retrieved_at` 及所引关键原值。不手改 facts-file 或伪装 warehouse 行。
- 官方原文可补充本地缺失的数值和解释，也可纠正不适用的自动计算。合并/重述有疑点时先找官方调整后同期及口径说明；核实后可用，仍不明才省略同比，不能因程序没算就放弃核对。
- 金额、占比和毛利率用现有计算结果或临时 Python 核算，保留必要原值、单位、分母和公式。不让 AI 心算替代确定性计算，不用半年利润乘二重算 TTM。
- 区分数据不存在、覆盖不足、查询失败、快照不可回放和真实无记录；本地 gaps/quality_note 是取数信息，不直接成为公司经营风险。

## 6. 正文和辅助信息各司其职

正文讲生意和经济含义，不讲 `company_profile`、异常 `gross_margin`、程序未算同比或哪次下载失败。来源区保留核查细节；资料限制只保留尚未解决且影响理解的问题，如特定新业务没有单独披露收入。

限制必须和正文一致：没有取得结算说法的依据，就从正文删除该说法或改为明确的待核问题，不能一边引用一边免责。已经解决的缺口不要继续列为未知；不重复“没有排名”“不能等于利润”等提醒凑篇幅。

## 7. 逐篇自检与交付

record 前逐篇检查：

1. 陌生读者能否复述核心生意、客户需要以及规模/盈利来源？欠缺的是核心事实还是可省略细节？核心问题是否完成了必要补证？
2. 关键解释有没有事实支撑？是否把结构比例说成增长主因，把扣非接近归母说成主营证明，或把合同写成当期收入？
3. 每个关键数字、表格、单位和比较口径能否对应备料或已核对官方原文？来源 ID 可解析，文档归属、版本、原截止和估值日一致？
4. 正文、表格、limitations 和来源有无矛盾？是否混入内部字段、失败记录或无关宣传？是否可以删掉重复内容？
5. 是否仍为公司介绍，没有改写推荐理由、目标价、仓位或收益承诺？

自检发现问题就修正文，不把问题包进免责声明。自检与程序结构校验各有用途，record 成功不代表语义已经正确。按运行 Prompt 保存；已有介绍正常复用，不自动批量重写。
