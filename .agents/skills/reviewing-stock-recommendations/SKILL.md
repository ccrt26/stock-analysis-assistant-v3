# 正式推荐复盘

## 唯一职责

本 Skill 不发现候选、不选择股票、不改变历史推荐，也不是第六个选股视角。

它只接收：

- 明确正式推荐的记录；
- 推荐日期和当时完整理由；
- 推荐后的价格与成交事实；
- 市场、行业、公司和价格四个 Skill 的 review 结果；
- 已有 `ForwardEpisodeReviewV1` 字段。

它负责把这些事实合成一份用户能理解的复盘。复盘的固定推理顺序是：

```text
结果 → 最有证据的主要解释 → 推荐日最重要的预期是否实现 → 当前阶段 → 未来1—3个交易日
```

这里判断的是当前最有证据的解释，不声称证明唯一真实原因。

## 每次必须回答

1. 这只股票在具体哪一天开盘前被推荐，当时最重要的可检验预期是什么；
2. 到今天走了多少个交易日，实际涨跌、期间最高、期间最深下跌以及距离20%观察目标的进展；
3. 这段涨跌更可能由市场共同变化、行业共同变化、公司变化、股票自身变化还是多种因素共同造成；
4. 为什么这一解释比其他解释更有证据，哪些替代解释被什么事实削弱；
5. 推荐日最重要的预期是否真正实现，不能用“上涨了”代替验证；
6. 当前最接近继续走强、上涨后整理、开始失速、明显减弱、已经失败还是无法执行；
7. 未来1—3个交易日更可能怎样发展、为什么，以及什么事实会改变这个基准判断。

不得退化成“得到支持”“部分支持”“仍需观察”“资料不足”或复述市场、行业、公司、价格四路事实。

## 主要解释的比较方法

- 股价与市场接近且没有重要公司新事实时，市场共同变化优于股票自身解释。
- 股价与行业接近、行业上涨面同步且没有公司增量时，行业共同变化优于股票自身解释。
- 公司变化只有与主营直接相关、有经营含义，且事件前后的相对价格表现与之对应时，才可成为主要解释。
- 股票自身变化需要明显跑赢市场和行业，并有多个收盘推进；一次盘中冲高或单日放量不够。
- 多种解释并存或关键证据冲突时写混合或未知，并指出仍缺哪项比较。
- 成交必须结合价格方向、收盘位置、上影、回落和持续时间解释；成交额本身不是上涨原因。
- 不从价量推断主力、机构、游资或账户身份。

`best_supported_explanation` 只保存上述最有证据的主要解释。`current_assessment` 和 `current_weak_or_failed_link` 供内部保持合同一致，不直接生成用户结论。`current_review` 是公开分析的语义权威，必须在一段话中完成主要解释、替代解释比较、核心预期验证、当前阶段和后续基准判断。

## 相对行业与行业上涨面

相对行业表现与行业上涨面不是同一件事：

- `relative_industry_*` 表示股票相对形成日有效申万二级行业的表现；
- `sector_breadth_*` 表示 `original_group_code` 对应行业或主题中上涨成员的比例。

相对行业存在但行业上涨面缺失时，只能说不能核对多数成员是否同步；行业上涨面存在但相对行业缺失时，仍可说明多数成员是否上涨。不得把其中一项缺失写成全部行业数据不可用。只有原推荐依赖行业共同变化时，行业上涨面缺失才是关键限制。

## 阶段与可执行性

- 继续走强：多个收盘继续提高，且相对表现与原预期同步增强。
- 上涨后整理：已经上涨，仍接近推荐后高位，但短期推进放缓而未形成明确反对。
- 开始失速：成交或盘中冲高增加，收盘却不再提高，或从高点回落扩大。
- 明显减弱：原核心预期的重要一环已经转弱，但尚未完全失败。
- 已经失败：推荐日核心预期被后来事实直接反对。
- 无法执行：行动日停牌、无可靠开盘价或不能按原条件参与；这不是一般的“资料不足”。

行动日已有可靠入口、后来才停牌时，要先说明停牌前进展；行动日无可靠入口时才说无法评价20%目标。控制权变化等公告只改变公司背景，不直接预测复牌方向；复牌后更可能先出现高波动，方向等待实际成交确认。

## 分析原则

- 股票上涨不自动证明当初理由正确；必须比较市场、同行和原预期。
- 股票下跌也不自动证明公司事实错误；要指出失败发生在哪一层。
- 不按每天1%的线性速度评价。
- 停牌期间不虚构价格进展；先说停牌前走到哪里，再说新公告怎样改变公司背景，最后说明复牌后需要验证什么。
- 一条无关月报、公告标题或局部数据缺失不能决定整只股票的结论。
- 能用已有价格、行业和公司事实分析时，不得把整段结论写成“资料不足”。
- 最近1、3、5日字段只有在观察天数覆盖相应窗口时，才能称为完整的推荐后表现；D1—D4 的五日字段只能作为近期背景。
- 不使用“冻结时点、冻结结论、原逻辑、传播链、正常双向成交”等用户难以理解的词。
- 必须使用具体推荐日期，并以正式推荐记录的 `action_date` 为准。
- 不新增定时任务，不新增报告模型或 schema。

## 输出

继续填写现有 `ForwardEpisodeReviewV1`，不增加schema。

`original_reason_plain_language`：
写成“该股票在YYYY年M月D日开盘前被推荐，当时主要因为……”。

`current_review`：
必须包含“主要解释 → 为什么胜过替代解释 → 核心预期是否实现 → 当前阶段 → 未来1—3个交易日基准判断与原因”。建议用150—300个中文字符自然表达，不按字符数自动判定质量。

`outlook_1_3d`：
使用现有七类表达未来1—3个交易日的基准判断；确实无法判断方向时，在 `current_review` 明确写“未来1—3个交易日方向暂时无法判断”，不要用横盘预测掩盖未知。

`confirmation_condition` 与 `invalidation_condition`：
各写一个完整中文句子，分别说明什么事实增强判断、什么事实改变判断。

其他枚举只供内部记录，不直接显示给用户。
