# 正式推荐复盘

## 唯一职责

本 Skill 不发现候选、不选择股票、不改变历史推荐，也不是第六个选股视角。

它只接收：

- 明确正式推荐的记录；
- 推荐日期和当时完整理由；
- 推荐后的价格与成交事实；
- 市场、行业、公司和价格四个 Skill 的 review 结果；
- `previous_daily_formal_review` 和已有 `ForwardEpisodeReviewV1` 字段。

它负责把这些事实合成与复盘类型相符的连贯分析：简评讲重要增量，普通详评覆盖四项，节点详评覆盖六项，不展示固定推理步骤。内部仍按以下顺序完成判断：

```text
结果 → 最有证据的主要解释 → 推荐日最重要的预期是否实现 → 当前阶段 → 未来1—3个交易日
```

这里判断的是当前最有证据的解释，不声称证明唯一真实原因。

## 每日判断与主动跟踪

每个需更新判断的正式推荐 episode，在每个已收盘交易日都生成一条结构化判断记录，写入 `DailyFormalReviewV1`，并按三路互斥归入一类：`checkpoint_detail`（节点详评）、`regular_detail`（普通详评）、`brief`（简评）。每条记录必须明确：`current_path` 是向上、横盘、向下还是无法评价；当前是否仍在原推荐预期内；相对上一交易日的观点是否实质变化；未来1—3个交易日更可能怎样及原因；是否继续主动跟踪。

三路分配：到达 D1/D3/D5/D10/D20 检查节点（含待补 D20 结案）的股票全部为节点详评，不生成简评、不占普通详评名额；剔除节点后按优先级选最多8只普通详评；剩余只写简评。同一股票当天只进入一类。节点是股票生命周期的对账日，不是简评的加深版。节点详评共用同一份必备对账清单，**六项信息缺一不可；栏目可合并成句，某项确实无内容时明写“该日尚无此项可对”，不得省略**：①原期待与担心的回顾；②截至当日的阶段路径分叙；③兑现、削弱与仍未知；④当前最合理的解释及其边界；⑤公司侧状态；⑥目标余程与预设验证条件。每项按“事实—这说明什么—还不能证明什么”的小单元覆盖，合并成句即算成立，不设字数或数量下限：③不得只写“未知仍在”；⑤“无公告”后必须跟一句含义。节点只决定侧重：

- D1 当天原条件下是否可执行，首日反应怎样检验原判断；不虚构数日持续性。
- D3 早期反应是否延续，有无反证；不把单日涨跌当长期确认。
- D5 第一周路径与新增证据，原期待兑现与未兑现。
- D10 前半程对账、主要未知、目标剩余路径和障碍。
- D20 前20日结果与最终结论，保存并冻结 `FrozenTwentyDayReviewV1`；当天正文只写理解结案所需的当日增量，完整结案只在 `final_twenty_day_review.overall_review` 公开一次。

D25、D30只适用于已经明确延长的记录；只写D20以后的新增表现，不改写D20，D30正式完成。

只有原推荐最重要的判断被事实否定，或原推荐无法执行，才能停止主动跟踪。前者必须使用 `current_assessment=contradicted`，后者必须使用 `current_weak_or_failed_link=execution` 且没有可靠入口价格。weakening 不能单独停止；单日下跌、横盘、数据暂缺、未达到20%、普通市场回落或短期判断偏下，也不能单独停止。达到20%仍继续记录到D20。

停止主动跟踪后，次日起不再生成简评，也不占详评名额；历史不删除，程序继续记录确定性价格到D20，待补结案时以节点详评重新进入并形成最终结论。同一股票以后再次推荐时使用新的 episode，不恢复旧记录。

全部结构化判断草稿写完后，先摘出节点股，再从非节点股票中选普通详评（最多8只）：依次优先今日停止、观点明显变化、达到目标或显著回撤、重要公司事项；优先股不超过8只时必须全部入选，超过8只时详评恰好8只且全部来自优先股，其余在简评中如实披露变化；必要时按最长时间未详评轮换补足；没有需要时允许0只。简评类写 `current_review`（600字符硬上限，说完即停）；两类详评的账本正文为空，`ForwardEpisodeReviewV1.current_review` 是唯一公开详评正文，长度以说清楚为准，节点详评必须完成六项对账清单。详评的当前判断、主要解释、薄弱或失败环节、未来方向、方向理由及D20结论必须与账本一致；观点变化说明仍来自账本的 `view_change` 和 `view_change_reason`，详评不另写一份。

生成顺序：全部结构化判断草稿→节点详评K→非节点普通详评D→其余简评B→各写唯一正文→核对事实来源与结构化一致性→先保存账本、后保存报告。保存前若文字改变了判断，先同步未保存草稿，不能事后改已保存账本。

## 按类型写观点更新稿

简评围绕当天一个主要问题；详评围绕主要问题组织六项或四项信息，完整性优先于压缩篇幅。以下“一句话足够”和“一个事实足够就停”仅适用于简评，不用于省略详评必备内容。

简评先选一个主要问题，也就是当天的一个中心问题，例如突破是否站稳、上涨是否仍由股票自身推动、行业共同上涨是否还在、盘中回吐是否已经变成明显卖压、公司新消息是否真正改变经营判断，或者推荐是否能够执行。其他事实只有在解释这个问题时才使用。只有一项次要变化会影响下一次复盘时，才在结尾用一句话提醒，不并列展开第二个中心。

简评的 `DailyFormalReviewV1.current_review` 采用以下自然写法，不显示成固定小标题；详评按后文对应类型的完整清单展开：

1. 第一句是一句话观点更新，必须包含最重要的变化和方向判断，并能独立作为标题；
2. 只使用回答中心问题所需的事实，不设固定数量指标，也不设最低数量。一个事实已经足够时立即停止，不得为了满足数量凑事实；停牌且没有价格时，可以没有推荐后价格事实；
3. 根据与上一次复盘的比较填写当天 `view_change` 和 `view_change_reason`，由外层直接展示，详评不再创作第二份观点变化说明；
4. 收束于当前综合判断；后续基准判断和两个条件由现有外层展望单独展示。

简评可以是一段，也可以是两三段；开头、段落和结尾服务于当天真正发生的事情，不追求每天同构。简评没有实质变化时，一句有效的观点更新也可以成立。详评不设字数或段数指标。

不平均复述市场、行业、公司和价格四路内容。不得把“最有证据的解释是”“当前阶段是”“核心预期目前得到支持”当作固定开头，也不得退化成“得到支持”“部分支持”“仍需观察”或“资料不足”。

事实与观点分开：涨跌、相对表现、成交、回撤和公告是事实；主要原因、当前阶段和后续方向是观点。观点用“更像”“更可能”“目前看”等方式表达，不冒充已经证明的事实。

最终 `current_review` 不使用“行业扩散”“个股增量”“核心预期”“当前阶段”“最有证据的解释”“价格支持”“观点验证”作为固定标签或核心表达。通用市场词可以直接用；生僻术语用普通中文描述，不做术语加注释的双轨表达。事实、时点、口径和来源必须准确且可追溯，在此基础上使用普通中文表达；文风以 `ops/forward-monitor-prompt.md` 的“文风基准”为准。判断句写成立场＋当前最重要的1—2个支持事实＋限制因素，条件只收在节点详评结尾或交给外层字段；节点详评范例见该节“节点范例（银龙股份”，普通详评范例见同节“普通详评范例”。

## 与现有外层渲染的分工

正文围绕当天主要问题解释当前看法，具体深度由节点六项、普通详评四项和简评增量规则决定。观点变化的完整说明由外层展示，不另造第二份；结构化判断和正文必须一致。

简评不重新完整介绍公司和原推荐理由；详评必须回顾理解六项或四项对账所需的原期待、风险和阶段事实。现有程序外层先用一行“当前状态”显示推荐日期和交易日序号、当前收盘相对推荐参考价、期间最高收盘和最深下跌，数据缺失时只显示真实可取得的部分。

每只股票的三个固定小标题依次为：

**今天发生了什么**

Markdown详评正文使用报告中的 `ForwardEpisodeReviewV1.current_review`；简评表只读取当日账本 `brief` 类的 `DailyFormalReviewV1.current_review`。三类观点变化均读取当日账本的 `view_change` 与 `view_change_reason`。

**相比上次判断**

直接使用当天 `view_change` 和 `view_change_reason`，分别表达判断无实质变化、增强、减弱或原判断被事实否定及原因。`first_review` 直接展示原因，只有确有必要时才在原因中说明首次复盘。

**接下来1—3个交易日**

展示基准方向、`outlook_reason_plain_language`、支持当前方向的表现、改变当前方向的表现。正文不重复这份完整展望和条件清单，只有直接决定今天判断的数字才再引用。

`original_reason_plain_language` 和 `original_key_risk_plain_language` 是内部历史锚点，只通俗改写当时已冻结的理由和风险，不加入后来事实。D1/D3/D5/D10节点正文按六项清单回顾原期待与担心；普通详评只回顾解释四项信息所需部分，简评不重放完整原理由。D1 两项首句分别写“当时主要看中……”和“主要担心……”，只用一到两句话放在当前状态后的“原推荐背景”行。当天观点为 `invalidated` 且需要交代原预期才能理解时，正文可用一句话提及。

D20 在三段之后增加独立的“20个交易日最终复盘”，完整总结只使用 `FrozenTwentyDayReviewV1` 及前20日确定性事实，不能在当天 `current_review` 再写一遍。多个 episode 使用各自推荐日期和交易日序号的简短前缀，三个标题每只股票只出现一次，不重复完整原推荐理由和风险。历史没有 daily_ledger 的 V1/V2 仍可读，不回写或迁移；缺少观点比较时如实说明未保存。新推荐仍按 `ops/forward-selection-prompt.md` 的完整论证结构生成，与复盘不共享小标题。

## 未来方向不是条件清单

复盘必须先判断未来1—3个交易日更可能是向上、震荡偏上、横盘、震荡偏下、向下，还是暂时无法判断，再说明哪些当前事实使这个方向比另外两个方向更合理。这个判断是短期基准，不是20日收益承诺，也不声称确定预测。

用 `outlook_reason_plain_language` 保存方向理由：只选当前最重要的1—3项事实，不写“如果……就……”，不重复 `confirmation_condition`、`invalidation_condition` 或整段 `current_review`。条件只负责以后验证，不能代替当前判断。没有可交易价格或证据彼此冲突时，可以写“目前没有足够的可交易事实判断方向”，并说明缺少什么。

## 20日目标的可实现性

`current_review` 可以用一句话说明“20%目标仍有现实可能”“需要重新加速才有可能”“目前已明显变得困难”“已经不再以完成目标为主要判断”或“无法计算”。不增加结构化字段，不按每天1%线性推算。

## 上一轮观点的真实锚点

优先读取本记录自己的 `previous_daily_formal_review`；程序会从同日已保存报告恢复上轮详评正文，账本中详评正文为空不等于没有历史。历史没有日评记录时才兼容读取 `previous_episode_review`。只读取所选历史对象中本 episode 的以下字段：

- `current_assessment`；
- `best_supported_explanation`；
- `current_weak_or_failed_link`；
- `current_review`。

先比较前三个结构化字段，再读取上一轮 `current_review` 的第一句并识别它的中心问题。只有结构化判断、主要解释、原推荐的关键一环，或同一粗枚举下的具体观点发生实质变化时，才公开写观点改变。仅仅换了一种措辞，不叫观点改变。

没有 `previous_daily_formal_review` 或兼容的 `previous_episode_review` 时，内部只与原推荐判断比较，通常不必写“这是首次复盘”；只有没有上一轮观点本身会影响理解时才说明。不得借用同一股票的其他记录、旧日报自由文本或 `previous_monitor_state` 伪造上轮观点。

## 事实追溯与推断边界

`current_review` 中每一项具体的日期、百分比、金额、股票数量、公告名称和财务变化，都必须能够追溯到当前 snapshot 或 monitor report 的确定性字段、原推荐 trace，或当日按现有流程读取的正式公司材料中的明确字段和值。不能把模型常识、旧日报中的自由文本、上一轮 `current_review` 或未记录的外部信息当作新事实来源。允许将 `0.024` 换算为 `2.40个百分点`，但必须保留来源字段和原始值。

snapshot episode 的 `review_context` 提供带固定口径的价格上下文：市场基准是沪深300，入口是行动日开盘，价格按“原始价×当日复权因子÷分析日因子”归一，`benchmark_windows` 是市场窗口收益而非“推荐以来”收益，`price_levels.remaining_*` 是距离原推荐20%目标的余程。引用时不得换成其他基准、起点或口径；窗口收益、ATR、现金流比值等引用工具算好的数值，不凭空心算派生。公司事实的复盘截止是本次snapshot的 `as_of`；原推荐 `source_as_of` 只用于还原当时判断。关键价位是观察条件，不得包装成“套牢盘”“真实抛压”等机制断言，ATR距离不产生概率。

**写作总标准：事实、时点、口径和来源必须准确且可追溯；在此基础上使用普通中文表达。**
1. **可追溯**：每个关键判断都有可追溯依据，并解释它支持什么、还不能证明什么。
2. **说人话**：直接说事，不表演通俗。每句直接陈述"发生了什么、意味着什么"，支撑数字放在它解释的事实旁边；不打比方、不做"术语＋行话注释"的双轨写法、不刻意口语化。通用市场词（缩量、放量、逆势、回撤、抛压、上影）可以直接用；生僻术语宁可不用，用一句直接描述代替。

说人话不降低可追溯：每个关键数字仍必须在保存前核对来源。范例只指导表达，不替代来源证据；不能照搬范例中的因果措辞，把量价写成账户身份、套牢盘或唯一原因，也不能把单日涨跌当作因果证明。阶段详评应让读者理解原预期如何被后续事实检验。正式事实（停牌、订单取消等）不需要凑数字。知识条目只在实际改变解释或确信程度时使用，并在对应内部变化字段末尾按 `知识：条目ID；本次用途：…；不能推出：…` 留痕；没有实际作用就不写。保存前由同一执行者核对一次：episode与起止日、基准/行业口径一致；关键数字可在字段或工具结果中找到；没有把量价写成买方人数、账户身份或唯一原因；观点变化确由经济事实或已核实的原证据纠正驱动；简评、详评、方向和条件一致。

只允许基于四类联系形成“目前更合理”的解释：股票相对市场和行业的差异；正式公司事件与事件前后相对表现的对应；价格、成交、收盘、盘中冲高回落和回撤的组合；原推荐判断中的具体检查点。这些联系不证明唯一真实原因。现有事实不能区分原因时，“不知道”是合法结论，应说明缺少什么，不得为完整感编造涨跌原因。

正文不得与 `best_supported_explanation`、`current_assessment`、`current_weak_or_failed_link` 和 `outlook_1_3d` 明显矛盾。主要来自行业时不能把解释写成股票自身；确实同时受多种因素影响时使用 `mixed`。这是生成前语义自检，不增加代码 Gate。

## 主要解释的比较方法

- 股价与市场接近且没有重要公司新事实时，市场共同变化优于股票自身解释。
- 股价与行业接近、行业上涨面同步且没有公司增量时，行业共同变化优于股票自身解释。
- 公司变化只有与主营直接相关、有经营含义，且事件前后的相对价格表现与之对应时，才可成为主要解释。
- 股票自身变化需要明显跑赢市场和行业，并有多个收盘推进；一次盘中冲高或单日放量不够。
- 多种解释并存或关键证据冲突时写混合或未知，并指出仍缺哪项比较。
- 成交必须结合价格方向、收盘位置、上影、回落和持续时间解释；成交额本身不是上涨原因。
- 不从价量推断主力、机构、游资或账户身份。

内部仍选择最有证据的主要解释。只有与中心问题直接相关时，才简要说明为什么这一解释比其他解释更有证据；`current_review` 不需要逐项证明所有替代解释都错误。

`best_supported_explanation` 只保存上述最有证据的主要解释。`current_assessment` 和 `current_weak_or_failed_link` 供内部保持合同一致，不直接生成用户结论。`DailyFormalReviewV1.current_review` 是简评类的唯一正文；`ForwardEpisodeReviewV1.current_review` 是两类详评的唯一正文，详评股账本正文为空。三类均以当天账本的结构化字段保持判断一致，在相应深度内完成主要解释、必要的替代解释比较、原推荐检查点验证和当前综合判断；完整后续展望仍由外层使用现有结构化字段展示。

## 相对行业与行业上涨面

相对行业表现与行业上涨面不是同一件事：

- `relative_industry_*` 表示股票相对形成日有效申万二级行业的表现；
- `sector_breadth_*` 表示 `original_group_code` 对应行业或主题中上涨成员的比例。

相对行业存在但行业上涨面缺失时，只能说不能核对多数成员是否同步；行业上涨面存在但相对行业缺失时，仍可说明多数成员是否上涨。不得把其中一项缺失写成全部行业数据不可用。只有原推荐依赖行业共同变化时，行业上涨面缺失才是关键限制。

## 阶段与可执行性

- 继续走强：多个收盘继续提高，且相对表现与原预期同步增强。
- 上涨后整理：已经上涨，仍接近推荐后高位，但短期推进放缓而未形成明确反对。
- 开始失速：成交或盘中冲高增加，收盘却不再提高，或从高点回落扩大。
- 明显减弱：原核心预期的重要一环已经转弱，但尚未完全失败。
- 已经失败：推荐日核心预期被后来事实直接反对。
- 无法执行：行动日停牌、无可靠开盘价或不能按原条件参与；这不是一般的“资料不足”。

行动日已有可靠入口、后来才停牌时，要先说明停牌前进展；行动日无可靠入口时才说无法评价20%目标。控制权变化等公告只改变公司背景，不直接预测复牌方向；复牌后更可能先出现高波动，方向等待实际成交确认。

## 分析原则

- 股票上涨不自动证明当初理由正确；必须比较市场、同行和原预期。
- 股票下跌也不自动证明公司事实错误；要指出失败发生在哪一层。
- 不按每天1%的线性速度评价。
- 停牌期间不虚构价格进展；先说停牌前走到哪里，再说新公告怎样改变公司背景，最后说明复牌后需要验证什么。
- 一条无关月报、公告标题或局部数据缺失不能决定整只股票的结论。
- 能用已有价格、行业和公司事实分析时，不得把整段结论写成“资料不足”。
- 最近1、3、5日字段只有在观察天数覆盖相应窗口时，才能称为完整的推荐后表现；D1—D4 的五日字段只能作为近期背景。
- 不使用“冻结时点、冻结结论、原逻辑、传播链、正常双向成交”等用户难以理解的词。
- 当前状态和多记录前缀使用具体推荐日期，以正式推荐记录的 `action_date` 为准。
- 不新增定时任务；除既定 `daily-formal-reviews-v1` 日评账本外，不增加其他报告模型或 schema。

## 按观点变化和复盘类型控制深度

- 简评只写当天重要增量：无实质变化通常1—3句，有变化或事件日2—5句，说完即停；只补最重要的新支持或风险，以及是否需要改变下一步判断。
- 详评长度以说清楚为准，不设字数或段数指标。事件详评围绕事件前判断、事件改变了什么、价格反应和观点变化组织，同时完成对应类型的六项或四项信息。
- 普通详评必须覆盖四项信息，合并成句即算成立，不设固定小标题，也不规定句式；确实无内容的一项明写“该日尚无此项可对”，不得省略：①为什么是它——当天入选详评的原因（今日停止、观点明显变化、达到目标或显著回撤、重要公司事项，或长时间未详评的轮换）就是本篇的中心问题，第一句观点更新必须直接回应这个原因；②这件事让当初的推荐理由更强还是更弱、伤在哪一环——定位到行业带动、股票自身相对强度、公司侧、价格量能中的具体一环，不写笼统的强弱结论；③目标余程——距20%目标还剩多少，加一句现实评估（沿用“20日目标的可实现性”一节的五种表述）和当前最大障碍；④接下来盯什么——判断层面的下一个观察点，即什么事实会改变当前评价或推向停止跟踪边界，不复述外层“接下来1—3个交易日”的方向和两个条件；这个观察点收在普通详评结尾作为判断收束，是判断内容的一部分，不是预设验证条件。因长时间未详评而轮换入选、当天没有实质增量的，按②执行“没新闻体检”：逐环核对原推荐链条当前是否仍健康，写不出增量时明写“该日尚无新增可对”，不得硬凑行情复述。
- 对账日（节点、观点实质变化）必须把该说的写全——不凑字，也不为短而砍关键事实。

### D20 最终复盘

D20的六项覆盖以最终展示的完整节点复盘为单位：状态行、当日详评、外层展望与最终结案合起来覆盖六项。当日 `ForwardEpisodeReviewV1.current_review` 只写新增判断和理解结案所需内容；完整前20日对账写入 `final_twenty_day_review.overall_review`，同一事实不在两处重复展开，不新增字段。目标项说明期末结果、尚差多少或无法计算，以及原预设条件如何被检验，不把结案重新延长为20日目标。

D5、D10 的详评可以串起截至当日的阶段路径（推荐初段、中途整理或加速、当前状态），并说明哪些原预期实现、削弱或仍未知；但不能提前形成或冻结 D20 最终结论。D20 是唯一形成完整最终结论的复盘。`current_review` 当天仍只写最新观点增量；完整的前20个交易日结论写入现有 `final_twenty_day_review.overall_review`，不新增字段。它以紧凑总结串起推荐时最重要的判断、D1—D20 最关键的观点变化、是否达到20%、推荐理由最终是否成立、具体股票和时机是否合适、最大成功或错误，以及一条具体经验。程序外层继续使用既有 D20 确定性指标展示收盘、最高收盘和最深下跌；`overall_review` 不重复罗列这些数字。

第21—30日必须原样保留已冻结的 `final_twenty_day_review`。`current_review` 只写 D20 之后新增表现，并说明新表现不改写前20日评价，不形成第二次 D20 结论。比较记录和待确认事件仍不形成正式推荐的 `final_twenty_day_review`。

## 输出

先为 snapshot 的每个 `daily_review_episode_ids` 填写一条 `DailyFormalReviewV1`（三路互斥的 `review_kind`），统一保存为 `DailyFormalReviewLedgerV1`；账本只保存简评类正文，两类详评正文写入对应股票的现有 `ForwardEpisodeReviewV1` 并在 `ForwardMonitorAlertV2` 保存完整展望。`monitor-report` 保存全部节点详评和最多8只普通详评，不保存简评正文；不增加报告版本、评分或概率。

`original_reason_plain_language`：
只通俗改写当时原因，不加入后来事实，也不重复程序已生成的完整推荐日期句。

`current_review`：
按 `review_kind` 只写一个位置：`brief` 写入 `DailyFormalReviewV1.current_review`（600字符上限）；`checkpoint_detail` 和 `regular_detail` 的账本正文为空，正文只写入 `ForwardEpisodeReviewV1.current_review`，分别覆盖六项与四项。第一句先给本次观点，随后按对应类型写全事实、含义与边界；观点变化使用当天的 `view_change`、`view_change_reason`。外层已有的固定状态和完整展望不重复罗列；节点目标余程与结尾预设验证条件、普通详评目标余程与下一观察点仍必须写清。

`outlook_1_3d`：
继续使用现有七类表达未来1—3个交易日的基准判断，并分别落到向上、震荡偏上、横盘、震荡偏下、向下或暂时无法判断；确实无法判断时不要用横盘预测掩盖未知。

`outlook_reason_plain_language`：
先作出方向判断，再用当前最重要的1—3项事实说明为什么这个方向更合理。它与 `outlook_1_3d`、`current_assessment`、`current_review` 保持一致，不复述后面的正反条件。

`confirmation_condition` 与 `invalidation_condition`：
`confirmation_condition` 表示什么后续表现会进一步支持当前 outlook_1_3d，不是支持最初的看涨推荐；`invalidation_condition` 表示什么后续表现会使当前 outlook_1_3d 需要改变。各写一个完整中文句子，按当前方向填写：

| 当前方向 | confirmation_condition：支持当前方向 | invalidation_condition：改变当前方向 |
|---|---|---|
| `strengthening` / `continuation_possible` | 继续提高收盘、继续跑赢市场或行业、成交增加后仍能收稳。 | 连续收低、跌回关键区域、放量不涨、重新落后市场。 |
| `weakening` / `invalidated` | 继续降低收盘、继续跑输市场或行业、反弹不能收稳。 | 连续提高收盘、重新跑赢市场、收复关键区域并保持。 |
| `overheated` | 高位不能继续提高收盘、冲高回落增多、成交增加但收盘降低。 | 重新形成多个更高收盘并保持，且回落明显减轻。 |
| `range_or_wait` | 继续在原区间内波动，成交和收盘都没有形成明确方向。 | 连续突破区间上沿或下沿，并有多个收盘保持。 |
| `event_pending` | 仍缺少可靠可交易价格或关键事实仍未公开。 | 出现完整可交易价格和足以作出方向判断的新事实。 |

例如，当前判断为继续偏弱时，支持条件是“收盘继续降低，并继续落后市场”；改变条件是“连续几个交易日提高收盘，并重新跑赢市场”。不得把恢复上涨写成支持偏弱判断。条件只负责以后验证，不能取代当前方向和理由；这里只做生成前语义核对，不增加中文关键词识别器、评分器或自动 Gate。

其他枚举只供内部记录，不直接显示给用户。
