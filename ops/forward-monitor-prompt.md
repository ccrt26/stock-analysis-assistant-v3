# 现有 18:45 每日任务中的股票跟踪步骤

这一步在下个交易日前一自然日晚间每天只运行一次，属于现有 18:45 任务，不创建新的 Scheduled Task，也不新增定时任务。程序处理全部跟踪记录；当天需更新判断的正式推荐按三路互斥生成复盘：到达 D1/D3/D5/D10/D20 检查节点（含待补 D20 结案）的股票全部做节点详评，不生成简评、不占普通详评名额；剔除节点后按优先级选最多8只做普通详评；剩余股票只写简评。同一股票当天只进入一类，只生成一种正文。节点详评共用同一份六项必备对账清单，缺项明示，节点只决定侧重。面向用户不展示内部字段名、英文值或交易日缩写。

## 1. 程序准备全部跟踪记录

只在 selection prepare 确认明天为交易日后运行；若明天休市，不另加复盘。周日复盘分析日为周五，selection 与 monitor 共用周日18:30截止。长假同理，在下个交易日前一自然日晚间使用最近已收盘交易日。

使用 selection prepare 原样返回的形成日与截止时间运行：

```bash
./.venv/bin/python -m stock_analyzer.ops.forward_monitor prepare \
  --analysis-date <formation_date> \
  --as-of <selection_as_of>
```

程序处理全部跟踪记录，并生成 `local_archive/forward_monitor/snapshot-<analysis_date>.json`。snapshot 的 `daily_review_episode_ids` 是当天必须逐条生成结构化判断并分配唯一正文类型的正式推荐记录，`evaluation_only_episode_ids` 是已停止普通日评但仍保留D20评价的记录，`detailed_review_candidate_codes` 是当天可进入详细复盘的股票。不得建立人工维护的第二套股票池，不得打分。

同一份市场 Skill 结果同时供选后跟踪和当天新选股使用，市场 Skill 每天只分析一次。

## 2. 生成全部结构化判断并按三路分配正文

开始写作前读取 `.agents/skills/reviewing-stock-recommendations/SKILL.md`，包括“按已有合同逐篇执行与复查”，并按上文分类知识库入口读取对应类型的指南与范文。四项／六项是必答内容，不是作文模板；按已有合同逐篇完成证据核对、内容落位与外层去重复检查，不另改分析框架或呈现。

进入普通详评写作时，实际读取 `.agents/skills/reviewing-stock-recommendations/references/regular-review-calibration.md` 的认可稿与改稿对照。先拟第一篇的告知标题并写完正文，核对标题／开头是否讲清今天为何单独告知、调整依据与原观察条件是否相符、四项是否实质回答、与外层有无重复；必要时改稿后再写其余。当前任务运行过程简短说明核对的具体事实与改稿结果，不只说“已通过”，不把检查记录加进最终报告、不另建日志或委派。当天没有普通详评时跳过，不凑股票；其余各篇仍按既有要求逐篇自查。

写作前必须实际打开分类知识库材料（用文件读取打开具体路径，链接不等于已读；失败时如实降级）：

1. `local_archive/knowledge-vault-path.txt` 存在且路径有效时，先读取该子库 `AGENTS.md` 与 `10_方法与范文/00_已确认写作要点.md`，每次任务各读一次，不逐股重复。
2. 只读当天实际出现的复盘类型指南：节点详评读 `10_方法与范文/复盘范文/关键节点复盘/00_阅读指南.md`，普通详评读 `…/深度复盘/00_阅读指南.md`，简评读 `…/简单复盘/00_阅读指南.md`。
3. 按类型、节点阶段和本篇要解决的写作问题，选读最贴近的已确认范文全文及紧邻适用边界；存在明显不同的节点阶段或难点才增读，取消跨类型合计两篇的限制。没有合格范文的类型按指南与既有规则照常写作，不降低事实要求。
4. 已确认改稿对照只在与本篇问题直接相关时读取；同一次任务内已读的同类材料复用，不机械重读。
5. 读取失败：沿现有路径检查一次，仍失败则用仓库现行对应规则写作（普通详评可用 `references/regular-review-calibration.md` 兜底），在任务过程信息中说明一次"自定义知识库未读取成功，已按现行对应复盘规范完成"，不写入逐股正文、不停整份研究、不声称已应用范文。
6. 知识库文字不参与三路分配、不预选观点方向；新成稿不自动升级为范文；`20_个股档案/`、`30_批量复盘/`、优化史与专题不是日常写作输入，本股历史以正式 trace、snapshot 和上轮正文为准。

节点详评、普通详评和简评的 `current_review` 首个独立单行段落为 AI 手写标题“股票名｜核心结论”，空行后接正文；源标题为纯文本，不写 Markdown `###`，简评标题与正文合计仍受600字符硬上限约束。标题和正文是同一份公开原文，既有网页只将这个明确的标题首段提取为标题并显示一次；无此标题的旧稿沿用原格式。

每篇节点详评（D1/D3/D5/D10/D20及待补D20）完成阶段分析后，按复盘 Skill“输出”的节点标题要求提炼首段，突出截至节点的主要阶段结果与当前核心判断。保存前逐篇单独读标题，再与本篇正文及现有结构化判断核对；D20结合该篇最终结案检查。标题示例见下文节点范例区域，六项对账和既有正文存放位置不变。

只处理 snapshot 的 `daily_review_episode_ids`。每个 ID 恰好一条 `DailyFormalReviewV1`，总体写入 `DailyFormalReviewLedgerV1`，版本固定为 `daily-formal-reviews-v1`。conditional、比较股、落选股、未决股、evaluation_only 普通日期和 completed 记录不得进入。

先用 snapshot 的 `checkpoint_review_episode_ids`（节点股的全部合格episode）把当日股票分成三组：K＝节点详评股，D＝普通详评股（从非节点股票按优先级选最多8只），B＝其余简评股。三组互斥，合起来覆盖全部当日需更新判断的股票；同一股票当天只进入一组。

每条记录先读取本 episode 的 `previous_daily_formal_review`；历史兼容时可读取 `previous_episode_review`，`previous_monitor_state` 只用于旧 V1 记录，不得借用同一股票另一 episode 的观点。

每条记录填写 `review_kind`（同股所有episode一致）：节点股为 `checkpoint_detail`，普通详评股为 `regular_detail`，简评股为 `brief`。只有简评类写 `DailyFormalReviewV1.current_review`（600字符硬上限，含标题首段，说完即停）；两类详评的 `current_review` 必须为空，详评正文只写入 monitor-report 的 `ForwardEpisodeReviewV1.current_review`，不得为详评另配隐藏简评。结构化判断（当前结论、主要解释、薄弱环节、观点变化、展望、跟踪决定）三类都要完整填写；上轮观点读取规则不变。

生成顺序：全部结构化判断草稿→摘出 K→非节点中选 D→其余 B→各写唯一正文→同一执行者核对来源与结构化一致性→先 record 账本、后 record 报告。两类详评正文逐只撰写，禁止用程序模板拼接生成；历史补写只按小批量进行（每批不超过8只）并逐批自检。保存前发现详评改变了判断，先同步未保存草稿，不能事后改已保存账本。观点变化说明以当天日评的结构化字段为准，详评不另造一份。

先生成：

```text
local_archive/forward_monitor/pending-daily-formal-reviews-<analysis_date>.json
```

然后记录：

```bash
./.venv/bin/python -m stock_analyzer.ops.forward_monitor \
  record-daily-formal-reviews \
  --snapshot-file local_archive/forward_monitor/snapshot-<analysis_date>.json \
  --review-file local_archive/forward_monitor/pending-daily-formal-reviews-<analysis_date>.json
```

成功后正式文件是 `local_archive/forward_monitor/daily-formal-reviews-<analysis_date>.json`。`live` 记录必须作出 `keep_active_tracking`、`stop_active_tracking` 或 `complete_observation`；`copied_live_archive` 和 `backfill` 只能使用 `historical_not_applied`。

只有两种情况允许 `stop_active_tracking`：原推荐最重要的判断被后续事实否定，且 `current_assessment=contradicted`；或者原推荐无法执行，`current_weak_or_failed_link=execution` 且 `entry_open` 为空。weakening 不能单独停止；单日下跌、横盘、数据暂缺、未达到20%、普通市场回落或短期展望偏下也不能单独停止。达到20%不提前结束，继续记录到D20。

停止主动跟踪后，次日起不再生成普通每日 AI 简评，也不占详评名额；历史不删除，程序仍保存确定性价格到D20；到D20（或更晚的待补结案）以节点详评重新进入并形成最终结论。新推荐必须建立新 episode，不能恢复或覆盖旧 episode。

节点详评共用同一份必备对账清单，**六项信息缺一不可；栏目可合并成句，某项确实无内容时明写“该日尚无此项可对”，不得省略**：①当前主要方向与参与意见，以及这个节点最重要的阶段结论；②原来关键期待与本阶段最关键路径，不逐日记流水账；③市场/板块/公司/技术中真正改变当前机会的证据，原判断外的新变化也可影响当前意见；④为什么更倾向该方向，主要反证/未知是什么，过去上涨不是未来保证；⑤从当前价格看的机会与代价，为什么在相关时间内可能发生，旧20%目标只作原推荐评价参照；⑥哪些事实或已知时点会改变意见。每项按“事实—这说明什么—还不能证明什么”的小单元覆盖，合并成句即算成立，不规定句式、不设字数或数量下限：③不得只写“未知仍在”，须带上未知的具体内容，确无内容时用“该日尚无此项可对”；⑤给出从当前价格出发的现实评估，不把原20%目标当作新买入的合理价位；⑥给出最有价值的改变事实或已知重评时点。节点只决定侧重，不决定要素有无：D1 当天原条件下是否可执行、首日反应怎样检验原判断，不虚构数日持续性（长期路径与持续性明示“尚无可对”）；D3 早期反应是否延续、有无反证；D5 第一周路径与新增证据；D10 前半程对账、主要未知与当前机会变化；D20 当前意见与固定结案同时存在，结案按第20日合同输出到专属字段，当天正文不重复整段结案。节点依据：D20 是观察期定义，D1 是执行性制度检验，D3/D5/D10 是与本地验证窗口一致的检查节奏；修改节点位置必须给出本地数据证据。D25/D30只用于已经明确延长的记录，且不得改写D20；D30必须完成；不新增其他节点。

公告正文继续按 V4 规则按需读取，不批量下载。原五个 Skill 继续负责选股；复盘时，市场、板块、公司和价格四个专业 Skill 的 `phase: review` 只提供各自事实与解释，不重新推荐股票。`reviewing-stock-recommendations` 负责跨时间综合；总控只检查记录一致性。公司事实是否仍成立，和股价成交是否实际支持该事实，必须分开写。不得改写原始完整判断、当时理由或前20个交易日的冻结结论。

### 当前机会意见（current-opportunity-v1）

每天对每条需复盘的正式记录，先依据当前事实与参考价形成“当前机会意见”，写入日评账本的 `current_opportunity` 对象；它是唯一权威存储，不写入 alert 或详评对象，也不在正文外再造第二份。

- `reference_close` 只取本 episode `review_context.price_levels.current_close`，`reference_date` 是 snapshot.analysis_date；这是分析日口径的收盘参照，不是原推荐入口，也不是次日保证可买价格。本日可信收盘缺失时两个 reference 字段为空，不拿前日收盘冒充本日；可以解释以前走势，但不支持“现在按此价考虑参与”。
- `outlook_5_10d` 面向本次分析日之后的实际交易日，是当前机会观察窗口：不重启原推荐周期，不设固定盈利目标。原 `outlook_1_3d` 七种枚举不变；两个窗口可有不同方向，理由须说清差异。
- `participation` 四种：`consider`（当前条件下可考虑参与，必须有明确当前证据、价格依据和参与限制，禁止写成无条件立即买入）、`wait`（等待所述条件，说明等什么及为什么值得等，不是万能兜底）、`avoid`（当前暂不参与；可与原推荐仍有效并存，不自动停止跟踪或标记选错）、`insufficient`（关键资料不足；不把方向未知自动写成横盘）。
- `participation_reason` 说明首选意见的依据与实际含义；涉及收盘确认、等待突破等方案时，写明信号何时知道、下一可用时段与价格变化后需重评。没有充分执行材料的“考虑”不得写成已经满足的买入指令。
- `change_condition` 写最有价值的改变事实或已知重评时点，不任意发明数值、日期或线性日涨幅。
- 同股同日、相同事实截止/参考价/窗口时，当前意见计算一次并保持一致；原推荐评价与结案仍逐 episode。
- 展示：Markdown 与两个网页从已保存账本读取该对象显示“当前机会”区域；状态行与目标标注为“原推荐参考价/原20%观察目标”。`view_change` 维持旧复盘口径，不重新定义为买卖信号。
- 研究顺序：先读本股当前截至 snapshot.as_of 的事实与原记录身份、回顾上轮当前意见及必要原理由；四专业 Skill 给出当前事实、对下一段的支持、最强反证和未知（允许相关新变化超出原推荐原因，但不新增股票、不改旧身份）；复盘 Skill 综合形成当前方向、1—3日节奏、参与意见与改变条件——先依据证据形成判断，不从范文预选方向；原推荐是否被支持/否定及跟踪决定作为独立判断保留；再按三路写唯一正文。

### 第20日：当前意见与原推荐结案同时存在

固定结案仍使用 `FrozenTwentyDayReviewV1`，完整旧结案仅放 `final_twenty_day_review.overall_review` 并公开一次；当天 `current_review` 写当前更新，`current_opportunity` 写当前窗口，不把新判断塞进被冻结的原结案。固定结案按自然段说清五件事：①本次原来期待什么、最担心什么；②原第1—20日是否以收盘触达20%，第20日期末结果与过程最大上涨/下跌/回撤，使用既有程序数据、来源与单位清楚；③哪个原判断获得支持/被削弱/仍无法判断——上涨不自动证明原原因，下跌不自动否定公司事实；④差异更像原信息理解/候选选择/时机/执行/后来新变化还是无法区分，用具体原证据说明，不凭未达20%直接给价格Skill判错；⑤提出一个可供批量检查的问题，或明确没有可靠可迁移教训，不把单例经验写成今后必用规则。`weak_or_failed_link`、`decision_review` 沿用现有枚举，把握不住用 unknown。

晚补结案：原第20日以后的上涨或新事件不改前20日触达/期末结果；数字仅取原前20日；新文章当前意见可用本次 as_of，旧结案的原因资料必须使用原第20日允许的事实截止，二者明确分开；连原截止也无法可靠恢复时，仅用第20日15:00上海时间前可确认事实作保守说明并写明盘后资料未纳入；缺少完整路径保持 missing/unknown，不记未达标，不借用后一天开盘或删除缺失日。后来发现归因可能错，可在批量研究或知识库“事后讨论”纠正认识，旧正式结案不偷偷覆盖。到期只结束这一条推荐评价，不自动卖出、不把股票永久拉黑；第21—30日沿原流程，新5—10日判断超出旧生命周期不授权新日常任务。

### 数据缺口只补一次

如果 snapshot 出现 `missing_price_path`、`missing_current_price_context`、`missing_market_context` 或 `missing_sector_context`，且对应交易日已经收盘，先按缺失类型使用现有流程定向补一次：

```bash
./.venv/bin/python -m stock_analyzer data run-stage \
  --stage pre-research \
  --data-date <analysis_date> \
  --as-of <selection_as_of>
```

`pre-research` 按分区精确补缺，并按同一个18:30截止重建派生结果；不得用当前时间或默认日末截止替代 `selection_as_of`。补数后重新运行一次 monitor prepare，仍缺失就明确具体限制，不得循环重试。不得为一只股票执行全市场财务回填、增加数据源或增加任务。

若缺少的公司财务或公告正文会直接改变原推荐判断，公司 Skill 沿现有官方链接定向读取一次；无关月报、例行公告、单个公告标题或非核心细节不得主导整只股票的复盘。仍无法取得时只说明哪一项无法核对，继续分析其他已有事实。只有推荐参考价或整段行情确实不存在，才能说不能评价距离20%观察目标的进展。

相对行业表现与行业上涨面必须分开：`relative_industry_*` 表示股票相对形成日有效申万二级行业的表现，`sector_breadth_*` 表示 `original_group_code` 对应行业或主题的成员上涨面。前者存在而后者缺失时，只能说无法核对多数成员是否同步，不得说行业数据全部不可用；后者存在而前者缺失时也不得抹掉上涨面事实。


## 3. 生成走势复盘日报

完成全部结构化判断并正式记录账本后，生成严格符合 `DailyForwardMonitorReportV2` 的复盘日报。prepare 输出 `checkpoint_review_stock_count`（节点股数）与 `regular_detail_stock_limit`（普通详评上限，非必填篇数）。报告恰好覆盖两类详评股票：全部关键节点股（K）加上从非节点股票中选出的普通详评股（D，0—8只，按需可为0）。一只股票在报告中只出现一次，同股多个正式 episode 的每条记录分别复盘；每条使用一个 `ForwardEpisodeReviewV1`，前20个交易日的最终结论使用 `FrozenTwentyDayReviewV1`：

```text
local_archive/forward_monitor/pending-report-<analysis_date>.json
```

报告必须严格对应当天 snapshot：

- `market_propagation_mode` 只能是 `broad_sustained_participation`、`one_day_repair`、`sector_rotation`、`concentrated_speculation`、`weak_or_fragmented`、`unclear` 之一；
- `pool_summary` 和 `unreported_attention_count` 必须与 snapshot 完全一致；
- 每只详评的 `episode_ids` 必须包含该股票当天全部需更新判断的正式 episode，不得混入 conditional、比较或落选记录；`roles`、交易日序号和原始完整判断必须从这些记录完整得出。
- `episode_reviews` 中的 `episode_id` 必须与该股票当天全部需更新判断的正式 episode 完全一致，不得缺少、重复或多出；不得用该股票最大交易日序号替其他记录结案。
- `alert_type=routine_detail` 表示当天没有重大异常，但按轮换进入详细复盘；它不是第二套关注池。
- 每条记录的 `ForwardEpisodeReviewV1` 只填写通俗原因与风险、当前判断、现有证据最支持的解释、当前最弱环节、独立展开的详评正文、成对比较解释和 `final_twenty_day_review`，不增加分数、概率或更多分类。
- 每只新提醒必须填写 `outlook_reason_plain_language`，用当前最重要的1—3项事实说明未来1—3个交易日为什么更可能向上、横盘、向下或暂时无法判断。先作出方向判断，不写“如果……就……”，不重复两个验证条件，也不照抄整段 `current_review`；它必须与 `outlook_1_3d`、`current_assessment` 和 `current_review` 一致。没有可交易价格或证据冲突时可以说明目前无法判断方向，并明确缺少什么。
- best_supported_explanation 等枚举继续在内部填写；current_review 才是公开分析核心，要写成连贯的观点更新短评，不向用户解释内部字段。why_reported 只说明今天为什么复盘，不参与涨跌归因，不直接展示。
- 具体推荐日期必须取该次正式推荐记录的 `action_date`，放在当前状态的简短前缀中；同股多个 episode 分别保留推荐日期和交易日序号，不能用复盘日期或当前日期代替。
- `confirmed_active` 和 `legacy_v1_not_rewritten` 两类正式推荐记录在第1至第19个交易日，`final_twenty_day_review` 必须为空；第20个交易日必须首次形成。第20天漏跑时，`pending_final_review` 必须持续排在提醒原因第一位，直到结论成功保存并在下一次 prepare 恢复。第21至第30个交易日不得改写这个结论，只能更新当前走势评价。snapshot 已有 `frozen_twenty_day_review` 时必须原样使用；漏跑后首次建立也只能依据 `d20_*`、前20个交易日以内的事实和已冻结原判断。
- 比较记录的 `final_twenty_day_review` 始终为空；`conditional_event` 也始终为空，二者都不能写成正式推荐的最终结论。
- `original_reason_plain_language` 和 `original_key_risk_plain_language` 只通俗改写当时已经冻结的意思，作为内部历史锚点，不加入后来事实；各自第一句写成简短的“当时主要看中……”和“主要担心……”。简评不重复完整原理由和风险；节点详评仍须回顾六项清单中的原期待与担心，普通详评核对四项所需的原推荐理由。D1 可取这两个字段的首句作简短背景，D20 的完整结案另用最终复盘字段。
- 原始完整判断缺失时，内部保留 `missing_original_research_thesis`；复盘按已知部分继续：episode 仍保存的 `original_primary_reason`、原风险、`original_market_recognition` 或原决定引用都是可用锚点，只有未知的具体部分如实说明未保存。不能机械说"只能复盘价格表现"，也不能把记录完整性问题写成投资判断变弱：数据缺口只进入 `data_limitations`，观点变化只由经济事实或已核实的原证据纠正驱动。
- 内部仍可使用真实成对价格路径帮助判断最初是否选对股票，但比较记录不进入本轮重点详评，不在用户报告展示替代股名称或表现。
- 当前状态只显示推荐后的交易日序号、当前收盘相对推荐参考价、期间最高收盘和最深下跌，缺失项不补猜。若 `current_review` 确需引用相对表现，按真实1、3、5或20个交易日窗口说明，不把这个窗口写成“从推荐以来”。
- D1—D4 的五日收益、连续性和最大上涨日字段可能跨越形成日前后，只能作为近期背景，不得冒充为完整的推荐后五日路径。

### 内部日报和用户复盘分开处理

snapshot、原始事实与 trace 是内部完整记录，继续保存全部推荐、比较、待确认事件、公告候选、成对价格和 attention 原因。`daily-formal-reviews-<analysis_date>.json` 是状态账本：保存当天全部需更新记录的结构化判断，以及仅简评类（`brief`）的正文；两类详评正文只存 `DailyForwardMonitorReportV2`（全部节点详评和最多8只普通详评），不保存未进入正式推荐的事件线索或比较记录。它们仍留在 snapshot、原始事实与 trace 中，不等于删除。不得为了让最终文字更短而删掉内部事实或改变记录合同。

### 正式推荐股票的今日复盘

“正式推荐股票的今日复盘”只能出现被明确正式推荐过的股票。

允许展示：

- `confirmed_active`
- 历史上明确正式推荐、但无法无损重建V4分类的 `legacy_v1_not_rewritten`

禁止展示：

- `conditional_event`
- comparator
- nearest_nonselection
- rejected
- unresolved
- 普通观察股
- 内部关注股

待确认事件保留在 snapshot、原始事实与 trace，但不得写入 `daily-formal-reviews` 或 `monitor-report`，也不得出现在“正式推荐股票的今日复盘”中，并且不得单列给用户凑内容。面向用户不展示比较股名称，也不显示“还有多少内部股票未展开”。同一股票同时有正式推荐和比较记录时，对外只讲正式推荐 episode。

### 复盘不是行情播报

复盘在内部先恢复当初推荐时真正期待发生的事情，再用推荐后的事实检验；公开正文从今天的变化开始，不完整介绍公司或重新论证当初为何推荐。

内部仍要恢复当初期待看到什么，选择最有证据的主要解释，判断哪一项核心预期真正实现以及当前阶段，并给出未来1—3个交易日的判断。但 `current_review` 不展示这套推理步骤，而按以下原则形成观点更新稿：

简评是复盘对账主线的当日切片：上轮复盘留下悬念，今天用事实回答，落点落在原推荐链条的具体一环。以下各步是简评的增量写法；节点详评和普通详评以对应六项／四项完整覆盖为准，不能因“一句话足够”或“一个事实足够”省略必备内容。

1. **标题即中心判断**：首个独立单行段落写“股票名｜当天中心判断”，读者不看正文就知道今天在回答什么问题、结论偏向哪边；标题与正文合计仍在600字符内。标题来自第2步的中心问题，不写成“第几天＋维持判断”式标签，也不复述外层已展示的价格数字。
2. **一个中心问题**：选择这只股票当天最重要的问题，其他信息只有能改变该判断时才使用。中心问题优先从上一轮的观察条件和明示未知里来，而不是当天涨幅最大的那件事。只有一项次要变化会影响下次复盘时，才在结尾用一句话提醒。
3. **一句话观点更新**：第一句直接给出最重要的变化和方向判断。
4. **最少决定性事实**：只使用回答中心问题所需的事实，不设固定数量指标，也不设最低数量；一个事实足够时立即停止，不得凑数。停牌且没有价格时，可以没有推荐后价格事实。每个被引用的事实后面跟一句它说明什么，不让数字裸奔。
5. **与上一次复盘比较**：结合上一轮结构化字段与文字中心，填写当天 `view_change` 和 `view_change_reason`，由外层直接展示，不在详评重写一份；无上一轮时只与原推荐判断比较，不机械声明首次复盘。
6. **当前综合判断**：说清原推荐的关键一环是实现、减弱还是未知，并写明今天伤的是或撑的是哪一环（行业带动、股票自身相对强度、公司侧、价格量能），不写笼统强弱；后续基准判断由现有外层展望单独展示。

简评的三条红线：不复述外层已展示的价格数字和“维持／增强／减弱”卡片原文；不写把股票名换掉仍然成立的行情复述；标题、观点和每个事实都能追溯到当天 snapshot 或正式材料，不得把单日缩量、盘中回落写成买方人数、账户身份或唯一原因。

不平均复述市场、行业、公司和价格四路内容，不以“最有证据的解释是、当前阶段是、核心预期目前得到支持”作为固定句式。只有与中心问题直接相关时，才简要说明为什么这一解释比其他解释更有证据；`current_review` 不需要逐项证明其他解释全部错误。数据限制只有会改变结论时才写一句；例行公告不进入分析正文。

例如：

- 当初因为突破前高而推荐，后来跌回前高下方：这会削弱推荐，因为突破只有站稳才说明市场接受了更高价格。
- 当初因为行业普遍上涨而推荐，后来同行多数转弱但该股仍上涨：行业理由减弱，但股票自身可能仍强。
- 当初因为公司新合同而推荐，后来公告真实但股价和成交没有变化：公司事件仍然真实，但短期上涨预期没有被市场行为验证。
- 股票上涨并不自动证明原理由正确。若大盘和同行涨得更多，原先认为它更强的判断仍可能错误。

事实与观点分开。`current_review` 中每一项具体的日期、百分比、金额、股票数量、公告名称和财务变化，都必须能追溯到当前 snapshot 或 monitor report 的确定性字段、原推荐 trace，或当日按现有流程读取的正式公司材料中的明确字段和值。百分比和日期可以换算格式，但要保留来源字段和原始值。上一轮 `current_review`、旧日报中的 `company_change` 等 AI 自由文本只能作观点锚点，不能作新事实来源。相对表现、公司事件与价格反应、价格成交组合、原推荐检查点只支持目前更合理的解释，不证明唯一原因。现有证据不能区分原因时，直接说不知道并说明缺什么，不为完整感编故事。

### 数值口径与证据核对

snapshot episode 的 `review_context` 提供带固定口径的复盘价格上下文：`post_entry_sessions`（行动日至分析日逐会话路径）、`recent_sessions`（分析日及前4个会话的量价与量比）、`benchmark_windows`（沪深300的1/3/5/20日窗口）、`benchmark_return_since_entry` 与 `stock_excess_since_entry`、`price_levels`（入口参考价、当前收盘、前60日高点、ATR20、目标价与剩余距离）。使用规则：

- `basis` 标注了口径：市场基准是沪深300（`benchmark_code=000300.SH`），入口是行动日开盘，价格是“原始价×当日复权因子÷分析日因子”的归一口径，金额单位为人民币元。引用这些数字时不得换成其他基准、起点或口径。
- 相对入口收益以行动日开盘为起点；`benchmark_windows` 是市场窗口收益，不是“推荐以来”收益；`remaining_*` 字段是距离原推荐20%目标的余程，保留符号。
- 允许直接做格式换算（百分数、四舍五入、元/亿元）；窗口收益、ATR、现金流比值等必须引用工具算好的数值或按字段原值引用，不凭空心算派生结论。
- 关键价位（前高、目标价）是观察条件，不是“套牢盘”“真实抛压”之类的机制断言；ATR距离不产生成功概率。
- 公司事实的复盘截止是本次snapshot的 `as_of`，不是原推荐的 `source_as_of`，也不是执行时的当前时钟。原推荐 `source_as_of` 只用于还原当时判断。
- 公司经营核对只在原判断相关、阶段检查或重大变化时按需进行，使用相同报告期、合并范围与可比同期；现金流、利润、应收、存货各自回答什么必须说清，不相互顶替。

**写作总标准：事实、时点、口径和来源必须准确且可追溯；在此基础上使用普通中文表达。**
1. **可追溯**：每个关键判断都有可追溯依据，并解释它支持什么、还不能证明什么。
2. **说人话**：直接说事，不表演通俗。每句直接陈述"发生了什么、意味着什么"，支撑数字放在它解释的事实旁边；不打比方、不做"术语＋行话注释"的双轨写法、不刻意口语化。通用市场词（缩量、放量、逆势、回撤、抛压、上影）可以直接用；生僻术语宁可不用，用一句直接描述代替。

说人话不降低可追溯：每个关键数字仍必须在保存前核对来源。范例只指导表达，不替代来源证据；不能照搬范例中的因果措辞，把量价写成账户身份、套牢盘或唯一原因，也不能把单日涨跌当作因果证明。阶段详评应让读者理解原预期如何被后续事实检验。正式事实（停牌、订单取消等）不需要凑数字才有分析价值。

知识条目不按配额引用。当某条知识实际改变了一项解释或确信程度时，在对应alert的 `stock_change`/`company_change`/`market_change` 内部字符串末尾追加简短记录：`知识：条目ID；本次用途：具体哪项解释被限制/支持；不能推出：具体边界。` 没有实际作用就不写。

保存前由同一执行者对照来源核对一次：

- 股票/episode、起止日、沪深300/行业口径是否一致；
- 每个关键数字是否能在明确字段或本次工具结果中找到；
- 是否把回落、前高、成交变化写成买方人数、账户身份或唯一原因；
- 新判断是否真的由经济事实或已核实的原证据纠正导致；
- 简评、详评、方向和条件是否一致；条件尚只部分出现时是否如实说明；
- 每句是否直接说事；删掉比喻、"行话叫××"式注释和刻意口语化后是否更清楚；
- 是否存在"描述＋术语标注"双重解释；能直接描述就不标术语；
- 支撑数字是否紧跟它解释的事实，有没有堆成没有主语的数字串；
- 事实有含义吗（每个关键事实配了它说明什么）；
- 判断给理由了吗（立场后跟支持事实与限制因素）；
- 边界划了吗（还不能证明什么已写明）。

`current_review` 可以用一句话说明“20%目标仍有现实可能”“需要重新加速才有可能”“目前已明显变得困难”“已经不再以完成目标为主要判断”或“无法计算”。这只是结合实际路径更新可实现性，不新增结构化字段，也不按每天1%线性推算。

### 文风基准（照此行文，不照抄内容）

文风目标：像内行的人当面平实地讲盘面——句子短、直接说事、数字紧跟它解释的事实。不表演通俗：不打比方；不做"术语＋行话注释"的双轨写法；不刻意口语化。本节只定文风：三段式小标题、观点变化与两个条件由外层展示、字段分工、事实追溯和字数参考仍按上文各节执行。

节点详评六个动作：判断开场、事实配含义、对比生张力、三分兑现、否定划界、判断带论证。

D20 范例暂缺，留位待补；此前 D20 详评按同一六动作与小单元要求撰写。

判断句规格：正文里的判断写成“立场＋当前最重要的1—2个支持事实＋限制因素”。普通详评可以在正文核对上次约定的条件今天是否发生，结尾按第四项写判断层面的下一观察点；节点详评结尾按范例收预设验证条件。完整未来方向与正反条件仍交给外层，不得用“如果……就……”代替当前判断，内部枚举不得直译成正文。

当前采用的三类范文按第 2 节的知识库入口在股票知识子库分类维护；下列历史样稿、标题提炼示例及其更正记录已原样迁至 `.agents/skills/reviewing-stock-recommendations/references/review-writing-legacy-examples.md`（历史样稿与更正记录，默认不作为每日必读范文，仅用于核对历史写法与更正依据）。本 Prompt 正文不再无条件内嵌全部历史范文全文。

### `current_review` 与现有渲染器的分工

简评 current_review 只负责当天重要增量及其含义；详评正文按节点六项或普通详评四项完成对账，允许回顾必要的原期待、阶段事实与目标余程。观点变化的完整说明交给 `view_change_reason`，不在正文再列一遍。节点详评、普通详评和简评的标题首段由网页提取为标题显示一次，正文不再重复标题行；无标题的旧简评按首句展示，不回写。

- 不再重复完整推荐日期；
- 不再重复当前、最高、最低的全套路径；
- 不再重复距离20%目标的固定进度句；节点六项和普通详评四项要求的目标余程与现实评估仍须写清；
- 不再重复未来1—3个交易日的完整展望；
- 不再重复 `confirmation_condition` 和 `invalidation_condition`；节点详评结尾按既有范例收预设验证条件，普通详评结尾收判断层面的下一观察点。

只有某个日期或数字直接决定中心判断时，才可在 `current_review` 中再引用一次。`original_reason_plain_language` 只通俗改写当时理由，不再自行加完整推荐日期；`original_key_risk_plain_language` 只改写当时风险。

### 日常复盘、事件复盘、阶段小结与 D20

- 简评只写当天重要增量及其含义，独立可读：无实质变化通常1—3句，有变化或事件日2—5句，说完即停；600字符硬上限不变，标题首段计入其中。标题规则见“复盘不是行情播报”一节，与普通详评同格式。
- 事件详评围绕事件前判断、事件改变了什么、价格反应和观点变化组织，仍完成对应类型的六项或四项信息；例行公告不进入正文。
- 详评长度以说清楚为准，不设字数或段数指标：节点详评必须完成上文六项对账清单（缺项明写“该日尚无此项可对”），写完为止，不凑字也不砍事实。
普通详评必须覆盖四项信息，合并成句即算成立，不设固定小标题；确实无内容的一项明写“该日尚无此项可对”，不得省略：①今天为什么值得详写；当前方向与参与意见是调整还是维持；②哪些变化及必要历史支持本次判断，最有力反证如何影响意见；③以当前价格和时间要求看是否值得参与；看涨不等于值得追入，便宜不等于好机会；④下一步需要观察/执行的关键条件与重新判断时点，不把条件两边罗列后拒绝作当前判断。因轮换而详评可以维持意见，不能为了“有变化”制造事件；正文不强制固定段数或小标题。普通详评范例见文风基准节。
- D5/D10 阶段小结可以回顾推荐至今的关键阶段，但不得提前形成或冻结 D20 最终结论。
- D20六项按最终展示的完整节点复盘核对：状态行、当日详评、外层展望与最终结案合起来覆盖六项；当日正文只写新增判断和理解结案所需内容，完整前20日对账放最终结案，同一事实不在两处重复展开。目标项说明期末结果、尚差多少或无法计算，以及原预设条件如何被检验，不重新延长原20日目标。
- D20 最终复盘的完整总结仍只在 `final_twenty_day_review.overall_review` 出现一次。`current_review` 当天仍只写增量；完整总结检验推荐理由、具体股票、时机、最大成功或错误和一条具体经验；D20 收盘、最高收盘和最深下跌仍由程序外层展示。
- 第21—30日必须原样保留已冻结的 `final_twenty_day_review`；`current_review` 只写 D20 之后新增表现，并说明它不改写前20日评价，不形成第二次 D20 结论。比较记录和待确认事件仍不形成正式推荐的 `final_twenty_day_review`。

最终 Markdown 的两类详评每只股票先以“当前状态：”一行显示推荐日期、推荐后的第几个交易日、当前收盘较推荐参考价涨跌、期间最高收盘和期间最深下跌；只显示真实取得的价格部分。随后只使用以下三个固定小标题：

**今天发生了什么**

本栏目读取当前类型的唯一正文，不再生成第二份摘要。关键节点复盘：按节点六项回看截至该阶段的关键路径和原期待兑现情况；第20日完整结案仍在专属字段只出现一次。普通深度复盘：围绕今天入选详评的真实原因，完成既有四项；仅回顾解释本次变化所必需的历史，不要求把整段推荐历程重新讲一遍。简单复盘：正文仍取当天账本，只讲当天增量，不从详评压缩生成。共用页面标题不代表三类正文的问题、证据组织和展开范围相同。

**相比上次判断**

直接使用当天 `view_change` 与 `view_change_reason`，不让详评再次创作：`unchanged` 为判断没有实质变化，`strengthened` 为判断增强，`weakened` 为判断减弱，`invalidated` 为原判断已被事实否定，随后展示原样保存的原因。`first_review` 直接展示原因，只有确有必要时才在原因中说明这是第一次正式复盘。

**接下来1—3个交易日**

依次展示当前基准方向、`outlook_reason_plain_language`、进一步支持当前方向的表现、会让我改变当前判断的表现。理由必须在两个条件之前，不写两边都可能的空话。

原推荐背景与对账按以下分工出现：

- D1/D3/D5/D10节点正文须回顾六项中的原期待与担心；D20在最终结案中完成回顾。D1、D5、D10、D20 的详评可展示一到两句原推荐背景（“当时主要看中……；主要担心……。”），忠实于原trace；已有同episode的可靠白话背景可复用。原始完整判断未保存时，使用episode仍留存的概要理由与风险，并注明这是当时留存摘要；不得因thesis缺失抹掉这些概要锚。
- 简评不公开完整原理由和原风险；普通详评和 `routine_detail` 回顾理解四项信息所需部分，不把“只讲今天”用于省略原推荐理由的核对。
- 当天 `view_change=invalidated` 且不说明原判断就无法理解时，`current_review` 可以用一句话提及原来期待什么。
- D20 在三段更新之后增加独立的 `**20个交易日最终复盘**`，展示 `FrozenTwentyDayReviewV1` 的通俗结论及前20日确定性价格事实；完整结论只出现一次，不再写入 `current_review`。D20 后继续观察时保留原最终结论，只更新此后的事实。
- 同一股票多个 episode 使用简短的“推荐日期（第几个交易日）：”前缀区分，三个标题每只股票只出现一次，不重复完整原推荐理由和风险。

没有 daily_ledger 的旧 V1/V2 报告继续可读，不回写、不迁移历史文件；旧 V2 新渲染采用同一三段模板，正文使用已有 `current_review`，缺少上次观点比较时如实说明未保存，不补写。

outlook_1_3d 保留现有七类，公开方向固定为：strengthening“未来1—3个交易日更可能继续向上”，continuation_possible“未来1—3个交易日更可能震荡偏上”，range_or_wait“未来1—3个交易日更可能横盘整理”，weakening“未来1—3个交易日更可能震荡偏下”，overheated“未来1—3个交易日更可能高位震荡，短线偏下”，invalidated“未来1—3个交易日更可能继续偏弱”，event_pending“目前没有足够的可交易事实判断方向”。确实无法判断方向时不得用横盘预测掩盖未知。

公开支持标签随方向分别为“会进一步支持向上判断的表现”“会进一步支持震荡偏上判断的表现”“会继续支持横盘判断的表现”“会进一步支持偏弱判断的表现”“会进一步支持高位震荡偏下判断的表现”“会继续维持暂时无法判断的事实”；改变条件统一为“会让我改变当前判断的表现”。

`confirmation_condition` 表示什么后续表现会进一步支持当前 outlook_1_3d，不是支持最初的看涨推荐；`invalidation_condition` 表示什么后续表现会使当前 outlook_1_3d 需要改变。各写一个完整中文句子，按当前方向填写：

| 当前方向 | confirmation_condition：支持当前方向 | invalidation_condition：改变当前方向 |
|---|---|---|
| `strengthening` / `continuation_possible` | 继续提高收盘、继续跑赢市场或行业、成交增加后仍能收稳。 | 连续收低、跌回关键区域、放量不涨、重新落后市场。 |
| `weakening` / `invalidated` | 继续降低收盘、继续跑输市场或行业、反弹不能收稳。 | 连续提高收盘、重新跑赢市场、收复关键区域并保持。 |
| `overheated` | 高位不能继续提高收盘、冲高回落增多、成交增加但收盘降低。 | 重新形成多个更高收盘并保持，且回落明显减轻。 |
| `range_or_wait` | 继续在原区间内波动，成交和收盘都没有形成明确方向。 | 连续突破区间上沿或下沿，并有多个收盘保持。 |
| `event_pending` | 仍缺少可靠可交易价格或关键事实仍未公开。 | 出现完整可交易价格和足以作出方向判断的新事实。 |

例如，当前判断为继续偏弱时，支持条件是“收盘继续降低，并继续落后市场”；改变条件是“连续几个交易日提高收盘，并重新跑赢市场”。不得把恢复上涨写成支持偏弱判断。条件只负责以后验证，不能取代当前方向和理由；这里只做生成前语义核对，不增加中文关键词识别器、评分器或自动 Gate。

四路 `market_change`、`sector_change`、`company_change`、`stock_change`、`why_reported`、成对比较和待确认记录继续保留在内部 JSON 和 snapshot，公开 Markdown 不直接拼接这些文字。不得为了缩短公开文字而删除内部事实或记录。

行动日停牌、没有可靠开盘价或无法按原条件参与时，阶段必须写“无法按计划执行”，不得当作普通资料缺失。若推荐后才停牌，先分析停牌前的可执行价格路径。

用户不是来读取行情表。每只股票在内部恢复当初期待，再用最少的关键事实说明今天的变化怎样更新判断。不要机械分成“市场方面、行业方面、公司方面、个股方面”，也不要依次朗读内部判断、薄弱项和解释分类。无法可靠区分原因时直接说不知道，不能编故事。

内部成对比较继续用于判断当时是否选错股票，也继续填写结构化内容；最终对外不出现替代股名称、代码、角色、单独表现或比较栏目。

### 必须说人话

- 不显示内部字段名、英文枚举、记录编号、内部角色、交易日缩写或流程状态。
- 不机械重复“目前……整体……仍需观察”“从数据来看”“综合来看”等空话。每句话都要说明一个具体变化、原因或后续含义。
- 不把固定栏目逐字复制成空模板；问题可以相同，但表达要根据这只股票真正发生的事情自然组织。
- 如果一句话换成任何股票名称仍然成立，说明太空泛，必须重写。
- 不从量价猜测机构、主力、游资或账户身份；没有证据的原因就说未知。
- 只保留必要的一次时间边界说明；不提供收益承诺、仓位、自动交易、止盈或止损建议。

普通详评（非节点股，最多8只）按以下顺序考虑：

1. 今日停止主动跟踪；
2. 观点明显变化；
3. 达到20%或出现显著回撤；
4. 重要公司事项；
5. 必要时按最长时间未详评轮换补足。

这只是复盘资源顺序，不是投资排名。不得按股票代码、涨幅、推荐顺序、行业或发动机机械挑选，不建立分数或权重。优先股不超过8只时必须全部纳入普通详评；超过8只时详评恰好8只且全部来自优先股，其余股票在简评中如实披露重要变化。节点股不参与该队列（已全部节点详评）；没有普通详评需要时允许0只，不为凑数注水。

D21—D30 的 `late_activation` 面向用户必须写成“这只股票在前20个交易日结束后才开始明显走强，因此不会改变前20天的原评价结果”。达到原目标只说明已达到，仍记录到 D20，不自动生成新的买入建议。提前判断失效后不再放入普通详细提醒，但程序仍记录到 D20。
