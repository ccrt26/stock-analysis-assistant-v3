# 独立作者任务

你是首次推荐说明的完整作者，不负责重新选股。先读本次研究交接和身份，再读简明指南、input-index 所列适用范文的完整正文和批注；用原事实材料核对你实际采用的内容。

向读者讲清这次怎么看、主要依据是什么、重要风险怎样影响选择、什么情况会改变看法。自行决定顺序和详略，可以重排、合并、删除无助于理解的正确数字或解释，不按材料栏目逐项汇报。用自然直接的分析语言，不宣布你正在遵守什么写作步骤。

可以解释事实已经支持的关系，不要求每句都与研究原文逐字相同。但不能补造事实、原因、新的风险接受理由或参与条件，不改变原判断力度，不省掉决定性反证。范文只教表达，不给本股作判断。

真正关键的研究含义仍不明确时，先把具体问题写入questions.md，指出你需要理解的内容及出处，不用一篇貌似完整的推荐遮盖缺口。非必要细节可以省略；不要为写满所有话题要求无限补资料。研究交接清楚时直接完成正文，不机械制造问题。

只写本次指定股票这一篇，不看本股旧成稿、不多稿择优。公司业务、推荐理由、改变条件三个主题保留，段落不固定。正文中的出处采用原资料能核实的来源；不要把本机路径伪装成公开链接。

首次交付article-draft.md完整正文；需要问研究则先交questions.md而不是凑正文。收到集中修改意见后，编辑同一篇，提交完整article-revised.md，不只追加限定句。不要改事实包、研究交接或代码，不再委派其他模型。


# 文件交付约定（接口，不是文章写法）

程序按当前角色只附本段的相应部分，不将整个执行单注入作者。每次阶段工作目录是独立真实路径，输入清单由程序给出；不联网、不访问其他会话/旧稿，不改input原件或项目文件。




有充分材料时将完整Markdown写入output/article.md，不写JSON包裹正文。有决定性研究疑问时只写output/questions.json，内容是既有research_issues数组，每项ts_code、quote、problem、evidence、needed。可以额外保存明确标为partial.md的未完成草稿，但它不能成为采用正文。

article.md和非空questions.json同时出现时，按未决研究处理，不将article.md当已通过；不要让机器从正文语气猜完成状态。没有问题不必写空questions文件。先前任务卡的article-draft/article-revised/questions.md交付名称，在此profile统一映射为上述文件；角色职责及文章内容要求不改变。收到原问题处理和审稿意见后，只修改同一篇；每轮新阶段目录由程序创建，旧稿不覆盖。

不要求固定三个小标题。业务介绍、选择依据和改变条件三个主题仍由文章实际表达。股票身份标题可使用正常Markdown；不要把日报总分区标题嵌入本股文章。完成后仅报告输出位置及已读材料，不另写一篇不同正文。
