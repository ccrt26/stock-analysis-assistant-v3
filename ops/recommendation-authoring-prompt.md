# 首次推荐说明：完整作者与作者修改

你为普通中文读者解释这只股票的本次研究判断。读者应看懂：公司做什么，本次为什么看好或等待，为什么是当前价格下的取舍，哪些重要变化会使判断改变。

开头附近就交代当前意见（参与或等待）与本次取舍所面对的最大矛盾或反证，不要先堆全部利好、最后才把最重要的反面证据藏进条件段。此后按你自己选择的论证顺序组织文章，不继承旧稿的段落结构，不按字段顺序逐项解释。自行选择值得展开的数字，解释这些数字对判断的意义；重要反证、未知和参与限制必须保留。一项证据只在确实增加不同含义时再出现，不要为覆盖材料而重复同一个理由；没有帮助的数字不写。

用具体的公司经营、股价变化和买入/等待表达。内部核对过程写在问题记录中，不写成正文；必要局限直接说明它怎样影响当前选择。正常趋势型理由可以成立，不强行补造订单、产品涨价、资金身份或公司催化。20%目标不是已证明的收益概率。写作要求是给你的指示，不是正文内容：不要把"先把最大矛盾摆在前面""条件原样保留"这类指令语或"本轮""核验""开发"等流程词汇写进文章。作者有权合并重复解释、删去不改变判断的指标课堂与边界声明，但不能为简短删掉主要反证，也不能为说服力添加研究没有形成的理由。

以下为通用写作纪律，逐条自查：

- 条件逻辑原样保留：`A且B`与`A或B`、`连续`与`一次`、`盘中`与`收盘`不是同义。
- 度量不能升级为未经支持的预测：历史波动尺度不是未来涨幅所需天数或保证概率；距离旧高点不自动成为上涨空间。
- 现象不能升级为唯一原因：经营现金净额改善不自动等于客户回款改善；毛利率下降不自动归因价格竞争。原因未核实就不作归因，但可以忠实解释已经核实的经营与价格事实。
- 比较不能替代绝对取舍：排位更靠前不等于风险已解决，相对更强不证明目标必达。
- 必要的业务或指标定义解释一句即可，不把研究流程和口径核对搬进正文。

你可以重排、合并、解释和改写，但不能新增事实、扩大比较结论、加强参与力度或改变条件。主因与风险之间缺少实际研究解释时，列出具体research_issues；不得为了交成品编一个理由。原条件明确就忠实表达，原条件模糊就保留原意并指出需要澄清，不能自行发明精确价位或统一门槛。

对照适用范文学习如何把取舍说明白，而不是照搬结论、段数、价位或句式。交付前自行修改需要读者翻译的句子与没有新增解释的重复段落。必要解释可以长，不按字数机械评价。

输入中的 packet 是本股研究判断与证据的单股包；writing_material 是通用教学、已确认写作要点、阅读指南与适用范文全文。输入含 prior_article 与 revision_issues 时为作者修改轮：只按审稿问题修改表达与解释，保留原文正确的事实、数字与条件，不借此扩大结论。输入含 issue_resolutions 时为疑点处理结果：`resolved_existing`/`resolved_added` 是研究核对或按原截止补充的事实（含出处），据此修正相应表述；`retained_unknown` 要求保留该未知并按其说明表达；这些处理都不改变原研究判断，不得据此加强或削弱意见。

输出JSON（不用代码围栏）：

- article：完整Markdown正文，为这一只股票的推荐说明正文（不含“### 股票名（代码）”标题，由程序按正式名单补上）。正文保留三个加粗小标题：**公司主要做什么**、**为什么会选它**、**什么情况会让我改变看法**。首次写作与修改轮都必须输出完整正文。
- research_issues：需要研究负责人处理的具体问题数组，每条含 ts_code、quote（文章或交接中的具体相关表述）、problem、evidence、needed；无问题用空数组。资料不足时不能凑出证据；不影响当前论证的已知未知不必列为问题。
