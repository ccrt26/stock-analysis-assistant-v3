# 股票知识库整理入口（人工触发，无定时任务）

这是 Obsidian 股票知识子库的唯一整理入口，只能由用户明确触发，不注册定时任务，不新增选股 Skill，不自动运行。它只做知识沉淀：从既有本地正式记录只读取材，写成人能读的笔记；不改写 trace、Forward CSV、日评账本、复盘报告、D20 结论或任何正式产物。

开始前按顺序读取：

1. `local_archive/knowledge-vault-path.txt`——其中是本机股票知识子目录的真实绝对路径。文件不存在或路径无效时，如实说明并停止；不猜路径，不另建第二个库。
2. 知识子库内的 `AGENTS.md`——十条子库规则是唯一边界，与其冲突时以它为准。
3. 只读取本次任务需要的资料：对应股票的原 trace / Forward CSV 行 / 日评账本 / 复盘报告 / 优化数据包 README 与 manifest，不全库扫描。

## 三种触发模式

### 一、整理个股记录

输入：股票名称或代码 + 推荐日期（同股多次推荐按日期区分，不合并）。

1. 从 Forward CSV 与原 trace 取当时冻结的事实：形成日、行动日、原截止、机会类型、推荐理由、最强反证、关键未知、参考价与观察目标；市场／板块／公司／价格四路当时判断按 trace 中实际保存的拆开引用，没有记录的明写"当时未保存"，不补造。
2. 从日评账本与复盘报告取过程中的关键变化（观点明显变化、节点日、停止跟踪）与 D20 结案；`review_origin=backfill` 的补写记录只能作背景，不当作当时的判断。
3. 用 `99_模板/推荐记录模板.md` 写一篇笔记放入 `20_个股档案/<名称代码>/`，frontmatter 带 `note_type: stock_record`、`status`、`updated`、`ts_code`、`run_id`、`episode_id`、`as_of`。日期一律用该条记录自己的 `action_date`，不用笔记创建日。
4. 原判断区只摘录或忠实转述当时内容；一切事后认识写进"事后讨论"小节，不得混入原判断。事实性摘录可直接落盘（`status: source_excerpt`）；AI 自己的归因与解释先存 `draft`，经用户确认才改 `approved`。

### 二、整理改稿或范例

输入：一篇待整理的文章（首次推荐说明、三类复盘或公司介绍），或一次改稿。

1. 用 `99_模板/范文与改稿模板.md` 写入 `10_方法与范文/` 对应子目录。
2. 范文必须写清"具体好在哪"与"不能照搬什么"；没有用户指定时最多提名两篇，状态 `draft`。用户明确说“采用”或“作为范文入库”即是认可，按授权标 `approved`，不重复求确认；AI 自己的新稿不能自动认可。采用后同步本类型 `00_阅读指南.md`，有可迁移写作要点时合并更新 `00_已确认写作要点.md` 的对应内容，不追加同义规则。
3. 提名不把"涨得最多的股票文章"当标准；改稿对照要写原稿与修改稿的差异和教训一句话。
4. 被替代的旧范例标 `superseded`，不删除；对应指南改指向新采用稿，保留各自适用边界。
5. 只改文字组织、解释方式或可读性时，优先更新这里的范文、对照与指南，供日常任务按现有入口读取；不把每次改稿变成 Skill/Prompt 的新条款。研究方法、证据要求或运行合同确需改变时，才修改对应正式文件并遵守原批准范围。日常研究只读这些材料，不自动整理入库。

### 三、做一批优化复盘

输入：一个行动日批次或数据包目录（`local_archive/skill_optimization/` 下的导出包）。本模式只是知识库侧的整理入口；完整的批量研究方法、五环节问题清单、提案格式与"批准后才实施"流程以 `ops/selection-method-review-prompt.md` 为准（默认 diagnose 模式，不因"整理知识库"视为同意修改选择规则）。

1. 先定本批研究问题，再看结果；成熟度以包内 `fixed_d20_status` 为准，未成熟记录不进完整 20 日分母，缺失记录单列。
2. 用 `99_模板/批量复盘模板.md` 写草稿放入 `30_批量复盘/`，`status: draft`；五环节（市场／板块／公司／价格／总控）各自对照原判断、结果、支持例、反例与解释边界，字段名以 forward_monitor 实际字段为准（如 `weak_or_failed_link`、`decision_review`、`best_supported_explanation`），不新建平行标签体系。
3. 只提出资料能支持的问题；最多给一项优先修改假设，没有充分依据就写"本批不改"。
4. 用户明确批准某条方法修改后，按 `ops/selection-method-review-prompt.md` 的 implement 流程实施，并用 `99_模板/优化决定模板.md` 记入 `31_优化史.md`；知识库笔记本身不是对任何 Skill 的修改。

## 通用边界

- 笔记状态只用四种：`source_excerpt`（资料摘录）、`draft`（草稿）、`approved`（已确认）、`superseded`（已替代）。
- 原 `as_of` 是当时研究截止，`updated` 是笔记编辑日期，两者不互相覆盖。
- 引用必须能回溯：原文件相对路径、记录编号、数据包目录与截止日；不把网页截图当唯一来源。
- 历史形成日模拟／回放不读取个股档案、批量复盘或后来规则中包含未来结局的内容；文风范例也不带入该股票的未来事实。
- 不批量回填历史正式推荐，不为无内容对象建档，不批量拷贝日报；只保存会支持以后比较的关键记录。
- 本入口不修改五个 Skill、正式合同、定时任务或网页；不提交 GitHub。
