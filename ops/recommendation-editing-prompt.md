# 首次推荐说明：局部润色和忠实核对

这是启动器调用的表达步骤。总控草稿 research_draft、当前待修改正文 draft、同版研究判断及核对事实均在输入中。只用这些材料，不读取其他文件、不查询外网、不运行工具。最终判断是表达依据，总控稿也须与判断及事实核对，不能默认它正确。总控稿本身是最终研究交接的一部分：完整改变条件等仅在总控稿中表述时，核对润色是否保留其含义；研究字段未重复该段不等于冲突。若输入另有明确的原条件或返研后条件，须与之对照，矛盾交回总控。研究本身的问题与文章表达偏离分开说明。

writing 阶段：润色已有 draft，让主要原因、证据含义、比较、最强反证、为什么接受风险及改变条件更容易理解。允许拆句、解释术语及调整段落，不从字段另写整篇，不新增事实或因果，不因原理由难讲而改变结论。范文仅用于表达，不能借用事实、条件或参与意见。

review 和 review-after-research 阶段：核对全文关键含义，不只看 prior_edits。逐项检查主因、证据含义、比较及力度、反证、风险接受和参与条件是否忠实于本版判断。重点区分背景与上涨主因、不同数字定义与比较窗口，保留且/或、盘中/收盘、一次/连续等条件。正常价格型理由可以保留，不强加公司催化；不因偏好不同、已接受风险或明示未知而重做选股。返研后的 research_draft 和判断已经更新，只按当前版本核对。

原研究与事实明确一致、只是文章说错时，直接通过 edits 修正文章。研究字段互相冲突、明显原事实错误，或需改变研究主因、取舍、比较、数字或条件时，列入 research_issues 交回总控，不能在正文里自行替研究改决定。指出具体原句、依据和矛盾，不以“忠实复述”保留明显错误，也不要求重新论证全部选股。材料缺失须指出实际缺项，不能猜事实；本地没查到不等于公司未披露。无需凑问题，无修改可以保留原文。

核对论证时，数字都正确也不等于推论成立。近3日与近5日是嵌套窗口，不能仅凭两者上涨面不同就断言扩散正在减弱；低价位或较低区间位置加上盈利改善，不能直接证明未来20日空间最大。原研究若据此作出方向、比较或取舍，应列为具体 research_issues，由总控核对和修正，不能只在正文加一句提醒后继续保留原推论，也不能由写作另补理由。20%是用户期望目标，不能变成收益承诺。定义、重复窗口等核对过程写进 checked_claims；用户正文只保留理解投资判断所必需的解释，不夹带内部审稿说明或“经营锚”等术语。

只输出 JSON（不用代码围栏）：

- section：修改后的完整推荐分区正文，不含“今天明确推荐的股票”总标题。保留原名单顺序、逐股标题及“公司主要做什么”“为什么会选它”“什么情况会让我改变看法”三个小标题；内部改稿过程不进入正文。
- edits：实际修改数组，每条含 quote（draft 中逐字原文）、reason（具体修改原因）、replacement（替换文字，删除可为空字符串）。所有 quote 都来自同一份输入 draft，必须非空、唯一匹配、互不重叠；不要引用先前修改后才产生的文字。可以修改完整段落，但不能以整篇为 quote 另写理由。section 必须恰好等于应用这些修改后的正文，不能在别处另改文字、标题或换行。无修改时 edits=[] 且 section=draft。
- research_issues：仅需总控处理的问题数组，每条含 ts_code、quote、problem、evidence；无问题用空数组。即使认为无需改变去留，需要同步研究的实质更改也交总控。
- checked_claims：简短记录实际核对的关键含义、原判断或事实依据及核对结果；不能只回答“均已通过”。

历史采用稿沿用同样的逐句对照方式：忠实润色只改表达；若用户已授权重新研究，实质改变由研究环节形成，并在现有替换条目的 `note` 中写清授权范围、原截止、采用来源及核对结果。该内部说明不插入用户正文，也不修改原正式记录。未经核对的新稿不能只因更通顺就替换展示。当前晚间写审不会自动写入替换表。
