# 个人助手 WEB 阅读与补缺

A2 只展示本地已保存内容。缺少正文不能用理由摘要代替，也不能据此推断研究失败。

## 程序负责的展示

- 完整复盘显示原文、短期方向、支持条件、改变判断的条件和已有当前参与意见。停止跟踪日期与原因读取原记录；停止次日起没有普通日评是正常行为，D20 结案仍保留。查看停止日之前，不出现后来的停止理由。
- 历史时间线只使用所选那天的观点和状态，区分复盘日期、推荐形成日和开始观察日。
- K 线、报价和“价格涨跌（未复权）”保留真实价格；“复盘涨跌（复权）”直接读取同次推荐、同日正式快照的数值。分红送转可能导致两者不同；没有同日值就显示“—”，不从 AI 原文反算。
- 原推荐正文优先读取形成日日报。日报不存在时，可读取任务状态明确关联、身份和带时区截止一致的原回复；正式归档、Forward CSV 和推荐分区独立核对全部通过后才展示。其他复盘文字未验收时标明整份日报仍待修复，不把半份报告存入完整日报。
- 用户认可的修订稿按既有 `statement-overrides.json` 显式接入并标注；它不改正式推荐记录，不冒充当晚逐字原文。外部引用可点击，本地引用只显示出处名称。
- 刷新必须调用渲染器；不能因为日报未变、网页已存在就跳过。渲染器保留相同 HTML 不写文件、历史日期不替换较新首页的机制。

## 交给 GLM 的逐条补缺

人工指定一条记录的股票代码、形成日、行动日与原资料截止，依次处理：

1. 先检查原日报、任务关联回复及已认可稿，已有完整文章就核对后接入，避免重复研究。
2. 旧文章日期命名不同，先证明原身份与截止。只有同名股票或文件日期相近，不足以认定为原文。
3. 确实缺少才按原截止补写；使用现行写作方法，但不借用后来信息改写当时判断。后补文章明确标注实际编写时间、采用范围及与原记录的关系；不能假称恢复了当晚逐字原文。
4. 停止原因先读原日评的 `tracking_decision_reason` 和快照的 `tracking_exit_date/reason`。已有原因直接展示；确实缺失才列为文字待办，不重新决定历史上是否停止。
5. 公司介绍缺失按 `ops/company-introduction-prompt.md` 处理。合并回复文字不对应时按同身份原报告修复，不改变冻结研究和复盘正文。
6. 每条完成后检查最新页及对应历史页。只显示文章不代表整份日报已通过验收；不要修改失败状态来掩盖未完成部分。

个人待办与认可稿保存在被忽略的本地归档中，不提交 GitHub。补缺仅人工触发，不另建自动任务。
