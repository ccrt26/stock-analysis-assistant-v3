# 五个选股 Skill 的批量研究与改进（人工触发）

这是个人助手的人工研究流程，不是每日任务、不新增选股Skill、不建立自动训练系统。本文件由 V3 执行包 03 号文件接入；修改须走仓库评审，不在知识库或本文件之外另存副本。

## 0. 先确定本次是哪种工作

默认模式为`diagnose`：读取一批原始记录与结果，找可解释的问题，提出具体方法修改提案；不修改选择规则。

仅当用户明确批准了某份提案中的具体差异，才使用`implement_approved_change`。一句“做复盘”“优化一下”“整理知识库”不等于批准任意选择规则。

用户输入应明确：研究日期范围或已有数据包、本次结果截止、研究问题。缺日期但用户让助手自行选时，按下节固定方法选择；不得根据后来最强或最弱股票选择范围。

读取根AGENTS、当前架构、V4正式合同、原批次使用的五个Skill版本及本批manifest/README。方法版本未知时不能拿当前Skill假装当时使用的方法。

## 1. 批次怎么取

默认人工启动频率为每月一次；这只是使用建议，不注册新定时任务。用户可随时指定批次。单股刚到20日，不自动改规则。

未给日期时：从原研究日期序列中，选择尚未有正式批量研究结论的最早连续5个研究日，包含合法零入选日；使用原action_date排序，不用文件创建时间或收益排序。若已有成熟记录，只纳入截止时已成熟的正式记录进行完整20日统计；未成熟、缺失、无法参与、条件事件等明确分列。

“5个研究日”只是控制个人工作量，不是统计上足够的证明。同一问题覆盖不足时，下次可以接续后面批次，但不得只补成功例或只补失败例。

原观察期：第1日就是原计划观察/参与日，20个真实开市日不因停牌或缺行情而顺延。条件事件不是正式推荐；它后来正式入选也必须是另一条新记录，两个身份不混合。

### 在看结果之前留下研究问题

在本地分析目录先写`00_问题与范围.md`，仅需包含：

- 本批原action_date起止、行情截止、原样本来源。
- 正式/legacy/条件/落选/未决分组与拟比较的原始候选集合。
- 方法版本是否可核实、哪些运行有本地未提交方法变化、模型身份是否未知。
- 一项主要问题、为什么现在检查它、准备观察什么结果和可能推翻它的事实。
- 这批结果是否已经被研究者看过；已看过就标“历史诊断”，不得称盲测。

研究问题可以来自先前明确提出的担心、原反证和此前批量未决问题。不能看完一只股票大涨后，先构造一条刚好解释它的规律再宣称事先预期。

## 2. 先把每条推荐的结果接完整

使用既有优化导出器和校验器，不复制一套计算程序。

### 需要读取的资料

```text
data/research_runs.jsonl             # 原trace、方法辅助信息
data/candidate_ledger.jsonl          # 当时所有实际候选及去留
data/decision_trace.jsonl            # 原证据、原值、来源Skill、对选择的作用
data/review_contracts.jsonl          # 原命题与关键条件
data/formal_selections.csv           # 正式身份、固定20日数字
data/candidate_outcomes.csv          # 候选同窗价格对照，不是模拟实际买入
data/candidate_daily_price_volume.csv
data/daily_price_volume.csv
data/daily_formal_reviews.jsonl      # 每日判断与新current_opportunity，含origin
data/monitor_reviews.jsonl           # 详评与原固定结案；已结束记录不能漏读
data/market_context.jsonl
data/sector_context.jsonl
data/price_context.jsonl
manifest.json / README.md
```

原始正式记录是依据，Obsidian的已有认识只提供要检查的问题，不覆盖原数据。派生重建行不冒充原来实际使用的值；原decision_trace.formation_values优先用于判断当时如何取舍。

### 把三个时间对象分开

1. 原推荐：起点为原action_date参考开盘；主要评价为前20日。
2. 每日当前判断：起点为该次复盘的as_of/analysis_date及reference_close；1—3日、5—10日是它自己的未来窗口。
3. 真实买卖：需要真实成交、交易约束、成本、退出等；本入口不把任何参考价格路径当作实际盈利。

本次五个选择Skill的研究以第1项为主。第2项若发现日评预测反复失准，另列为复盘方法问题，不能全算在原选股Skill头上。第3项本轮不新建账户评估系统。

### 必须给出的汇总

同时报告：研究日数、推荐次数、不同股票数、正式完整20日数、未成熟数、数据缺失数、无可靠入口数、条件事件数、legacy数。

正式主要结果：

- 前20日收盘20%触达：分子/完整可评价分母，未知不是未触达。
- 第20日期末收益中位数及样本分布；可给均值，但不得仅报均值。
- 期间最深下跌、最大收盘回撤、盘中最大上涨分别展示，不能统称最大回撤。
- 同窗口相对沪深300；行业仅在同窗同口径可核实时使用。
- 第5日、第10日的结果与启动时间，帮助理解速度，但不改变原20日评分目标。
- 选择数量及零入选日，避免仅靠越来越少选股美化触达率。

利用导出每日路径计算第n日时：

```text
原参考收益Rn = 第n日收盘×当日复权因子 ÷（原第1日开盘×第1日复权因子）-1
```

n来自原交易日历编号；缺原入口或该日则为空，不换用最近可用收盘。基准同起止。程序计算，中间结果可保存在本地分析CSV，不用AI估算。

同股重复推荐和同日共同市场环境有依赖。必须报告次数与不同股票数；有明显重叠时，补看每股最早一条、不与其前20日重叠的后续记录的结果，原全量仍保留。不能把这类辅助去重当作严格独立样本证明。

## 3. 第20日结案怎样进入研究

每条正式episode只取一份首次正式保存的完整固定结案。后来报告重复携带的原结案不算新样本。结案晚补时，数字仍为前20日，原因不能使用第21日之后才出现的消息。

读取`weak_or_failed_link`和`decision_review`可以定位案例，但不能直接统计“价格Skill被标错7次，因此应该改价格Skill”。需要回查原理由、原证据、实际路径。

将每个值得深入的案例区分为以下解释，不建立新生产枚举：

- 数据或时点错误：例如原值/行业/事件公开时间错误。
- 现有方法未执行：例如价格反证已明确记录，但总控仍沿用原排序且不解释。
- 方法本身可能不佳：规则确实执行了，同类对照却显示其辨别方式存在问题。
- 后来出现的新变化或偶然结果：原截止时不可能知道，不能直接倒推当时应避开。
- 当前仍无法区分：证据不足。

“一只未达目标”不自动等于“选择方法错误”；“一只达标”也不自动证明原因果解释正确。

## 4. 五个 Skill 分别研究什么

### 市场Skill：不是给市场状态算选股胜率

对照当时共同上涨、单日修复、集中上涨、轮动等判断与实际搜索重点，看是否误把共同上涨当成个股独立强势，或让市场标签代替个股比较。

需要：原市场状态与原值、实际发现来源、候选相对表现、原反证、同类机会在不同研究日的结果。

可能改：搜索重点、环境对证据解释的影响、反证强度。不能凭少量弱市失败案例写“弱市一律不选”，不能把市场Skill改成直接输出股票。

### 板块Skill：共同方向正确，不代表成员选对

在当时有效的板块成员、共同动力和原近邻之间比较。区别“板块判断错”与“板块机会在、个股比较错”。

需要：原板块及成员关系、成员角色、相对表现与成交、原近邻/选择理由；行业数据不匹配则不能强归因。

可能改：成员角色判断、近邻比较问题和共同动力的证据要求。不能把后来龙头事后补进当时比较名单。

### 公司Skill：事件是真的，不等于近期有推动

检查新增性、重复披露、法律/业务阶段、主营联系、规模与利润影响、兑现时间及原风险是否读对。无新公告不等于无机会，有公告也不自动有短线收益。

需要：原披露链、原可得时间、原短期判断，之后真实进展与价格反应。事后重找公告最大反应日不等于原来可预测。

可能改：哪些资料足以支持近期推动、什么应降为背景、怎样处理材料性与关键未知。不能恢复固定财务打分。

### 价格Skill：确认和已经付出的涨幅是否值得交换

先读当前及原版本§3A等已有要求，不把已有“剔除最大日、最大日之后、多个收盘”等再写一遍当新优化。

检查原来是否真有连续性、是否多指标重复计同一天证据、确认得到时价格是否已经不利、最强价格反证是否影响结果。分别检查明确公司/行业变化型与主要依靠价格型机会，不能把两者混成一个统一门槛。

需要：实际formation_values、原证据使用角色、选择/降级/拒绝结果、同类原近邻、原已涨幅与后续20日/早期5日10日路径。

可能改：证据组合的解释、比较次序、反证如何改变取舍，或者删除过严却无效的要求。禁止搜索一个能最好拟合本批股票的数值阈值。

### 总控Skill：四路意见都有，最后为什么这么选

检查同类比较→跨类比较→绝对质量停止的实际执行。问：选了谁、没选谁、依据是什么、最强反证有没有被消化、为何继续增加名单。

需要：原candidate_ledger、decision_trace、nearest_nonselections、原primary_reason/selection_reason，以及同日期同窗口结果。

可能改：冲突证据的取舍、近邻比较和停止补位的方法。不能用权重投票代替解释，也不能要求恰好选够几只。

## 5. 结果对照必须包括什么

在本地分析目录生成`01_样本对照.csv`，每行一条原候选（run_id+ts_code），至少包含：

```text
run_id, ts_code, action_date, selection_output_class, final_fate,
method_revision, version_status, source_skills,
original_reason, original_counterevidence, original_decision_ids,
evidence_origin, original_comparison_id,
fixed_d20_status, return_day5, return_day10,
fixed_d20_hit_20pct_close, fixed_d20_terminal_return,
fixed_d20_mae, fixed_d20_max_close_drawdown,
fixed_d20_excess_market_return,
review_question, case_interpretation, missing_evidence
```

不要求用模糊文本硬解析出不存在的结构。原比较对象不能唯一核实就留空并说明；不能自动把本批后来最好者设为原近邻。conditional的正式20日字段不适用，候选价格对照只作内部描述。

结论至少同时包含：同类支持例、同类反例、原近邻比较、另一种解释和未排除的限制。某一类确实不存在时说明，不编出凑数案例。

不能仅依据已推荐集合评价“全市场漏选率”；没有完整形成日合格范围，就只谈已进入候选账的取舍问题。

## 6. 怎样写一条真正能执行的修改提案

输出`02_研究结论与后续验证.md`，包含：

1. 这批能回答的问题与尚不能回答的问题。
2. 原始结果汇总和身份/成熟度/版本限制。
3. 哪个环节的问题最有证据；具体案例及原值。
4. 本批结论是“无需改”“修数据/执行连接”“候选方法修改”中的哪一种，以及理由。
5. 至多一项优先连贯的方法修改；不要求五个Skill各改一项。一个假设可涉及多个必须配合的文件。
6. 后续验证安排与可能否定该修改的结果。

有方法提案时必须给以下内容：

```text
提案名称：一个具体问题，不写“全面增强科学性”。
负责环节及文件：确切路径、章节。
原文：当前实际生效的相关原文，注明版本。
拟替换原文：完整可直接替换的文本，不写“适度优化/加强判断”。
为什么改：原证据与支持/反例。
改后哪种决定会不同：实例与原截止事实，不使用未来结局当理由。
可能的代价：会错过什么、会增加什么风险或研究耗时。
不改哪些内容：身份、目标、公式、其他未受影响规则。
需要数据：已存在什么、缺什么；缺资料不能变成硬性全库扩建。
后续怎么看：固定新批次、原指标、对照问题和否定条件。
审批状态：待用户明确批准。
```

若方法已写清却没有执行，不允许仅再加一句“务必严格执行”。要定位断点：相关资料没传给下一Skill、原反证未被输出消费、近邻没进入比较，或者执行者忽略明确输入。修正实际连接或做一次同输入的局部取舍对照。

历史重新运行是诊断，不是独立收益验证。已经见过结果时，即使用原时点资料重写，也不能声称AI完全不知道未来。

## 7. 用户批准后才实施具体选择规则

先核对批准内容是否明确指向上述提案与完整差异；不自行顺带修改其他规则。

按仓库现有执行规则完成必要一次审查、精确修改、相关测试和Git提交。只改获批原文、直接相关入口/知识条目/测试，原推荐及结案不回写。测试证明的是新要求能被执行，不是更会赚钱。

将实际method_revision和生效后的首个研究run记录下来。Obsidian`31_优化史.md`写批准依据、完整差异链接、生效版本、要检查的未来批次与反例；不是每篇日报都去读这份优化史。以后选择只读已经进入正式Skill/知识条目的规则。

不同时大改市场、板块、公司、价格、总控然后把结果改善归功于某一条。若一个真实问题必须跨文件修改，视为一个连贯改动，说明依赖。

## 8. 后续新批次怎样看是否有帮助

修改前就约定要看原20日结果、早期5/10日路径、下跌/回撤、选择数量与原近邻取舍。保留同类机会和市场环境差异，不能只挑新版本表现好的一段。

默认观察生效后接续的连续研究日批次；样本未成熟先保持待观察。若需要避免同股窗口重叠，可同时看不重叠记录的辅助对照，不删除原全量。不要因为某几天结果差就立即再调一版。

这里采用个人助手能承担的最低成本方式：正式研究照常只运行一套，原候选与决策完整保留，成熟后比较。没有同日双版本前瞻对照时，不能声称已经识别“修改本身造成”的全部收益差异；市场变化、模型变化与样本选择仍可能影响结果。

未来结论只能是：获得初步支持、仍不清楚、出现反证需要撤回/修订。一个新批次改善不是永久有效证明。试过但失败的改法同样记录，不只保留成功版本。

新5—10日当前预测应独立检查：同一复盘日期的观点与该日之后第5/10个交易日的实际路径对照，保留两者而不选较好的一天；未定义横盘容忍范围时不凭空计算精确命中率，先报告原判断和实际路径。等待条件未出现不算真实亏损，consider也不是实际成交。这部分的误差首先属于复盘/参与判断方法，不直接改原选股规则。

## 9. 成功与停止条件

本入口的成功不是必须修改规则，而是把能够支持的判断做清楚：有哪些原证据，什么真实结果，支持和反例如何，最值得改什么，怎样知道改动无效。

资料不足时交付已完成对照与精确缺口，不编原因、不无限重试、不扩建全市场回测。缺一项行业对照只限制对应归因，不使其他可评价部分失效。

正式结果和研究数据包只读；分析产物放本地独立目录；KB存草稿与获批认识。没有明确发布授权不上传真实研究包、Obsidian全文或个人路径。
