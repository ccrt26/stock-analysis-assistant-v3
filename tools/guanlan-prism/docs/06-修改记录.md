# V2 → V3 变更记录

## 保留

base.css与prism.css的基础视觉、effects.js装饰光场、core.js既有图表口径、品牌SVG；原推荐/价格/正文快照不改。保留搜索、收藏、回放、星图、明暗、专注与导出。

## 新增

- src/rules.js：当天普通详评、方向转换、精确当天报价、观点标签、失效范围状态、市场字段。可独立Node测试。
- src/v3.css：六项改动的布局覆盖与常驻滚动条。
- tools/adapt_snapshot.py：读取既有数据并附加市场字段/详评名单，不联网。
- V3规则、接口、执行指令、单测、浏览器验收、真实截图。

## 修改

app.js重新实现overview/records/journal相关展示：市场四卡、八只深读、完整横向卡片、方向更新滚动列表；全局移除首字DOM；表格字段与筛选改为用户要求。原图表实现和回放逻辑保持。

shell.html升级标识为V.03，增加规则模块和动态数据说明。build.py加载新模块，取消demoShowcase分支，构建与实际数据采用同一逻辑。

## 移除

- chooseExamples和硬编码预选股票名单；
- 卡片“不同状态示例/近期推荐”切换与前四条截断；
- 表格重点关注/观点调整/待参考价旧筛选；
- 表格最高收盘涨跌与观点列行业；
- V2陈旧执行说明、结果文件和与本版规则冲突的验收脚本。

普通详评数量和方向更新数量不同是正确行为，不要“修成一样”。失效历史仍保留在完整记录中，不被删除。

## 2026-09-08 入选日措辞修正（纯展示层）

`recDate`一直是入选日（行动日）：推荐在其前一交易日盘后形成，当日开盘参与并定参考价。页面此前把该日期统一标成"推荐"，读作"推荐发生在当天"，与源合同（formation_date/action_date）和日报原文（"今晚新增推荐从明日进入首日观察"）冲突。本次只改措辞，不改数据、身份、排序与任何计算。

- app.js：所有"日期+推荐"绑定点改为"入选"——详情页标题、走势聚焦小标与下拉选项、观点更新元信息、卡片"入选日期"、清单表头/搜索占位、星图选中面板与入选明细、复盘日志、全文搜索结果、"计划/原入选日""原入选记录"；"推荐前走势"改"入选前走势"，"N次推荐"改"N次入选"。
- shell.html：数据说明中"同代码不同推荐日期单独保留"改"同代码不同入选日期单独保留"。
- rules.js：仅注释措辞。
- docs/02 同步表格列与卡片措辞；docs/03 补充 recDate 口径说明。
- 数据合同不变：recDate 字段、code:recDate 身份、排序、参考价与20日观察窗口计算全部保持原样。

事件等待型条件记录（conditional_event）按复盘合同不进 daily-formal-reviews 与 monitor-report、永不写复盘，但 build_payload 此前把它们与正式推荐一并放进 stocks：网页出现 7 条这类记录（融发核电、亚康股份、丽珠集团、中国船舶×2、阳光股份、北京科锐），配进度条与涨跌，复盘栏永远"尚未复盘／未保存复盘"，读作漏复盘的正式推荐。本次让网页与日报同口径：

- render_monitor_web.build_payload 的 selected 集合移除 conditional_event，只保留 confirmed_active／legacy_v1_not_rewritten；次日待首日（d0，本就只收确认正式推荐）不变。线索记录仍完整保留在 snapshot/trace，不删除、不改写。

- 测试：test_v4_payload_shape 改为断言条件记录不进入；删除 test_conditional_event_uses_first_reaction_reference，新增 test_conditional_event_leads_never_displayed。
