# 数据接口与口径

## A. 直接接入现有快照

`tools/build.py:render_html(snapshot)`接收字典，返回完整HTML字符串。输入示例就是data/snapshot.json。不会改写正文、参考价或价格数组。

必备原字段：analysis_date(YYYY-MM-DD)、as_of、market_name、dates、market、review_dates、stocks。推荐与复盘日期使用完整YYYY-MM-DD。

**日期定位（displaySchemaVersion 2）**：正式生成器输出 `sessionDates`（完整ISO交易日序列，与market/industry/candles等长同序、严格递增、末日记analysis_date），页面与生成器的定位/比较一律用它；`dates`保留为MM-DD显示数组，只用于展示，不参与年份比较或查找。没有sessionDates的旧快照：dates为完整ISO或可自洽证明同年的MM-DD时按受约束兼容规则读取（tools/web_display_contract.resolve_session_dates 与 src/core.js 同合同）；跨年、倒序或末日不一致时明确拒绝显示并提示从原归档重新生成，不猜年份。新生成的events日期使用完整ISO；读取旧事件MM-DD时按dates同一序号受约束转换，定位不到即排除。

每条stock保留code/name/recDate/formedOn/episodeId/recIndex/ref/refKind/days/d0/phase/stage/stageType/attention/trigger/suspended/dataIssues/trackingStatus/trackingExitDate/trackingExitReason/company/reasonFull/reasonRisk/industryName/industrySource/industry/candles/reviews/events/companyIntroduction。未知值用null或对应空数组，不用0替代缺失。身份code:recDate；episodeId透传上游episode_id仅供追溯，UI身份仍是code:recDate；同一UI身份出现多个不同episode时生成器明确报错，不静默覆盖；如果真实系统同日同股有多个episode，接入方必须扩展身份贯穿收藏、搜索、导出与回放。

**companyIntroduction（推荐时点公司资料，可选）**：`tools/render_monitor_web.build_payload` 按 `(ts_code, action_date)` 原推荐身份从 `local_archive/company_introductions/<action_date>/<ts_code>.json` 读取，加载前对照原归档 trace 核对 formation_date/action_date/as_of 与正式身份（confirmed_active／legacy_v1_not_rewritten）；无法证明身份匹配时该字段缺省，绝不取同代码最新一篇。结构为 `{schema_version, ts_code, name, formation_date, action_date, as_of, generated_at, sections:[{title, paragraphs, table?, source_ids}], sources:[{id, kind: warehouse|official_document, title, available_at, locator, ...}], limitations}`。渲染约定：sections 是唯一正文（段落按原文转义、普通表格列行渲染、来源可折叠）；资料始终显示为"推荐时点资料"，滑动价格/复盘时间轴不改变其内容与截止；后补文章显示实际编写时间（generated_at），不把编写时间倒填为推荐当天。旧 `company` 简要字符串保留兼容：无新版介绍时继续显示并注明"旧快照中的简要资料；完整推荐时点介绍暂缺"；两者皆无时显示"这次推荐的完整公司介绍暂未生成"，不虚构主营描述。介绍缺失是资料暂缺，不得写成公司风险。

`trackingStatus`／`trackingExitDate`／`trackingExitReason`直读上游episode的同名字段（值域active／evaluation_only／completed）。`evaluation_only`＝已停止主动跟踪：此后按复盘合同不再生成每日复盘，详情页对无当日复盘的回看日显示"停止跟踪·无当日复盘"提示并给出最后一篇复盘入口，不把旧复盘重复当作当日结论；缺这三个字段的快照（自行接入方）回退为原"最近原记录"行为。

正式管线的数据构建（tools/render_monitor_web.build_payload）只输出正式推荐（confirmed_active／legacy_v1_not_rewritten）与次日待首日（d0）记录；事件等待型条件记录（conditional_event）按复盘合同不进日报与台账、永不写复盘，网页与日报同口径不展示，记录本身仍保留在 snapshot/trace。前端对 refKind='event' 的提示逻辑保留给自行接入快照的接入方，正式管线不会再提供此类记录。

`recDate`是入选行动日（首日观察日）：当日开盘参与并确定参考价，第1个观察日从当日计。`formedOn`是推荐形成日（盘后报告写出该推荐的日期；正式管道取episode的formation_date，D0取该报告analysis_date，load_d0_entries已校验二者一致）。展示层日期标签一律用formedOn标"推荐日期"，recDate用于首日观察标注、主图坐标、记录身份与排序；formedOn缺失时（示例快照）回退显示"入选日期 recDate"。排序键仍为recDate：formation→action逐日严格配对，两者可见顺序一致。

**交易日历与起点**：正式生成器用本地SSE trade_calendar（is_open）推导交易日序列，不以行情分区文件是否存在决定开市日；有交易日但缺行情时该日保留、对应数组位置为null。日历为空或覆盖不足（窗口内连续无记录超过10天）时生成器明确失败并保持既有发布页不变，不用周历或行情目录代替。全局裁剪不会裁掉任何展示记录的首日观察日期。首日观察日期不在交易日序列时recIndex/ref为null并写dataIssues，绝不用数组第0日顶替；首日存在但开盘缺失时参考价留空，不改用收盘价或其他日期价格；推荐后无价格数据只写dataIssues（missing_price_path，表述为"价格数据缺失"），停牌/无法执行必须来自明确状态，不由空数组推断。参考价一律为原始未复权开盘价。

**dataIssues**：`[{code, recordKey, reviewDate, message, origin}]`，只记录实际检测到的确定性缺口/结构冲突（missing_rec_session／missing_entry_quote／missing_price_path等），origin为display_data_adapter；页面仅在对应记录（及对应复盘日）位置渲染并HTML转义，无缺口时为空数组，不为"原文数字核对"造提示。

**D0去重身份**：正式记录与次日待首日（D0）的去重键是`(完整ts_code, action_date)`；同股在更晚行动日的再次入选会同时保留（各自ref独立），仅同一行动日的重复条目被去重。

**取价接口（页面 core.js）**：`quoteOnIndex(s,i)`只取该日有效bar（缺失返回null）；`lastAvailableQuote(s,end)`取最近有效bar及其真实index/date。首页、清单、搜索、星图、详情的当日收盘与较参考价收益统一按exact-date口径；图中历史点保留，展示最近有效价格必须带其实际日期。maxDrawdown/high是已发生的历史极值，报告日缺价时仍可显示；ret/remaining/volDelta等需要当前日真实值的字段为null，不补零、不连成假报价。

candles=[open,high,low,close,amount_亿元]；这是既有展示接口的单位。不要把Tushare原始成交额单位不经处理直接塞进这里。此次新增的marketIndices是指数点数，不是金额。

**详情指标条（页面 core.js metrics）**：「推荐以来最大回落」＝推荐后（recIndex..end）各日收盘÷截至该日的运行峰值收盘−1取最小值（`maxDrawdown`，收盘口径、值≤0，无回落为0，无有效收盘为null）；「量能较5日均量」＝当日成交额÷前5个交易日（end−5..end−1，不含当日，可跨推荐日边界）有效成交额均值−1（`volDelta`，基线有效天数`volN`不足5时按实际天数计，当日或基线缺额时为null）；`volToday/volBase/volN`一并返回供副标题如实标注覆盖。回看（end小于最新）时两格只用≤end的数据。

## B. 新增市场行情字段

```json
{
  "presentation": {
    "marketCodes": ["000001.SH", "399001.SZ", "399006.SZ", "000688.SH"],
    "deepLimit": 8
  },
  "marketIndices": [
    {
      "code": "399001.SZ",
      "name": "深证成指",
      "trade_date": "2026-09-04",
      "close": null,
      "previousClose": null,
      "series": [],
      "source": "由接入方填写真实本地来源"
    }
  ]
}
```

这是**缺失值接口示例**，没有虚构指数点位。填入真实数值后原位置自动显示。series是按日期顺序的历史收盘，仅到当前交易日；中间缺失留null断线。没有series时不画曲线。trade_date不等于analysis_date时整项当日数值为空。

旧快照的上证market数组是唯一的兼容回退；不能把它复制为深证/创业板/科创指数。指数涨跌=(close/previousClose−1)×100，与个股推荐收益无关。

`adapt_snapshot.py`支持从已存在的index_daily风格CSV/JSON读取ts_code/code、trade_date、close、pre_close/previousClose。YYYYMMDD转换为YYYY-MM-DD，金额单位不参与。相同指数同日冲突报错；只有较旧日期时保持其旧日期，让页面显示待更新。该工具不调用Tushare、不查网络、不写事实仓。

## C. 当日普通详评名单

默认从每条记录当日最新review_kind读取regular_detail。原快照已经足够，不需编造额外名单。已有上游排序可提供：

```json
{
  "dailyDeepReview": {
    "date": "2026-09-04",
    "recordKeys": ["000768.SZ:2026-09-03", "300170.SZ:2026-09-01"]
  }
}
```

示例仅展示结构，不是建议替换原8只名单。被引用记录还须有当日regular_detail，空名单表示当天没有，不进行补位。最多8只不同股票，同股多次推荐在组内分别查看。名单缺失时保留源输入顺序，没有额外排序依据。

## D. 观点方向、复盘标签与结构化枚举

每条review已有date/day/review_kind/base/outlookReason/viewLabel/viewReason/assessmentText等。UI原文和正文不重写。新生成的每条review额外携带结构化枚举（严格透传原值，无值为null）：

```json
{"viewChange": "strengthened", "assessmentCode": "supported",
 "outlookCode": "continuation_possible", "outlookDirection": "up"}
```

source→display映射：view_change→viewChange；current_assessment→assessmentCode；outlook_1_3d→outlookCode；outlookDirection由outlookCode三类归并（strengthening/continuation_possible→up；range_or_wait→sideways；weakening/overheated/invalidated→down；event_pending/空/未识别→null）。没有值不默认unchanged；未知枚举（如future_new_enum）页面显示"未识别状态"，不显示维持原判、不假装尚未复盘、不自动归为失效。方向更新比较相邻两次已有复盘的枚举方向；信心变化（viewChange）不等于方向变化；首次复盘无前值不虚构转换。

旧快照没有枚举时按rules.js中精确中文映射（BASE_DIRECTIONS／LEGACY_VIEW_LABELS）；无法识别的新文案不走关键词猜测，不计入方向变化，应由接入方提供结构化枚举或扩展有据可核对的精确映射。保留原base/viewLabel用于查看。

viewLabel是原推荐支持度的变化：观点增强/观点减弱/维持原判断/首次复盘/判断失效（中文仅作显示）。不是方向。因此viewChanged=true不代表进入观点更新；同方向类别的信心变化只保留在全量观点调整页。复盘日期相同的多份记录取截止内最新保存版本，生产导出需保证as_of边界已经处理。

## E. 来源、只读口径、失效与当日收盘

**sourceInfo与observationPolicy**：正式生成器输出`sourceInfo`（kind=frozen_archive、label=本地冻结复盘归档、externallyVerified=false）与`observationPolicy`（primaryDays=20、targetReturn=0.2、origin=existing_v4_contract）。页面导出、页脚与公司资料来源沿用它；未知来源写unknown，不把本地归档说成外部核验。20个交易日／20%观察目标集中只读展示，页面不提供修改历史目标的开关；真实归档以后明确携带冻结口径时优先原口径。回放尺按primaryDays渲染，记录明确已有超出天数时如实显示既有后续观察，不自动延长研究、不改写D20结论。

可选stock.invalidated是研究系统给出的**当前**失效状态。没有时优先读最新复盘的viewChange/assessmentCode枚举，再按旧精确中文，最后无复盘时按stage明确失效回退。不能从价格算出失效，也不能合并同代码所有历史记录的状态。旧数据有恢复标签时如实按源当前观点展示，本前端不追溯改写它的研究逻辑。

表格close=当前交易日candles[index][3]，不进行前值填补。若停牌数据供应方把前收复制到本日，生产适配时应依据真实停牌/交易状态把本日无成交报价标为缺失，不能让占位前收冒充新收盘。

其他旧图表和回放的历史指标仍沿用core.js的原口径，全文原数字不会因为当前字段变化而被替换。回放是按归属复盘日期展示，不是严格实时可见回测。

## F. 不可更改

不得为漂亮程度补行情、改推荐日期、改参考价、填回看中的未来数据、迁移历史结论或写新荐股理由。data/source-manifest.json提供本包原始快照哈希与示例计数，便于确认未改写。

## G. 观察星图同股合并（仅展示层派生）

星图不新增任何输入字段。`rules.js` 从既有 stocks 只读派生：`atlasGroups` 按完整代码分组（组内按 recDate 升序，同日按输入顺序；同身份重复载入只算一次）；`atlasBasis` 给出股票视图主点（最早记录的 recDate+ref+交易日序号成套）；`atlasRecordPoint` 给出记录视图每点（该次自己的 ref 与序号）；`atlasGroupClose` 取同股同日（dates 同一序号）第一份有效收盘副本，不跨日拼接、不叠加成交额；`atlasBadge` 生成次数徽标；`atlasRange` 输出两种模式共用的真实数据轴范围（lo/hi 必含 0 与全部可绘制点，basis 固定为"本报告最早记录"）。

不可绘制的原因枚举：`待首日观察`（d0 计划记录）、`缺参考价`（ref 缺失或非正）、`交易日历不足`（recIndex 缺失或超出 dates）、`报告日无真实收盘`。这些记录进入星图下方"暂未绘制"列表并注明原因，不参与坐标计算，也不得改用其他日期或另一条记录的参考价顶替。原始 stocks 数组、记录身份与其他页面的筛选、收藏、导出键一律不变；同日同股多个 episode 仍要求接入方扩展身份（见本文件第三节），前端不做猜测性合并。

轴说明随模式变化：股票视图纵轴"较最早记录参考价涨跌"、零线"零线＝该记录原参考价"、横轴"自本报告最早记录的首个观察日起的交易日"；记录视图纵轴"较该次入选参考价涨跌"、零线"零线＝该次原参考价"、横轴"自该次入选的首个观察日起的交易日"。不改变按股票/按记录的计算方式。已知限制：同一图内密集数据时，名称标签放不下会按既有规则省略文字（点、徽标与悬停提示保留），本轮不引入新的标签排版引擎。
