# 03｜数据接口与口径

## 一句话接入方式

已有程序继续产生数据；本包只接收同一结构的 JSON，再用 `render_html()` 渲染。不要另起一套研究或行情计算系统。

页面读 `<script id="snapshot" type="application/json">…</script>`。`tools/build.py` 负责安全内联 JSON（把 `<` 转义），无需浏览器 fetch 或 API。拆分版 index.html 同样内联数据，只有 CSS/JS 分文件。

## 顶层字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `analysis_date` | `YYYY-MM-DD` | 行情/观察截止日期，驱动页头与页脚 |
| `as_of` | 带时区的字符串或空 | 源快照截止；原样展示，不改成打开网页的时间 |
| `market_name` | string | 基准名称，如本例的上证指数 |
| `dates` | string[] | 图表交易日轴；本例格式 MM-DD，与所有行情数组一一对齐 |
| `market` | (number\|null)[] | 基准路径，长度与 dates 一致 |
| `review_dates` | string[] | 复盘日期选项，使用 YYYY-MM-DD |
| `stocks` | object[] | 每次独立观察一条，允许同股票多条 |
| `date_files` | object[]，可保留 | 来源报告文件索引；本页不跳转访问这些本地旧报告 |
| `presentation` | object，可选 | 仅控制聚焦与示例卡片的展示，不改变研究名单或排序结论 |

**原 DEMO 的日期轴是假定同一公历年里的 MM-DD 序列。** 本包基准快照处于2026年8—9月；跨年真实数据不在当前截图验收范围。接入跨年数据时，应在薄适配层明确提供完整日期映射，并对 `core.dateAt()` / 事件导出的日期拼接做对应测试，不可把去年12月拼成今年12月。修改日期绑定不授权改视觉或复盘口径。

## 每条独立观察

| 字段 | 类型 | 要求 |
|---|---|---|
| `code`,`name` | string | 股票代码、名称 |
| `recDate` | YYYY-MM-DD | 这一次推荐/条件事件记录的日期 |
| `recIndex` | integer | 观察起点在 dates 数组中的零基索引 |
| `ref` | number\|null | 原参考价；缺失就保留null，不用最新价格替代 |
| `refKind` | string\|null | 如 formal / event，保留原区别 |
| `days` | integer | 已观察交易日数；本版主要展示第一至第二十天 |
| `d0` | boolean，可选 | 首个观察日未到达 |
| `stage`,`stageType`,`phase` | string | 源阶段；与复盘观点分开保留 |
| `attention` | boolean | 源报告重点标记，不由 UI 重打分 |
| `trigger` | string | 原重点原因，可为空 |
| `suspended` | boolean | 原快照停牌状态，不从无数据自动推定停牌 |
| `company` | string | 原公司资料 |
| `reasonFull`,`reasonRisk` | string | 原推荐理由和风险，不重写 |
| `industryName`,`industrySource` | string | 原行业路径说明 |
| `industry` | (number\|null)[] | 与dates对齐；缺失处null |
| `candles` | (array\|null)[] | 与dates对齐，结构见下 |
| `reviews` | object[] | 原复盘记录；空数组合法 |
| `events` | array[] | 原事件；空数组合法 |

### 身份

`key = code + ':' + recDate`。这是页面的记录身份。按代码去重会毁掉不同推荐时间、参考价与原判断的差异，禁止这么适配。

### candles 的准确顺序

```text
[开盘, 最高, 最低, 收盘, 成交额（亿元）]
```

不是某些图表库常用的 `[open, close, low, high]`；也不是“成交量手数”。如原接口单位为元或万元，在适配处明确换算到亿元一次，不要两边重复换算。缺失的整日可为null；某个字段缺失也用null，不填0。

## reviews 字段

`date`（复盘归属日期）、`as_of`（记录实际截止，可选）、`day`（第几个观察日）、`checkpoint`（源检查日，可为null）、`headline`、`copy`、`summary_copy`、`review_kind`、`facts`、`base`、`outlookReason`、`assessmentText`、`viewLabel`、`viewReason`、`confirm`、`risk`、`viewChanged`、`fromTo`。

`viewChanged` 才代表观点是否调整，不能仅凭当天涨跌判断。`assessmentText` 由 `core.reviewTone()` 映射为展示颜色；未知文本显示中性，不增加研究结论。正文保留已有原文，即使包含原文中的不恰当说法或与结构化字段不一致，也不由前端悄悄修订。

`confirm`、`risk` 依照当前复盘文字，在界面显示为“支持这次走势判断的表现”“会改变这次走势判断的表现”，不机械等同于看涨信号/看跌信号。

`events` 的原始格式为 `[MM-DD, 类型, 标题, 说明]`。正文右侧判断过程主要从 reviews 中的检查日与观点调整构造；导出仍保留对应截止以前的源events。

## 已实现的展示计算

设原参考价为P0，当前所选日及之前的最新有效收盘为P，观察起点后截至所选日的最高有效收盘为H：

- 较参考价涨跌：`(P / P0 - 1) × 100%`。
- 最高收盘涨跌：`(H / P0 - 1) × 100%`。
- 距最高收盘回落：`(P / H - 1) × 100%`。**不是历史最大回撤。**
- 现价仍需上涨：`(P0 × 1.2 / P - 1) × 100%`。不是 `20% - 已涨百分比`。
- 相对表现：每条序列的首个观察日收盘归一为100。它与原参考价收益不是同一口径。
- 缺少参考价/首日未到达/所选日早于观察起点：不显示推荐后涨跌。

20%沿用示例的观察目标，不代表收益承诺。页面没有账户资金、仓位、交易成本或真实成交记录，不能把这些值标为“我的收益”。

## 回看边界

回看时，价格、最高收盘、复盘与事件只能到所选观察日。没有当日新复盘则显示最近一条，并注明日期。历史导出裁掉未来价格与复盘，且不拿最新源阶段伪装成历史阶段。

但这仍是**按复盘归属日期回看**，不是严格按信息实际可得时点重跑的回测。部分复盘在归属日期之后生成；界面与说明已保留这个区别。

## 演示聚焦与正式接入

默认成品使用指定的几条样例，方便展示增强、减弱、待首日等不同状态。这不是新选股结果。真实接入调用：

```python
html = render_html(snapshot, demo_showcase=False)
```

这样聚焦和卡片默认按输入记录顺序选取前几条，不保留演示中的指定股票。已有后端明确安排了首页展示对象时，可以传：

```json
{
  "presentation": {
    "demoShowcase": false,
    "heroKeys": ["603969.SH:2026-08-21"],
    "cardKeys": ["003816.SZ:2026-08-28"]
  }
}
```

上面的两个键只是包内样例，**不是要求生产固定展示这两只股票**。不存在的键被忽略，剩余位置取已有记录；不造新记录。

## 必须如实保留的限制

原数组与复盘文字可能冲突，前端不会替研究程序判哪个事实对。已有德尔股份样例会提示原文收盘26.56与数组26.65不同。未枚举的其他原文冲突不代表已被核验。

当前星图坐标轴按本例的 -12% 至 +12% 设计。生产数据超出该范围时，需要对 `drawAtlas()` 扩展数值轴范围和刻度，保持组件、坐标含义和视觉不变，不能裁掉真实收益或把超范围值夹到边缘。第21–30天后续观察、最终20天结论等超出本 DEMO 当前主观察窗口的正式业务，不得声称本包已完整实现；沿用现有后端语义，再做最小展示接入与专项测试。
