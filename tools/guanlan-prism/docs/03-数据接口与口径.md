# 数据接口与口径

## A. 直接接入现有快照

`tools/build.py:render_html(snapshot)`接收字典，返回完整HTML字符串。输入示例就是data/snapshot.json。不会改写正文、参考价或价格数组。

必备原字段：analysis_date(YYYY-MM-DD)、as_of、market_name、dates、market、review_dates、stocks。当前原接口dates为同一自然年内MM-DD序列；candles/industry/market按该顺序对齐。跨年接入必须先对齐原程序日期解析及图表标签，不得直接把不同年份MM-DD混在一起。推荐与复盘日期使用完整YYYY-MM-DD。

每条stock保留code/name/recDate/formedOn/recIndex/ref/refKind/days/d0/phase/stage/stageType/attention/trigger/suspended/company/reasonFull/reasonRisk/industryName/industrySource/industry/candles/reviews/events。未知值用null或对应空数组，不用0替代缺失。身份code:recDate；如果真实系统同日同股有多个episode，接入方必须扩展身份贯穿收藏、搜索、导出与回放，不能静默覆盖；原示例不存在这个情况。

正式管线的数据构建（tools/render_monitor_web.build_payload）只输出正式推荐（confirmed_active／legacy_v1_not_rewritten）与次日待首日（d0）记录；事件等待型条件记录（conditional_event）按复盘合同不进日报与台账、永不写复盘，网页与日报同口径不展示，记录本身仍保留在 snapshot/trace。前端对 refKind='event' 的提示逻辑保留给自行接入快照的接入方，正式管线不会再提供此类记录。

`recDate`是入选行动日（首日观察日）：当日开盘参与并确定参考价，第1个观察日从当日计。`formedOn`是推荐形成日（盘后报告写出该推荐的日期；正式管道取episode的formation_date，D0取该报告analysis_date，load_d0_entries已校验二者一致）。展示层日期标签一律用formedOn标"推荐日期"，recDate用于首日观察标注、主图坐标、记录身份与排序；formedOn缺失时（示例快照）回退显示"入选日期 recDate"。排序键仍为recDate：formation→action逐日严格配对，两者可见顺序一致。

candles=[open,high,low,close,amount_亿元]；这是既有展示接口的单位。不要把Tushare原始成交额单位不经处理直接塞进这里。此次新增的marketIndices是指数点数，不是金额。

## B. 新增市场行情字段

```json
{
  "presentation": {
    "marketCodes": ["000001.SH", "399001.SZ", "399006.SZ", "000688.SH"],
    "deepLimit": 8
  },
  "marketIndices": [
    {
      "code": "399001.SZ",
      "name": "深证成指",
      "trade_date": "2026-09-04",
      "close": null,
      "previousClose": null,
      "series": [],
      "source": "由接入方填写真实本地来源"
    }
  ]
}
```

这是**缺失值接口示例**，没有虚构指数点位。填入真实数值后原位置自动显示。series是按日期顺序的历史收盘，仅到当前交易日；中间缺失留null断线。没有series时不画曲线。trade_date不等于analysis_date时整项当日数值为空。

旧快照的上证market数组是唯一的兼容回退；不能把它复制为深证/创业板/科创指数。指数涨跌=(close/previousClose−1)×100，与个股推荐收益无关。

`adapt_snapshot.py`支持从已存在的index_daily风格CSV/JSON读取ts_code/code、trade_date、close、pre_close/previousClose。YYYYMMDD转换为YYYY-MM-DD，金额单位不参与。相同指数同日冲突报错；只有较旧日期时保持其旧日期，让页面显示待更新。该工具不调用Tushare、不查网络、不写事实仓。

## C. 当日普通详评名单

默认从每条记录当日最新review_kind读取regular_detail。原快照已经足够，不需编造额外名单。已有上游排序可提供：

```json
{
  "dailyDeepReview": {
    "date": "2026-09-04",
    "recordKeys": ["000768.SZ:2026-09-03", "300170.SZ:2026-09-01"]
  }
}
```

示例仅展示结构，不是建议替换原8只名单。被引用记录还须有当日regular_detail，空名单表示当天没有，不进行补位。最多8只不同股票，同股多次推荐在组内分别查看。名单缺失时保留源输入顺序，没有额外排序依据。

## D. 观点方向与复盘标签

每条review已有date/day/review_kind/base/outlookReason/viewLabel/viewReason/assessmentText等。UI原文和正文不重写。新接口可加outlookDirection=up/sideways/down/unknown/null，它必须表示未来1—3日的基准方向，与base同义。

旧快照按rules.js中BASE_DIRECTIONS精确映射base。无法识别的新文案不走关键词猜测；不计入方向变化，应由接入方提供结构化方向或扩展有据可核对的精确映射。保留原base用于查看。

viewLabel是原推荐支持度的变化：观点增强/观点减弱/维持原判断/首次复盘/判断失效。不是方向。因此viewChanged=true不代表进入观点更新；同方向类别的信心变化只保留在全量观点调整页。复盘日期相同的多份记录取截止内最新保存版本，生产导出需保证as_of边界已经处理。

## E. 失效与当日收盘

可选stock.invalidated是研究系统给出的**当前**失效状态。没有时按最新结构化复盘，再无复盘时按stage明确失效回退。不能从价格算出失效，也不能合并同代码所有历史记录的状态。旧数据有恢复标签时如实按源当前观点展示，本前端不追溯改写它的研究逻辑。

表格close=当前交易日candles[index][3]，不进行前值填补。若停牌数据供应方把前收复制到本日，生产适配时应依据真实停牌/交易状态把本日无成交报价标为缺失，不能让占位前收冒充新收盘。示例的停牌记录已经为空。

其他旧图表和回放的历史指标仍沿用core.js的原口径，全文原数字不会因为当前字段变化而被替换。回放是按归属复盘日期展示，不是严格实时可见回测。

## F. 不可更改

不得为漂亮程度补行情、改推荐日期、改参考价、填回看中的未来数据、迁移历史结论或写新荐股理由。data/source-manifest.json提供本包原始快照哈希与示例计数，便于确认未改写。

## G. 观察星图同股合并（仅展示层派生）

星图不新增任何输入字段。`rules.js` 从既有 stocks 只读派生：`atlasGroups` 按完整代码分组（组内按 recDate 升序，同日按输入顺序；同身份重复载入只算一次）；`atlasBasis` 给出股票视图主点（最早记录的 recDate+ref+交易日序号成套）；`atlasRecordPoint` 给出记录视图每点（该次自己的 ref 与序号）；`atlasGroupClose` 取同股同日（dates 同一序号）第一份有效收盘副本，不跨日拼接、不叠加成交额；`atlasBadge` 生成次数徽标；`atlasRange` 输出两种模式共用的真实数据轴范围（lo/hi 必含 0 与全部可绘制点，basis 固定为"本报告最早记录"）。

不可绘制的原因枚举：`待首日观察`（d0 计划记录）、`缺参考价`（ref 缺失或非正）、`交易日历不足`（recIndex 缺失或超出 dates）、`报告日无真实收盘`。这些记录进入星图下方"暂未绘制"列表并注明原因，不参与坐标计算，也不得改用其他日期或另一条记录的参考价顶替。原始 stocks 数组、记录身份与其他页面的筛选、收藏、导出键一律不变；同日同股多个 episode 仍要求接入方扩展身份（见本文件第三节），前端不做猜测性合并。
