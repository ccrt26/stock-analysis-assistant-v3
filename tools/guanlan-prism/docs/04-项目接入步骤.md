# 04｜接入现有股票助手的最短路径

## 先说明范围

本包是独立展示层成品，尚未接入用户的本地仓库或事实仓。下文给的是对现有代码的检查和最小接入方法，不捏造现有后端文件名，也不要求重建架构。

## 1. 定位实际生成链路

GLM5.3 进入用户指定的项目根目录，先确认当前目录与工作区，再阅读项目自身的 AGENTS/README。可以用以下只读搜索找到现有报告生成处：

```bash
pwd
git status --short
rg -n 'monitor-report-|观察日报|推荐观察台|reasonFull|recIndex|application/json' src tools ops tests
```

没有 rg 时使用现有编辑器搜索即可。需要查清四个事实：谁组装 JSON；谁写 HTML；谁传入行情日期与 as_of；谁决定输出文件位置。必须用当前实现确认，不能仅凭过去讨论猜测。

原有获取数据、研究、复盘、落库与任务调度继续使用原程序。页面好看不需要改选股 Skill 或复盘规则。

## 2. 原样保留本包源文件

在项目适合的位置放一个独立展示目录。名称由本地约定决定；这是新增目录，不声称项目已有某个特定路径。目录内完整保留：

```text
src/shell.html
src/base.css
src/prism.css
src/core.js
src/app.js
src/effects.js
tools/build.py
```

最简单的方式是原样保留这个包的目录结构。`build.py` 通过自身位置定位资源，不依赖当前终端路径。

保留外层页面隔离，避免宿主项目中的全局 CSS 改写本稿的 button、table、h1、svg、dialog 等元素。优先继续生成独立 HTML。确有现成框架必须嵌入时，采用项目已有的隔离方法，不把任务扩张成框架迁移。

## 3. 用原输入组装合同，不重新研究

依据 `docs/03` 把现有导出字段映射为本包结构。字段一致时直接传入；不一致时只写一个薄适配函数。这个函数只负责名称、单位、数组对齐、完整记录身份和空值，不负责荐股、排名、补文或判断支持度。

标题日期、页脚日期、记录数量已经由输入元信息绑定。示例中指定的聚焦股票在生产模式不会固定保留；有自己的展示顺序时，使用 presentation.heroKeys/cardKeys。

不要把 `snapshot.json` 复制成生产数据后每天继续展示同一份“漂亮”样本。

## 4. 调用渲染函数

`tools/build.py` 提供：

```python
render_html(snapshot, *, demo_showcase=False) -> str
```

这是纯 HTML 渲染，不访问行情、网络、数据库或券商。以下示例可在本包根目录实际运行，用于理解接入调用：

```python
import importlib.util
import json
from pathlib import Path

root = Path.cwd()
spec = importlib.util.spec_from_file_location(
    "guanlan_prism_renderer", root / "tools" / "build.py"
)
assert spec is not None and spec.loader is not None
renderer = importlib.util.module_from_spec(spec)
spec.loader.exec_module(renderer)

snapshot = json.loads((root / "data" / "snapshot.json").read_text(encoding="utf-8"))
# 验收包内视觉使用True；实际报告使用False。
html = renderer.render_html(snapshot, demo_showcase=True)
out = root / "dist" / "integration-example.html"
out.write_text(html, encoding="utf-8")
print(out)
```

实际项目中，应把 root 改为这个展示目录的确定位置，把 snapshot 换成已存在的导出函数结果，把 out 换成原报告输出位置。只接三个位置，不额外设计发布服务。

现有链路更容易调用脚本时，也可以直接用 CLI：

```bash
# 原样重建包内示例，保留截图中的展示顺序
python3 tools/build.py

# 从一份兼容数据生成另一个报告，不修改原数据文件
python3 tools/build.py --data data/snapshot.json --out dist/production-order-example.html
```

第二条故意走“正式显示顺序”：输入数据虽然相同，首页聚焦按数据顺序而非演示指定顺序，因此不应拿这张首页直接对比演示指定对象的截图。视觉验收必须把数据、模式与选中对象都固定相同。

## 5. 分两次验证，防止原因混在一起

第一次使用同一份示例数据和 demo_showcase=True，核对页面是否原样。参考 `tests/capture.py` 生成对照图，不使用“看起来差不多”的口头判断。

第二次才使用实际数据与 demo_showcase=False。核对数字、日期、图表、空值、同股多次记录与归属日期，确认没有把演示名字/日期写死进正式报告。

如果实数超出当前坐标轴、跨年日期或超出第一至第二十天主观察窗口，按照数据规范增加最小兼容处理与专项测试，必须清楚汇报改动；不修改原有业务口径，不裁剪事实，也不能声称样例测试已经覆盖这些生产情况。

## 6. 如何集成自动生成

展示生成接在现有“本次复盘/推荐数据已经形成”的位置，复用已有任务，不新加一个时钟任务。输出仍可以是本地 HTML。原报告保留到新页面经过验证，再由用户或既有发布约定决定是否替换入口。

本次不自动修改 launchd、不上传 GitHub、不覆盖用户其他文件。用户后续明确授权后再做相应动作。

## 最后交给用户的结果

需要一个可以实际打开的报告路径、一份已经接入的源码、清楚的生成命令、真实测试输出以及同数据的效果截图。只有文档、只有示例截图或只有静态漂亮封面，都不算完成接入。
