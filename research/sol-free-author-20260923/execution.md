## 6. 执行：各写一次、各核一次

附带`author_prompt.md`是作者完整任务，`fact_check_prompt.md`是核对完整任务。外层只能附真实输入文件位置，不能重新扩写成一份长要求，也不能要求固定标题、字数、数字数量、固定语气或逐条回应原研究。

附带`run_sol_stage.sh`只负责一次Codex调用，显式指定：

```text
model = gpt-6-sol
model_reasoning_effort = xhigh
forced_login_method = chatgpt
```

它不导入股票助手生产代码，不自动重试，不自动更换模型。输出用Markdown，不要求业务判断生成复杂JSON，避免再因互斥字段格式错误打断文章交付。

准备目录后先对脚本运行一次`bash -n`。这是本地语法检查，不是模型测试。然后按下列顺序执行，PATHS由外层按真实文件位置设置：

```bash
# PACKAGE_DIR：本包四个文件所在目录；RUN_ROOT：已经准备好材料的临时根目录。
# 均必须是已存在的绝对路径，不把示例字符串当实际路径。
export RUN_ROOT
bash -n "$PACKAGE_DIR/run_sol_stage.sh"

bash "$PACKAGE_DIR/run_sol_stage.sh" 300398.SZ author
# 只有退出成功、result.md确为实际正文，才原样复制到本股check/input/article.md。
# 若只交了决定性资料缺口，不伪装成文章；该股不启动核对会话。
cp "$RUN_ROOT/300398.SZ/author/run/result.md" \
   "$RUN_ROOT/300398.SZ/check/input/article.md"
bash "$PACKAGE_DIR/run_sol_stage.sh" 300398.SZ check

bash "$PACKAGE_DIR/run_sol_stage.sh" 001378.SZ author
cp "$RUN_ROOT/001378.SZ/author/run/result.md" \
   "$RUN_ROOT/001378.SZ/check/input/article.md"
bash "$PACKAGE_DIR/run_sol_stage.sh" 001378.SZ check
```

以上命令由外层逐步执行，不把整块盲跑。先确认上一步实际交付，再运行下一步。某一股失败，保留失败；另一股的独立任务可以继续。不会因为某股失败而重新跑成功稿，不删除run目录重抽，不自动恢复额度失败为新样本。脚本对同一阶段第二次启动会拒绝覆盖。

每次读取实际客户端能提供的请求/会话元数据，记录配置模型和实际报告模型、档位、开始结束时间、退出状态及可获得用量。不要让AI自报“我是Sol”代替执行证据；客户端未报告的字段写“未取得独立核实”，不伪造。发现实际换成Astra或档位不符，停止后续业务会话，不改标签掩盖。只读本轮日志的必要元数据，不遍历全部历史会话，不读取或上传隐藏推理。

核对者只纠事实与原研究含义，不审文风。若原研究的“持续”没有时长定义，就如实标为原研究歧义，不自动指定新时长，也不迫使作者发明条件。本轮不因这个问题重新开研究流程。明确的文章误写与原研究缺口分开呈现。
