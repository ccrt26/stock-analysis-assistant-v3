# 实施说明与边界

## 为什么必须增加一个最小理由字段

方向枚举只能表达结论，两个条件只能表达以后怎样验证。缺少中间的当前理由时，公开文字会把条件误当解释。新增 `outlook_reason_plain_language` 只保存 AI 基于当前最重要 1—3 项事实写出的短期方向理由；字段可空以兼容历史 V2 报告，但新 pending report 的每条 alert 必须填写。没有增加报告版本、评分、概率或新方向枚举。

历史记录没有该字段时，渲染器仍能使用原有方向和两个条件，不回写历史。新记录固定按“方向—理由—支持表现—改变表现”输出。

## 为什么不用公告标题关键词过滤

程序只能可靠确认“出现了公告”，不能仅凭“进展”“权益变动”或“核查意见”等标题判断它是否改变执行、控制权核心安排、收入、利润或现金流。标题关键词会把真实重大变化误删，也会把重复配套文件误判为重大事件。因此 snapshot 继续把 `new_official_event` 作为候选，是否公开由公司 Skill 和复盘 Skill 阅读正式内容后作语义判断。

## 为什么只放宽公告单独触发的强制公开要求

`pending_final_review`、固定检查点、首次达到目标、相对表现变化、价格情景变化、突破变化、行业状态变化、后期启动、过热和数据问题都会改变正式推荐的评价或履约完整性，仍属于 mandatory。只有 `new_official_event` 被排除在强制集合之外，因为“有公告”不等于“原判断发生变化”。公告重要时 AI 仍可主动选入；公告没有新条款时可以省略，也不要求凑满 8 只。

同一股票可能同时有正式记录和比较记录。强制原因按每条 episode 自己的 `attention_reasons` 计算，避免比较记录的检查点把正式记录的纯公告候选错误升级为 mandatory。

## 为什么内部记录仍完整

原始公告事实、snapshot、`attention_stocks`、每条 episode 的 `new_announcements` 和内部 trace 全部保留。`DailyForwardMonitorReportV2` 只保存 AI 实际选入的 alert 与 `unreported_attention_count`；省略可选公告候选不是删除内部证据，也没有新增表达“公告不重要”的字段。

公开合并报告不再展示事件线索、conditional 名称或数量、最近未选和比较股；内部 V4 trace、候选比较、事件公司证据和首个交易日观察条件保持原样。

## 未知方向的处理示例

当行动日没有可靠价格、后续事实也不足以判断时，内部仍使用既有 `event_pending`，公开方向写“目前没有足够的可交易事实判断方向”。`outlook_reason_plain_language` 要说明缺少可交易价格或事实冲突，后面的正反条件只用于以后验证。这个字段级示例用于验证未知方向兼容；如果某只股票没有实质新变化而未进入用户重点复盘，就不会为了展示“未知”而强行放回公开报告。

## 为什么没有重做选股或复盘系统

本次只修改提醒优先级、一个向后兼容的文字字段、未来判断的公开顺序和正式推荐的展示分段。没有重做五个选股 Skill，没有改变七种发动机、四种输出状态、11 个价格场景、20%目标、D20、入口价格或最终选择规则；也没有增加数据库、表、数据源、定时任务、评分器或预测概率。
