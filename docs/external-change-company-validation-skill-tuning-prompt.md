# 外部变化的公司验证调优 Prompt

## 任务性质

这是一次单点、可回滚的 Skill 调优。Prompt 通过独立审查后，在当前工作区内自动连续执行到验证和汇报。只有必须由用户授权的外部动作，或证据迫使唯一目标、修改文件或验收标准发生变化时，才停下请求介入。

## 唯一调优目标

修正公司 Skill 对“新变化”的过度公司事件化理解：

- 总控随板块或价格候选提交待验外部变化命题时，该命题可以来自形成日前的行业需求、产品价格、供需、竞争格局或板块共同变化，不必同时存在当日新公司公告。
- 公司 Skill 在这种验证任务中，应核对公司是否真实参与相关业务、外部变化如何传导、影响是否有材料性，以及存在什么公司反证。
- “没有当日新公司事件”不能单独推出“没有新变化”或 `insufficient`；但“只有行业/概念标签，没有真实业务联系或传导”仍然必须是 `insufficient`。

这次不以“永鼎股份必须最终入选”为目标。永鼎股份只是已暴露的开发案例，用来检查公司 Skill 能否对“外部变化＋历史已公开公司事实”做公司传导验证。最终是否入选仍由总控结合板块、价格、反证和可交易性决定。

## 冻结范围

原则上只允许修改：

`.agents/skills/researching-company-events/SKILL.md`

允许的实质性编辑最多两处，且都必须服务于上述唯一目标。不改 Skill 名称、触发描述、输出合同或证据充分性的三档定义，不重写整个 Skill。

如果 RED 验证表明真实阻塞不在公司 Skill，或必须改动总控、市场、板块、价格、数据层或代码才能继续，立即停止实施并汇报证据，不自行扩大范围。

## 明确不做

- 不新建 Skill，不修改另外四个 Skill。
- 不让公司 Skill 重复判断板块是否扩散、价格是否启动或行动日是否可参与。
- 不把价格异动本身写成外部经营变化；价格 Skill 只提交待解释候选，公司 Skill 仍需找到独立的公司业务事实与传导。
- 不建立总分、权重、固定阈值、Gate、状态机、事件配额或候选数量配额。
- 不新建候选管理系统、记分表、回测框架、永久脚本、数据表或报告系统。
- 不改数据，不联网补证，不使用 `2026-08-12` 及之后行情调参。
- 不切换分支，不新建 worktree，不提交，不推送。
- Prompt 审查完成后，后续不再启用子智能体。

## 编辑前基线（RED）

公司 Skill 的精确编辑前 SHA-256 为：

`7ef67cab55a8fb545a5dd2ed2bf8e925491c1368b4f495a58a01869a4d1819e9`

已知语义衔接如下：

- 当前总控明确规定：“没有当日新公司事件不阻止板块或价格线索入池，但必须经公司传导验证”。
- 当前公司 Skill 的核心问题只写“形成日前公司发生了什么真实变化”，发现阶段也从“形成日前出现了什么新变化”开始，验证阶段没有明确接收其他 Skill 已建立的外部变化命题。
- 因此，一个合理执行者可能把“公司当日没有新事件”误当成“没有可验证的新变化”。这与总控已冻结的独立线索路径存在语义缺口。

在修改前，必须用下列三个案例对精确编辑前文本做是/否检查。只有确认“案例 A 的验证路径没有被明确教授”，才允许编辑。如果编辑前 Skill 已经明确满足三个案例，不修改，直接汇报真实瓶颈不在该 Skill。

## 冻结案例

所有形成日事实都必须满足 `available_at <= 2026-08-11 23:59:59 Asia/Shanghai`。只验证公司视角如何处理原始命题，不查询未来收益，不作最终选股。

### 案例 A：外部变化＋真实业务联系＋无当日实质新公司事件

永鼎股份 `600105.SH`：

- 板块视角已可观察到“通信线缆及配套”组 5 日等权收益约 `+8.52%`、上涨面约 `92.31%`；这只是板块原始命题，公司 Skill 不重复认定板块强弱。
- 公司历史时点主营明确包含有线通信产品，`2025-12-31` 口径中“光通信”营业收入约 `10.70` 亿元、分部利润约 `2.16` 亿元，事实在形成日前已可见。
- `2026-07-06` 半年度业绩预增公告预计净利润增长 `57%–120%`，明确说明光通信板块受数字经济和 AI 算力需求带动，光纤市场量价齐升，板块利润大幅增长；可用时间为 `2026-07-07 00:00:00+08:00`。
- `2026-08-11` 当日公告为子公司银行授信担保进展，不应被强行写成光通信新催化。

期望行为：公司 Skill 可使用已有主营和业绩原因验证“公司真实暴露＋传导”，并根据材料性、反证和缺口给出 `sufficient` 或 `partial`；不因为当日没有新光通信公告就自动 `insufficient`，不把担保公告硬凑成催化，也不代替总控做最终入选。

### 案例 B：只有概念或行业标签

某股票因主题成员标签或板块上涨被提交，但形成日前只能找到概念词、公告标题或宽泛经营范围，无法证明相关产品、收入、利润、订单、客户或产能联系。

期望行为：仍然返回 `insufficient`，明确“真实业务联系/传导无法确认”。外部变化能作为待验证命题，不能代替公司证据。

### 案例 C：形成日可见的直接公司变化

江波龙 `301308.SZ`：

- 形成日可见的业绩预告预计 `2026 年半年度` 净利润增长约 `62204.03%–74393.95%`，原因包含存储产业景气、供应协议、自研芯片/软件和端侧 AI 存储需求；本地可用时间为 `2026-08-11 21:32:39.131531+08:00`。
- 公司主营明确为 Flash 和 DRAM 存储器研发、设计与销售。

期望行为：保留现有公司事件发现和验证路径，核对低基数、现金流、供应、一次性因素及价格/板块待验问题。新指引不得让直接公司事件线索丢失或被外部变化取代。

## 验收标准（GREEN）

修改后必须同时满足：

1. 明确区分公司 Skill 的两种任务：在发现阶段可以从公司自身事件找线索；在验证阶段可以接收总控随板块/价格候选提交的待验外部变化命题。
2. 外部变化命题进入公司验证后，必须回答真实业务暴露、可能传导、材料性、公司反证和缺口。
3. 没有当日新公司公告不再单独触发 `insufficient`；已有形成日可见且仍有效的历史公司事实可用于验证。
4. 只有概念标签、宽泛经营范围或公告标题时，仍然不能证明直接受益，不能因为板块强就提高证据充分性。
5. 不要求所有公司必须有当日新事件，也不反向要求所有公司必须属于强板块；两条来源都保留。
6. 公司 Skill 仍不判断板块动力、价格启动、剩余空间、行动日参与或最终入选。
7. 不新增字段、评分、阈值、新状态或扫描流程，不扩大第一轮公告正文阅读。

## 最小修改设计

只允许在现有结构中补足两处语义：

1. 在“核心问题”附近说明：公司 Skill 自主发现时从公司变化找线索；验证总控随板块/价格候选提交的待验外部变化命题时，只负责公司业务联系、传导和反证。
2. 在“验证阶段”附近说明：没有当日新公司事件不单独降为 `insufficient`；使用形成日前已可见且仍能支持当前命题的主营、收入、利润、订单、客户、产能或其他公司事实验证传导；找不到真实业务联系或核心传导时仍为 `insufficient`。

使用正向、条件化的判断方法，不把它写成“凡是板块线索就放行”的例外条款。

## 严格执行顺序

### 1. 保护当前工作区

- 记录 `git status --short`。
- 保留已修改的 `.agents/skills/orchestrating-stock-research/SKILL.md` 和 `.agents/skills/analyzing-price-trading/SKILL.md`。
- 保留未跟踪的 `docs/candidate-discovery-balance-skill-tuning-prompt.md`、`docs/price-attribution-skill-tuning-prompt.md`、`bingo/` 和 `who-is-it/`。
- 不覆盖、不清理、不回滚上述内容。

### 2. 验证 RED

- 重新核对公司 Skill SHA-256。不一致时先判断是否存在并行改动，不覆盖。
- 对照总控的独立线索语义和案例 A、B、C，逐项记录编辑前公司 Skill 是否明确教授预期行为。
- 只有案例 A 失败、案例 B 和 C 原有边界需保留时，才进入编辑。

### 3. 只做一轮最小编辑

- 按“最小修改设计”使用 `apply_patch` 编辑公司 Skill。
- 如果出现第三处实质性编辑、输出字段变化、另一个 Skill 改动、新脚本或新数据产物，视为超出范围，不保留。

### 4. 验证 GREEN

- 使用修改后文本重新应用案例 A、B、C，逐项回答是/否。
- 检查案例 A 是否可验证公司暴露和传导，但未被写成必须入选。
- 检查案例 B 是否仍然 `insufficient`，防止概念股被放宽。
- 检查案例 C 是否仍按原有公司事件路径处理，防止调优过度防御或反向偏置。
- 不打分，不查询未来收益，不根据单只股后来涨跌作第二轮调参。

### 5. 完成前验证

1. 使用 Skill Creator 的 `quick_validate.py` 验证 `.agents/skills/researching-company-events`。
2. 运行 `git diff --check`。
3. 读取 `git diff -- .agents/skills/researching-company-events/SKILL.md`，确认只有两处语义编辑。
4. 读取最终 `git status --short`，确认用户原有改动未被覆盖。

不为该语义调优新建永久测试框架、脚本、评分表或回测报告。

## 停止与回滚条件

下列任一情况立即停止，不做第二轮补丁：

- 编辑前 Skill 已经明确满足案例 A，真实缺口不在公司 Skill。
- SHA-256 与冻结值不同，且无法安全区分并行改动。
- 必须修改其他 Skill、数据层或代码。
- 最小编辑无法同时通过案例 A、B、C，或它使公司 Skill 开始代替板块/价格/总控作结论。
- 已完成一轮最小修改和冻结验证。

如果验证不支持修改，只逆转本轮对公司 Skill 新增的补丁，不使用 `checkout`、`reset`、覆盖或其他可能抹掉用户已有改动的方式。保留本 Prompt 和验证证据。

## 子智能体限制

- Prompt 编写完成后，只启用一个 `GPT-5.6 Sol`、`xhigh` 子智能体做只读审查。
- 审查者只读取本 Prompt 和当前五个 Skill；不修改文件，不执行调优，不查询未来行情，不启动其他子智能体。
- 审查只回答：目标是否单一，责任 Skill 是否正确，RED/GREEN 是否可执行，案例是否自洽，是否放松了概念股，是否过度工程化/过度防御，以及是否可直接执行。
- 如果审查者发现问题，先核对建议是否符合仓库现实；只修改本 Prompt。如果必须复核，使用同一子智能体，不新开审查者。
- Prompt 确认无误后，关闭审查阶段。后续执行不再使用子智能体。

## 最终汇报

最终只给出一份可复核汇报，包含：

1. 冻结目标、修改范围和明确未做的事项。
2. Prompt 文件位置、独立审查结论与建议采纳情况。
3. RED 语义缺口和案例 A、B、C 的 GREEN 结果。
4. 公司 Skill 的精确两处改动及为何没有扩大公司 Skill 职责。
5. Skill 结构验证、`git diff --check` 和最终工作区状态。
6. 唯一结论：“保留修改”、“回滚修改”或“未修改，阻塞在……”。

不把该语义验收写成收益保证，不因永鼎股份后来的涨停声称调优已经证明预测能力。
