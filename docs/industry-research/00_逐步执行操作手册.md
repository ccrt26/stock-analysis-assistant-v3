# 热点反向穿透法：从零开始逐步执行操作手册 V2.0

> 只按“第1步、第2步……”操作；每一步都说明谁执行、给什么、产出什么、你读什么、下一步用什么

## 这次相对 V1.0 改了什么

旧版的问题不是没有规则，而是用户要在大量技术文件中自己判断“现在该用哪个”。V2.0 改成一个唯一入口：**先做第0步，之后每次只打开当前运行目录里的 `00_下一步操作.md`。** 技术 Skill、方法文档和 YAML/JSON 模板由 ChatGPT/Codex读取，用户不再逐个选择。

### 你在整个流程中只做四件事

1. 第一次把最小执行包交给 Codex 安装；
2. 每个新主题确认一次 `00_研究范围.yaml`；
3. 每一步只读当前的人话报告和 `00_下一步操作.md`；
4. 把 `00_下一步操作.md` 中的提示词、仓库分支和 commit 交给下一位执行者。

## 你需要亲自看的文件只有这些

| 时点 | 你打开什么 | 其他文件怎么办 |
|---|---|---|
| 安装前 | 本手册、安装 Prompt | ZIP 内技术文件不用逐个看 |
| 每一步开始 | `00_下一步操作.md` | 它会列出本步必读文件和可复制提示词 |
| 每一步结束 | 当前步骤的人话报告/摘要 | YAML、JSON、CSV主要给下一方和审计使用 |
| A、B、C阶段结束 | 阶段最终报告 | 由你决定批准、带缺口继续、退回或停止 |
| D日常 | 月度摘要或重大触发摘要 | 无重大变化不看每日状态 |

## GitHub 交接的固定格式

从第2步开始，推荐不再手工上传一堆文件。每次只向下一方提供：

- 仓库链接；
- 分支名；
- 最新 commit；
- 本次运行目录路径；
- `00_下一步操作.md` 路径；
- 一句话：**“只执行该文件写明的当前步骤，完成后更新它并停止。”**

只有无法访问 GitHub 时，才使用每个步骤卡片中的“手工上传兜底”。

# 附录四　永远不能越过的边界

- ChatGPT 不跳过 Codex 的本地财务、估值、点时和实体核查。
- Codex 不从关键词、公司简介、主题标签或公告标题认定供应关系。
- 认证、专利、送样、一次中标不能自动证明重复订单、收入、利润和核心份额。
- 数据不存在、覆盖不足、查询失败、真实无记录和未知必须分开。
- 不用当前最新数据倒填历史，不覆盖旧版本，不静默删除未知。
- 任何阶段允许零候选；不固定公司数量，不用一个总分弥补硬门失败。
- 全流程不自动交易、不决定仓位、不承诺收益。
