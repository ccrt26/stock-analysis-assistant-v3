# 热点反向穿透法：傻瓜式实际执行手册 V3.0

> 适用状态：你已经让 Codex 完成了 V2.0 的本地安装 commit，但安装分支尚需补全、推送、审阅和合并。以后不再让你填写产业研究的技术表格；ChatGPT 起草，用户只审批，Codex 只负责仓库、本地数据、计算和监控。

## 先说结论：上一版哪里做错了

上一版有一部分是对的，也有一部分没有严格执行 V4 的分工。

| 事项 | 上一版安排 | 判断 | V3.0 修正 |
|---|---|---|---|
| 把文档、Skill、模板装进本地仓库 | Codex 执行 | 正确。它是明确、可验证的文件操作 | 保留，但必须补上 push、ChatGPT 审阅和合并 |

| 创建研究分支、目录、commit | Codex 执行 | 正确。它是仓库操作 | 放到 ChatGPT 范围草案得到用户批准之后 |

**最关键的纠偏：**安装是技术动作，所以第一位可以是 Codex；但安装之后的第一个实质研究动作必须是 ChatGPT，而不是 Codex，更不是让你手工设计范围。

## 一句话分工

- **ChatGPT：**研究负责人。负责陌生产业、范围、付款人、四张图、七视图、精确产品节点、公司关系、证据含义、商业解释、持续性和失效条件。
- **Codex：**本地执行负责人。负责文件、分支、commit/push、实体和证券代码、点时本地数据、财务估值计算、重复监控和历史留痕。
- **用户：**审批负责人。只需要确认研究范围、阅读关键报告、决定继续/修改/停止；不填写 YAML，不设计系统边界，不替模型做产业研究。

## 以后用什么标准决定交给谁

| 问题特征 | 交给谁 | 例子 |
|---|---|---|
| 需要全网、多语种、PDF、标准、技术和商业因果判断 | ChatGPT | 谁是最终付款人、液冷应该拆到哪里、认证能证明什么、谁可能是非上市供应商 |

| 涉及研究范围或资金行动 | 用户批准 | 同意研究边界；是否实际行动、仓位与退出 |

# 第三部分　每个阶段为什么这样接力

## A阶段：ChatGPT → Codex → ChatGPT

- 第一次 ChatGPT：从开放世界定义产业、节点和线索；
- Codex：告诉我们本地能映射和取得什么；
- 第二次 ChatGPT：判断本地事实是否改变产业关系，完成三道地基门。

如果让 Codex先从本地A股名单拼产业链，容易把关键词和主题标签当成真实关系。

## B阶段：ChatGPT → Codex → ChatGPT

- ChatGPT先按业务模式定义“查什么”；
- Codex按点时合同取数和计算；
- ChatGPT再判断数字是否来自目标业务、缺口是否阻断。

如果只让 Codex计算，它可能得到准确数字，却不知道数字是否属于液冷节点；如果只让 ChatGPT看网页数字，又无法保证点时和重跑一致。

## C阶段：ChatGPT → Codex → ChatGPT

- ChatGPT建立生意链、证据约束和三情景假设；
- Codex机械计算；
- ChatGPT综合产业、公司、财务、持续性和预期差。

这就是“Codex负责账本没有算错，ChatGPT负责账本说明了什么生意”。

## D阶段：Codex → ChatGPT → Codex

- Codex长期守候固定条件；
- 重大变化交给 ChatGPT解释；
- 用户批准后，Codex保存新版本。

这样既不会每月重做整个产业研究，也不会让价格变化自动改写产业逻辑。

# 第四部分　遇到问题时怎么处理

| 情况 | 正确处理 | 不要做 |
|---|---|---|
| Codex说缺少产业范围 | 退回 ChatGPT起草，不让用户填技术字段 | 用户临时编系统起点/终点 |
| ChatGPT找不到关键证据 | 写未知、缩小范围或停止 | 用媒体、专利、招聘补成订单 |
| Codex本地没有某字段 | 标记 unsupported/partial，并交ChatGPT判断影响 | 把缺失当零 |
| ChatGPT和Codex结论冲突 | 保留双方字段，新增 conflict，ChatGPT解释语义 | 一方覆盖另一方原始结果 |
| ChatGPT产出文件尚未入库 | 下一次 Codex步骤先原样保存，再执行本地任务 | Codex改写ChatGPT产业字段 |
| ChatGPT看不到本地分支 | 让Codex commit并push，再给远程分支和commit | 只说“已经提交”但不push |
| 一次补查仍不能确认 | 保留未知或停止 | 无限来回搜索 |
| 最终没有研究候选 | 接受零候选 | 为了有结果凑公司 |

# 第五部分　完成检查

执行文档只有满足以下条件才算“傻瓜式”：

- 安装之后第一个实质研究动作由 ChatGPT完成；
- 用户不填写 YAML/JSON/CSV；
- 第一次液冷试点范围由 ChatGPT预填；
- 每一步明确执行者、输入、Prompt、输出、用户阅读项和下一步；
- 每个 Codex步骤均要求 commit + push；
