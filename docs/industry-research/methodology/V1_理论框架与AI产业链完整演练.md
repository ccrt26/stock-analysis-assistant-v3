> 本报告最终想解决的不是“AI有哪些概念股”

# **第一部分 理论框架：从热点找到真正的利润**

## **1. 方法的定义**

**“热点反向穿透法”**不是从股票名称出发，也不是先找一张产业链表。它从最终需求和最终付款人出发，逐层向后追问：需求为什么增加，必须采购什么，哪一环最难替代，新增收入能否变成利润，市场是否已经充分预期。

> 一句话定义
> 热点负责发现变化，采购清单负责解释需求，产业链负责追踪钱流，瓶颈负责寻找议价权，财务负责确认利润，价格负责决定是否值得投资。当前报告只做到“财务之前”的产业级研究。

## **2. 为什么这套方法在理论上成立**

### **2.1 新技术要先补齐配套设施**

通用技术研究指出，人工智能、电力、计算机这类技术会渗透很多行业，而且要与设备、流程、人才、组织和基础设施一起投入，价值才会真正释放。\[1\]\[2\] 因此，技术突破出现以后，最先确定的往往不是所有下游应用都赚钱，而是社会必须先建设一批“让技术跑起来”的配套能力。

**通俗理解：发现了金矿，不代表马上能卖出黄金。先要修路、通电、建营地、买机器。配套建设往往比最终赢家更早出现订单。**

### **2.2 需求会沿供应链传导，但不会平均分配**

生产网络研究说明，一个行业的需求或供给变化会沿直接和间接供应关系传播；某种投入越专用、越难替换，冲击传播越明显。\[4\]-\[6\] 这意味着“上游”本身没有价值保证，真正重要的是缺少这个环节会不会让整个项目停下来。

**通俗理解：一台机器由一百个零件组成，最贵的零件未必最赚钱；那颗缺了就不能交付、又只有两家能生产的小零件，反而可能最有议价权。**

### **2.3 发明者未必拿走最多利润**

Teece的经典研究指出，当技术容易被模仿、商业化又依赖特殊制造能力、渠道、认证或其他配套资产时，利润可能更多流向掌握关键配套资产的人，而不是最早发明技术的人。\[3\] “卖铲子”真正指向的不是普通上游，而是关键配套资产。

### **2.4 公开关系有时不会被市场立刻算清楚**

客户—供应商研究发现，受到注意力限制的投资者可能先反映最显眼公司的信息，之后才逐渐把影响传导到经济上相关的公司。\[7\] 这为“从热点向第二层、第三层穿透”提供了可能，但不能把历史研究直接理解成“产业链一定补涨”。

### **2.5 热点也会制造拥挤和泡沫**

注意力研究表明，个人投资者更容易买入新闻多、成交异常和短期涨幅突出的股票；行业快速上涨、换手率上升和融资扩张也会提高后续大幅回撤风险。\[8\]-\[10\] 因此，热点只能作为雷达，不能直接作为买入信号。

> 理论结论
> “卖铲子”成立的必要条件不是“它在上游”，而是：必须采购、供给受限、难以替代、能留住利润、对公司足够重要、市场尚未完全算完。

## **3. 五问一否决**

| **问题**                         | **通俗解释**                                                       | **应该找的证据**                                   |
|----------------------------------|--------------------------------------------------------------------|----------------------------------------------------|
| **第一问：必须买吗？**           | 热点增长后，这种产品或服务是否无法绕开。                           | 采购清单、系统架构、客户招标、行业标准。           |
| **第二问：容易买到吗？**         | 供应商多不多，扩产快不快，认证难不难，技术路线是否稳定。           | 交付周期、产能利用率、长期协议、预付款、认证周期。 |
| **第三问：钱能留下吗？**         | 收入增长是否能转成毛利、净利润和现金流。                           | 售价、产品结构、毛利率、费用率、应收、经营现金流。 |
| **第四问：对公司够大吗？**       | 主题新增利润对上市公司原有利润是否足够重要。                       | 业务占比、客户结构、产能、增量利润弹性。           |
| **第五问：市场算完了吗？**       | 股价和估值是否已把未来几年的增长提前反映。                         | 一致预期、估值、筹码拥挤、扩产预期。               |
| **一票否决：怎样证明我们错了？** | 技术路线变化、需求延迟、供给过剩、客户自制、价格下跌、回款恶化等。 | 在研究开始时预先写明，不允许事后修改理由。         |

**提醒公式：机会质量 ≈ 真需求 × 瓶颈强度 × 利润捕获能力 × 业务重要性 × 市场预期差。它是乘法，不是加法；任何一项接近零，整个机会都可能失效。**

## **4. 四张图与四种状态**

| **工具**       | **作用**                                                                            |
|----------------|-------------------------------------------------------------------------------------|
| **需求图**     | 把最终使用需求翻译成必须采购的设备、部件和服务。 回答“矿是不是真的存在”。           |
| **钱流图**     | 从最终付款人、预算类型一路追到订单、收入和现金流。 回答“谁真正收到钱”。             |
| **瓶颈利润图** | 同时观察难替代程度和利润留存能力。 回答“哪把铲子可能最值钱”。                       |
| **时间图**     | 把政策、试验、订单、交付、扩产和过剩放到同一条线上。 回答“现在太早、刚好还是太晚”。 |

| **状态**       | **最低证据门槛**                                   | **最容易误解的地方**                             |
|----------------|----------------------------------------------------|--------------------------------------------------|
| **已出现订单** | 已有采购合同、在手订单、批量出货或规模部署。       | 并不等于利润好，也不等于价格便宜。               |
| **正在验证**   | 有试点、送样、客户认证、早期收入或局部部署。       | 关键看能否复制、扩大并改善利润。                 |
| **只有政策**   | 有明确规划、目标或试点任务，但缺乏可重复采购证据。 | 先建立观察指标，不提前假设受益公司。             |
| **只有概念**   | 只靠逻辑联想、关键词或很小业务关系。               | 在出现采购必要性、业务占比和财务证据前，应剔除。 |

> 非常重要：状态必须挂在“精确命题”上
> “液冷已出现订单”可以成立，但“所有散热公司都已受益”不成立；“运营商已部署国产AI芯片”可以成立，但“国产高端算力已全面替代进口方案”仍在验证。一个宽泛方向可以同时包含四种不同状态。

# **第二部分 AI演练前的证据底座**

## **5. 先确认AI不是只有热度**

这一步不是为了证明“AI永远会增长”，而是为了确认截至2026年8月，AI需求已经产生了可观察的使用量、资本开支、设备收入和基础设施订单。只有先证明真实支出存在，后面的产业链穿透才有意义。

| **观察指标**                    | **公开事实**                                                                         | **它能证明什么**                         |
|---------------------------------|--------------------------------------------------------------------------------------|------------------------------------------|
| **中国日均Token调用**           | 截至2026年3月超过140万亿，较2025年底三个月增长超过40%。\[13\]                        | 终端使用量不是静止的，推理需求正在扩大。 |
| **中国算力总规模**              | 近年来年增速约30%。\[13\]                                                            | 基础设施需求有持续扩张背景。             |
| **全球数据中心用电**            | IEA预计从2024年的415 TWh增至2030年的约945 TWh。\[18\]                                | AI扩张会形成真实的电力、配电和冷却需求。 |
| **Alphabet 2026资本开支**       | 预计1750亿至1850亿美元；2025年资本开支约60%用于服务器、40%用于数据中心与网络。\[19\] | 云厂商正在把需求转成设备和机房采购。     |
| **Microsoft FY2026 Q3资本开支** | 319亿美元，其中约三分之二用于GPU、CPU等短周期资产。\[20\]                            | 加速计算设备处于真实采购阶段。           |
| **NVIDIA FY2027 Q1**            | 数据中心收入752亿美元，AI网络收入148亿美元、同比增长199%。\[21\]                     | 需求不只在芯片，也向集群网络扩散。       |
| **中国三大运营商2026投资**      | 算力投入占比均提高到30%以上；中国电信算力基础设施投资255亿元、同比增长26%。\[14\]    | 中国本地付款人也在持续安排算力预算。     |

> 这组证据能证明什么、不能证明什么
> 能证明：AI已经产生真实使用和资本开支，产业链研究不是空中楼阁。不能证明：每个环节都会赚钱、每家相关公司都会受益、当前股价仍有空间。后面四张图就是为了继续排除这些错误推论。

# **第三部分 AI的四张图完整演练**

## **6. 需求图：从“AI很热”翻译成必须采购什么**

**图1 AI需求图：从使用需求到物理采购清单**

资料截至2026-08-26；本图是研究框架，不代表任何公司受益结论。

### **6.1 这张图怎么读**

- 第一层看最终使用：企业智能体、工业AI、消费终端、科研和政务应用，决定是否真的有人愿意使用和付费。

- 第二层看模型工作量：训练需要更多实验，推理需要更多Token和更低时延，数据处理需要持续存储、检索和更新。

- 第三层看计算与存储：加速芯片、服务器、HBM、先进封装、高速存储和推理软件成为直接需求。

- 第四层看集群协同：算力规模越大，交换机、光互连、连接器、PCB、线缆和异构调度越重要。

- 第五层看物理底座：机柜功率上升后，供配电、UPS、母线、液冷、机房、并网和备用电源会成为现实限制。

- 第六层看规模应用支撑：数据、安全、合规和行业运维决定AI能否进入企业核心流程。

### **6.2 这一步达到了什么效果**

> 把“概念名单”变成“采购清单”
> 演练后，我们不再只知道AI下面有算力、服务器和变压器，而是知道每一层为什么会被采购、由上一层什么变化触发，以及哪些环节只是配套、哪些可能成为新的限制。

**这张图还没有告诉我们谁能赚钱。它只完成第一道门槛：证明某个方向是“必须采购项”，而不是因为名称和AI相似就硬连上关系。**

## **7. 钱流图：从付款人追到订单、利润和现金流**

**图2 AI钱流图：相关不等于收款，收款也不等于利润**

### **7.1 为什么要区分三种钱**

| **预算类型**       | **典型用途与研究意义**                                                                    |
|--------------------|-------------------------------------------------------------------------------------------|
| **资本开支 CAPEX** | 建数据中心、购买GPU/服务器、网络、供配电和冷却。 最先形成设备和工程订单，金额大但周期长。 |
| **运营支出 OPEX**  | 购买云、Token、模型调用、软件订阅和运维。 更接近持续收入，但商业模式和客户续费更重要。    |
| **研发投入 R&D**   | 训练模型、购买数据、测试新架构和安全工具。 可能先形成试验和认证，不一定立即规模化。       |

### **7.2 钱流演练得到的关键判断**

- 云厂商和运营商的大额资本开支，会先流向芯片、服务器、存储、网络、供配电、冷却和数据中心建设。

- 设备厂商再向HBM、先进封装、光器件、关键电气部件和液冷零部件下单，第二层供应商才真正获得收入机会。

- 企业智能体、数据、安全和行业软件更多依赖运营支出与研发支出，收入可能更持续，但当前复制性和客户付费意愿需要单独验证。

- 最终不能停在“下游资本开支增长”。必须继续看到订单、交付、收入、毛利率和经营现金流，才能证明利润链完成。

> 这一步最大的作用
> 把“它和AI有关”改成“谁给谁付了多少钱”。例如，AI需要电并不自动等于所有发电企业受益；只有当数据中心新增预算明确落到某类供配电设备，而且该类设备对供应商收入和利润足够重要，产业逻辑才继续成立。

## **8. 瓶颈利润图：哪里既难替代，又可能留住利润**

**图3 瓶颈—利润图：需求大不等于利润大**

### **8.1 四个象限分别意味着什么**

| **右上：难替代、能留利润**     | 最值得继续深挖。通常具备稀缺产能、长认证周期、技术壁垒或关键客户关系。              |
|--------------------------------|-------------------------------------------------------------------------------------|
| **左上：利润潜力高、壁垒待证** | 软件、数据和安全可能毛利高，但客户是否持续付费、产品是否可复制仍需验证。            |
| **右下：需求真实、容易被压价** | 服务器组装、IDC工程等可能订单很大，但客户强势、资本密集或产品同质化，利润未必同步。 |
| **左下：普通供给或泛概念**     | 容易扩产、容易替代，或主题新增需求占行业总需求太小。                                |

### **8.2 当前AI中更接近“真铲子”的产业方向**

| **方向**                      | **为什么值得深挖**                                                                                               | **不能忽略的风险**                                   |
|-------------------------------|------------------------------------------------------------------------------------------------------------------|------------------------------------------------------|
| **AI加速芯片、HBM与先进封装** | 算力增长直接提高需求，供给集中、工艺与良率要求高；已出现批量出货和巨额资本开支。\[19\]-\[21\]\[25\]              | 技术迭代快、客户集中、扩产后供需反转。               |
| **高速光互连与AI网络**        | 集群规模扩大后，通信带宽和能耗成为系统限制；NVIDIA网络收入快速增长，并出现多年采购承诺与产能权安排。\[21\]\[24\] | 产品代际快、单价下降、路线切换。                     |

> 这一步把“有订单”和“值得赚钱”分开了
> 服务器、机房工程可能很早拿到大订单，但利润率未必高；某个价值量较小的光器件、电气部件或液冷连接件，如果长期难替代，反而可能有更强利润弹性。下一阶段公司研究必须围绕这种差异展开。

## **9. 时间图：方向正确，也可能研究得太早或太晚**

**图4 AI产业方向时间图：证据越靠右，兑现越清楚，竞争风险也越高**

### **9.1 时间图中的七个阶段**

- 政策/研究：国家或企业确认方向，但采购对象和金额还不清楚。

- 标准/演示：出现样机、标准、概念验证，能做不等于能批量交付。

- 试点/认证：客户开始测试，产品关系较真实，但规模和利润未确定。

- 小批量订单：第一次收到钱，仍要看是否重复、是否跨客户复制。

- 规模订单与收入：需求被合同、交付和财务数据证明。

- 扩产与竞争：行业利润被看到，大量公司进入，价格和份额开始承压。

- 过剩与降价：需求仍增长，但供给更快，收入增长不再等于利润增长。

### **9.2 时间图揭示的当前差异**

- 加速芯片、服务器、HBM、先进封装、高速网络、供配电已经进入规模订单与扩产并存阶段。研究重点不再是“有没有需求”，而是供给何时追上、价格和份额能否保持。

- 液冷已经出现真实订单，但不同技术路线、接口标准和关键部件价值分配仍在变化，属于“订单已出现、产业仍在验证”的混合阶段。

- 算力调度、推理优化、企业智能体、端侧AI、数据和安全已有试点或早期收入，但大规模复制和利润模型尚未稳定。

- 政策提出的算力互联、算电协同、普惠算力和智能体普及目标非常明确，但不能把政策目标直接当作所有相关企业的订单。

> 时间图的价值
> 它让我们避免两种错误：第一，技术刚展示就把未来五年的收入一次性算进去；第二，等到所有人都看到订单、所有企业都扩产以后，才把它当成“新机会”。

# **第五部分 为什么要这样做，最终达到了什么效果**

## **10. 用最通俗的话解释每一步**

> 画需求图：先确认矿里真的有金
> 为什么做：热点很容易让人从“AI很重要”直接跳到“某个材料会涨”。需求图强迫我们从真实使用开始，把每一层必须采购的东西写出来。
> 做到什么：得到一张有因果关系的采购清单，知道为什么需要芯片、网络、供电、冷却、数据和安全。
> 避免什么：避免因为名称相似、媒体热度或产业链表里出现，就把公司认定为受益者。

> 画钱流图：看谁真的收到钱
> 为什么做：产业链上“会用到”某样东西，不代表最终付款人的预算一定流到这个环节。钱流图从云厂商、运营商和企业的预算出发，一直追到订单、收入和现金流。
> 做到什么：区分资本开支、运营支出和研发投入，知道设备订单通常先出现，软件和数据收入需要另外验证。
> 避免什么：避免把宏观资本开支直接平均分配给所有上游企业。

> 画瓶颈利润图：不是卖得多就一定赚得多
> 为什么做：服务器组装可以有大收入但低毛利；关键光器件或电气部件价值量不一定最大，却可能因为难替代而有更强议价权。
> 做到什么：把“需求强度”和“利润留存”分开，筛出真正值得进一步研究的瓶颈环节。
> 避免什么：避免只看行业增速、订单金额或营业收入，忽略毛利率、竞争和现金占用。

> 画时间图：方向对也可能时点错
> 为什么做：一项技术从政策、演示、认证、订单到扩产和过剩，需要经历不同阶段。不同环节的商业进度也不一样。
> 做到什么：知道哪些方向已经有订单，哪些还在试点，哪些正在进入扩产竞争。
> 避免什么：避免在样机阶段把未来利润全部算进去，也避免在所有人扩产后才把它当成新发现。

> 分四种状态：把“计划做”与“已经付款”分开
> 为什么做：政策、试点、订单和概念经常被放在同一篇研报里，读起来都像利好。四种状态要求每个命题达到最低证据门槛。
> 做到什么：形成可以动态升级和降级的观察清单，而不是一张永远不变的AI概念名单。
> 避免什么：避免政策目标、企业表态、送样测试和批量收入被混为一谈。

## **11. 这次AI演练已经取得的结果**

| **已经得到什么**                    | **具体效果**                                                                                                     |
|-------------------------------------|------------------------------------------------------------------------------------------------------------------|
| **把“大热点”缩小了**                | AI不再是一个无法下手的大词，而被拆成计算存储、集群网络、供配电、冷却、机房、调度、应用、数据和安全等可验证方向。 |
| **找到了当前证据最硬的支出方向**    | 加速计算、HBM与先进封装、高速网络、数据中心供配电、液冷和AIDC已有资本开支、合同、批量出货或收入证据。            |
| **区分了订单与利润**                | 服务器和工程订单真实，但不自动等于高利润；关键部件和稀缺产能需要继续研究议价权。                                 |
| **区分了全球产业事实与A股公司事实** | 全球出现大额订单，只证明这一产业方向成熟；A股公司是否受益仍要重新核对产品、客户、占比和财务。                    |
| **建立了证据升级路径**              | 一个方向可以从政策进入试点，从试点进入订单；也可以因技术替代、扩产过快或价格下跌而降级。                         |
| **明确了暂时不选股的理由**          | 现在选股会把产业判断、公司判断和价格判断混在一起。先把产业方向分清，下一阶段才能更有效地核查公司。               |

## **12. 现在我们知道什么，还不知道什么**

> • AI需求已有真实使用量、资本开支和订单支撑。
> • 当前物理瓶颈主要集中在计算/存储、集群互连、供配电和高密度冷却。
> • 调度、应用、数据与安全已进入验证，但商业复制尚不稳定。
> • 政策、试验、订单和概念可以被明确区分。
> • 哪家A股公司的相关产品真正进入客户供应链。
> • 相关业务占公司收入和利润到底多大。
> • 新增收入能否提高毛利和经营现金流。
> • 当前股价是否已经把增长全部反映。
> • 哪个方向会因扩产、降价或技术路线变化失效。

> 这次演练的真正产物
> 不是一张“AI股票名单”，而是一张研究地图：哪些方向已有付款，哪些还在试验，哪些只是政策目标，哪些只是市场联想；每个方向下一步需要补什么证据，也已经写清楚。

## **13. 对后续研究最有价值的方向排序**

| **研究层级**                         | **包含方向**                                                                                   | **下一步动作**                                             |
|--------------------------------------|------------------------------------------------------------------------------------------------|------------------------------------------------------------|
| **第一层：订单与瓶颈都较清楚**       | 加速计算/HBM/先进封装、高速光互连与AI网络、数据中心供配电、高密度液冷关键环节。                | 下一步查具体产品、客户、产能、毛利、现金流和扩产风险。     |
| **第二层：有部署但商业模式仍需验证** | 国产高端算力全栈、异构调度、推理优化、企业智能体、工业AI、端侧AI、行业数据、AI安全、800V供电。 | 下一步查跨客户复制、独立付费、续费、单位经济性。           |
| **第三层：政策观察**                 | 全国标准化算力交易、数据交易、算电市场、AI治理独立预算、未来能源和余热利用。                   | 只设置升级指标，不提前映射公司。                           |
| **直接剔除：泛概念**                 | 所有发电企业、所有变压器/铜铝/热管理/机器人零部件都受益等宽泛命题。                            | 除非出现产品、客户、订单、占比和利润证据，否则不进入候选。 |

# **附录A 热点穿透研究检查表**

以后面对任何热点，都可以先按下面的顺序完成一页研究卡，再考虑是否进入公司层面。

| **检查项**          | **必须回答的问题**                                       |
|---------------------|----------------------------------------------------------|
| **1. 热点命题**     | 精确写出终端需求，不使用“AI+”“国产替代”这类宽泛词。      |
| **2. 最终付款人**   | 谁决定预算，钱来自资本开支、运营支出还是研发投入。       |
| **3. 真实支出证据** | 至少两类：使用量、资本开支、招标、合同、批量出货、收入。 |
| **4. 必须采购清单** | 每增加一份终端需求，哪些设备、部件或服务必须增加。       |
| **5. 瓶颈证据**     | 供应商数量、认证周期、交付周期、产能利用率、长期协议。   |
| **6. 利润链**       | 售价、毛利率、产品结构、费用、应收、库存和现金流。       |
| **7. 时间阶段**     | 政策、演示、试点、订单、交付、扩产还是过剩。             |
| **8. 当前状态**     | 已出现订单 / 正在验证 / 只有政策 / 只有概念。            |
| **9. 升级条件**     | 什么证据出现后，状态可以向前升级。                       |
| **10. 失效条件**    | 技术替代、需求延迟、扩产过快、价格下跌、客户自制等。     |

# **附录B 高星GitHub项目能提供什么，不能提供什么**

现有高星项目没有一个能够直接完成“热点发现 → 产业链穿透 → 瓶颈判断 → A股公司利润映射 → 价格判断”。它们更像不同的研究零件。以下星标规模仅为2026年8月26日前后的公开快照，会随时间变化。

| **项目**                  | **可借鉴**                             | **不能替代**                               |
|---------------------------|----------------------------------------|--------------------------------------------|
| **OpenBB（约7.2万星）**   | 统一接入金融、宏观和公司数据。         | 数据入口，不替代产业因果判断。             |
| **Qlib（约4.8万星）**     | 把想法连接到数据、实验、回测和评估。   | 适合验证信号，不会自动识别真实产业瓶颈。   |
| **GraphRAG（约3.6万星）** | 表达热点—需求—设备—部件—公司的关系图。 | 每条关系仍必须附证据和时间。               |
| **AKShare（约2.2万星）**  | 提供中国金融与经济数据接口。           | 接口可用不等于数据口径可靠，仍需交叉核验。 |
| **FinGPT（约2.1万星）**   | 阅读新闻、公告和金融文本。             | 语言模型判断不能代替订单和财务证据。       |
| **RD-Agent（约1.4万星）** | 把研究做成提出假设、实验、纠错的循环。 | 可借鉴研究流程，不应直接照搬为荐股系统。   |

> GitHub真正给出的启发
> 不要让AI背一张静态产业链表。应保存“关系 + 证据 + 时间 + 状态”，并持续检验关系是否真的转成订单、利润和现金流。
