# A 股候选池内最终选股准确性调优执行 Prompt

## 唯一目标

只优化现有候选池内的最终取舍准确性：诊断当前五个 Skill 为什么会在已经进入同一形成日候选池的股票之间选错，并仅在历史证据可重复、形成日可见、能够排除相似失败反例且通过后段盲态验证时，对现有 Skill 保留一版最小修改。

候选发现范围、数据平台、运行平台和自动化能力不属于本轮目标。修改版必须使用原版已经冻结的同一候选池，不得增加、替换或重新发现候选。

“完成分析”“生成文件”“测试通过”都不等于选股变准。只有验证结果满足本文成功标准，才能保留 Skill 修改并表述为“本样本内选股变准”；否则精确回退修改。

## 开始前必须遵守

完整阅读并遵守：

- `AGENTS.md`；
- `docs/architecture/current-v3-architecture.md`；
- `.agents/skills/orchestrating-stock-research/SKILL.md`；
- 市场、板块、公司和价格四个专业 Skill；
- `docs/` 中实际涉及完整复跑、候选链、成熟历史、对照诊断、最终取舍和前期上涨问题的报告。

先列出实际读取的历史报告文件。历史报告只用于识别已暴露案例和形成诊断假设，不自动拥有当前方法解释权。

市场、板块、公司和价格是互补视角，不是投票或四道 Gate。最终允许 0—5 只和空名单，不得使用固定总分、权重、类型配额、代码顺序、报告完整度或候选来源数量替代实际比较。

## 明确不做

本轮不创建实验平台、机器学习模型、CLI、数据库、数据平台、新 Agent、评分器、红绿灯 Gate、固定阈值体系、状态机、哈希封存体系、大量 JSON 审阅包、大规模测试框架、自动交易、持仓或风控功能，也不恢复旧 V3 的评分、关注池、Supabase、Cloudflare 或自动报告路径。

除仓库规则要求且已经完成的一次 Prompt 审查外，不再启动子智能体。

不得：

- 把程序确定性排行冒充完整五 Skill 研究；
- 把宽事件表面、全市场价量排行或来源交集直接当成候选池；
- 用未来价格补写形成日理由、类型、优先顺序或反证；
- 因未来结果重新定义原版候选池；
- 为取得更多样本复制日期、重复计算同一事件或把报告级案例冒充完整回放；
- 未经用户另行授权推送分支、创建 PR 或进行其他外部发布。

## 固定评价口径

每次正式评价必须冻结：

- `formation_date`：形成日；
- `action_date`：形成日后的第一个交易所开市日；
- `as_of`：形成日 `23:59:59+08:00`；
- `evaluation_cutoff`：本次评价允许使用未来行情的截止日期。

形成日研究只允许使用 `available_at <= as_of` 的事实。候选池、原版去向、原版理由、反证、未知、优先顺序和行动日参与条件全部冻结后，才能读取该日期的未来结果。

未来窗口按从 `action_date` 开始的连续 20 个交易所交易日计算，行动日计作第 1 日。只有完整覆盖 20 个交易日的日期才是成熟样本。

价格口径：

- 正常可执行时，以行动日开盘价为统一入口；
- 入口开盘价和未来收盘价必须使用同一复权基准，不能用未复权开盘价与复权收盘价直接比较；
- 第 1—20 日任一收盘价相对入口达到或超过 20%，记为收盘达标；
- 盘中最高价触及不算主目标；
- 第 20 日终点收益只作辅助观察；
- 20% 是候选冻结后的评价标签，不是形成日筛选阈值或收益承诺。

每只候选至少记录：

- `executable_on_action_date`：`true | false | unknown`；
- `hit_20pct_close_within_20d`；
- `first_hit_day`；
- `max_close_return_20d`；
- `terminal_return_20d`；
- `selection_success`。

其中：

- 有可靠事实证明行动日不可正常参与时，`executable_on_action_date=false`，主评价字段 `selection_success=false`；
- 因查询失败、数据缺失或报价可靠性不足而无法判断时，记为 `unknown`，不得当作失败或成功；该候选所在日期不得进入完整配对验证指标；
- 正常可执行且 20 日内收盘达标时，`selection_success=true`；
- 正常可执行但未达标时，`selection_success=false`。

必须区分真实无记录、数据不存在、覆盖不足、查询失败、当前快照不可回放和实际不可交易，不得合并成一个“无数据”状态。

## 样本真实性与暴露状态

先只按时间、成熟度、数据能力和已有候选链盘点全部可能日期，不读取尚未暴露日期的未来标签。样本分为：

1. **完整形成日答卷**：形成日前已经冻结或能够在盲态下实际完成专业 Skill 线索、去重候选、逐只去向、最终名单和理由，可作候选级比较；
2. **报告级历史旁证**：文档中存在案例和结果，但缺少完整候选链，只能支持对应案例；
3. **新回放日期**：当前原版五个 Skill 在不读取未来结果的情况下实际完成候选提交、共同验证和最终取舍后，才成为完整答卷。

每个日期还必须标为：

- `unexposed`：候选池和原版答卷冻结前，未来结果未在现有报告或本轮分析中出现；
- `exposed`：未来结果已经被报告、设计或人工分析使用；
- `exposure_unknown`：无法确认是否暴露。

只有 `unexposed` 日期可以承担验证结论。其他日期只能进入开发或旁证。

`security_master` 在 2026-07-13 以前没有严格形成日可用版本。此前日期若只能依靠代码、当日报价、涨跌停和交易事实构造保守范围，必须标为“历史身份能力部分支持”，不得称为严格正式形成日回放；名称只作展示，不能成为形成日证据。

新回放日期默认按真实交易日每隔 5 日预先选取，以减少任意挑选。日期不得根据未来涨跌增删。由于 20 日窗口仍可能重叠，必须额外标记窗口重叠、重复股票和同一催化或事件链；这些重复观察不得被表述为相互独立的多次改善。

若真实完整候选链、成熟日期或未暴露日期不足，降低结论强度，不得用邻近日期、报告级案例或身份能力不足的日期凑样本。

## 原版基线必须先冻结

在揭示任何未暴露日期的未来结果前：

1. 确定全部开发日期和验证日期；
2. 保存修改前五个 Skill 的原版文本或 Git 版本；
3. 对所有新回放日期用原版 Skill 完成候选发现、共同验证和最终取舍；
4. 冻结每个日期的原版候选池、逐只去向、理由、未知和优先顺序；
5. 冻结后不得因开发结果或拟议修改改变原版答卷。

候选池只包含该日期原版专业 Skill 实际提交并进入总控候选链的具体股票，按代码去重。市场 Skill 只能改变搜索环境和问题，不能凭空增加股票。

候选链必须满足：

`去重候选数 = selected + rejected + unresolved`

`unresolved` 属于未入选，评价入选组与未入选组时不得把它排除以改善指标。

旧答卷若没有形成日前冻结的优先顺序，原版第一优先指标记为不可评价，不得事后补排。新回放必须在揭盲前明确排序。

修改版只能重新比较这个已经冻结的候选池，不得重新运行发现阶段来增删候选。若专业 Skill 被修改，也只能改变其对池内候选的验证或解释，不能改变本轮对照中的候选提交范围。

## 开发与验证切分

按时间顺序切分可用的完整日期：

- 约前 70% 为开发集；
- 约后 30% 为验证集；
- 已暴露日期只能放入开发集或旁证；
- 验证集必须由时间更靠后的未暴露日期组成。

切分和日期清单必须在读取未暴露未来结果前冻结。

若验证日期过少、20 日窗口高度重叠、主要由同一股票或同一事件驱动、身份能力不足，或第一优先指标无法评价，只能做探索性分析，不能宣称验证成功，也不能据此保留 Skill 修改。

## 开发阶段诊断

揭示开发集未来结果后，把同日候选分为：

- 入选且成功；
- 入选但失败；
- 未入选但成功；
- 未入选且失败。

优先配对同日“入选失败 A”和“未入选成功 B”。逐对回答：

1. A 当时为什么入选，B 为什么未入选；
2. 两者形成日可见的真实差异是什么；
3. 是否使用了不对称标准；
4. 即使标准对称，所用标准是否系统性偏向了失败特征；
5. B 是否仅因缺少公司催化或材料较少被淘汰；
6. A 是否因故事更完整、来源更多或报告更丰富被高估；
7. B 的后来成功是否只是高波动、不可参与或短暂冲高；
8. 是否存在与 B 形成日特征相似但后来失败的反例；
9. 哪项形成日事实既能解释成功者，又能排除相似失败反例；
10. 该差异是否会真实改变池内最终取舍，而不只是改善事后叙述。

后来成功只负责把 B 叫回来复查，不自动证明形成日应该选择 B。

`decision_miss` 只有在以下条件同时成立时记录：

- A、B 都属于同日原版候选池；
- A 入选但失败，B 未入选但成功；
- B 在形成日已经满足可参与性和关键证据要求；
- 形成日证据支持 B 应优于 A，或至少证明原决策使用了错误或不一致的比较标准。

不要求错误一定来自“不对称标准”；标准本身错误也可以构成决策遗漏。

重点检查但不预设结论：

- 隐性公司 Gate；
- 不同因果起点混用同一证据要求；
- 催化新鲜度与价格确认阶段错配；
- 板块扩散与少数龙头集中混淆；
- 价格异常因缺少公司故事被误杀；
- 故事完整度、来源数量或材料丰富度替代实际比较；
- 机械惩罚前期上涨；
- 把低位直接当作剩余空间；
- 非经常性利润、现金流和重大负面反证；
- 高成交低推进、冲高回落、流动性不足和价格透支。

## 机会类型只作诊断假设

可用以下三类帮助组织同类比较：

- `company_catalyst`：公司自身新变化及其业务、收入、利润、现金流或预期传导是命题起点；
- `sector_diffusion`：行业、主题或产业链多成员共同增强是命题起点；
- `independent_price_anomaly`：不能被市场或板块共同变化解释的持续、可交易个股价量增量是命题起点；
- `unresolved`：形成日证据不足以确定主要因果起点。

类型不是候选来源、评分、配额或 Gate。开发阶段可以使用类型分析比较标准是否错配，但不得预先假定“加入类型”就是答案。

类型无法确定不能自动导致淘汰。它只能作为关键未知参与取舍；只有开发证据证明类型识别本身跨日期、跨股票改善了比较，才允许把相关要求写入 Skill。

类型内可检查：

- 公司催化型：真实性、新鲜度、事件阶段、主营相关性、材料性、财务传导、非经常性影响、公开后交易天数、价格识别和公司反证；
- 板块扩散型：板块相对表现、上涨面、中位数、成交扩散、领导集中度、扩散阶段、个股相对同类增量、真实业务联系和价格透支；
- 独立价格异常型：相对市场、行业和同类表现，持续性、成交推进效率、冲高回落、长上影、流动性、价格位置、连续涨停、行动日参与性和重大公司负面事实。

不得因为板块型没有新公司公告，或价格型没有可解释的公司故事，就自动淘汰；也不得因为贴上某一类型就降低公司身份、重大反证、剩余路径或可参与性要求。

## 唯一允许的修改

完成全部开发日期比较后才能决定是否修改。

只有某一判断问题同时满足以下条件，才允许形成一版最小 Skill 修改：

- 出现在多个不同形成日；
- 涉及多只独立股票，而不是同一股票或同一事件的重复窗口；
- 存在形成日可见的区分事实；
- 能够解释成功候选并排除相似失败反例；
- 会直接改变候选池内的最终取舍或优先顺序；
- 不依赖未来标签、固定总分、权重、配额或硬阈值。

优先修改总控 Skill 的比较问题、证据对称性、同类替代比较或优先顺序表达。只有证据明确指向专业 Skill 的职责错误时，才修改对应专业 Skill。

不得新增总分、权重、类型配额、多层 Gate、固定阈值、状态机或新 Agent。不得为了让历史结果好看写入股票、日期、行业或事件专用规则。

若开发证据不满足门槛，五个 Skill 不修改，结论为“证据不足，未证明选股变准”。

## 验证阶段

开发阶段只能形成唯一一版修改。验证时：

1. 使用已经冻结的原版候选池和原版答卷；
2. 修改版只在同一候选池内重新作最终比较；
3. 在不读取验证未来结果的情况下，冻结修改版逐只去向、理由和优先顺序；
4. 两版全部冻结后，一次性读取验证未来标签；
5. 看过验证结果后不得追加第二版修改、改变类型或重写形成日理由。

至少比较并报告分子、分母和比率：

- 原版与修改版入选数量；
- `selection_success` 达标率；
- 两版均有第一优先股票日期上的配对第一优先达标率；
- 各版本空名单日期和仅一方有第一优先的日期；
- 入选组与全部未入选组的达标率；
- 修改版新增入选、删除入选和优先顺序变化；
- 每日选择数和总选择数；
- 三类机会类型及 `unresolved` 的候选、入选和结果；
- 改善涉及的独立日期、股票和事件簇；
- 重叠窗口或重复事件是否造成伪重复。

只有同时满足以下条件，才能表述为“本样本内选股变准”并保留修改：

- 修改版入选 `selection_success` 达标率严格高于原版；
- 在两版都产生第一优先股票的可比日期中，修改版第一优先达标率不低于原版；
- 修改版入选组达标率高于其全部未入选组；
- 修改版总入选数量不高于原版，改善不是靠多选股票获得；
- 改善至少出现在两个不由同一股票、同一事件或高度重叠窗口解释的验证单元；
- 验证日期未暴露且数据能力足以支持正式评价。

仅仅指标持平不构成变准。

若任一条件不满足，或验证样本过少、暴露、不可配对、身份能力不足，精确回退 Skill 修改，只保留诊断报告和结果数据；结论必须是“未证明选股变准”或“仅有探索性证据”。不得进行第二轮补丁。

## 最少必要程序工作

优先使用现有查询能力和临时 Python/SQL。只有候选级标签无法可靠复算时，才允许增加一个小脚本：

`scripts/analyze_stock_selection_accuracy.py`

该脚本只能：

- 读取已冻结的候选结果；
- 读取未来 20 日行情；
- 按固定口径计算标签；
- 汇总原版与修改版结果。

不得生成候选、替代 Skill 判断、接入 CLI、新增数据库或演变为长期实验框架。

验证仅包括：

- 形成日研究没有读取未来；
- 行动日、复权入口和 20 日标签计算正确；
- 数据缺失与真实不可执行状态没有混淆；
- Skill 格式有效；
- 现有相关测试未被破坏。

## 最终汇报

最终必须明确回答“选股是否变得更准”，并同时报告：

- 历史数据范围和 `evaluation_cutoff`；
- 完整形成日答卷、报告级旁证和新回放数量；
- 开发与验证日期、暴露状态和独立性限制；
- 原版入选达标率及分子、分母；
- 原版第一优先达标率及可评价日期数；
