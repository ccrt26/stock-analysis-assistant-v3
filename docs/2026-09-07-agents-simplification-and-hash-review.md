# AGENTS 精简与哈希边界优化方案

日期：2026-09-07。本文是本次维护方案与结果记录，不是日常研究入口。

## 执行 Prompt

目标：减少根 AGENTS 的重复指令和无关上下文，纠正哈希使用边界中的歧义，使 AI 在已授权范围内直接完成工作，同时完整保留已批准的研究、复盘和数据边界。

范围：精简 `AGENTS.md`；本文件记录哈希依据、规则去向及验证结果。现有 Skill、运行 Prompt 和架构文档已经维护详细研究合同，本轮不重新复制或改写。GitHub 提交同时包含上一轮已实施且仍未提交的 Astra 约束、复盘文案和插件边界优化，详见 `docs/superpowers/plans/2026-09-07-astra-agent-constraints-optimization.md`。

执行：
1. 从程序的实际生成与消费位置判断哈希用途，核对现有测试；不按字段名认定必要或冗余。
2. 根 AGENTS 保留职责、不可违反的研究边界、任务必读入口、授权和验证纪律及易误触发插件限制。合并执行与哈希重复表述，架构文档已读且未变时不重复通读。
3. 时间安排、节点与普通详评内容、分流和存储细节沿用原 Prompt／Skill，根文件明确相关任务开始前必须读取。压缩以不丢失约束为准，约 1800—2200 字符仅作参考。
4. 澄清数据层哈希、修复备份、独立多文件交付与普通任务的边界；不把哈希当真实性、时点安全或研究正确性的证明，不新增红绿灯或审批系统。
5. 实施后逐条核对规则去向，运行既有研究哈希、修复备份和本次待提交复盘／展示相关测试，检查 Skill 元数据、文档引用和 Git 差异。
6. 明确暂存相关文件后提交并正常推送 GitHub；读取远端确认提交一致。排除原有 `tmp/`、本地事实仓、归档、凭据与含本机路径的项目配置，不做强制推送。

不做：不修改生产代码、数据 schema、存储实现、时点逻辑、正式选股／复盘合同、历史记录或自动任务，不运行正式选股、复盘保存或真实数据修复，不修改全局插件或托管缓存。不为字数目标删除有效约束。

审查边界：上一轮独立方案审查已完成。本轮是等义压缩与哈希说明纠偏，不改变数据或研究合同，由主智能体实施后复查；若发现必须修改上述高风险实现，停止该部分并按项目规则处理，不扩大本次范围。

验收：根文件明显缩短，移出的有效条款在必读入口仍可找到；必要哈希仍有实际程序用途，普通任务无额外哈希负担；相关验证通过；GitHub 收到且仅收到本次及上轮相关维护内容。验证失败须先查明原因，不能只删测试断言求通过。

## 哈希评估及理由

现行 AGENTS 的总体方向正确：保留数据层能力，限制普通任务重复制造校验文件。需要优化的是适用边界与措辞，当前证据不支持删除生产哈希实现。

| 用途 | 实际代码依据 | 判断 |
| --- | --- | --- |
| `business_key_hash`、`payload_hash` | `storage/research_warehouse.py::_merge` 用业务键找同一记录，用内容判断是否有修订；相同内容重试保留原事实，有变化保存旧版本与可用时间 | 保留；支撑去重、修订与历史查询，不能直接移除 |
| `content_hash` | `ResearchWarehouse._commit_batch_locked` 比较分区内容，无增改则跳过重写 | 保留；用于识别逻辑内容，而非单纯重复文件字节校验 |
| `file_sha256` | `validated_partition_manifest` 核对文件与元数据，写入恢复按旧／新文件哈希判断当前状态 | 保留；本地事实仓未纳入 Git，Git 提交无法代替这项核对 |
| `input_manifest_hash` | `ResearchQuery.materialize_snapshot` 绑定截止时点和实际返回的事实，`research_features._unchanged_partition` 与派生存储据此避免无效重算 | 保留；已有实际消费者，不是要求 AI 为每篇报告再计算一次 |
| 修复备份的 `manifest.json` 与 `checksums.sha256` | `ops/research_data_repair.py::create_repair_backup` 保存修复前数据库、目标文件及基线，并记录备份文件摘要 | 合理；旧规则只允许“研究样本交付”，漏掉了修复备份；摘要可供后续核验，不等于已完成恢复演练 |
| 普通 Prompt／Skill／说明、日常报告和分支合并 | Git 管版本，现行日常流程不需要 AI 新增独立校验包 | 不额外增加；读取版本按需进行，不把抄写 SHA 变成必经仪式 |

上述代码路径均相对于 `src/stock_analyzer/`。内容哈希与文件哈希对象不同，存在两种名称不等于重复计算同一用途。输入清单绑定的是实际读取的快照；其中底层分区修订可能使缓存保守失效，本轮不声称它达到最佳缓存效率，也不借精简规则改变算法。

两处旧措辞需要纠正：

- “manifest 和 checksums 只用于多文件研究交付”过窄：允许实际数据修复备份，也无需让每个清单都配一个校验文件。
- “每日荐股和日常复盘不新增输入哈希”易误读为禁止程序按合同生成：明确限制的是 AI 额外制造流程，既有程序自动记录仍保留。

哈希只能帮助核对内容及版本是否对应。错误数据也能有稳定哈希，来源、时间与研究推理仍须分别验证。

| 本次评估的代码证据、条款映射与验证记录 | 本文；不加入日常必读链 |
