# A股五 Skill 历史时点选股诊断与最小调优 Prompt

## 一、目标

在不使用形成日决策截止时点之后信息的前提下，诊断并最小化修复现有五个 Skill 对“未来20个交易日形成可操作显著上涨路径、重点观察约20%涨幅”的漏选问题，提高最终0—5只股票的选择准确性和相对区分度。

保持以下定义不变：

1. 主目标仍为未来20个交易日约20%，不改成10日目标。
2. 增加“前10日达到”和“第11—20日达到”两个启动速度子标签，仅用于识别系统是否排斥准备阶段股票。
3. 最终允许0只，不凑数，不承诺收益。
4. 严格沿用项目既有合格股票范围、排除条件、形成日截止时点、行动日、起算价、复权、停复牌、涨跌停、达标、收益与相对收益口径。除非发现明确实现错误，否则不另造或悄悄改变口径。
5. 事实对应时点与系统可获得时点必须分开。历史判断只准使用 `available_at <= formation_cutoff_at` 的事实。

## 二、成功标准

只有同时满足以下原则，选股逻辑改动才可保留：

1. 合格范围、候选、理由、反证、未知和最终名单冻结后，才能读取未来行情。
2. 最终入选组相对淘汰组、未发现组或原基线表现出更好的目标区分度；不能只用漏选赢家绝对数量证明改善。
3. 最终仍为0—5只，候选池不能在最终选择或留出结果没有改善时明显膨胀。
4. 改善必须在冻结的留出日期上存在，且不是不可成交、未来催化、当前快照混入或评价口径变化造成。
5. `decision_miss` 必须同时证明漏选股在形成日达到绝对入选标准，并且相对当时实际入选股存在不对称取舍；不能因为当时不足5只就降低标准。
6. 没有改动满足条件时，保留当前选股逻辑并报告诊断结论，不为交付强行修改。

## 三、范围

使用并遵守：

- `orchestrating-stock-research`
- `interpreting-market-macro`
- `researching-sectors-industries`
- `researching-company-events`
- `analyzing-price-trading`

允许：

- 读取和复用现有历史模拟、审计、成熟日期、开发/留出划分、评价脚本和报告；
- 为三个诊断模块做最小必要的代码、测试、Prompt 或 Skill 修改；
- 运行必要的本地验证和历史评价。

不做：

- 不引入完整外部项目、额外研究 Agent、评分器、固定权重、固定 Gate、第六个 Skill、自动交易、仓位模型、关注池、扫描平台或新报告系统；
- 不堆叠技术指标、K线形态、人物投票或“主力/游资意图”推断；
- 不建设抽象层、迁移系统或大规模重构；
- 不把当前快照带入历史分析；
- 不把后续上涨写回形成日理由，不依据留出样本再尝试第二套逻辑；
- 不覆盖用户已有改动，不修改无关文件，不用 `git reset` 或 `git checkout` 恢复工作区。

## 四、执行顺序

### 步骤1：盘点并冻结基线

1. 检查工作区、现有实现、历史报告、成熟形成日、开发/留出划分和可复用结果。
2. 只使用未来20个交易日评价窗口已经完整成熟的形成日。
3. 复用口径一致且时间边界可验证的既有结果；无法验证 point-in-time 或不符合五 Skill 决策合同的结果不能证明最终选择有效性。
4. 已有固定开发/留出日期时沿用；没有时按成熟度、数据覆盖和时间先后冻结一次，不按未来收益选日期。
5. 冻结合格股票全集、五个 Skill/Prompt 版本、候选链、最终名单、理由、反证、未知和评价口径。
6. 任何选股逻辑修改前完成基线冻结。

### 步骤2：实现最小历史数据质量标记

只对影响入选、淘汰或漏选归因的关键事实统一记录：

- `provider`
- `dataset`
- `fact_as_of`
- `available_at`
- `quality: complete | partial | unreliable`
- `missing_fields`
- `capability_status: supported | partial | unsupported`

必须区分：真实无记录、数据缺失、历史覆盖不足、查询失败、只有当前快照、当时外部已有但系统未取得、发布时间无法确认。

复用已有时间合同和仓库结构，不建设数据平台，不给所有原始字段机械加标签。无法确认截止时点前可得的事实不能支持形成日命题，但要保留为数据质量问题，不能误写成“当时不存在”。

### 步骤3：生成三组结果对照

对每个成熟形成日，使用冻结的合格范围和候选链，把股票划为三个互斥组：

- `selected`：最终入选；
- `rejected`：进入候选池但未入选，`unresolved` 保留原状态后归入本组；
- `undiscovered`：属于当时合格范围但没有进入候选池。

候选链断裂、代码映射失败或处理错误单独报告，不能静默算作 `undiscovered`。三组必须覆盖完整合格范围。

三组统一报告：数量、可执行数、20日目标数量和比例、前10日达到、第11—20日才达到、最大收盘路径、20日终点、相对市场收益、可靠时才报告相对行业收益、达标前最大不利变化和逐形成日结果。

分别判断：

1. `selected` 相对 `rejected`：最终取舍是否有效；
2. `selected + rejected` 相对 `undiscovered`：候选发现是否有效。

未发现组远大于候选组时，同时比较比例、逐日表现和市场基准率，不用赢家绝对数量判定失败，不建立综合评分。

### 步骤4：对漏选赢家作时点化原因分类

只在开发样本中倒查 `rejected` 和 `undiscovered` 的后来达标股票。未来结果只确定审计对象和评价结果，不能成为形成日证据。

按以下顺序给每只股票一个主要归因：

1. `non_executable`：行动日按既有规则不能正常参与；
2. `future_catalyst`：决定性事实在形成日截止后才可获得；
3. `data_capability_miss`：关键事实当时外部已存在，但系统历史能力没有取得；
4. `discovery_miss`：系统已有形成日证据，但股票没有进入候选池；
5. `decision_miss`：已经进入候选，达到绝对入选标准，且相对实际入选股存在不对称取舍；
6. `no_point_in_time_case`：形成日前证据不足，只能靠事后价格或未来叙事解释。

可加不超过一个次要标签：`fast_activation`、`late_activation`、`broad_market_or_sector_co_move`、`high_adverse_path`。次要标签不改变主要归因。

`decision_miss` 必须引用冻结的形成日证据，并指出应与哪类实际入选股重新比较。后续收益只能验证取舍结果，不能制造替代理由。

### 步骤5：定位重复问题并作最小修改

- `discovery_miss` 集中：定位市场方向、行业到成员、公司变化或价格准备阶段的具体缺口；
- `decision_miss` 集中：检查已启动偏好、准备阶段惩罚、同类比较不对称、未知分类或透支判断；
- `data_capability_miss` 集中：先修关键历史数据能力或状态表达，不放宽选股逻辑；
- 有效漏选集中为 `late_activation`：改善“未识别、合理准备、初步确认、已经透支”的证据化区分，但不把低位或没涨自动解释为空间；
- `future_catalyst`、`non_executable` 或 `no_point_in_time_case` 为主：不修改选股逻辑。

一次只实施一个窄改动。先做最小失败检查，再修改。开发样本不改善、候选明显膨胀、最终选择不改善或引入时间泄漏时，只撤销本任务的对应改动并记录失败原因。允许零选股逻辑改动。

### 步骤6：冻结修改并运行一次留出验证

1. 开发样本修改后冻结逻辑。
2. 留出样本只运行一次正式比较。
3. 不能依据留出个股结果修改规则、换逻辑或重划日期。留出失败后撤销本任务的选股逻辑改动并结束本轮。
4. 比较最终0—5只、三组区分度、候选池规模、可执行目标达成、启动速度、最大不利变化、终点及相对收益和数据质量问题。
5. 只有符合成功标准的改动才保留；否则只保留诊断合同和无效实验记录。

### 步骤7：验证与汇报

检查：合格全集与三组守恒、三组无重叠、`unresolved` 和完整性异常未隐藏、形成日与未来隔离、截止时点、行动日可执行性、开发/留出隔离和相关测试。

最终报告包含：目标与口径、日期划分、基线、三组结果、漏选归因、入选失败与有效 `decision_miss` 对照、数据质量缺口、最小修改、开发与留出验证、保留或不修改结论、剩余风险和下一步。

## 五、执行纪律

1. 先证据、后修改；先开发、后冻结、再留出。
2. 结果评价不能回写形成日理由。
3. 未来20日结果只负责评价和确定开发集审计对象，不拥有候选发现或最终选股权。
4. 不按证据数量、Skill赞成票、总分或报告长度排序。
5. 市场和板块不是硬 Gate；公司真实传导、价格剩余路径和最强反证必须实际比较。
6. 缺失、失败、不支持、不可知和真实不存在必须分开。
7. 只补能改变取舍的证据，只允许现有流程的一轮定向补证。
8. 保护工作区已有改动；所有修改使用小范围补丁，只撤销本任务自己的改动。
9. 不在没有证据时扩大任务；只有权限、凭据、用户选择或无法自行消除的真实阻碍才暂停。
10. 自动执行到验证和报告结束；除 Skill 编辑的必要独立行为验证外，不再启动子智能体。
