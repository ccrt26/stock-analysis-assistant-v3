# 股票分析助手 V3 统一研究数据底座设计

**日期：** 2026-07-13  
**状态：** 已获用户方向认可，作为本轮实现依据  
**范围：** 数据获取、统一落地、历史迁移、质量校验、研究查询与每日自动补齐  
**不在本轮范围：** 重新制定选股评分、生成正式报告、激活报告、部署报告服务

本文规定设计与实现边界，不单独宣称本机运行状态；实际能力、真实回填和调度激活状态以 `docs/operations/production-capability-matrix.md` 的最新核验记录为准。

## 1. 为什么现在重构数据底座

此前 V3 已经完成了若干数据与报告能力，但 Phase 3 的实战分析暴露出两个根本问题：

1. 报告把“系统有数据、数据通过校验”当成分析内容，却没有讲清楚为什么选择一只股票。
2. 研究脚本若直接扫描旧 Parquet 目录，会把同一业务事实的多个保存版本重复计算。

与此同时，两轮 7 月 10 日选股与 7 月 13 日复盘说明，后续分析不能只依靠 80 日日线。市场状态、行业与主题热度、公司业务、估值、财务、公告风险、交易结构和日内走势，都需要进入同一套可追溯数据基础。

因此本轮不继续完整执行旧 Phase 3，而是先把数据基础重构正确。待数据补齐并经过实战复盘后，再单独重建分析框架。

## 2. 对旧设计的取舍

### 2.1 继续保留的原则

- 系统用于决策支持，不替用户自动交易。
- 先分析全市场和热点，再缩小候选，最后逐只解释。
- 所有结论必须能追溯到当时可获得的数据，禁止使用未来信息。
- 规则与知识库用于约束和解释，不机械遍历 74 项知识。
- 大模型只能在已核验事实边界内推理，不得虚构资金身份、事件或公司事实。
- 复盘同时评价结果、分析方法和知识使用是否正确。

### 2.2 暂停并等待后续重建的部分

旧 Phase 3 中以下能力不再作为当前正式分析依据：

- 旧的综合评分和固定权重。
- 根据少量趋势指标推导的“预期上涨空间”。
- 旧的行动建议、仓位和关注度生成逻辑。
- 以少量候选股票数据替代全市场行业、主题和基本面数据的做法。

旧代码在本轮迁移完成前可以暂时存在以便核对，但新的研究入口不得再依赖这些结论。后续重建分析框架时再决定删除或重写。

### 2.3 被本设计取代的存储做法

本设计取代“每次运行把完整历史快照写入新的 `version_id` 目录，并允许研究者直接扫描所有版本”的做法。旧版本树只作为迁移输入，不再作为新分析入口。

## 3. 业务目标

本轮完成后，普通研究流程只需要面对一个数据入口，并能可靠回答：

- 截至某一天，当时全市场有哪些股票和指数行情？
- 哪些行业或可追溯主题正在相对走强，强度是否有广度和成交支持？
- 某家公司做什么业务，盈利质量、估值和财务变化怎样？
- 当时已公开的公告、减持、解禁、质押、处罚、问询、停牌和退市风险有哪些？
- 日线信号在分钟走势中是持续推动、开盘冲高、尾盘拉升，还是高成交低效率？
- 一项事实来自哪里、何时首次可用、是否后来被修订、通过了哪些校验？
- 每天自动任务是否把应该到达的数据全部补齐，哪些数据因上游滞后仍在等待？

## 4. 明确不做的事情

- 不购买或伪造 Level 2、逐笔委托、账户身份数据。
- 不把第三方“主力净流入”当作机构真实买卖。
- 不使用 AKShare 或 BaoStock 作为正式生产数据源或交叉验证依赖。
- 不声称拥有覆盖所有市场叙事的“官方概念板块”。
- 不每天重复下载五年全量历史；日常只增量获取并自动修补缺口。
- 不在本轮生成、激活或发布股票推荐报告。

## 5. 总体结构：一套事实，三个层次

系统只保留一个正式研究仓库，分为三个逻辑层次，而不是三套互相复制的数据。

### 5.1 事实层

保存外部来源提供或由确定性规则标准化的业务事实，例如：

- 股票 2026-07-10 的开高低收、成交量和成交额。
- 某股票在一段有效期内属于申万二级行业。
- 某公告在 2026-07-10 18:42 首次公开。
- 某公司 2026 年一季报的营业收入，以及该报表的公告时间。

同一业务键在当前事实区只有一份当前有效值。若来源后来修订，当前值更新，同时把变更前后值写入修订记录。

行业与主题按实际可获得性分层处理：申万 L1 指数行情用于一级行业基准，L2/L3 保留完整历史成分并由成分股日线确定性复算；官方主题指数目录作为候选事实保留，分析入口只返回截至当时同时具备有效成分和已到达行情的主题交集。板块日线只纳入 A 股交易日历中的开市日，避免境外成分指数的非 A 股交易日混入选股窗口。

### 5.2 派生层

保存可以从事实复算的研究特征，例如相对收益、行业上涨比例、成交占比、历史分位、日内效率和波动率。派生值必须记录：

- 公式版本；
- 输入数据截至时间；
- 计算时间；
- 输入事实覆盖与质量状态。

修改公式只产生新的派生版本，不复制原始事实。

### 5.3 分析快照层

一次选股或复盘只保存一个轻量清单：分析日期、使用的事实截止时间、公式版本、候选范围和事实键。需要复现时按清单读取事实和派生结果，不再复制五千多只股票的整套历史文件。

## 6. 统一仓库与目录

统一仓库继续使用本地 DuckDB + Parquet，但只有仓库服务可以决定文件位置和读取范围。

建议目录：

```text
local_warehouse/
  research.duckdb
  facts/
    equity_daily/trade_date=YYYY-MM-DD/part-*.parquet
    daily_basic/trade_date=YYYY-MM-DD/part-*.parquet
    index_daily/trade_date=YYYY-MM-DD/part-*.parquet
    minute_bar/trade_date=YYYY-MM-DD/scope=.../part-*.parquet
    ...
  manifests/
    ingestion_run/*.json
    analysis_snapshot/*.json
  quarantine/
```

DuckDB 保存事实目录、运行清单、质量结果、数据可用时间和修订索引；宽表事实保存为按业务日期分区的 Parquet。应用代码只能通过统一仓库类查询，不允许直接对 `version_id=*` 或 `facts/**` 做无约束 glob。

## 7. 业务唯一键

每类事实必须在写入前声明业务唯一键。首批关键定义如下：

| 数据集 | 业务唯一键 |
| --- | --- |
| 股票日线 | `trade_date + ts_code` |
| 复权因子 | `trade_date + ts_code` |
| 每日估值 | `trade_date + ts_code` |
| 涨跌停价格 | `trade_date + ts_code` |
| 指数日线 | `trade_date + index_code` |
| 股票分钟线 | `trade_date + ts_code + minute + frequency` |
| 指数分钟线 | `trade_date + index_code + minute + frequency` |
| 证券主数据 | `ts_code + valid_from` |
| 行业归属 | `ts_code + industry_system + level + valid_from` |
| 主题指数成分 | `theme_code + ts_code + valid_from` |
| 财务报表 | `ts_code + report_period + report_type + statement_type` |
| 业绩预告/快报 | `ts_code + report_period + announcement_type` |
| 主营构成 | `ts_code + report_period + classification + item_name` |
| 公告元数据 | `source + announcement_id` |
| 股东增减持 | `ts_code + holder_name + announcement_date + change_begin + change_end` |
| 限售解禁 | `ts_code + float_date + holder_name + share_type` |
| 回购 | `ts_code + announcement_date + process + expected_end_date` |
| 融资融券 | `trade_date + ts_code + exchange` |
| 停复牌 | `ts_code + suspend_date + resume_date + reason` |

如果上游没有稳定编号，适配器使用经过标准化的字段生成确定性哈希，但必须保留原始字段与来源。

## 8. 来源、时间与修订语义

每条事实至少携带以下治理信息：

- `source_name`：来源名称；
- `source_endpoint`：来源接口或栏目；
- `source_record_id`：来源记录编号或确定性哈希；
- `source_updated_at`：来源声称的更新时间，如有；
- `available_at`：研究者最早可以合理获得该事实的时间；
- `ingested_at`：本地实际获取时间；
- `ingestion_run_id`：本次获取任务；
- `payload_hash`：标准化业务内容哈希；
- `quality_status`：通过、待复核或隔离；
- `revision_no`：同一业务事实的修订序号。

### 8.1 关键时间原则

- 行情的 `available_at` 不早于对应交易时点结束。
- 财报和公告按公开时间进入分析，不能按报告期末提前使用。
- 融资融券等滞后数据按真实发布日期进入，不能把 T+1 发布的数据标作 T 日盘后已知。
- 行业或指数成分按有效期查询，不能用今天的成分倒填历史。
- 来源只给日期不给时刻时，采用保守可用时间并记录时间精度。

### 8.2 修订原则

若业务键相同且 `payload_hash` 相同，重复获取是幂等操作，不产生新事实或修订。若内容变化：

1. 新值经过完整校验；
2. 旧值写入 `fact_revisions`；
3. 当前事实原子替换为新值；
4. 记录发生变化的字段、来源更新时间和运行编号。

历史证据因此以小型变更记录存在，而不是每次保存完整市场副本。

## 9. 原子、幂等的落地流程

一次数据获取只能经历以下状态：

```text
planned -> fetching -> staged -> validated -> committed
                         |            |
                         v            v
                    quarantined     failed
```

具体规则：

1. 先登记任务范围和预期数据集。
2. 数据写入临时 staging，不可被研究查询读取。
3. 对业务键、重复、行数、覆盖率、数值范围、交易日和跨表关系做校验。
4. 同一数据集和业务日期在一个事务中替换或合并。
5. Parquet 先写临时文件，校验后原子改名；DuckDB 元数据与清单一并提交。
6. 任一必需数据集失败，该业务日期不得标记“完整”。已完成的数据可以保留为已提交事实，但任务保持待追补。
7. 重跑只补缺口或修订，不产生重复记录。

## 10. 正式数据源政策

### 10.1 结构化市场与公司数据

Tushare Pro 作为首要结构化来源，用于其账户权限覆盖的：

- 股票、指数和交易日历；
- 日线、复权因子、涨跌停、每日估值；
- 申万行业分类和成分；
- 中证、上交所、深交所可追溯主题指数及成分；
- 财务报表、财务指标、主营构成、业绩预告和快报；
- 股东增减持、解禁、回购、融资融券等。

接口无权限、返回不完整或尚未发布时必须明确失败或等待，不得悄悄换成口径不同的网页数据。

### 10.2 官方事件和风险来源

公告与风险事实优先取自：

- 巨潮资讯；
- 上交所、深交所、北交所；
- 中国证监会及其派出机构；
- 公司正式公告链接。

首批实现以巨潮公告元数据和可追溯原文链接为核心；交易所或监管风险栏目作为后续同一事实模型的来源扩展，不另建旁路。

### 10.3 不进入正式链路的来源

AKShare 和 BaoStock 不作为正式源，也不作为每日交叉验证依赖。原因不是它们完全无用，而是其网页封装、口径变化与服务可用性会增加生产链路不确定性。研究者临时浏览互联网信息时可以使用公开网页，但必须作为带日期和来源的研究证据保存，不能覆盖正式事实。

## 11. 首次历史补齐范围

首次迁移以 **2026-07-13** 为截至日，按数据性质采用不同窗口。

> **2026-07-14 范围修订：** 历史窗口不再统一设为五年。已经接近完成的五年全市场紧凑日线底库保留，避免制造半成品，也为估值分位和历史验证提供可选底座；日常选股默认只读取最近 82 个交易日，市场状态最多读取最近 250 个交易日。其他数据按业务价值分别采用 250 个交易日、1 年、20 个交易日或“12 季/5 年度”窗口。今后每日任务只增加当天事实和追补已登记缺口。

### 11.1 全市场价格、交易与估值：五年

覆盖全部当时上市、退市和暂停上市证券，补齐约五年交易历史：

- 股票日线；
- 复权因子；
- 每日估值与流通市值；
- 涨跌停价格和交易状态；
- 上证、深证、创业板、科创及主要宽基/风格指数日线；
- 交易日历和证券有效期。

五年日线是一次性历史底库，不是每日分析窗口。正式分析必须显式选择窗口：短期选股默认 82 个交易日；市场状态、年度位置和稳健性比较最多使用最近 250 个交易日；五年数据只供长期估值分位、规则复盘和另行批准的历史验证使用，不能机械地全部输入每日报告。

### 11.2 行业：完整申万 2021 体系

- 申万一级、二级、三级行业目录；
- 全市场股票归属；
- 成分生效和失效日期；
- 行业指数最近 250 个交易日行情。

若上游历史成分不能完整提供，必须把缺失期标记为未知，不得用当前成分回填。

### 11.3 主题：受控、可追溯集合

主题只纳入中证、上交所、深交所等有稳定代码、成分和历史行情的主题指数。保存主题目录、定义、成分有效期和最近 250 个交易日指数行情。

新闻中出现但没有稳定成分口径的“新概念”，只能进入研究证据区，不能冒充完整概念分类。最终分析必须区分“可复算主题指数”与“市场叙事”。

### 11.4 公司、财务和估值

- 公司基本资料、上市状态、主要业务说明；
- 最近 12 个季度以及最近 5 个完整年度的利润表、资产负债表、现金流量表和财务指标；
- 同期主营构成；
- 与上述报告窗口相关的业绩预告和业绩快报；
- 五年每日估值，用于历史分位和同行比较。

同一报告期的初始披露和修订按公告可用时间保留修订关系，避免未来数据穿越。

### 11.5 公告、公司行动与风险

全市场补齐可稳定获取的公告元数据和原文链接，并结构化补齐：

- 股东及高管增减持；
- 限售股解禁；
- 回购；
- 股权质押；
- 停复牌；
- 立案、处罚、监管措施、问询、风险警示和退市相关事件；
- 重大资产重组或重要合同等可追溯事件类别。

首次补齐优先覆盖五年稀疏结构化公司行动和近一年公告元数据；停复牌这种按交易日展开的数据只保留近一年。历史公告全文按候选需要获取，不盲目下载全市场全部 PDF。

### 11.6 融资融券与交易结构

补齐最近 250 个交易日内交易所/Tushare 可提供的融资融券明细，并记录真实可用日。缺少融券、北交所或历史口径时分项标记，不把部分市场合计解释为全市场资金方向。更早记录不作为当前五日选股的必需数据。

### 11.7 分钟线

分钟线成本较高，采用分层保存：

- 主要指数：补齐最近 20 个交易日；
- 每日冻结的宽候选池：补齐分析日前 20 个交易日；
- 最终进入逐股分析的候选：必须有完整的当日及所需比较窗口分钟线；
- 不长期保存全市场五年分钟线。

候选池在获取分钟线前冻结并记录，禁止根据未来表现事后改变样本。

### 11.8 明确无法免费补齐的数据

Level 2 逐笔成交、逐笔委托和账户身份不在本轮数据范围。系统必须把该缺口转化为表达约束，而不是忽略：

- 可以说“成交占比提升”“上涨时成交更活跃”；
- 不可以说“机构正在买入”“主力没有出货”；
- 日线和分钟线只能形成概率判断，不能证明交易主体。

## 12. 热点板块如何计算

正式热点判断不依赖第三方“主力资金流”。对每个行业或受控主题，在同一成分与时间口径下计算：

1. 相对主要宽基指数的 1、3、5、20 日收益；
2. 成分股上涨比例、中位数收益和等权收益；
3. 板块成交额占全市场成交额的比例及其连续变化；
4. 涨停、接近涨停、创 20/60 日新高股票的集中度；
5. 成分收益离散度和头部股票贡献度，判断是普涨还是少数龙头拉动；
6. 分钟线中的上涨持续性、开盘贡献、尾盘贡献、冲高回落；
7. 高成交低涨幅、放量滞涨和板块内部快速分化等拥挤/兑现迹象。

这些指标分别对应相对强弱/动量、市场广度、成交参与度、横截面集中度和日内价格路径等可复算研究思路。它们支持“板块更强、参与面扩大、成交关注持续提升”这样的结论，不支持识别机构身份。

热点只能作为候选优先级和市场背景，不是个股必涨证据。后续分析框架仍需结合公司业务相关性、基本面、估值、事件、交易结构和风险。

## 13. 知识库与数据可用性的连接

知识条目不再只记录“用/不用”，而是为每次分析保存以下状态之一：

- `applied`：数据充分，规则按原意正确使用；
- `limited`：方向适用但数据不足，只能弱化结论；
- `not_applicable`：该股票或情景不适用；
- `blocked_by_data`：缺少关键数据，禁止形成对应结论；
- `conflicted`：与另一条知识或事实冲突，需要说明取舍。

特别是 `src_cn_program_trading_rules_2025` 必须作为常驻约束：程序化交易会改变日线量价的解释，而本地没有微观委托和账户数据。因此，“上涨放量”“收在高位”“逆势上涨”只能描述现象，不可直接翻译成机构承接或没有出货。

每个数据集登记它能支持和不能支持的知识结论。数据补齐成功不代表规则自动成立；规则必须经过适用性和时间点检查。

## 14. 旧 Parquet 重复问题与迁移

### 14.1 已确认的事实

旧正式行情目录按运行版本保存完整 82 日快照。若无版本过滤直接扫描：

- 物理记录数：3,450,498；
- 唯一 `(trade_date, ts_code)`：436,580；
- 重复记录：3,013,918；
- 共 8 个版本；
- 大量日期被重复 7 或 8 次，2026-07-13 仅 1 次。

已抽查的 431,310 个重复键在收盘价、成交量和成交额上没有版本冲突，说明主要问题是完整快照重复保存，而非同一事实互相矛盾。

### 14.2 会造成的影响

若研究代码直接扫描旧目录：

- 成交额、上涨家数、样本数可能放大 7 至 8 倍；
- 不同日期因版本数不同被赋予不同权重；
- “最近 80 行”可能只覆盖约 10 个独立交易日；
- 板块热度、量比、波动、相关性和回测结果都会失真。

当前按精确版本读取的旧报告不一定受影响，但这不足以使旧目录成为安全的通用研究入口。

### 14.3 迁移方法

1. 冻结旧正式版本树为迁移输入，不再写入新版本。
2. 扫描全部版本的并集，按业务键和内容哈希去重，不能只取最后一个快照，以免丢失早期日期。
3. 若同一业务键存在内容冲突，按来源更新时间、获取时间和质量规则选择当前值，并写入修订或隔离记录。
4. 把去重结果写入统一事实区。
5. 逐日比对唯一股票数、开高低收、成交量、成交额和内容哈希。
6. 所有验证通过后，把旧目录列入清理清单；清理前保存迁移清单和审计摘要。
7. 删除旧版本树后，全仓库检查不得再存在生产代码对 `version_id=*` 的读取。

用户当前没有依赖旧目录运行的正式报告，因此不保留并行正式仓库。保留的是必要的修订审计和迁移清单，而不是多套可被误用的行情副本。

## 15. 每日自动任务

“每日全量获取”指当天应覆盖的数据范围完整，不是每天重抄五年历史。

每日任务不得因为历史底库存在五年数据，就重新扫描或重新下载全部五年。正常运行只处理当天、晚到修订、当前低频资料和明确登记的缺口。

### 15.1 分阶段时间安排

- **18:30 收盘核心批次：** 交易日历、证券状态、全市场日线、复权因子、涨跌停、每日估值、指数日线、行业/主题指数日线及当日应有成分变更。
- **21:30 晚间补充批次：** 财报、业绩预告/快报、公司行动、公告元数据和晚间发布的风险事件；冻结下一研究日需要的候选分钟线范围。
- **下一交易日 08:00 滞后核对批次：** 融资融券等 T+1 或晚到数据，重查前一交易日缺口与来源修订。

若来源在上述时点仍未发布，任务保存“等待上游”状态并在后续批次继续追补，不能伪造空数据为成功。

### 15.2 每次运行做什么

1. 根据交易日历和每个数据集的水位线生成应有分区。
2. 检查本地缺失、失败、隔离和来源更新的分区。
3. 只获取新增、缺失或需修订的范围。
4. 执行数据集级校验和跨数据集校验。
5. 原子提交通过校验的数据。
6. 生成一份人可读的日度数据健康摘要：已完成、等待上游、失败原因、下次重试。

### 15.3 完整性定义

每个交易日按数据集分别标记：

- `complete`：预期范围全部到达并通过校验；
- `complete_with_declared_gaps`：上游明确不覆盖的范围已登记；
- `waiting_upstream`：合理发布时间尚未到或来源暂未更新；
- `failed`：获取或校验失败；
- `quarantined`：存在冲突或异常，禁止研究使用。

只有收盘核心必需数据全部 `complete`，该交易日才可以用于完整市场筛选。滞后数据必须通过 `available_at` 控制其能参与的分析日期。

### 15.4 自动恢复

- 任务以业务日期和数据集为幂等键，可安全重跑。
- 网络失败按指数退避重试，不扩大到无关历史范围。
- 每天都会回看最近若干交易日和低频数据水位，自动发现晚到数据。
- 超过允许等待时间仍未完成时告警，并保留明确缺口；不会静默降级到非正式来源。

## 16. 查询和导出边界

统一仓库提供两类正式入口：

1. `as_of` 查询：给定分析时间，只返回当时已可用且质量通过的事实。
2. 冻结导出：为外部研究工具生成去重、带清单和校验摘要的临时数据包。

外部大模型或临时脚本不得直接扫描内部 Parquet。导出包必须说明：事实截止时间、包含的数据集、每表唯一键、行数、缺口和哈希。

## 17. 质量校验

### 17.1 单表校验

- 业务唯一键无重复；
- 主键和日期非空；
- OHLC 关系合理、成交量和金额非负；
- 股票代码、交易日和频率合法；
- 行数和覆盖率在基于交易状态计算的合理范围；
- 同一来源分页无丢页或重页。

### 17.2 跨表校验

- 日线股票应能在证券主数据的有效期内找到；
- 调整因子、估值和涨跌停与日线覆盖差异有解释；
- 行业成分有效期不重叠；
- 财务报告公告时间不早于合理披露时点；
- 分钟线聚合后的开高低收和成交量与日线在允许口径差异内一致；
- 公告结构化事件可以追溯到公告或来源记录。

### 17.3 迁移校验

- 旧版本并集的唯一业务键与新事实逐键核对；
- 已知重复问题必须由自动测试复现并证明修复；
- 新仓库对任意日期的求和和计数不因历史运行次数变化；
- 删除旧版本前后，新仓库查询结果完全相同。

## 18. 实现与验收边界

本轮实现完成必须同时满足：

1. 只有一个新的正式研究仓库和一个代码查询入口。
2. 旧 8 版本行情并集完成去重迁移，业务键唯一，逐日校验通过。
3. 首批范围内的缺失数据自动补齐到 2026-07-13，无法取得的项目有明确来源限制和缺口记录。
4. 行业、受控主题、估值财务、公告风险、公司行动、融资融券和分钟线进入统一事实模型。
5. AKShare、BaoStock 和旧版本快照写入不再属于生产依赖。
6. `as_of` 查询能阻止未来公告、财报或滞后数据穿越。
7. 每日三阶段任务可重复运行，能识别缺口、追补、校验和原子落地。
8. 自动化测试覆盖唯一性、幂等、修订、时间点读取、失败不半落地、迁移和日程编排。
9. 用真实 2026-07-13 数据完成一次端到端验收，并输出数据健康摘要。
10. 不生成、不激活、不部署股票分析报告。

## 19. 主要风险与控制

- **Tushare 权限或频率限制：** 预先探测接口，按数据集限速、分页、断点续传；无权限即登记缺口。
- **巨潮网页接口变化：** 适配器与事实模型解耦，保留原始标识、来源链接和响应哈希；失败不换黑箱源。
- **五年数据量与获取耗时：** 按月/季分块、保存水位、可恢复执行，避免单次事务过大。
- **历史行业成分不完整：** 不用当前成分倒推，缺失区间显式标记。
- **分钟线口径差异：** 与日线聚合核对并记录允许偏差，异常批次隔离。
- **误删旧证据：** 只有新仓库逐键验证、迁移清单保存且代码引用清除后才清理旧版本树。
- **把可计算信号写成资金身份：** 由知识约束和报告措辞检查共同阻止。

## 20. 后续分析框架如何接入

数据底座验收后，下一阶段才基于两轮实战与复盘重新制定分析框架。届时每只股票的结论应围绕“为什么选它”组织：市场环境、热点与业务相关性、公司基本面、估值、价格与交易结构、事件、风险、达到目标所需条件和失效条件。

本设计只保证这些分析拥有正确、完整、可追溯的事实，不提前固定评分权重或替大模型做结论。
