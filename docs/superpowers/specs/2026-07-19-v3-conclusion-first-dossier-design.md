# 股票分析助手 V3：结论先行研究档案 V03 设计

## 1. 问题定义

`v3-forward-research-dossier-02` 已经能够完整展示公司、行业、主题、多期财务、交易指标、估值和公告，但仍存在一个结构性问题：报告主要完成了“事实收集”，没有稳定完成“分析”。

普蕊斯档案中的典型问题包括：

- “价格位置和成交活跃度达到召回条件”是机器语言，没有解释成普通读者能理解的市场行为；
- “当前主要反对证据”只是多个客观事实的拼接，没有说明这些事实如何削弱当前判断；
- “当前最大缺口”混入数据缺失和未来尚未发生的验证，挤占了顶部最重要的分析位置；
- 第二至第六部分列出了事实，却没有固定回答“说明什么、为什么与本次入选有关、什么事实与它冲突”。

V03 的目标不是增加更多数据，而是建立一个可复核的“事实 → 有限分析 → 结论边界”转换层。

## 2. 已确认方案

采用方案 C：结构化结论引擎。

每个核心部分必须输出以下五类内容：

1. **本节结论**：先用一句普通中文说明判断；
2. **为什么这样判断**：引用形成日可见的具体数据；
3. **与本次入选的关系**：说明这些事实是入选原因、背景支持还是反对证据；
4. **主要矛盾**：指出哪些事实削弱或限制结论；
5. **不能推出什么**：防止把短期量价、公告标题或财务增长外推成收益承诺。

V02 保持不可变。V03 使用独立版本 `v3-forward-research-dossier-03` 和独立产物路径。

## 3. 目标与禁止边界

### 3.1 目标

- 顶部只展示已经分析过的结论，不展示原始机器条件或数据缺失清单；
- 所有选择条件翻译成带具体数字的普通中文；
- 将反对事实合成为“它实际削弱了什么判断”；
- 将数据缺失、尚未发生的未来验证和分析结论彻底分开；
- 第二至第六部分均在数据之前或之后提供结构化分析；
- 对每个结论保留证据字段和形成日截止；
- 在本地事实不足时，允许补充形成日截止前的官方互联网资料。

### 3.2 禁止边界

V03 仍不得产生：

- 买入、卖出、仓位、加减仓、止损、止盈或目标价；
- 收益预测、未经校准的概率或“必然上涨”等表达；
- 新选股分数、排名、行业配额或选股规则改变；
- 形成日之后的事实；
- 媒体、自媒体、论坛或无法确认发布时间的互联网材料；
- 对公告标题的收入、利润或订单影响扩写；
- Supabase、发布、调度、生产任务或自动交易能力。

## 4. 结论层与事实层

### 4.1 结论对象

每只股票生成以下结构化分析对象：

```text
top_conclusion
company_analysis
industry_theme_analysis
selection_analysis
financial_analysis
trading_valuation_analysis
announcement_analysis
data_gaps
```

除 `data_gaps` 外，每个对象统一包含：

```text
headline            一句话结论
meaning             对普通读者的解释
selection_link      与本次入选的关系
counterpoint        主要矛盾或削弱因素
boundary            不能推出什么
evidence            结构化证据字段和值
```

### 4.2 顶部固定结构

“30 秒读懂”改为：

1. **核心判断**；
2. **为什么现在值得看**；
3. **当前最大的矛盾**；
4. **接下来要验证什么**；
5. **结论边界**。

顶部不再展示“当前最大缺口”。数据缺失统一移至末尾的“数据可得性与缺口”。

## 5. 普蕊斯目标表达

V03 对普蕊斯的顶部目标表达应接近以下含义，但具体数值必须由代码从形成快照生成：

> 普蕊斯本次是量价驱动的短期强势观察对象，不是热点或新公司利好驱动。过去 20 个交易日明显跑赢市场，近 5 日保持上涨，形成日成交额约为近期平均的 1.82 倍，说明市场关注度突然提高；但形成日单日下跌约 10.74%，波动率和日常振幅也很高，说明资金分歧和兑现压力同时存在。三项确认足以让它进入持续观察，但确认质量受到形成日反向波动、经营现金流为负和缺少新公司催化的削弱。

这段话必须满足：

- 不出现“价格位置达到召回条件”等机器术语；
- 明确它为什么被系统捕捉；
- 明确它不是热点或公司公告驱动；
- 明确 5/20 日强势与形成日大跌之间的矛盾；
- 不转换为买卖指令。

## 6. 各部分分析规则

### 6.1 公司与业务

结论必须说明公司实际上如何提供产品或服务，避免仅复读公司全称。

普蕊斯必须明确：

- 它向药企、医疗器械企业等申办方提供临床试验现场管理服务；
- 它不是药品生产商；
- 其收入更依赖临床项目数量、执行进度和客户研发活动，而不是某一种药品销量；
- 若分业务收入和客户贡献无法从严格资料确认，放入数据缺口，不在顶部展示。

### 6.2 行业、板块与概念

结论必须区分：

- 一级行业标签；
- 本次实际发现热点；
- 同日热点背景；
- 普通指数成员；
- 主营业务事实。

对价格路线且没有热点支持的股票，必须直接说明：行业标签不能解释本次入选，当前异动主要来自个股量价。

### 6.3 为什么进入名单、为什么确认

选择分析必须将三个条件转换成普通中文：

- 近 5 日收益：近期方向；
- 20 日相对收益：是否明显跑赢市场；
- 成交比率：市场关注度是否高于近期常态。

同时检查内部冲突：

- 形成日单日收益为负且成交比率大于等于 1：标记“放量下跌，与中期强势冲突”；
- 形成日单日跌幅绝对值较大：说明确认并非连续平稳上涨；
- 高波动或高 ATR：说明路径不稳定，三项确认的可执行含义需要后续真实开盘验证。

### 6.4 财务分析

财务结论使用最近五期形成日可见指标，至少回答：

- 营收是增长、修复还是放缓；
- 利润改善是否快于收入；
- 扣非是否与净利润方向一致；
- 经营现金流是否支持利润改善；
- 毛利率、净利率和 ROE 的方向；
- 当前更接近“增长确认”“利润修复”“低基数反弹”还是“财务支持不足”。

不得把季度累计 ROE 年化，不得只因单期高同比称为高成长。

### 6.5 交易、风险与估值分析

结论必须同时覆盖：

- 1/5/20/60 日路径是否一致；
- 相对市场强弱；
- 成交放大是上涨确认还是与下跌同时发生；
- 波动率和 ATR 对路径稳定性的含义；
- PE/PB 相对自身历史分位是偏高、居中还是偏低；
- 历史样本不足时降低估值结论强度。

叙述阈值仅用于解释，不进入选股：

- 历史分位 `>= 70%`：相对自身历史偏高；
- 历史分位 `<= 30%`：相对自身历史偏低；
- 年化波动率 `>= 60%` 或 ATR 比率 `>= 6%`：路径波动较大；
- 形成日收益 `< 0` 且成交比率 `>= 1`：放量下跌冲突；
- 60 日价格位置 `>= 80%`：接近观察区间高位。

### 6.6 公告分析

公告结论分为：

- **支持当前公司逻辑**：存在形成日前公司产品、经营、业绩或合同类正式公告；
- **反对或供给压力**：减持、处罚、问询、终止等；
- **没有明显公司催化**：近期公告无法解释本次异动。

公告标题只用于确认事件存在。没有结构化金额或影响时，必须写“方向上相关，经济影响未知”。

## 7. 数据缺失与未来验证分离

### 7.1 数据缺失

数据缺失只放在“数据可得性与缺口”，分为：

- 本地事实缺失；
- 官方互联网资料补充成功；
- 本地和官方互联网均未找到；
- 找到资料但发布时间或证据口径不合格，拒绝使用。

### 7.2 未来验证

下一开盘、未来 5/10/20/30 日路径和尚未发生的新公告属于“待验证事项”，不是数据缺失。

## 8. 官方互联网补充层

### 8.1 来源边界

只接受：

1. 巨潮资讯正式公告和定期报告；
2. 交易所正式披露；
3. 公司官方网站的公告或公司介绍。

拒绝媒体转载、自媒体、论坛、行情门户二次整理和无法确认发布时间的页面。

### 8.2 时间边界

每条补充事实必须包含：

```text
ts_code
fact_category
fact_text
source_title
source_url
published_at
observed_at
```

`published_at` 必须不晚于形成日截止。`observed_at` 可以晚于形成日，但只能说明本次何时读取了早已公开的材料。

### 8.3 使用边界

互联网补充只允许完善：

- 公司如何赚钱；
- 主要产品或服务；
- 已公开的业务板块；
- 定期报告中的收入构成；
- 已公开且形成日前可见的正式公司事实。

它不得改变发现路线、动作确认、形成日行情、财务快照或原名单。

### 8.4 不可变补充包

补充事实使用独立版本：

```text
official-supplements/
  formation_date=YYYY-MM-DD/
    schema_version=v3-forward-official-supplement-01/
      supplements.json
      supplements.parquet
      manifest.json
```

相同身份相同内容幂等，不同内容冲突失败。V03 档案清单记录补充包哈希；没有补充包也能生成，但必须披露哪些字段仍缺失。

## 9. 模块边界

### 9.1 `dossier_analysis.py`

只负责将结构化事实转换为有限结论，不负责文件写入、网络请求或 Markdown 排版。

主要接口：

```python
analyze_dossier_facts(card, theme_info, history, metrics, announcements, supplements)
```

返回结构化分析字典。

### 9.2 `dossier_supplements.py`

负责补充事实校验、严格截止、官方域名白名单和补充包读取。

### 9.3 `dossiers.py`

继续负责事实组织和 Markdown 渲染，但 V03 渲染必须消费 `analysis_json`，不能在模板中临时拼结论。

### 9.4 `dossier_service.py`

继续负责形成包、决策卡、补充包和 V03 档案包身份校验及不可变写入。

## 10. V03 数据结构

在现有档案行上新增：

```text
analysis_json
supplement_facts_json
supplement_status
supplement_bundle_hash
```

`analysis_json` 包含顶部和第二至第六部分的结构化结论。V03 产物路径：

```text
research-dossiers/
  formation_date=2026-07-17/
    rule_version=v3-forward-baseline-01/
      schema_version=v3-forward-research-dossier-03/
```

## 11. 失败关闭

以下情况失败：

- 分析引用的证据字段不存在；
- 结论中的数字与原始字段不一致；
- 补充资料来源不在官方白名单；
- 补充资料发布时间晚于形成截止或没有可判断的发布时间；
- 补充事实试图改变路线、确认结果或行情字段；
- V03 顶部出现“数据缺失”“本地没有”等缺口文字；
- 第二至第六部分缺少本节结论或与入选关系；
- 相同 V03 身份内容冲突；
- 输出不在冻结 U 盘根目录。

## 12. 测试与真实验收

### 12.1 单元测试

- 价格路线翻译为具体数字和普通中文；
- 普蕊斯顶部不出现机器条件或缺失清单；
- 放量下跌被合成为明确矛盾；
- 经营现金流为负被解释为利润改善缺少现金支持；
- 无热点和无公司催化被解释为量价驱动，而非简单列字段；
- 财务、交易估值和公告均生成五层分析；
- 补充事实超时点或非官方域名失败；
- 没有补充事实时缺口只出现在末尾；
- V02 不变，V03 独立幂等。

### 12.2 普蕊斯真实验收

顶部必须明确：

- 量价驱动而非热点/公司催化；
- 20 日相对强、5 日上涨、成交放大是关注原因；
- 形成日约 `-10.74%` 与成交放大形成主要矛盾；
- 年化波动率约 `103.72%`、ATR 约 `10.34%` 说明路径不稳定；
- 经营现金流为负削弱财务确认；
- 数据缺失不出现在顶部。

### 12.3 以岭药业真实验收

顶部必须明确：

- 热点路线与细分医药共同性；
- 收入低增长、利润和现金流改善的组合含义；
- 形成日下跌与成交放大之间的矛盾；
- 产品/目录公告提供公司级方向支持，但经济影响仍未知；
- 估值分位样本不足时降低结论强度。

## 13. 验收标准

1. 用户先看到分析结论，再看到原始事实；
2. 报告不再出现“价格位置和成交活跃度达到召回条件”这类机器语言；
3. 反对证据明确说明它削弱了什么；
4. 数据缺失与未来验证均从顶部移走；
5. 第二至第六部分都回答“说明什么”和“与入选有什么关系”；
6. 每个分析结论可追溯到字段或官方补充来源；
7. V01/V02 与原形成包、决策卡保持不可变；
8. 所有真实新产物只写入 U 盘；
9. 不新增任何禁止能力；
10. 全部 V3 测试通过，真实 V03 复跑幂等。
