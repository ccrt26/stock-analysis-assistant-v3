# V3 可治理派生研究特征设计

> **当前状态权威：** 本文档定义必须实现的业务行为，不代表程序、真实数据或每日自动执行已经完成；最新实讯状态只以 [`docs/operations/production-capability-matrix.md`](../../operations/production-capability-matrix.md) 为准。

**日期：** 2026-07-14  
**状态：** 根据用户授权完成自检，可进入执行计划  
**依据：** `2026-07-13-v3-unified-research-data-foundation-design.md` 及其执行计划  
**范围：** 从统一事实仓复算市场环境、板块热点和个股交易背景，正式落地并每日自动执行  
**不在本轮：** 选股权重、五日涨幅预测、大模型结论、正式报告、激活或部署

## 1. 业务目的

当前统一仓已经能保证“每个业务事实只有一份当前有效值”，但普通用户真正需要的问题不是“今天收盘价是多少”，而是：

- 当前市场是全面走强，还是少数板块轮动？
- 哪些行业或主题的涨幅、参与面和成交关注在同时改善？
- 板块是普涨，还是只靠三只龙头拉动？
- 某只股票的强势是否超过市场和行业，它需要承担多大波动和系统性风险？
- 日线只能说明什么，哪些结论因缺少分钟、逐笔和账户数据必须降低可信度？

这些都不是上游接口直接提供的业务事实，而是从已经落库的行情、板块成分、涨跌停价和估值数据中确定性复算出来的研究特征。本设计的目标是把它们变成正式、可复现、可每日自动检查的数据产品，而不再是对话或临时脚本中的一次性计算。

## 2. 对原 Superpowers 设计与当前实现的审计

| 原设计要求 | 当前实现 | 结论 |
|---|---|---|
| 事实层单一有效值、修订可追溯 | 29 个事实数据集、DuckDB + Parquet、唯一键、修订和哈希均已实现 | 一致 |
| 派生层记录公式版本、事实截止、计算时间和覆盖质量 | 数据库没有派生结果表，磁盘没有派生分区 | **缺失** |
| 热点板块需复算 1/3/5/20 日强弱、广度、成交占比变化、涨停/新高、分化、日内路径和拥挤迹象 | `hotspot_features.py` 只有少量即时指标，测试只覆盖两个场景 | **部分实现** |
| 热点计算的输入必须来自 `ResearchQuery(as_of=...)` | 当前函数直接接收任意 DataFrame | **未落实** |
| 缺成分或分钟线时返回可见的限制，不造假值 | 当前无状态、无缺口说明 | **未落实** |
| 二、三级行业用历史成分与唯一股票日线复算 | 成分已落库，只有一级行业官方指数日线，未复算二、三级指标 | **数据已具备，计算缺失** |
| 市场状态所需的广度、成交、新高/新低和波动数据 | 宽基和全市场日线已落库，未生成正式市场环境快照 | **数据已具备，计算缺失** |
| 个股相对强弱、历史分位、日内效率和波动率 | 旧 Phase 3 有内存特征，但不属于当前统一仓，口径不够且没有正式落地 | **不可当作已完成** |
| 分钟线转其他周期不重复下载 | 已有分钟线聚合校验程序，但当前账号没有足够历史分钟权限 | 程序基础存在，数据能力 `limited` |
| 冻结 50 只分钟候选范围 | 已有本地计算和冻结表，在 next-morning 阶段自动调用 | 一致，但该候选只是采集范围，不是选股结论 |
| 数据健康摘要每日自动产出 | 已实现并接入三个固定时间任务 | 一致，但尚不检查派生结果 |

### 2.1 原计划为什么会漏掉

原设计第 5.2 节已经明确定义“派生层”，第 12 节也完整列出热点指标。但执行计划的任务 13 只指定了一个分析函数，没有为派生数据设计存储合同、原子提交、输入清单、查询入口和每日任务。同时，该任务所要求的涨停、日内路径和限制状态也没有进入实际测试。

因此本轮应该修复设计与执行之间的结构性缺口，不应再给现有函数补几个字段就结束。

## 3. 方案比较

### 方案 A：只扩展 `hotspot_features.py`

优点是改动少、很快能多算几个指标。缺点是仍然没有正式落地、没有输入版本、没有每日自动执行，也无法支持市场环境和个股背景。这会重复过去“临时能算，正式不可用”的问题。

### 方案 B：在统一仓内建立可治理派生层（推荐）

用一套通用的派生存储和运行记录，生产三类观察性特征：市场环境、板块热点和个股交易背景。三者都只记录可复算事实和表达边界，不做选股评分。公式改变时新建版本，不复制原始行情。每日晚间数据到齐后自动复算，次日补数后按输入哈希决定是否重算。

### 方案 C：等选股分析框架完全定稿后再建

优点是现在不写程序。缺点是每次实战都要重新写临时计算，后续复盘无法确认使用了哪个公式和哪批数据，反而会干扰分析框架的制定。

**决策：** 采用方案 B。

## 4. 整体结构

```text
统一事实层（29 类 API/官方事实）
        ↓ ResearchQuery（严格 as_of）
派生运行器（公式版本 + 输入清单 + 覆盖检查）
        ↓
统一派生层
  ├─ market_context
  ├─ sector_hotspot
  └─ stock_trading_context
        ↓
未来分析框架/复盘（只读，本轮不实现决策权重）
```

派生层属于现有统一研究仓，不创建第二套仓库，不从旧 Phase 3 正式报告仓读数，也不导入旧评分结果。

## 5. 派生存储与版本

### 5.1 磁盘目录

```text
local_warehouse/
  research.duckdb
  facts/                         # 已有事实，不改口径
  derived/
    market_context/analysis_date=YYYY-MM-DD/formula_version=.../data.parquet
    sector_hotspot/analysis_date=YYYY-MM-DD/formula_version=.../data.parquet
    stock_trading_context/analysis_date=YYYY-MM-DD/formula_version=.../data.parquet
```

### 5.2 元数据

在同一个 `research.duckdb` 中增加：

- `research_derived_runs`：一次计算的开始、结束、状态和人可读摘要。
- `research_derived_partitions`：特征集、分析日、公式版本、文件路径、行数、内容哈希、文件哈希、输入清单、输入清单哈希、覆盖状态、限制说明和计算时间。

业务唯一键为 `feature_set + analysis_date + formula_version`。同一公式、同一日期、同一输入哈希重跑必须幂等。当上游修订导致输入清单变化时，重算并原子替换该公式版本的当日分区；公式改变时使用新版本，保留旧版本以便复盘。

### 5.3 原子性

派生结果先写入 `.staging`，完成唯一键、行数、哈希和覆盖校验后再原子替换正式分区。任何计算或元数据提交失败都不得留下半份当日结果。

## 6. 严格时点输入

新增按分区读取的 `ResearchQuery` 入口，只读取指定日期窗口，但仍遵守 `available_at <= as_of`。若当前有效值在分析时点尚未可见，必须从修订记录中恢复当时可见版本，不允许用今天的修订倒灌历史分析。

每次计算把实际读取的事实分区及其 `content_hash` 写入输入清单。清单不只写“使用了日线”，而要能定位到具体数据集和日期分区。

## 7. 三类正式派生特征

### 7.1 `market_context-v1`：市场环境事实

数据窗口为最近 82 个交易日，宽基长窗口最多 250 日。当日产出一行全 A 股市场快照，并保留各宽基的可复算收益。

至少包含：

- 全市场 1/3/5/20 日等权收益、中位数收益和上涨比例。
- 上证、深证、创业板、科创 50、沪深 300、中证 500、中证 1000 和北证 50 的 1/3/5/20 日收益。
- 当日总成交额，相对 5/20 日平均的比率。
- 收益离散度，站上 20/60 日均线比例，创 20/60 日新高和新低比例。
- 涨停、接近涨停、跌停和接近跌停的家数与比例。
- 20 日实现波动，作为市场风险客观输入。

本特征集不直接输出“牛市/熊市”或“应该空仓”，避免在分析框架尚未定稿时把临时阈值变成永久决策。

### 7.2 `sector_hotspot-v2`：行业与受控主题证据

对申万 L1/L2/L3 行业和官方受控主题统一复算，不使用第三方“主力净流入”。

每个板块至少包含：

- 成分股 1/3/5/20 日等权收益、中位数收益、上涨比例和相对宽基收益。
- 板块成交额占全市场成交额的 1/3/5/20 日平均及 3/5 日变化。
- 涨停、接近涨停、20/60 日新高的成分占比。
- 当日收益离散度、头部三只正贡献占比，用来区分普涨和少数龙头拉动。
- 高成交但价格进展弱、上影/冲高回落、参与面收窄、成交占比上升但收益走弱等可观察拥挤迹象。输出单项事实和警示标志，不生成“一定出货”结论。
- 对已有官方指数日线的 L1 行业和主题，同时保留官方指数收益和自下而上等权收益的差异，作为口径交叉检查，不强行要求两者完全相等。

成分归属采用时点有效口径。当日板块快照使用当日有效成分；需要日序列的参与面和成交占比变化，每个历史交易日使用该日有效成分，避免把今天成分倒套到历史产生幸存者偏差。

当分钟数据可用时，增加上涨分钟占比、开盘阶段贡献、尾盘贡献、盘中最大回撤和从高点回落。当前没有分钟权限时，日线特征仍正常产出，`intraday_status=limited`，相关值为空，禁止用日线伪造分钟结论。

全部 272 个官方主题都有状态行。目前 43 个没有官方公开成分的主题保留 `limited_no_membership` 状态，指标留空，既不丢失目录事实，也不把它们冒充成可比热点。

### 7.3 `stock_trading_context-v1`：个股交易背景事实

本特征集把两轮临时分析中确实需要、又能用当前事实稳定复算的观察值正式化，但不沿用当时的选股阈值和权重。

每只股票至少包含：

- 1/5/10/20/60 日收益和相对宽基收益。
- 60 日 Beta、下跌市场日 Beta 和与宽基的相关性，作为系统性风险输入。
- 20 日年化实现波动、ATR 比率和 60/82 日价格位置。
- 20 日平均成交额、当日成交额相对 20 日平均、上涨日/下跌日平均成交额之比。
- 高成交日的上涨/下跌次数，日内收盘位置和实体对区间的推动效率，包括中位数、最低值和最低值日期，避免平均数掩盖单日异常。
- 市场下跌超过 0.5% 时个股上涨的天数与时间衰减计数。它只表示历史相对强弱，不翻译为“独立机构买盘”。
- 近 5 日涨停次数、最近涨停日及其后续收益、成交变化和冲高回落。
- 当日 PE-TTM/PB，以及 250 日和现有最长五年底库中的历史分位。负值 PE 不强行计算有意义的分位。

字段中必须常驻 `trader_identity_status=unavailable`。这是 `src_cn_program_trading_rules_2025` 的正确数据化用法：没有微观交易数据时，降低日线量价解释的可信度，禁止把成交现象翻译成账户身份或买卖意图。

## 8. 质量和限制状态

每一行派生结果都有自身覆盖状态；每一个分区还有总体状态。

- `complete`：所有当前应用特征均有足够事实。
- `complete_with_declared_gaps`：日线核心特征完整，但分钟线等已知非核心能力受限。
- `limited`：该行或该特征集缺少关键输入，不能参与横向比较。
- `failed`：计算、校验或落地失败，不替换上一份可用结果。

核心覆盖规则：

- 市场环境快照要求当日全市场有效行情覆盖率不低于 95%。
- 板块当日可观测成分覆盖率低于 80% 时不进入可比热点集合。
- 个股长窗口不足时保留可计算的短窗口字段，同时明确标注覆盖天数，不用 0 代替缺失。
- 43 个无成分主题和当前无分钟数据都是声明限制，不作为无限重试的网络故障。

## 9. 自动执行

不新建一套独立定时器，而是把派生计算作为现有三阶段数据任务的一部分：

| 时间 | 事实更新 | 派生动作 |
|---|---|---|
| 18:30 `close` | 全市场行情、涨跌停、估值和宽基 | 只校验核心事实是否到齐，不在板块日线未到时产生半份结果 |
| 21:30 `evening` | 板块日线、成分变更、公告和晚间资料 | 在事实提交后产出当日三类派生快照 |
| 次日 08:00 `next-morning` | 融资融券、晚到修订和缺口修复 | 重新生成输入清单；哈希未变则跳过，变化则幂等重算 |

三个现有 launchd 服务保持固定时间和数据专用属性，不包含选股、报告、激活、部署或发布命令。

同时提供手动补算命令：

```bash
python -m stock_analyzer data derive --data-date 2026-07-13
```

命令只读统一事实、写派生分区和运行元数据，不访问外部 API。

## 10. 健康检查和人可读输出

日度数据健康摘要增加三个问题：

1. 最新应有交易日是否同时有市场、板块和个股派生分区？
2. 派生文件行数、文件哈希和元数据是否一致？
3. 哪些能力是完整、带声明缺口，或因关键输入缺失不可用？

用户看到的摘要应说：

> 7 月 13 日市场环境、行业/主题和 5,270 只股票的日线研究特征已复算并落地；43 个主题因官方未公开成分暂不参与热点比较；盘中路径因当前无历史分钟权限未生成。

而不是只输出“Gate passed”或一串内部状态名称。

## 11. 2026-07-13 首次落地

实现完成后，使用当前统一事实仓为 2026-07-13 生成三类派生快照。不为了“看起来历史多”而默认回算五年的每一天：

- 日常分析从 2026-07-13 起每个交易日保留一份快照。
- 每份快照的计算可以读取 82/250 日历史窗口，估值分位才使用现有五年紧凑底库。
- 日后若为规则验证批量回算旧日期，必须有单独的历史验证任务，不让日常定时任务重复扫描全历史。

## 12. 验收标准

1. 原设计中的派生层在同一统一仓正式存在，不是临时 Markdown 或内存 DataFrame。
2. 三类特征的公式、输入窗口、覆盖条件和表达边界有测试。
3. 任何输入事实重复都在计算前失败，不能再次放大成交额或计数。
4. 热点结果同时覆盖 L1/L2/L3 行业和主题；43 个无成分主题明确为限制状态。
5. 分钟数据不可用时，日线特征正常产出且日内值为空；不伪造完整性。
6. 日线量价特征不含“机构买入”、“主力出货”或账户身份字段。
7. 晚间定时任务在事实到齐后调用派生计算，次日修订只在输入哈希变化时重算。
8. 健康检查验证分区存在、行数、文件哈希、输入清单和覆盖状态。
9. 实际为 2026-07-13 产出三类派生分区，读回校验成功。
10. 现有三个数据专用 launchd 服务仍正确加载，且任何自动链路都不包含报告、激活、部署和发布。

## 13. 设计自检

- **是否变成独立补丁？** 否。派生表、分区、查询、健康和定时任务全部进入现有统一研究仓。
- **是否提前重建 Phase 3 分析？** 否。本轮只产出观察性事实，不有选股权重、买卖建议和报告。
- **是否把无分钟权限当成无限故障？** 否。它是声明限制，日线能力照常产出。
- **是否把量价代理指标翻译成资金身份？** 否。所有相关字段只描述价格、成交额和相对强弱。
- **是否每天重算五年？** 否。一般特征只读 82/250 日，只有估值长期分位使用现有五年底库。
- **是否解决了“程序有但没有数据”？** 是。正式分区、输入清单、自动执行和健康验证都是验收必需项。
