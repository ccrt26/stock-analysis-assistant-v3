# 股票分析助手 V3：面向陌生读者的动作确认研究档案设计

## 1. 设计背景

2026-07-17 第一批真实前瞻观察已经为普蕊斯、以岭药业生成严格时点决策卡。现有决策卡能够回答“为什么进入名单”和“三项动作确认是否成立”，但仍不能让从未接触过该股票的读者建立完整认知：公司如何赚钱、属于什么板块、哪些概念有事实支持、业绩质量怎样、估值和交易指标处于什么状态，以及哪些结论仍不能成立。

本设计参考《东睦股份（600114）深度分析报告》的信息组织优点，但不复制其文本、栏目、评分或操作框架。参考报告只作为“陌生读者读完后应知道什么”的覆盖样本，不作为事实来源，也不进入任何前瞻形成证据。

## 2. 目标与非目标

### 2.1 目标

为每个 `action_confirmed=true` 的股票生成一份独立、不可变、严格时点的“研究档案”，使普通读者读完后至少能回答：

1. 这家公司是谁，主营业务是什么，服务或产品面向谁；
2. 它属于什么一级行业，哪些板块或热点与本次入选直接相关；
3. 所谓“概念”是正式成员事实、热点共同性，还是尚未证实的市场叙事；
4. 最近公开业绩如何，营收、利润、扣非利润、现金流、盈利能力和负债指标如何变化；
5. PE、PB、估值历史分位、波动、ATR、价格位置和成交比率是什么意思，当前值是什么；
6. 它为何此刻进入动作确认，而不是因为公司“听起来不错”；
7. 有哪些支持证据、反对证据、数据缺口和下一步应验证事实；
8. 哪些内容不能从当前严格时点数据推出。

### 2.2 非目标

本轮不生成或引入：

- 买入、卖出、加仓、减仓、止损、止盈或仓位建议；
- 目标价、收益预测、主观概率或未经校准的情景概率；
- 生命周期管理、持仓管理或自动交易；
- 新的选股打分、综合评分、排名或行业配额；
- 对公告标题的经济影响扩写；
- 未进入本地严格时点快照的网页、研报或未来事实；
- Supabase、发布、Cloudflare、生产任务或调度器变更；
- PDF 作为本轮权威格式。首版以 Markdown、JSON 和 Parquet 为权威产物，避免把排版工程混入事实框架。

## 3. 对参考报告的取舍

### 3.1 借鉴的能力

参考报告值得吸收的是信息顺序和读者视角：

- 先用白话说明公司及主营业务；
- 将一级行业、细分业务、热点或概念分开表达；
- 用多报告期数据而不是单个同比数字描述业绩；
- 将盈利能力、现金质量、负债和估值放在不同栏目；
- 解释指标含义，并在表格后写清“能说明什么、不能说明什么”；
- 同时列出催化事实、风险和后续观察点；
- 用分层表格降低陌生读者的阅读门槛。

### 3.2 明确不借鉴的内容

参考报告中的下列做法与 V3 前瞻观察边界冲突，不进入新档案：

- “核心持仓候选”、试探仓、核心仓和催化剂仓；
- 止损、止盈、价格梯队和目标价；
- 未给出可复核统计基础的事件概率、价格影响和情景概率；
- 将单日涨跌归因为“技术性回调”或“与基本面无关”的确定性表达；
- 用估算业务占比、估算毛利率和估算行业数字写成公司事实；
- 在缺少完整来源链时断言同业估值折价或市场份额；
- 把正式指数成员、市场概念和公司实质业务混为一类。

## 4. 方案比较与选择

### 4.1 方案 A：把现有决策卡扩成 15—20 页旧式深度报告

覆盖面最大，但会引入预测、同业研究、行业外部数据和操作框架；也会使每天少量严格事实被大量解释性文字淹没。不采用。

### 4.2 方案 B：只在现有决策卡后增加几个指标字段

改动最小，但不能形成“公司—行业—业务—业绩—估值—为何此刻—风险”的认知链，仍无法解决陌生读者“不知道是什么股票”的核心问题。不采用。

### 4.3 方案 C：新增分层研究档案

采用本方案。保留现有决策卡原样，新建 `v3-forward-research-dossier-01`：

- 第一层是 30 秒读懂摘要；
- 第二层是公司、行业/板块/概念、业绩、指标和事件的结构化事实；
- 第三层是事实、解释边界、反对证据和数据缺口；
- 附录给出术语解释和原始多期数据。

档案只解释已有动作确认对象，不改变名单、规则或确认结果。

## 5. 版本与不可变边界

### 5.1 既有产物保持不变

以下内容必须字节级保持不变：

- `v3-forward-baseline-01` 的 2026-07-17 形成包；
- `v3-forward-decision-cards-01` 的现有决策卡包；
- V01/V02 规则文件和已生成审计；
- 当前选股、压缩、动作确认和下一真实开盘语义。

### 5.2 新档案身份

新档案使用独立身份：

```text
schema_version = v3-forward-research-dossier-01
formation_date = YYYY-MM-DD
rule_version = v3-forward-baseline-01 或 v3-forward-baseline-02
```

相同身份、相同内容允许幂等复跑；相同身份、不同内容必须失败，不能覆盖。2026-07-17 的普蕊斯和以岭药业档案是形成日后生成的解释投影，不修改原形成证据。

## 6. 数据边界与来源

档案只能复用原形成包 `input_manifest_hash` 已覆盖的数据：

1. `company_profile`：公司全称、主营业务、公司介绍；
2. `industry_catalog` 与 `industry_member`：一级行业；
3. `theme_catalog` 与 `theme_member`：正式指数或主题成员事实；
4. `financial_indicator`：形成日前可见的多报告期指标；
5. `cash_flow`：形成日前可见的经营活动现金流；
6. `stock-trading-context-v2`：收益、相对收益、波动、ATR、价格位置、成交、涨跌停和估值历史分位；
7. `announcement`：形成日前已可见的正式公告标题、时间、链接和治理分类；
8. 原形成候选：路线、热点、公司证据状态、三项确认和风险提示。

本轮不把 `income_statement`、`balance_sheet` 或外部网页临时加入旧形成输入身份。虽然本地仓库可能存在这些数据，扩大快照会改变 2026-07-17 的输入清单身份，破坏“解释投影与原形成证据一致”的边界。

## 7. 概念、板块和业务的区分

档案必须明确区分四层，避免把指数标签写成公司产品：

1. **一级行业**：形成日有效的官方一级行业成员事实；
2. **本次发现热点**：本次 `hotspot` 路线实际使用的热点组；
3. **正式主题/指数成员**：形成日有效的主题成员关系，仅证明被纳入相应指数或主题，不自动证明公司收入来自该概念；
4. **主营业务事实**：公司画像中的主营和介绍，是解释“公司做什么”的主要依据。

首版不自动创造“概念映射等级”。只有本次发现热点可以写成“本次选择直接相关”；其他主题成员只在附录披露数量和最多若干代表项，并附“指数成员不等于业务收入证据”。若严格时点数据没有业务概念证据，必须写“未形成可验证的业务概念映射”，不能凭公司名称或常识补写。

## 8. 档案结构

### 8.1 30 秒读懂

每只股票开头固定回答：

- 公司全称与证券代码；
- 一级行业；
- 一句话主营业务；
- 本次发现路线和热点；
- 三项动作确认结果；
- 一句话边界：为何值得继续研究，以及当前最大的反对证据或缺口。

该摘要不能出现“应该买”“可以买”“确定上涨”等措辞。

### 8.2 公司与业务

包含公司全称、主营业务、公司介绍和“如何理解这门生意”。“如何理解”只重组画像中已出现的客户、产品、服务和流程事实，不引入行业常识。

若没有结构化主营构成数据，明确显示：

> 本地严格时点快照没有可复核的分业务收入与毛利构成，因此不编写业务占比。

### 8.3 行业、板块与概念

展示一级行业、本次热点、路线、正式主题成员摘要和证据边界。对价格路线对象，如果没有热点支持，明确写“本次不是因热点入选”。

### 8.4 为什么进入名单、为什么此刻确认

分别解释发现阶段和确认阶段：

- 发现阶段使用哪个入口；
- 动作阶段逐项展示近 5 日收益、20 日相对市场收益和成交比率；
- 每项同时展示阈值、原始值、是否满足和白话解释；
- 明确三项确认不衡量公司长期质量，不等于买入指令。

### 8.5 多报告期业绩与财务质量

使用形成日前可见、按报告期去重后的最近五期数据。字段按可用性展示：

- 报告期；
- 营收同比；
- 净利润同比；
- 扣非净利润同比；
- 经营现金流同比；
- EPS；
- 毛利率；
- 净利率；
- ROE；
- 资产负债率；
- 流动比率；
- 每股经营现金流。

不对累计期指标擅自年化。报告明确提示季度、半年度和年度口径不可直接横向当作同一周期绝对值比较；同比字段可用于看方向，但低基数可能放大增速。

### 8.6 指标体检

展示形成日 `stock-trading-context-v2` 的：

- 1/5/10/20/60 日收益与相对市场收益；
- 20 日年化实现波动率；
- 20 日 ATR 比率；
- 60 日价格位置；
- 20 日平均成交额和当日成交比率；
- 近 5 日涨停次数；
- PE-TTM、PB；
- PE/PB 的 250 日历史分位及样本完整性。

指标后写固定口径解释，不把指标自动转换为“好/坏”总分。

### 8.7 公告与公司级事实

复用现有决策卡的最多五条公告。标题、可见时间、事件类型和原文链接可以展示；除非本地结构化事实直接支持，否则不写收入、利润、订单金额或事件成功概率。

### 8.8 证据矩阵

将结论分为三类：

- **已确认事实**：严格时点结构化数据直接支持；
- **谨慎解释**：由多个已确认事实形成的有限解释，必须同时写适用边界；
- **当前未知**：业务构成、市场份额、客户贡献、同业估值、事件经济影响等当前快照没有的内容。

### 8.9 反对证据与下一步验证

反对证据复用现金流、价格消耗、成交放大、估值位置、减持和缺少公司催化等严格事实。下一步只写“需要观察哪些事实”，不写持仓动作、止损价或卖出条件。

### 8.10 术语词典

每份档案附固定简明解释：成交比率、三项确认、相对收益、价格位置、波动率、ATR、PE-TTM、PB、估值分位、营收同比、扣非净利润、经营现金流、毛利率、净利率、ROE、资产负债率。

## 9. 数据结构

每只股票在 `dossiers.parquet` 中一行，复杂字段使用稳定 JSON 字符串：

- `summary_json`
- `industry_and_themes_json`
- `action_confirmation_json`
- `financial_history_json`
- `trading_metrics_json`
- `announcements_json`
- `evidence_matrix_json`
- `opposition_and_unknowns_json`

顶层还保留形成日、规则版本、股票代码、股票简称、公司全称、主营业务和一级行业，便于审计与查询。

所有真实运行产物只写 U 盘冻结目录：

```text

    formation_date=2026-07-17/

          stocks/
            301257.SZ.md

      research-dossier-v3-forward-baseline-01.md
  manifests/
```

`stocks/*.md` 是同一不可变包内的单股阅读投影。它们必须列入清单哈希，不能作为包外可变文件。

## 11. 命令入口

新增手工研究命令：

```bash
python -m stock_analyzer.evaluation.v3_forward dossier \
  --formation-date YYYY-MM-DD \
  --warehouse-root PATH \
  --archive-root PATH \
  --output-root /Volumes/ZHUTONG/股票分析助手-V3回测/2026-07-19-v3-forward-observation
```

该命令不注册生产 CLI、不建立调度器。V02 后续真实形成日若存在动作确认对象，由人工运行同一命令生成档案；本轮不增加自动后台执行。

## 12. 失败关闭条件

以下任一情况必须失败：

- 找不到唯一形成包；
- 找不到或校验失败的既有决策卡包；
- 输入清单哈希与原形成包不一致；
- 公司画像、财务、现金流、主题成员或公告事实超过形成截止；
- 档案包含非动作确认股票；
- 多报告期去重后同一股票同一报告期仍重复；
- 相同档案身份内容冲突；
- 输出根不等于冻结 U 盘目录；
- 生成内容出现目标价、仓位、止损、止盈、自动交易指令字段。

字段缺失本身不导致失败；必须在档案中明确标注缺失以及因此不能判断的内容。

## 13. 验收标准

1. 普蕊斯和以岭药业分别有可单独阅读的研究档案；
2. 未接触过股票的读者能在开头看到公司、行业、主营、本次入选原因和最大不确定性；
3. 板块、热点、正式主题成员和主营业务四者没有混写；
4. 最近五期财务指标按形成日可见事实生成；
5. 交易、风险和估值指标有原始值、口径和白话解释；
6. 普蕊斯明确说明其为临床试验现场管理服务企业，不写成药品生产商；
7. 以岭药业明确说明其主营药品研发、生产和销售，并区分正式公告存在与经济影响；
8. 没有目标价、仓位、止损、止盈、收益承诺或自动买卖内容；
9. 2026-07-17 V01 形成包和既有决策卡包哈希不变；
10. 档案包相同内容幂等、不同内容冲突失败；
11. 全部新增真实运行产物只位于冻结 U 盘目录；
12. 相关测试和回归测试通过，禁止能力扫描无命中。
