# 顶层定时股票研究与价格指标持久化设计

> 历史记录：本文保留当时方案与事实，不作为当前运行入口或调度依据。当前时序以 `docs/architecture/current-v3-architecture.md` 和 `ops/forward-selection-prompt.md` 为准。

**日期：** 2026-08-20

## 目标

保留现有三个本地数据定时任务，把价格 Skill 各场景所需的完整确定性输入纳入数据落盘后的派生计算；删除 Python 再启动 `codex exec` 的嵌套研究链路。交易日上午 09:05 只由 Codex 自带的一个顶层 Scheduled Task 在本地项目中直接调用股票研究总控 Skill，并由总控在同一研究会话中使用四个专业 Skill，输出 0—5 只正式推荐股票或空名单。

完成代码改造后，必须补算并持久化截至 2026-08-19 形成日的价格指标，验证股票覆盖、公式版本、输入时点和可查询性。

## 选择的方案

采用“数据任务确定性计算 + 一个顶层 AI 研究任务”的结构：

```text
18:30 收盘数据任务
21:30 晚间数据任务 → 派生研究观察和价格场景输入
09:00 次晨数据任务 → 补数后重算或跳过未变化的派生结果

09:05 顶层 Scheduled Task
  → 显式调用 $orchestrating-stock-research
  → 总控在同一研究会话中使用四个专业 Skill
  → 输出 0—5 只推荐股票或空名单
  → 调用确定性归档入口保存统一 selection 记录
```

不采用以下方案：

- 不保留 Python → `codex exec`：它重复启动 AI，增加中文路径、沙箱、虚拟环境和子进程故障面。
- 不把最终选股改成程序化指标筛选：指标只提供事实和状态，不拥有最终选股权。
- 不取消 09:05 AI 定时任务：否则只能在用户手工发起研究时产生推荐，不能满足每天自动输出。

## Skill 调用方式

09:05 Scheduled Task 只创建一个顶层研究会话。任务提示必须显式写出：

1. 使用 `$orchestrating-stock-research`；
2. 冻结 `formation_date`、`action_date` 和带时区的 `as_of`；
3. 按总控合同依次使用：
   - `interpreting-market-macro`；
   - `researching-sectors-industries`；
   - `researching-company-events`；
   - `analyzing-price-trading`；
4. 保留四个专业 Skill 的实际线索或明确空线索，并完成候选守恒检查；
5. 只使用 `available_at <= as_of` 且交易日期不晚于 `formation_date` 的事实；
6. 返回 0—5 只推荐股票或有理由的空名单，不按数量补位。

这里的“使用五个 Skill”是同一个顶层 AI 会话依照五份研究方法完成工作，不启动五个模型进程，也不允许任何仓库代码再次启动 Codex。

## 确定性价格场景输入

以当前 `analyzing-price-trading` Skill 的六个信息维度和 11 个研究场景为字段合同，复用 `src/stock_analyzer/analysis/price_indicator_features.py` 的现有公式实现，将完整的场景就绪输入作为新的每日派生特征集持久化到 `DerivedFeatureStore`。用户列出的六类指标是核心组成，不是固定清单。持久化范围包括：

- 原始路径和相对强弱：1/3/5/10/20/60 日收益、同期相对市场收益、5 日相对连续性和斜率；
- 趋势和方向：EMA20、MACD 12/26/9、ADX/DMI14，以及近期方向交叉；
- 路径效率和振荡：20 日效率比、RSI14、K/D 9/3（初始 K、D 为 50）和近期交叉；
- 波动状态：20 日实现波动、ATR20、BOLL 20/2（总体标准差 `ddof=0`）及带宽变化；
- 收盘和成交质量：上涨天数、收盘位置、上影/冲高回落频率、放量天数、量价效率、涨停收益贡献、方向成交余额和价格成交效率；
- 长期位置、剩余路径和参与条件：60/82/250 日价格位置、前高距离与突破、流动性和成交额倍率。

代码中的场景阈值字段清单与布尔事件字段必须全部可由该派生结果获得；实现和测试应逐项反查 11 个场景，防止只接入六个技术指标。每日派生不自动把场景变成评分、投票、Gate 或买卖信号，也不要求每只股票必须命中场景；场景解释和最终取舍仍由价格 Skill 和总控 Skill 完成。

价格口径固定为本地 `raw OHLC × adj_factor`。输入由 `ResearchQuery` 在明确的 `as_of` 下物化；任何交易日期晚于 `formation_date` 或 `available_at > as_of` 的记录都不得进入计算。短历史不补值，保留 `limited` 和限制说明。

技术指标组件继续标记现有公式版本 `price-indicator-conditional-states-v2`；组合后的完整价格场景输入使用独立的派生公式版本 `price-analysis-context-v1`，并沿用输入清单、内容哈希和原子提交机制。相同输入重复计算必须得到相同内容；输入未变化时允许跳过重算。

## 数据任务

保留并继续使用现有三个 LaunchAgent：

- 18:30 `research-data-close`：收盘核心行情取数，不在数据不完整时提前派生；
- 21:30 `research-data-evening`：晚间事件和分类补充后运行全部派生特征；
- 09:00 `research-data-next-morning`：补充晚到事件和交易结构后再次运行全部派生特征。

完整价格场景输入直接接入现有 `run_research_features`，不增加第四个本地指标定时任务。健康检查将其纳入 `derived_ready_for_research`；场景输入缺失、公式过期、文件哈希错误或输入清单过期时，09:05 正式研究不得把派生层视为就绪。

## 移除嵌套运行器

删除仓库内下列职责：

- `CodexResearch`；
- `_resolve_codex_bin`；
- 临时 ASCII 项目视图和虚拟环境软链接；
- `subprocess.Popen(... codex exec ...)`；
- Codex stderr 活动日志和心跳；
- 09:05 `forward-selection` LaunchAgent 模板及其安装/检查逻辑；
- 只用于内层 Codex 调用的提示模板和测试。

原 `forward_selection.py` 中与 AI 启动无关的确定性职责可保留或收窄为简单入口：形成日和行动日解析、`as_of` 校验、数据就绪检查、结构化结果校验、统一 `selection` 归档和 D20 到期结算。它不得启动模型，也不得把价格指标变成程序化选股规则。

## 2026-08-19 补算

代码和测试通过后，使用本地已经落盘、且在明确截止时点可见的事实，为 `analysis_date=2026-08-19` 运行一次派生计算。

补算验收必须核对：

- 价格场景输入派生分区存在；
- 组合公式版本为 `price-analysis-context-v1`，技术指标组件版本为 `price-indicator-conditional-states-v2`；
- 输入清单中的截止时点不晚于研究冻结的 `as_of`；
- 输入行情交易日期不晚于 2026-08-19；
- 结果可以按 `analysis_date`、`ts_code` 查询；
- 当前可研究股票中，有有效 2026-08-19 日线且历史长度充足的股票取得完整场景输入；短历史股票被明确标为 `limited`；
- 同一输入重跑为幂等跳过或产生完全相同的内容哈希。

若 2026-08-19 的关键本地事实本身缺失，先通过现有数据任务补齐事实；不得联网补猜指标值，也不得使用 2026-08-20 的行情倒算 2026-08-19 结论。

## 错误处理

- 三个数据任务继续各自记录成功、受限或失败；某一派生特征失败不覆盖其他已提交特征。
- 09:05 顶层任务发现核心数据或价格场景输入未就绪时，报告具体缺口并停止正式推荐，不补猜。
- 顶层任务超过 09:30 完成仍可返回结果，只要冻结的 `as_of` 早于行动日 09:30，且所有输入满足该截止时点。
- Skill 没有提交实际线索、候选链不守恒、结果不合格或股票不可参与时，不写正式 selection 记录。

## 测试与验收

实施使用测试先行，至少覆盖：

- `run_research_features` 持久化完整价格场景输入并参与幂等跳过；
- 11 个场景依赖的阈值字段和布尔事件字段均有确定性来源；
- 价格场景输入只使用形成日及以前、且截止时点可见的事实；
- 公式版本、实体键、质量状态、输入清单和内容哈希正确；
- 健康检查把价格指标纳入派生就绪条件；
- 晚间和次晨任务触发价格场景输入派生，收盘任务不提前派生；
- 仓库内不存在 `codex exec` 或等价的内层 AI 启动路径；
- 保留的归档入口能验证并保存统一 selection 结果；
- 截至 2026-08-19 的实际补算通过覆盖和幂等核对；
- 全部相关旧测试和完整测试套件通过。

## 明确不做

- 不新增固定评分、权重、Gate 或指标买卖信号；
- 不新增 DAG、队列、候选缓存平台、云服务或兼容层；
- 不连接券商、不自动交易、不决定仓位、不承诺收益；
- 不恢复旧 V3 报告发布、Supabase、Cloudflare 或关注池路径；
- 不修改三个现有数据任务的取数职责和时间安排。

## 外部配置

仓库改造完成后，使用 Codex 自带的 Scheduled 功能配置或更新 09:05 顶层任务，使其：

- 选择当前本地项目，直接在主项目目录运行；
- 工作日 09:05 触发；
- 使用明确、耐久的研究提示并显式调用 `$orchestrating-stock-research`；
- 允许读取本地事实和派生结果，并只授予保存 selection 结果所需的最小写权限；
- 保持电脑开机且桌面应用运行。

仓库代码不再管理这个 AI 定时任务，也不通过 CLI 或 Python 启动它。
