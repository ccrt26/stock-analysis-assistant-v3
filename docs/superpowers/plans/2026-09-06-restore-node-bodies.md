# 节点详评正文补做方案（Restore Node Bodies）

> **背景：** 三路互斥改造已上线（dfd77b6）。历史重生成时发现两处偏差：
> ①节点股原有深入分析正文被 regen.py 的机械拼接文本覆盖（含银龙 9/3 的 codex 正文）；
> ②38 只"原有详评未覆盖的节点股"的正文由机械拼接器生成，质量不达标（固定句式、
> 与 headline 重复、无个股叙事）。
>
> **用户要求（原文要点）：** 已入选股票此前的"深入（≤8只）/简评"分配不再变动；
> 新增的判断只有一条——该股是否经过关键节点，是则**增加**关键节点详细分析，
> 否则维持原有深入/简评设置。补做前先写方案、经子智能体审核确认后执行，
> 完成后更新 WEB 每只股票。

## 1. 补做范围

- **恢复**：凡节点股在重生成前的备份报告（`2026-09-06-regen-backup/monitor-report-*.json`）
  中已有详评正文的，一律恢复原始正文（含银龙 9/3 的 codex 正文）。恢复的正文
  即为该股当天的节点详评/普通详评正文。
- **新写**：重生成前备份报告中没有正文的节点股（38 只，见 §3 清单），由 GLM
  按新复盘能力**逐只真实撰写**节点正文：每只使用它自己的路径数据（收益/回撤/
  相对市场与行业/量比）、原推荐理由与反证、公告状态、当日判断与展望，按节点
  问题（D1 执行性 / D3 早期持续性 / D5 第一周 / D10 前半程对账）展开；禁止
  固定句式拼接、禁止与 headline 重复的统计开头、禁止把节点问题原文当段落。
- **不动**：股票集合、K/D/B 分类结果、账本结构化判断、简评正文、快照、
  其他已保留的普通详评正文、report/ledger 的 JSON 结构、校验规则。

## 2. 实施步骤

1. 从备份提取全部原始正文映射（episode_id → 正文）。
2. 对 38 只缺口股各生成一张事实卡（当日快照字段 + 原理由/反证 + 账本判断）。
3. GLM 逐只撰写节点正文，写入 `bodies.json`（每只独立成文，禁止模板句）。
4. 重写各日 monitor-report（alert 正文＝备份正文优先、否则新写正文）＋
   重新渲染 Markdown；账本/快照不再改动。
5. 校验：报告模型校验、三路分组校验、逐日抽查（银龙 9/3 必须是恢复的
   codex 正文；新写正文每只开头句不同、含至少 3 个该股专属数字）。
6. 运行 update_monitor_web 重建逐日 HTML 与 index，验证 payload。
