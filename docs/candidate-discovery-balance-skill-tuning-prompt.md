# 候选发现平衡调优 Prompt

## 任务性质

这是一次单点、可回滚的 Skill 调优。自动连续执行到验证和汇报；只有出现必须由用户授权的外部动作，或者发现任务目标本身必须改变时，才停下请求介入。

## 唯一调优目标

修复 A 股候选发现对“新公告、新财报、当日事件”过度依赖的问题：

- 在每个形成日，公司事件、板块强度和价格/成交必须是三个独立的候选线索来源，不得把“有新公告”当成入池的隐性前提。
- 一只股即使没有当日新公告，只要出现可验证的板块共振或相对强势，也应能先进入轻量候选，再接受公司与风险验证。
- 价量异动本身不等于最终入选理由；最终仍必须有可证伪的公司/行业传导链与可交易性证据。

这次不以“永鼎股份必须入选”为目标。`2026-08-11` 永鼎股份只是一个已暴露的开发案例，用来检查它是否能因板块/价格线索被发现，不用次日涨停反推它必须成为最终选股。

## 冻结范围

优先且原则上只允许修改：

`.agents/skills/orchestrating-stock-research/SKILL.md`

若证据表明问题不在该 Skill，或必须改动第二个 Skill 才能达到目标，立即停止修改，在汇报中说明证据，不自行扩大范围。

允许的实质性编辑最多两处，并且必须都直接服务于上述唯一目标。不重写整个 Skill。

## 明确禁止

- 不新建 Skill，不改动市场、行业、公司、价格四个专项 Skill。
- 不建立固定技术指标打分、权重模型、硬门槛、配额或排名公式。
- 不新建长期观察池、状态机、数据库表、指标平台或新数据管道。
- 不修数据、不改代码、不写回测框架，不新增永久脚本和与目标无关的报告。一次性只读查询或临时计算可用于验证。
- 不改最终 `0–5` 只的总量约束，不改证据时间切片、执行日和交易性约束。
- 不为了解释单只股而添加专用规则，不以未来涨跌筛选当时候选。
- 不切换分支、不提交、不推送。
- 审查 Prompt 的单个子智能体完成后，后续执行不再启用子智能体。

## 执行顺序

### 1. 确认原始失败，然后才能编辑

1. 完整阅读总编排 Skill 和四个专项 Skill，记录 Git 工作区现状，保留用户已有改动。
2. 先保存编辑前 Skill 的精确快照。如果存在 `2026-08-11` 原始执行产物，将它作为“历史实际链”证据；如果不存在，明确标记“历史实际链不可恢复”，不用重放冒充历史记录。
3. 使用精确的编辑前 Skill、同一研究任务、同一合格股票范围，以 `2026-08-11 23:59:59 Asia/Shanghai` 为 `as_of`，只用该时点前可得的原始事实作一次冻结重放。
4. 将原始 Skill 的行为写成简短基线：哪些股因何进入、永鼎股份在哪一环节没有被提交、所需板块/价格数据当时是否可用。
5. 只有确认“无新公告是未提交候选的实际原因，且当时数据足以进行完整范围的轻量发现”，才把它认定为 Skill 指令缺口。否则不改，直接报告真正阻塞。

### 2. 冻结开发案例和未见样本

编辑前固定下列验证集，不在看到结果后换日期。对每个日期先用交易日历记录 `formation_date`、形成日 `23:59:59 Asia/Shanghai` 的 `as_of` 与其后首个真实交易日 `action_date`：

- 已暴露开发案例：`2026-08-11` 永鼎股份，只检查候选发现，不作未来表现验证。
- 开发日期：`2026-02-27` 和 `2026-03-12`。分别保留事件线索、板块/价格重新活跃线索，并包含一个缺少传导证据的价量假阳性。
- 未见日期：`2026-03-25` 和 `2026-04-07`。两个日期的当时候选和结论必须先冻结，然后才可查看后续价格路径。

在查看任何开发日期的未来价格前，先仅用形成日事实固定每个日期的具体 `ts_code`、线索来源和角色（事件候选、板块/价格重新活跃候选、或应被否决的价量假阳性），并写下是/否验收表。验收只判断“应发现的是否被发现、应保留的是否保留、应否决的是否未升格”，不打分、不根据未来收益定义角色。

若某个固定验证日期的核心数据确实不完整，不换日期，标记为无法评估并继续其余案例。只有 `2026-08-11` 原始失败案例的核心数据不可用，或剩余可评估案例已不足以支持判断时，才停止调优。

### 3. 作最小修改

只在总编排 Skill 中补足这两类语义，根据现有结构决定是一处还是两处：

1. **轻量发现范围**：每个形成日都从当时的完整合格股票范围做轻量发现；新公告、旧名单或已有叙事都不是候选边界。“完整范围”表示候选边界完整，通过现有结构化事实做横截面轻量发现；不表示逐股读公告、逐股建立深度因果链或新建扫描平台。
2. **独立线索与后续验证**：公司、板块、价格可以分别提出候选；没有新公告不阻止板块/价格线索入池，但该股必须再经公司传导、反证和交易性验证，才能最终入选。

用原则性语言，不写指标清单或数值阈值；保留现有“原始事实—派生指标—结论”证据约束。

### 4. 先做开发验证

对已暴露案例和两个开发日期重放原始与修改后行为，按编辑前冻结的是/否验收表回答：

- 板块、公司、价格是否真正能独立产生候选。
- 没有新公告、但有板块/价格重新确认的股票是否不再漏掉。
- 原有事件型候选是否仍被保留。
- 缺少公司/行业传导证据的单纯价量异动是否没有被自动升格为最终入选。
- 新增深度验证对象是否全部来自冻结的独立板块/价格线索，而不是将无线索的股票无差别扩张进来。

只有上述行为明显改善且没有破坏原有约束，才打开未见样本。

### 5. 未见样本只打开一次

1. 仅使用形成日截止前事实，分别冻结原始和修改后的候选、最终 `0–5` 只结论、理由与否定条件。在查询任何 `action_date` 之后的行情前，将两版结果写入一份仓库外的临时封存记录，并在最终汇报中原样摘要展示。
2. 确认封存记录已写入后，再查看从执行日开始的后续价格路径。未见结果的“明显退化”在打开前固定为：修改后独有的最终入选同时缺少形成日公司/行业传导证据，且其后续可执行收益或最大不利波动劣于被它挤掉的原始入选；若无法同时满足，不因单一收益差异判定退化。
3. 对未见样本同时报告候选发现是否更平衡，以及最终选择的可执行收益、最大有利涨幅、到达时间、第 20 个交易日收益、相对同期市场及最大不利波动。
4. 未见结果只用于判断这次修改是否具有初步泛化，不据此进行第二轮调参。

## 停止条件

下列任一情况立即停止，不做第二轮补丁：

- 原始失败无法重现，或 `2026-08-11` 原始失败案例的核心数据在形成日不可用，或剩余可评估案例已不足以支持判断。
- 必须改动第二个 Skill、数据层或代码才能继续。
- 修改使事件型候选明显丢失，或把普通价量异动大量推入深度研究。
- 未见样本显示发现并未更平衡，或最终选择出现明显退化。
- 已完成一轮最小修改和固定验证。

如果验证不支持修改，只逆转本轮对总编排 Skill 新增的补丁，不使用覆盖、`checkout` 或其他可能抹掉用户原有改动的方式。保留本 Prompt 和汇报证据。

## 最小验证

完成最终编辑后，只运行一次与实际改动相关的轻量结构/格式检查，再运行 `git diff --check`。不为此新建测试框架。

## 最终汇报

最终只给出一份可复核汇报，包含：

1. 冻结的调优目标与未做事项。
2. Prompt 审查意见以及是否采纳。
3. 原始失败证据，包括永鼎股份漏在哪一环。
4. Skill 的精确改动及为何是最小改动。
5. 开发案例与未见样本的原始/修改后对比，将“候选发现”和“最终入选”分开讲。
6. 价格路径指标、数据缺口、关键查询或命令、最终 Git diff。
7. 唯一结论：“保留修改”、“回滚修改”或“未修改，阻塞在……”。

不把回放表现写成未来收益保证，不因单一次涨停声称逻辑已被证明。
