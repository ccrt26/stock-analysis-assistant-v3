# 成熟历史选股诊断与五 Skill 调优 Prompt

## 任务性质

这是一次先诊断、后决定是否调优的完整历史时点研究。Prompt 通过一次独立审查后，自动连续执行到验证和汇报；只有必须取得用户授权、核心数据不足以支持最小结论，或证据迫使任务目标和范围发生改变时才停止。

## 唯一目标

判断当前五个股票研究 Skill 在成熟历史形成日上，是否能够从当时完整的合格股票范围中发现并选出未来约 20 个交易日更可能形成可操作显著上涨路径的 0—5 只股票；同时解释后来上涨但未入选的股票，是合理未选、数据不足，还是发现、交接、比较、公司传导、价格归因、未知分类或可交易性判断存在可重复的问题。

只有形成日前已有证据、跨成熟日期重复、能够写成通用原则且不会明显扩大假阳性的问题，才允许进入单点 Skill 修改。允许最终结论为“证据不足，不修改”。

## 时间边界

每个形成日分别取得：

```yaml
task_type: historical_simulation
research_objective: "未来约20个交易日形成可操作显著上涨路径，重点观察约20%涨幅"
formation_date: YYYY-MM-DD
action_date: 形成日之后第一个真实交易日
as_of: "formation_date 23:59:59+08:00"
```

形成日分析只使用 `available_at <= as_of` 的版本。需要区分：

- `event_date`：经营或公告事实实际对应的日期；
- `first_publication_at`：该事实第一次公开可见时间；
- `revision_available_at`：后续版本可见时间；
- `changed_fields`：后续版本实际改变的字段；
- 本地入库或重建时间。

不得把本地形成日更新、摘要补齐或原因字段修订自动写成形成日新催化。旧事实仍可验证公司业务与传导，但其新鲜度必须按首次公开时间解释。

## 第一阶段：封存全部原版形成日答卷

在读取任何开发日期或未见日期的未来行情前，使用当前五个 Skill 依次完成：

1. 先用 `2026-01-26` 检查冻结格式和候选台账能否生成，但不打开未来行情；
2. 冻结全部五个开发日期的原版形成日答卷；
3. 冻结全部五个未见日期的原版形成日答卷；
4. 将未见日期答卷保存在仓库外临时目录，记录文件哈希；
5. 核对所有形成日查询均未越过各自 `as_of`；
6. 只有全部基线答卷封存完成后，才允许打开开发日期未来行情。

每个形成日必须冻结：

1. 市场研究结论和搜索含义；
2. 板块、公司和价格发现阶段全部线索；
3. 非股票线索的来源、交给谁及是否转成股票；
4. 去重后的完整股票候选池；
5. 每只候选是否进入共同验证；
6. 每个视角对每只候选的结论、证据充分性、最强反证和未知；
7. 最终 0—5 只、选择理由、同类比较、行动条件和放弃条件；
8. 每只未入选候选的最先淘汰环节和形成日理由。

至少保留下列候选台账字段：

```yaml

discovered_by: []
```

## 第二阶段：打开开发日期未来路径

全部原版形成日答卷封存后，才读取五个开发日期行动日起 20 个真实交易日的行情。

### 统一可执行价格口径

- 主要评价入口为行动日开盘价；
- 复权收益统一按 `(P_t × AdjFactor_t) / (P_entry × AdjFactor_entry) - 1` 计算，入口、后续开盘、收盘、高低价和基准保持同一复权语义；
- 行动日停牌、无可靠开盘价或成交、全天无成交、开高低收均锁在涨停价的一字涨停等无法正常参与状态标记 `not_executable`；
- 只有日线数据不足以判断能否成交时标记 `unknown`，不得假设成交；
- 不把不可成交涨停价或盘中瞬时价格视为可执行买入；
- 个股形成日写下的行动条件另行判断是否满足，但不得事后新增条件；
- 复权口径在入口、后续收盘、高低价和市场基准中保持一致。

### 每只股票的确定性评价指标

```yaml
executable: true | false | unknown
entry_price: null
max_close_return_20d: null
max_intraday_return_20d: null
first_close_target_day: null
terminal_close_return_20d: null
relative_equal_weight_universe_return_20d: null
relative_index_returns_20d: {}
max_adverse_excursion_before_target_or_end: null
original_action_conditions_met: true | false | unknown
```

20 日窗口包含行动日，共 20 个真实交易日。目标达成主要以任一复权收盘价相对入口达到 20% 判断；`15% ≤ 最大收盘涨幅 < 20%` 只标记为 `near_target`，用于复盘优先级，不是选股规则；盘中最高涨幅单列，不冒充收盘可执行达标。最大不利变化使用行动日起至首次收盘达标日；未达标则使用完整 20 日窗口。相对市场的主要基准是同一形成日合格股票范围的可执行等权收益；可靠宽基指数分别报告，不合成为任意单一指数。

### 对称评价对象

同时评价：

1. 全部最终入选股；
2. 全部候选池中后来可执行达标或接近目标的未入选股；
3. 入选后表现较差并可能挤掉更优同类的股票；
4. 全合格范围中未被发现但后来可执行达标的股票。

对第 4 类先保留完整机械列表，再按共同上涨原因、行业或主题聚类做代表性深度研究；优先选择形成日前已有可验证板块、公司或价格线索的股票。不得因深度研究数量有限而声称其余股票没有漏选问题。

## 第三阶段：开发样本错误归因

对每个重点漏选或误选案例依次回答：

```text
形成日前是否已有可用证据
→ 哪个发现 Skill 是否提交线索
→ 线索是否进入候选池和共同验证
→ 最先在哪一步被淘汰或误判
→ 当时理由按当时证据是否成立
→ 与挤占名额的入选股相比是否真的更有形成日优势
→ 修复是否能写成跨股票、跨日期通用原则
```

每只案例只能指定一个最先错误环节，其他问题作为次要原因。错误分类使用：

- `discovery_miss`
- `handoff_loss`
- `premature_pruning`
- `freshness_error`
- `company_transmission_error`
- `sector_comparison_error`
- `price_attribution_error`
- `unknown_misclassification`
- `tradability_error`
- `common_exposure_error`
- `data_gap`
- `reasonable_non_selection`

特别检查：

1. 事件首次公开时间、修订时间和字段变化是否被正确解释；
2. 证据充分性、最强反证和未知是否绑定到每条候选，而非多只候选共用顶层结论；
3. 非股票线索、股票线索和候选是否全部有去向；
4. 次要未知是否被错误升级为阻断，或关键未知被放过；
5. 行动条件是否明确观察时间、数据和满足/不满足结果；
6. 最终 2—5 只是否存在行业、主题、上游变量或历史收益共同暴露。

## Skill 修改门槛

### 结构和合同问题

候选字段缺失、线索无声消失、事件时间语义矛盾等结构问题，必须在一个开发日期明确复现，至少再由一个独立开发日期确认，并能说明它如何影响候选传递、验证或最终取舍，才允许修改。

### 选股判断问题

价格透支、板块成员比较、公司传导、未知分类等判断问题，必须同时满足：

1. 至少两个成熟开发日期重复出现；
2. 至少涉及三只独立股票；
3. 形成日前确实已有足够直接或可追溯证据；
4. 问题不能只由未来涨幅定义；
5. 能写成通用原则，不是股票专用规则；
6. 不会明显增加缺少公司或行业传导的普通异动股；
7. 责任 Skill 唯一或能够先对一个明确接口问题作最小修改。

未达到门槛时，不修改 Skill，只报告观察和下一步所需证据。

## 第四阶段：单点最小修改

若达到修改门槛：

1. 只选择重复证据最强、最先阻断且收益最大的一个问题；
2. 修改前保存精确 Skill 内容与 SHA-256；
3. 先使用开发案例证明原 Skill 会产生该失败；
4. 按 `skill-creator` 和 `superpowers:writing-skills` 的测试优先方法，设计失败场景和反例；
5. 只修改一个明确责任 Skill，或只修改一个跨 Skill 候选合同问题的最小必要文件集合；若需要同时重写多套分析逻辑，停止并报告；
6. 不增加评分、阈值、Gate、状态机或新系统；
7. 使用相同开发案例验证问题改善，并检查原有事件型、板块型和独立价格型候选没有被破坏。

如果最小修改无法同时改善目标问题并保留旧能力，只逆转本轮精确补丁，保留诊断证据。

## 第五阶段：未见日期只打开一次

只有存在已冻结的 Skill 修改时才打开未见结果。打开前，使用冻结修改版完成五个未见日期的形成日答卷，不得读取这些日期行动日及之后行情；将修改版答卷写入仓库外临时目录并记录哈希，确认原版与修改版答卷都已封存。

确认封存后，只打开一次未来 20 日结果，比较：

- 应发现候选是否减少漏掉；
- 普通价量异动和无传导候选是否明显增加；
- 原有事件型和独立公司候选是否仍能发现；
- 最终是否仍为 0—5 只；
- 深度验证对象是否无理由膨胀；
- 入选股达标、相对收益和最大不利变化是否退化；
- 漏选错误是否减少；
- 是否出现新的系统性误选。

看完未见结果后不得追加第二轮补丁。若没有达到修改门槛，未见日期继续封存，不为增加报告样本而打开。

## 停止与回退条件

出现任一情况停止当前修改并保留诊断：

- 原始错误无法稳定复现；
- 修改只能解释某一只股票；
- 必须使用形成日之后的信息才能成立；
- 真正阻碍是数据缺口；
- 新增候选多数缺少公司或行业传导；
- 候选或深度研究数量明显膨胀而质量没有改善；
- 原有重要候选类型明显丢失；
- 必须同时重写多个 Skill 的分析逻辑；
- 可评价开发日期少于 4 个；
- 达到修改门槛但可评价未见日期少于 4 个。

未见评价完成后，问题改善且没有重要退化则 `保留修改`；问题未改善，或误选、不可参与、最大不利变化及旧能力明显恶化则 `回退修改`；没有达到修改门槛则 `证据不足，不修改`。不得只因少量收益指标更好就保留修改，必须同时检查错误类型和假阳性。

## 最小验证

如果没有 Skill 修改：

- 核对日期、窗口、可执行价格和未来信息隔离；
- 核对候选台账守恒；
- 核对每个重点案例都有形成日证据、未来评价和唯一错误分类；
- 运行 `git diff --check` 并确认除 Prompt 和报告外没有本轮改动。

如果有 Skill 修改，另加：

- 使用 Skill Creator 的 `quick_validate.py` 验证修改 Skill；
- 运行冻结开发案例的修改前/后行为测试；
- 打开未见日期后完成原版/修改版对比；
- 运行相关现有测试和 `git diff --check`；
- 读取最终 diff，确认没有扩大范围。
