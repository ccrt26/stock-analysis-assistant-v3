# 价格主要场景验证与 Skill 修正执行 Prompt

## 目标

基于当前架构和本地可用的时点安全事实，把价格 Skill 从“按指标依次筛选”的近似漏斗，修正为：

1. 先分离基准共同变化与个股相对路径，但不作因果或交易者身份推断；
2. 并列观察趋势、原始价格路径、相对强弱、收盘质量、量能、振荡、波动及长期位置；
3. 识别有限的主要价格场景并作条件化解释；
4. 最后综合最强支持、最强反证、关键未知、替代股差异和参与条件。

场景条件、样本划分、对照组、结果指标及支持/否定规则必须在查看未来结果前冻结，再用历史时间后移样本验证。本轮不重新选股，也不改动正式选股逻辑。

## 开始前

- 先阅读 `docs/architecture/current-v3-architecture.md`、`.agents/skills/analyzing-price-trading/SKILL.md`，以及与现有价格特征、测试和本地冻结样本直接相关的文件。
- 检查并记录当前工作树状态，保留全部既有改动；不得 reset、删除、覆盖或顺手整理无关文件。
- 盘点本地事实的日期、股票、字段及可回放范围。缺失、覆盖不足、查询失败、不可回放和真实无记录必须分别报告，不得补猜。
- 若现有数据无法支持某个场景的历史验证，该场景只能标为“证据不足”，不能写成已验证解释，也不能据此宣告本轮调优完成。

## 有限场景体系

以少量场景族覆盖主要价格问题，不穷举指标排列组合：

1. 趋势延续：既有趋势延续、初步激活；
2. 回撤与反转：上升趋势回撤、强下跌超卖、反转尝试；
3. 区间与噪声：震荡噪声；
4. 突破：有效突破、失败突破；
5. 衰竭与冲击：趋势衰竭、单日脉冲或透支；
6. 背离：量价背离。

行动日停牌、涨跌停封死、无可靠报价或其他明确无法正常参与的情况，是覆盖在场景之上的事实约束，不作为需要从价格指标预测的独立场景。历史不可完整回放时必须标明边界。

同一股票可以同时符合多个场景；场景是条件化解释模板，不是互斥状态机，也不是前一道未通过就停止的漏斗。

## 冻结与历史验证

查看未来标签前，形成可复查的冻结记录。每个场景至少固定：

- 场景定义及其适用问题；
- 原始 OHLCV/价格位置条件；
- 相对基准或同类股票的强弱条件；
- 多日收盘路径和收盘质量；
- 量能水平、持续性与异常性；
- 仅在确实改变解释时采用的技术状态；
- 预期解释及可观察的未来含义；
- 对照组构造；
- 最强反证；
- 支持、否定、证据不足的预先判别规则；
- 样本纳入、排除、缺失值和不完整未来窗口规则；
- 开发期与时间后移验证期的确切边界。

开发期只用于确定研究分组和场景定义；完成冻结后才允许读取时间后移期结果。若发现实现或数据错误，应留下版本化更正记录并完整重跑，不得根据不利结果静默换条件、换样本或换口径。

对照组采用与形成日、可交易范围及关键前置状态可比的最简单可复现方案，复用现有能力，不建设通用匹配框架。

所有形成日特征只能使用 `available_at <= as_of` 的事实。未来行情仅在条件与样本冻结后用于评价，不得进入特征或反向影响分组。

## 评价要求

评价窗口及公式须预先固定。至少报告：

- 样本数、形成日数量、股票数量及日期覆盖；
- 20 个交易日内的目标触达率；目标价格或条件须逐场景预先定义；
- MFE、MAE 和 D20 收益，并明确采用高低价还是收盘价计算；
- 相对对照组的方向与幅度；
- 2025 年和 2026 年分段表现；若任一区间覆盖不足，明确标为不足；
- 按形成日聚类的不确定性，避免把同一天大量股票当成完全独立样本；
- 缺失、删失、停牌及不足 20 个交易日样本的处理数量；
- 最强反证和结果可能受市场环境影响的边界。

支持、否定和证据不足的判别规则应在看结果前固定，并综合效应方向、幅度、不确定区间、跨期一致性和覆盖情况，不能只依赖单一均值、胜率或 p 值。

现有样本已经被研究接触，因此结果只能称为“时间后移探索验证”，不得称为独立盲测、样本外证明或因果证明。

## Skill 修正规则

- 只有得到历史支持的场景组合及解释，才能作为可用解释写入价格 Skill。
- 被历史否定的组合应保留否定结论，并明确不得据此形成相应故事。
- 证据不足或未命中已验证场景时，Skill 必须要求输出未知或未决，不能由 AI 自由拼接指标故事。
- 技术指标单独出现不能构成场景结论。
- 除基准共同变化分离和最终综合外，趋势、路径、振荡、波动、量价及长期位置均为并列证据，不形成固定顺序漏斗。
- Skill 的场景输出至少包括：命中条件、最强支持、最强反证、关键未知、与替代股的差别及行动日参与条件。
- 不把市场、板块或公司因果塞进价格 Skill，不从量价推断机构、主力、账户或其他主体身份。

## 修改范围

只允许修改：

- 完成验证必需的价格特征或场景验证代码；
- 对应测试；
- 一次性验证脚本和冻结结果/报告；
- `.agents/skills/analyzing-price-trading/SKILL.md`。

复用现有冻结样本和本地行情，不新建数据库、通用研究框架或生产服务。

不得修改：

- 总控、市场、板块或公司 Skill；
- 正式选股 Python 逻辑；
- `opportunity_type`；
- 0—5 只和空名单架构；
- 本轮候选或历史选股结果。

不得建立总分、权重、投票、Gate、参数搜索、行业配额、自动交易或生产硬阈值。开发期分位数只可用于历史研究分组，不能直接成为每日机械规则。

不得 commit 或 push。

## 验证与验收

- 对新增或改变的确定性行为，相关单元测试须先出现预期失败，再在实现后通过。
- 运行场景业务验证、相关测试、完整测试、Skill 格式校验和最终差异检查。
- 冻结记录、验证结果和通俗结论必须可复查，并能对应到具体场景、数据覆盖及判定依据。
- 检查最终差异仅包含本轮必要文件，且没有覆盖用户既有改动。
- 如果某个主要场景只有否定结果或证据不足，忠实保留，不按数量补出“有效场景”。

## 完成汇报

完成后向用户汇报：

- 修改了哪些文件及各自用途；
- 各场景的冻结条件、样本覆盖、核心指标和“支持/否定/证据不足”结论；
- 哪些解释进入 Skill，哪些被禁止或保留为未知；
- 测试和校验命令及实际结果；
- 数据覆盖、时间后移验证和行动日可参与性方面的剩余风险；
- 是否仍有证据缺口。

不得自行把结果表述为永久证明，也不得重新选股。最后请用户基于上述证据共同确认价格 Skill 是否已完成本轮调优。
