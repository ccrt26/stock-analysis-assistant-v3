# 候选链路可审计性审计与单点调优 Prompt

## 唯一目标

审计当前五个 Skill——`orchestrating-stock-research`、`researching-company-events`、`researching-sectors-industries`、`analyzing-price-trading`、`interpreting-market-macro`——在新的成熟历史形成日中，能否把四个专业 Skill **实际提交**的股票及非股票线索完整交接为可追溯的去重候选，并为每只候选留下共同验证状态、最终去向和唯一首要理由。

本轮只解决候选链路可审计性，不以提高历史收益为目标，不放宽价格确认或最终入选标准，也不改变候选发现范围。

## 固定样本与定义

开发形成日固定为：

- `2026-04-07`
- `2026-04-21`
- `2026-05-06`

未见流程形成日固定为：

- `2026-06-23`
- `2026-07-07`

形成日、对应行动日、20 个交易日未来窗口及其起止口径，均沿用当前 `orchestrating-stock-research` 的既有定义，不另创新口径。开始研究前仅用交易日历核对：

1. 每个形成日有效；
2. 对应行动日存在；
3. 截至本轮执行日，完整 20 日窗口已经结束；
4. 最晚的开发样本未来窗口早于第一个未见流程形成日。

此步骤不得读取价格、涨跌幅、收益、排名、新闻复盘或其他未来结果。任一条件不满足即停止并报告，不得看结果后更换日期。

“实际提交的线索”仅指四个专业 Skill 在其原始形成日答卷中明确输出的对象或主题，不得由编排层事后补造：

- 明确股票代码的线索按 A 股代码归一化去重；
- 只有名称但暂不能唯一映射代码的，保留为未决线索，不得猜测；
- 板块、产业链、政策、事件等非股票线索，也必须保留原文和来源，并记录为“已转成股票”“有形成日理由不转”或“未决”；
- 某个专业 Skill 没有提交线索时，明确记录为空，不得静默省略。

“共同验证”指每只去重股票候选均进入公司、板块、价格、市场宏观四视角检查，并分别留下支持证据、反证和未知项；未知不得被自动解释为通过或淘汰。

## 防未来污染与封存

所有形成日研究严格使用当前五个 Skill 的点时规则，只允许使用在该形成日既定信息截止时点已经公开、当时可得的材料。实际行动日状态以及行动日之后的行情，均不得提前读取。

每份原始专业答卷、候选台账、编排结论和 Prompt 都保存为独立文件，不覆盖旧版本，并生成 SHA-256。封存后不得改写；任何复跑都另建版本。未来行情只能在本 Prompt 要求的全部形成日版本均封存后统一开启。

本线程此前读取过部分相邻日期的未来行情，因此本轮不是完全独立的新实验。报告必须披露这一限制；若它足以影响结论，只能声称完成流程审计，不得声称收益泛化。

## 执行顺序

1. 保存当前五个 Skill 的路径、版本或文件哈希，并把当前 `orchestrating-stock-research` 作为可精确恢复的失败基线。
2. 在不读取任何样本未来结果的前提下，用未修改的五个 Skill 完成三个开发形成日的基线答卷并封存。
3. 为每个日期建立完整候选链路，至少包含：
   - 专业 Skill；
   - 原始线索原文与来源；
   - 线索类型；
   - 股票代码归一化结果；
   - 去重关系；
   - 是否进入共同验证及状态；
   - 四视角支持、反证与未知；
   - `selected`、`rejected`、`unresolved` 三者之一；
   - 最先决定其当前去向的处理环节；
   - 唯一首要理由；
   - 可选的次要理由，但不得与首要理由并列。
4. 逐日验证以下守恒：
   - 去重股票候选数 = `selected` + `rejected` + `unresolved`；
   - 每条原始股票线索都能追到一个去重候选；
   - 每条非股票线索都具有“已转成股票”“有理由不转”或“未决”之一；
   - 去重不得造成来源、反证或去向丢失。
5. 只有同一结构性缺口在至少两个开发日期重复出现，并且能够指出当前 Skill 文本缺少或含糊的具体约束时，才允许进行**一次**最小修改。修改范围仅限 `orchestrating-stock-research` 的候选台账合同；不得修改另外四个 Skill，不得改变公司、板块、价格或宏观判断，不得新增评分、阈值、配额、关注池、数据源或系统。
6. 若不满足修改条件，保持全部 Skill 不变，继续完成两个未见流程日期并封存，最终结论只能是“证据不足，不修改”。
7. 若进行了修改：
   - 保存完整 diff 和修改后哈希；
   - 先用修改版复核三个开发日期，所有输出另行封存；
   - 再在两个未见流程日期上分别运行原基线版和修改版，使用相同的形成日证据口径，分别封存；
   - 不允许根据未见日期再修改合同。
8. 修改版只有同时满足以下条件才算稳定改善：
   - 两个未见日期上的目标结构缺口均消失；
   - 台账守恒及逐线索可追溯性均成立；
   - 未引入新的缺失字段、矛盾状态或无首要理由记录；
   - 新增的深度验证候选能够逐一追溯到基线曾丢失的真实股票线索；无真实来源的候选扩张视为不合格。
9. 若修改版未稳定改善、引入新问题或造成无真实线索来源的深度候选扩张，立即精确恢复原 `orchestrating-stock-research`，并用原始哈希验证回退成功。不得尝试第二轮修改。
10. 只有上述所有基线版、修改版（如有）和未见流程形成日答卷全部封存并完成哈希后，才可读取各日期行动日起的 20 个交易日未来路径。
11. 未来结果只写入独立评估附录，用于区分：
    - 基于形成日证据的合理未选；
    - 已提交线索但未进入应有链路的遗漏；
    - 去重、转换或交接造成的丢失；
    - 已完整验证但形成日判断错误。

    不得据未来结果新增候选、改写形成日证据、理由或状态，也不得据此追加修改。

## 最终交付

交付：

1. 本轮实际使用的完整 Prompt、版本和哈希；
2. 一份审计报告，包含：
   - 日期与信息截止口径；
   - 五个 Skill 的基线哈希及修改哈希（如有）；
   - 每日原始线索、非股票线索处置、去重候选和完整台账；
   - 每日守恒等式及异常；
   - 开发日期重复缺口证据；
   - 修改前后 diff 与开发/未见对照（如有）；
   - 所有封存文件哈希；
   - 单独的未来结果评估附录；
   - 已知污染与“并非完全独立实验”的限制；
3. 唯一结论，且只能是以下之一：
   - `保留修改`：仅当修改版通过两个未见日期的稳定改善条件；
   - `回退修改`：发生过修改但验证失败，并已恢复且核对原哈希；
   - `证据不足，不修改`：没有满足修改门槛或无法形成可靠证据。
