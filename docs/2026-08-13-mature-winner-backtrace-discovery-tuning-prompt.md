# 成熟赢家倒查与候选发现首次漏失单点调优 Prompt

## 任务性质

这是一次先倒查、再决定是否修改 Skill 的历史时点诊断。Prompt 只允许审查一次；审查通过后自动执行到验证和汇报。只有必须取得用户授权、核心数据不足以形成可靠结论，或证据迫使唯一目标和文件范围发生变化时才停止。

## 唯一目标

判断当前五个股票研究 Skill 为什么会漏掉以下股票：

1. 形成日已经具有足以进入候选审查的公开事实；
2. 当前发现链没有把它提交为可追溯的具体股票候选或具体股票问题；
3. 行动日可正常参与；
4. 随后 20 个真实交易日内，复权收盘收益达到或超过 20%。

本轮只优化“成熟赢家在候选发现链中的首次漏失”，不是放宽最终 0—5 只入选标准，也不以让已知赢家事后入选为目标。候选被补充发现不等于最终应该选择。

“接近目标”只用于敏感性分析、失败对照和解释，不得单独触发修改、证明修改有效或支持保留修改。

若股票已经由任一专业 Skill 以具体股票线索，或以能够唯一指向该股票的具体问题提交，之后才在非股票线索转换、去重、共同验证或最终取舍中丢失，则首次漏失不在本轮两个责任 Skill 的发现阶段。此类案例只报告为下游链路或最终取舍问题，不得用于证明本轮需要修改。

若且仅若同一种候选发现首次漏失在多个开发日期和多只实际达标股票上重复出现，并能在冻结的未见日期上提高这类形成日可知赢家的发现召回，同时不造成明显候选噪声或旧能力退化，才最小修改一个责任 Skill。

最终结论允许为“证据不足，不修改”。

## 科学边界

未来 20 日结果只承担两个作用：

1. 按预先固定的可执行口径标记后来达标、接近目标、未达标和不可评价；
2. 选择需要倒查的成熟赢家，并在修改假设冻结后评价未见结果。

未来结果不得改写形成日事实、不得成为形成日理由、不得用于临时挑选更好看的日期、信号窗口、案例或规则。

开发样本只能产生并冻结一个最终修改假设。同一批开发赢家只能用于提出和检查该假设，不能同时充当未见有效性证明。修改是否有效只由未来仍关闭时已经封存的未见形成日输出决定。

“未见”是本轮执行过程中的程序性隔离，不自动代表任何人此前从未接触过相关行情。开始时记录固定日期或未见标签是否曾被用于选择日期、案例、规则或修改方向；若存在此类污染，相应日期不得作为保留修改的独立证据，并在报告中明确说明。

所有基线与修改版运行必须使用相同的数据版本、模型与运行配置、输入合同和调用顺序。记录模型、工具、关键配置和数据分区；若运行期间相关输入发生变化且无法恢复一致比较，相应日期标记 `not_evaluable`，不得把运行差异归因于 Skill 修改。

## 研究对象和允许修改范围

基线为执行开始时工作区中的五个 Skill：

- `.agents/skills/orchestrating-stock-research/SKILL.md`
- `.agents/skills/interpreting-market-macro/SKILL.md`
- `.agents/skills/researching-sectors-industries/SKILL.md`
- `.agents/skills/researching-company-events/SKILL.md`
- `.agents/skills/analyzing-price-trading/SKILL.md`

当前总控的 `candidate_chain` 审计合同是既有基线，本轮不得删除、改写或把它重新当作调优目标。市场和板块 Skill 继续履行现有发现、背景解释与同类比较职责，但本轮不修改。

若达到修改门槛，只允许在以下二者中选择**一个**责任 Skill 做一次最小修改：

- `researching-company-events`：仅处理形成日前已公开、仍具传导或阶段进展的公司事件没有进入发现线索的问题；
- `analyzing-price-trading`：仅处理形成日已存在、有个股增量含义但未处在最极端尾部的价格异常没有作为具体股票线索或具体股票问题提交的问题。

不得同时修改两个 Skill；不得修改总控最终选择逻辑、`candidate_chain` 合同、价格确认标准、公司证据充分性、股票范围、目标定义或其他代码。若证据指向非股票线索转换、共同验证、最终取舍、市场、板块、数据层或多个 Skill 联动，只报告诊断，不修改。

- 不重构现有数据代码，不建设可复用回测框架；
- 不切换分支、创建 worktree、提交、推送或创建 PR；
- 不改动 `AGENTS.md`、`bingo/`、`who-is-it/` 及其他用户现有改动。

## 版本和数据保护

开始时记录：

1. `git status --short`；
2. 五个 Skill 的 SHA-256；
3. 日线、复权、涨跌停、交易日历、证券身份、行业成员、公告和公司财务事实的最新分区与健康状态；
4. 本轮 Prompt 的 SHA-256；
5. 已存在的未跟踪文件和用户改动；
6. 模型、工具、运行配置和关键调用参数；
7. 最终报告路径在开始时是否已经存在。

后续运行使用已记录的同一输入边界。修改责任 Skill 前再次核对其 SHA-256；若相对开始时发生了非本轮变化，不覆盖用户修改，停止修改并报告。

所有中间计算、形成日封存、基线副本和行为检查写到仓库外的独立临时目录。仓库内只保留本 Prompt、最终报告，以及验证通过时的一个最小 Skill 修改。

任何回退只精确逆转本轮补丁，不使用 `checkout`、`reset` 或整文件覆盖。回退前若目标文件出现与本轮无关的新变化，不覆盖该变化，停止并报告需要用户处理的冲突。

## 股票范围和统一结果口径

沿用总控默认范围：上海主板、深圳主板和创业板；不含科创板、北交所和场内基金，并按形成日可见事实排除 ST/*ST、退市整理、停牌、尚未上市或当时已终止上市、无可靠报价及无正常成交的股票。不得因股票后来退市、风险变化或当前状态而把它从历史形成日范围中排除。

每个形成日：

```yaml
task_type: historical_simulation
research_objective: "未来约20个交易日形成可操作显著上涨路径，重点观察约20%涨幅"
formation_date: YYYY-MM-DD
action_date: 形成日之后第一个真实交易日
as_of: "formation_date 23:59:59+08:00"
```

结果评价固定为：

- 入口：行动日复权开盘价；
- 窗口：包含行动日在内的 20 个真实交易日；
- 达标：窗口内任一复权收盘价相对入口达到或超过 20%；
- 接近目标：最大复权收盘收益大于等于 15% 且小于 20%；
- 同时报告最大盘中路径、首次收盘达标日、20 日终点、相对合格范围等权收益和达标前或窗口结束前的最大不利变化；
- 行动日停牌、无可靠开盘或成交、全天无成交，或开高低收全部锁在涨停价等无法正常参与的情况标记 `not_executable`；
- `not_executable` 和核心行情不完整的股票不得计入修改门槛或保留修改的成功案例；
- 盘中瞬时触及 20% 不冒充收盘达标。

所有未来标签最多使用截至 `2026-08-12 23:59:59+08:00` 的数据，不读取或使用 2026-08-13 及之后事实。

## 第一阶段：未来关闭时封存基线

在查询任一固定日期的行动日及之后行情前，依次完成并封存八个日期的基线形成日研究：

1. 冻结市场简报、板块方向和共同证据；
2. 运行公司、板块和价格发现，保留全部 `candidate_leads`；
3. 转换非股票线索并建立去重候选；
4. 完成共同验证和最终 0—5 只取舍；
5. 按当前总控合同核对候选守恒和逐线索可追溯性；
6. 记录每只候选的来源、四视角支持/反证/未知、最终去向和唯一主要原因；
7. 为每个日期同时封存两份只用于诊断的宽表面，不把它们加入候选：
   - 公司审计表面：形成日前 60 个自然日内已经公开的结构化业绩、正式财务变化、并购重组、重大合同或中标、产能、资产、控制权等公司事实，以及同期公开的旧事件阶段进展；
   - 价格审计表面：按形成日合格范围分别保留 1、5、20 日相对市场收益、相对行业收益、成交变化和价格位置的横截面排序；每项只保留排序靠前的 100 只及其并集。

审计表面的 60 日和 100 只只是控制本轮倒查工作量的固定抽样边界，不是选股规则，不得写入 Skill。公司事实只有标题而无正文时只能记录标题存在和时间，材料性保持未知。

全部基线形成日文件记录哈希。形成日查询必须证明没有使用 `action_date` 及之后行情，没有使用 `available_at > as_of` 的公司、行业或身份版本，也没有使用当前身份或当前行业关系覆盖历史版本。

## 第二阶段：只打开开发未来并倒查成熟赢家

八个日期的基线均封存后，只打开四个开发日期的未来 20 日结果。

每个开发日期先保存合格范围内的完整机械结果列表，并分别报告：

- 可执行且收盘达标；
- 可执行且接近目标；
- 可执行但未达标；
- `not_executable`；
- `not_evaluable`。

对收盘达标股票再区分：

- 基线已发现并进入候选；
- 未进候选但出现在公司审计表面；
- 未进候选但出现在价格审计表面；
- 未进上述两类审计表面。

“未进审计表面”的后来上涨不能证明不存在发现漏诊，只说明本轮固定审计抽样没有覆盖，必须作为覆盖限制报告。

对所有“基线未发现、进入任一审计表面、行动日可执行且后来收盘达标”的股票逐只倒查，并指定唯一首要分类：

```text
not_knowable_at_formation
reasonable_non_discovery
company_discovery_miss
price_discovery_miss
baseline_discovered_or_downstream_loss
data_gap
identity_or_time_error
```

对接近目标股票可按相同方式做敏感性分析，但必须单独列示，不得计入修改门槛的达标案例数。

首次漏失按以下口径判断：

- 任一专业 Skill 已经提交具体 `stock` 线索，视为已发现；
- 任一专业 Skill 已经提交能唯一指向该股票的具体 `question`，也视为已发现；
- 只有泛化的 `direction`、`group` 或无法唯一映射的普通问题，不视为已经发现该股票；
- 已发现后在转换、去重、共同验证或最终取舍中丢失，分类为 `baseline_discovered_or_downstream_loss`；
- `baseline_discovered_or_downstream_loss` 只进入下游链路或最终取舍复盘，不得证明公司或价格发现 Skill 需要修改。

每个真正的公司或价格发现漏诊必须写清：

1. 形成日前可见的直接事实；
2. 当前责任 Skill 哪一句会导致或允许漏掉；
3. 当时为什么至少应提交具体股票线索或具体股票问题；
4. 为什么这仍不等于最终应买；
5. 同日、同一审计表面中符合拟议模式但后来未达标股票的表现和反证；
6. 为什么首次漏失确实发生在该责任 Skill，而不是候选转换、共同验证或最终选择。

## 第三阶段：失败对照和修改门槛

不得只研究赢家。对每个拟议通用模式，先只用形成日事实定义模式，再应用到同一日期、同一固定审计表面的全部股票。至少报告：

- 符合该形成日模式的股票总数；
- 后来达标、接近、未达标、不可执行和不可评价数量；
- 其中基线已发现与未发现数量；
- 新规则若用于发现，会新增多少具体股票候选或具体股票问题；
- 新增非赢家是否仍有形成日可解释性，还是普通噪声；
- 是否集中于同一行业、共同事件或重叠行情窗口。

只有同时满足以下条件才允许修改：

1. 同一首要漏诊类型至少在 2 个开发日期重复；
2. 至少涉及 3 只不同且行动日可执行、随后收盘达标的股票；
3. 每只股票的关键证据在形成日前已经公开可见；
4. 当前 Skill 文本存在一个明确、可复现的遗漏或含糊点；
5. 模式先由形成日事实定义，并已应用到同表面全部股票，而不是只在赢家身上事后成立；
6. 失败对照没有显示它会扩张成缺乏形成日解释的普通噪声；
7. 能用一段最小通用说明修复，不需要固定阈值、评分、名单配额或第二个 Skill 联动；
8. 修改只改变发现线索是否被提交，不改变公司证据充分性、价格透支判断或最终选择标准。

接近目标案例可以增强或削弱解释，但不能代替上述 3 只实际达标股票。

若公司与价格两类都达到门槛，只选择跨日期证据更强、首次造成漏诊更明确且新增噪声更少的一类；另一类只记入后续观察。若无法明确唯一优先项，不修改。

进入修改前，冻结唯一修改假设，至少写明：

- 唯一责任 Skill；
- 现有文本中的确切遗漏；
- 拟增加或澄清的通用行为；
- 预期补回的开发案例；
- 同表面对照中预期新增的非赢家；
- 明确不改变的候选验证和最终选择标准。

冻结后不得再提出第二个修改假设。

## 第四阶段：一次最小 Skill 修改

达到门槛后：

1. 保存责任 Skill 的原文和 SHA-256，并确认与开始时一致；
2. 用开发案例和同表面对照写出修改前应失败的行为检查，先确认基线确实失败；
3. 只修改一个责任 Skill 中与该漏诊直接相关的最小段落或输出要求；
4. 不增加分数、硬阈值、状态机、专用股票例子或新的资源文件；
5. 用相同开发案例复核发现漏诊是否消失，并检查原有公司事件型、板块型、独立价格型线索没有丢失；
6. 使用与基线相同的数据、模型、配置、输入合同和调用顺序，在未见未来仍关闭时重新运行四个未见形成日；
7. 封存修改版全部线索、候选、最终取舍、运行配置和哈希；
8. 修改版候选必须能追溯到修改所描述的形成日事实，不允许总控自行补候选。

若修改前失败不能稳定复现、修改后开发行为检查不通过、修改需要扩大范围、运行不可比较或出现明显旧能力回归，精确逆转本轮补丁，不尝试第二版，也不打开未见未来。

若开发阶段没有形成并通过唯一修改版本，未见未来保持关闭；不得为了补充报告或寻找新假设而打开。

## 第五阶段：未见未来只打开一次

只有唯一修改版的四个未见形成日输出全部封存后，才一次性打开未见未来。之后不得再修改 Skill、修改假设、案例定义、评价口径或失败对照。

逐日比较基线版和修改版：

- 审计表面内、形成日可知且行动日可执行的收盘达标赢家发现召回；
- 接近目标案例的独立敏感性结果；
- 新增候选中达标、接近、未达标、不可执行和不可评价数量；
- 每只新增候选的形成日事实和解释；
- 候选总量和共同验证工作量是否出现无理由膨胀；
- 原有候选是否丢失；
- 最终 0—5 只是否变化，变化来自哪条新增线索；

1. 开发阶段的同类首次漏诊在未见日期的实际收盘达标股票中再次出现；

4. 原有重要候选类型、候选守恒和最终 0—5 只能力未发生明显退化；
5. 未见结果整体支持修改，而不是只靠一只极端赢家；
6. 接近目标案例不是保留修改的唯一正面证据；
7. 至少 3 个未见日期可评价且未被污染。
