# 推荐说明执行方式改进：执行提示

状态：独立上下文审查结论为“通过（以修订版为准）”；以下补充优先于初稿，按通过版实施。

## 目标与验收

程序按本轮时点准备少量候选的核对事实；五个研究 Skill 负责选择、主要依据、反证、比较、参与与改变条件；启动器安排短上下文写作和新的短上下文审稿。实质问题交回总控，名单、理由和正文一致后才冻结。最终日报与本地 A2 原样使用检查后的正文。以海星、巨石、国际复材进行真实 GLM 诊断试验，不能把人工修订答案或未来行情交给被测模型。

## 范围和约束

- 复用 ResearchQuery、已有派生数据、stock_ai.py 的 ZCode 调用及 nightly_report.py 装配。仅增加必要的定向取数模块与顺序执行辅助代码，不建数据库、评分器、通用工作流引擎或新自动任务。
- 保留五 Skill 研究权；审稿不得自行更换入选理由、名单、条件或把参与改为等待。表达可直接修改；证据、推理、参与意见或条件缺口回到总控研究。
- 不改研究阈值、候选发现范围、Forward CSV/schema、D20、事实仓和历史推荐。现有推荐说明改稿保持原貌，本轮只核对分类及展示用途，不自动重写19篇。
- 本次先处理首次推荐，已有复盘记录/三路合同维持；公司介绍继续在正式身份确定后按原入口生成。已冻结/补交路径不得重新选股。
- 保留现有 GLM/DeepSeek 偏好和仅不可用时接替语义，写作/审稿沿用本次实际执行模型；试验明确使用 GLM-5.3-flash。不恢复自动公网发布，不创建提交/PR。
- 正常写作与审稿各一次；具体问题定向修复，不无限互审。遇到实质未决由总控决定未决/不选，执行失败不能伪造合法空名单。

## 实施工作

1. **定向事实入口**：输入股票代码（本轮候选及必要近邻）、formation/action/as_of；先使用现有时点查询获取行情、行业历史成员/名称层级、派生观察、财务/公告已有事实，输出到现有任务目录。统一日期、单位、比较窗口、有效成员数与覆盖；价格保留必要原始日线、指标定义与窗口日期。输出中区分事实与未验证的AI判断；来源不足明确记录，不从当下快照推断过去，不新增采集系统。该入口可在冻结前研究验证时调用；写作与审稿复用同份核对材料。
2. **研究交接**：现有夜间研究生成 pending trace 和市场说明、完成现有复盘，但不得先调用 record-trace；交接包含完整拟定论证和改变条件。启动器在后续步骤完成后才调用既有 record-trace。已冻结的恢复路径不应用新研究流程。
3. **短上下文写作/审稿**：由现有启动器顺序调用同一ZCode执行器，给每步独立输入与输出路径和阶段日志。写作只带核对材料、原判断、近邻比较、短教学及适用范文；审稿另带待审文章，输出具体原句、问题依据、修改与完整正文；无问题不用强造问题。只影响表达则使用修订稿；实质缺口返回总控定向处理后再核对受影响内容。保持当前有效调用的模型身份，不能让后一步覆盖研究步骤证据。
4. **最终保存与交付**：在正式冻结前保存已核对正文及其对应待冻结研究；核对身份、顺序和与待保存研究的对应，再用既有 record-trace 冻结。断点恢复沿用现有产物检查，只恢复缺失步骤；已冻结绝不重选。nightly_report 原样装配已核对正文，不由研究模型重写最终推荐。公司介绍依赖在此后衔接，出错不撤销正式研究。
5. **职责文档与展示**：删除写作区重复维护的研究判据，引用专业 Skill；补充相同交易窗口非独立证据、指标定义不得扩大等已有原则的执行说明，不新增选股门槛。知识库区分首次表达、历史润色、用户授权研究修订，复用现有指南。A2 用“研究说明”等准确名称承载采用稿，版本说明保留内部，正文只保留必要截止和参照；不自动上传。
6. **验证与真实试验**：针对日期/窗口/行业/单位、同四天的两指标、fade定义、短上下文输入、实质问题返回研究、冻结顺序、正文原样装配、空名单、already_selected/中断恢复及模型证据运行相称测试。三股用各自原截止事实与原稿，排除同篇人工答案及未来范文；真实GLM必须指出具体错误、修改表达并把研究问题返回，不能把“都改等待”当成功。记录实际效果、耗时及限制。若发现问题继续修正相关实现，不能以假模型测试冒充真实运行。

## 完成条件与后续观察

功能及测试通过，三股试验真实完成并如实报告，文档同步，现有历史记录未改。连续3—5晚质量观察属于后续证据，本次不能提前宣称已验证；在现有运行日志记录每阶段模型、问题与耗时供检查，不增自动任务。不因时限或成本停止必要实施；真实外部不可用则完成可做部分并明确剩余障碍。

## 独立审查确定的实施补充（优先）

1. managed 新研究与手动/既有冻结恢复明确分开。managed 研究只交完整 pending trace、市场说明和正式复盘，不执行 record、公司介绍或展示；外层负责后续。研究返回需有可验证完成产物，异常不等于空名单。
2. 编辑使用新会话、隔离 cwd、关闭不需要的读取/命令/网络能力，只注入事实、原判断、比较、教学和时间适用范文。实际 session/input/tool 记录证明效果，不能仅凭新 cwd 宣称隔离。
3. facts 先读取完整 universe 计算的原 cutoff 派生再裁剪，不能对少量股票重算行业百分位或分母；财务用现有可比查询，历史缺口不放宽 available_at。
4. 实质问题交回总控（必要交接的定向研究即可），同步 pending 与条件；只有存在具体新事实/问题才继续定向修复。编辑不得替总控改推荐或去留。
5. 每阶段及时保存 provider、配置型号、session、实际模型证据、起止时间、输入输出与错误。EvidenceBox 每次清理，后续调用不覆盖研究身份；只有原有供应商不可用原因才切换，研究问题不得靠换模型掩盖。
6. 冻结前原子保存采用正文、身份与准确对应的完整待冻结 trace；直接内容比较，无额外哈希。冻结前核对复盘归档、原合同和待处理问题；冻结后核对 CSV/trace/保留内容。
7. 恢复覆盖研究后缺写作、缺审稿、审稿后未冻结、CSV已写而trace未移动、trace已冻缺交付。CSV孤立时只有与冻结前保留内容逐字段相符才恢复原trace；冲突或缺对应内容报错不猜、不重选。空名单与conditional沿用总控真实解释。
8. nightly_report 明确采用正文来源，保留第一总标题前的截止和补跑说明。公司介绍在冻结与第一次展示尝试后接续，只处理缺项，失败不撤销推荐；必要时沿原合同第二次同步。
9. 测试特别覆盖CSV/trace中断、对应内容冲突、前文保留、阶段模型证据不被洗掉。三股试验不传人工答案/答案性问题清单/未来范文；正常写审和需要的研究返回都是真实GLM调用，仅隔离产物，禁止正式prepare/record/发布。模型漏判必须如实保留。
10. 不新增自动观察任务；后续3—5晚只依靠已有任务产生阶段日志，本次报告真实已验证的范围。
