# 节点详评标题提炼优化方案

## 最小执行提示

目标：后续每篇关键节点详评在开头提供 AI 根据该篇完整分析提炼的“股票名｜核心结论”标题，读者只读标题即可知道截至节点的主要阶段结果和当前判断；保存后的标题在 monitor/Prism 中完整显示一次。

范围：只改节点标题的写作要求、示例、自查、已有正文首段提取和显示，以及必要验证。沿用当前工作区已实现的普通详评和简评标题支持，保留其他未提交改动。不改研究方法、节点六项、三路分组、判断枚举、数据计算、正式记录模型、时点和 D20 冻结；不增加字段、任务、模型调用、标题生成程序、评分器或审批系统。不补写或重存历史报告，不刷新正式历史网页，不提交或推送。

## 实施内容

1. `.agents/skills/reviewing-stock-recommendations/SKILL.md`
   - 将首个独立单行段落标题要求覆盖到 `checkpoint_detail`，包含 D1/D3/D5/D10/D20 和待补 D20。沿用现有 `ForwardEpisodeReviewV1.current_review`，纯文本标题后空行接正文，不把 Markdown `###` 写入源标题，不新建标题字段。
   - 节点标题由本篇完整阶段分析提炼：说清原期待截至节点兑现或受损的主要结果，以及当前核心判断；仅在影响理解时带出关键障碍或未知。允许自然取舍，不规定固定三段、字数或每篇必带20%目标，不把六项清单压进标题。
   - 普通详评聚焦当天告知原因，节点聚焦截至节点的阶段结论。不能只写交易日、维持/增强/减弱标签，不能取“当初期待什么”等正文栏目充当标题。标题不得增加正文没有的事实、因果、承诺或更强判断；D1不预写持续性，D20概括已完成的最终结论而非延长目标。
   - 多次推荐使用本 episode 的阶段事实与判断提炼，不能把另一条记录的节点或结论混入；D20标题可概括同篇已有最终结案，不重复完整结案正文。
   - 扩展已有逐篇写后检查：只读节点标题能否理解阶段核心结论，再与该篇正文及现有结构化判断核对；没有实质改变判断时如实写维持并交代维持的具体内容。保留既有六项完整性自查，不另加首篇流程或审查者。
2. `ops/forward-monitor-prompt.md`
   - 删除“节点详评沿用原格式”的排除，同步首段格式及按复盘 Skill 逐篇提炼/自查的执行要求，网页只提取原文标题。
   - 在现有节点范文区域增加一个精简的标题提炼示例：收录本轮用户认可的“银龙股份｜相对强势延续十日，仍维持上涨后缩量整理判断，冲击20%尚需量能回升与前高突破”。注明它对应用户本轮提供的 D10 原文（该文含8.03元前高观察），并用一句话解释标题概括了相对强势、整理判断和目标障碍。
   - 旧节点范文正文不改写、不新增行情事实；明确新稿按其自身完整分析拟题，不把示例标题套给旧范文或其他日期。无需另建范文文件或扩展全部节点样本。
3. `ops/forward-selection-prompt.md`
   - 将既有合并/网页刷新后的标题与正文一致性检查从普通详评扩展至节点详评，仍只读取正式记录，不另拟标题，不扩展自动任务。
4. `tools/render_monitor_web.py`、`tools/guanlan-prism/src/app.js`
   - 仅将现有明确标题的提取/去重复适用范围补上节点详评，复用已有“本股票名称前缀、独立首段、后有正文”的识别方式；保留完整源 `copy`、`summary_copy`，只在展示时去掉重复标题。
   - 无明确标题的历史记录沿用当前行为；不同 episode/as_of 不合并，无数据不能由网页生成标题。既有简评、普通详评和页面布局不改。
