# 推荐说明、定向补证与知识库接入优化

日期：2026-09-13。用户授权：回答四项疑问；以最新认可的巨石全文替换推荐说明范文、删除其他公司同类范文并增加说明；制定方案，经一个独立子智能体审核后实施、检查并汇报。沿用本任务此前检查后提交 GitHub 的授权。

## 目标与现状

让正式选股先形成能由证据解释的完整判断，再写用户能读懂的正文；任何模型通过实际运行入口读取同一套知识库教学；已验收正文能到达 A2 主用 WEB。

只读诊断已确认：本地有巨石半年报元数据和原文链接，但没有此次引用的 8 月 27 日投资者问答记录，不维护公告全文库；原推荐使用了利润数字但未回答供需延续。本地日线与技术指标已经存在，45—47 元反复和指标含义未被充分综合。不能据此证明 GLM 当晚具体漏读了哪个文件。现有 Prompt 已要求完整论证；当前补证一轮/禁止替代来源限制可能使关键疑问过早停止。最终回复经 stock_ai.py 保存和检查，但成功路径未写入 WEB 所读 daily-research 文件。

## 最小实施范围与原因

1. **定向补证**：修改公司研究 Skill 的共同验证段，以及总控 Skill 的补证总约束。仅在本次正式选股、名单落盘之前，对已有少量候选的决定性疑问补证；先核对本地，区分无记录、覆盖不足、查询失败、尚未读取/解释。允许按文档身份寻找其他官方入口，必要时核验原始文件的可靠转载；一般报道只作线索，关键公司事实回到可核验原始材料。只使用截止前公开的那个版本，注明发布/可用时间与本次获取时间，后者不冒充前者；只有日期的截止日材料无法确定早于截止时保持未知。使用既有 trace 的证据/formation_values 留出处、事实与边界，不新增 schema、不写事实仓、不建设采集/全文系统。取消研究补证的固定一轮和事实条数上限；既有每股 1—2 条价格 decision 的保存格式保留，多项原值/出处合并承载，不将记录数量当作研究数量；围绕问题收敛，证据足够、没有可靠新线索或时间无法验证即停止。保留核心数据可靠性和未覆盖新公告候选的现行限制，不用外部材料伪造 runtime_capabilities。

2. **先判断后写作**：总控在最终取舍、record-trace 之前，基于已有 thesis/primary_reason 把市场环境、行业持续性、公司实际受益、价格量能及剩余路径合成完整判断，解释为什么现在、为什么本股、最强反证如何改变去留。四视角各司其职，不强制都利好，不把技术指标当独立投票，不把利润增长、低涨幅或 ATR 距离换算成 20 日 20% 成功概率，也不强制突破确认或一律等待。此时能修正取舍；冻结后只忠实表达、发现冲突报告而不暗改历史。Prompt 将首次推荐教学与范文实读移到拟定名单已有、但尚未保存的写作检查阶段，同任务复用；AI 对照实际成稿检查事实、因果、比较、目标代价、反证和条件与结构化判断一致。无需新增 AI 进程、质量分数、通过标志或另一份研究产物。

3. **知识库**：在用户既有 Obsidian 股票子库内，把本次认可的巨石文章全文保存为唯一已采用推荐说明范文，注明它是按原截止补充研究的教学案例，其等待结论不同于原正式推荐，不回写原记录。附每段/论证单元的用途、通用方法与不可照搬内容；明确事件型/行业型/价格型均可学表达，不复制事实、价位、因果和等待结论。替换旧巨石候选稿，删除其他公司的推荐说明范文（当前为裕同），同步指南、共同要点相关段落与实际读取入口，修复指向已删文件的链接；其他复盘/公司介绍范文和正式记录保留。用户本次明确删除优先于旧知识库默认 superseded 不删除约定，记录本次替代关系，不索要重复确认。个人全文和路径不进入 GitHub；仓库只存通用方法和读取规则。不能承诺任何模型无条件读取本机库，入口应要求实际打开全文，失败明确降级。

4. **正文到 WEB 的确定性衔接**：沿用既有 daily-research-<formation>.md 路径，在严格归档、CSV 和完整合并报告校验全部通过之后、权威同步之前，原样原子写入已验收的完整报告。同内容重复执行无变化；已有不同正文则报冲突，不覆盖。覆盖新完成及既有恢复/复核路径，不把失败 final-reply 文件或非空文件当成已验收正文；不放松已有检查。WEB 只从新推荐分区按股票身份提取完整正文，避免同股复盘段落干扰，同时兼容既有独立旧日报；缺少正文时明确显示尚缺完整正文，历史摘要单独标识，不充当已验收全文。已有人为采用的显示替换保持原身份和标识，新巨石教学文章不自动替换旧正式推荐。必要的加粗/段落呈现沿用现有安全渲染方式，不引入渲染库。旧 prism.html 继续冻结。

## 范围与不影响其他能力

研究补证和写前取舍变更仅用于正式选股/形成日研究；单股买入决策、季度产业研究、次晨提醒、公司介绍及正式日常复盘的方法与数据合同维持原状。若共享公司 Skill 被复盘调用，本次补证放宽须显式限定正式选股上下文的 `phase: validation`，不新增 phase 枚举。Prompt 的首次推荐入口与复盘入口分开。完成检查的正文归档复用原校验，不更改复盘正文、D20 或账本合同。

不重跑当晚 GLM、不改其失败状态、不修写或覆盖历史原推荐/复盘。已有失败合并报告仍须先修复原问题并通过现行验收；本次用隔离测试证明成功与失败路径，不用真实研究试跑代替开发测试。主用 WEB 可按原冻结参数重渲染显示改动，不能声称历史完整正文已补好。

独立上下文审查者返回“通过（以修订版为准）”。已采纳：正式选股的既有 validation 阶段限定；范文全文实读前核对事实截止、历史原方法版本不变；verify_completed_run 保持纯校验且 completed 复核也接入正文；写入失败/冲突归展示衔接待处理、保留模型身份异常；合并结构缺失/重复推荐分区不得降级为旧日报全文件搜索。其余范围和验收如下，不再启动其他审查者。

## 验收

- 独立方案审查后才实施上述规则/程序/知识库变更；审查者只审查，不实施或委派。
- 检查受影响 Skill/Prompt/架构引用无相反的一轮限制、无新场景强制等待规则；运行 Skill 格式校验，人工用行业/事件/纯价格及证据不足场景检查推理边界。
- Obsidian 唯一采用范文、approved 与独立研究身份正确、全文及批注存在、指南可从实际 Prompt 逐层读到，无已删除范文的失效引用；其他类型范文不受影响。
- 程序用临时目录测试：验收失败不生成 WEB 正文；成功精确保存、重复无变化、不同内容冲突保留；正常完成/恢复路径均有覆盖；同股复盘与推荐分区、正文缺失标识、已有采用改写身份；相关现有 stock_ai / renderer 测试通过。
- 核对差异，GitHub 仅提交程序、通用规则、方案与测试，不含个人知识库、正式产物、绝对路径或凭据。报告实测结果及不能由测试证明的 AI 写作质量/未来收益，不宣称已训练模型。
