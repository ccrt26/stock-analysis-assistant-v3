# 公司介绍质量与主动补证：本次解决方案

状态：一次独立审查通过（以修订版为准），已按通过版实施并完成本轮针对性验证。

## 最小执行提示

目标：让现有公司介绍 Skill 能独立写出可读、具体、有依据的公司介绍，并在关键资料受本地覆盖、接口或链接限制时主动寻找其他可靠官方取得方式。沿用个人助手、每次正式推荐通常只生成一次的定位。AI 选择问题并写解释，程序提供事实和确定性计算。

验收：读者能讲明公司卖什么、客户为何需要、规模与盈利来源及重要业务联系；没有无法支撑的推断、正文与限制自相矛盾、内部取数术语充当正文。单一下载失败不等于资料不存在；补读后的来源、版本及原截止能核对。已有文章与原公司研究 Skill 不改写，正式推荐、复盘、任务和 Web 同步合同不变。

范围：修改现有介绍 SKILL.md、公司介绍运行 Prompt、当前架构中对应的一小段说明；为已知的事实仓打开/读取失败补一个局部行为和相称测试。可以增加一份短写作对照参考，供初稿和自检使用，不建案例库或评分类系统。本文保留审查和完成记录。

不做：新服务、任务、长期爬虫、通用下载器、证据平台、审批系统、评分器、改选股 Skill、重写已归档文章、更新生产页面或扩大正式数据合同。

## 1. 两篇稿件中应该沉淀的能力

- 银龙稿的优点是把技术产品翻译成用途，说明谁使用、谁付钱；把收入规模与毛利来源分开；用具体项目说明主题联系及商业阶段；同行只比较真实重叠环节。继承解释方法，不继承公司专属段落或栏目数量。
- 船舶稿的优点是追到官方调整后同期，区分合同、交付、利润确认，量化仲裁事项的特定影响。应保留这些准确性，同时补足主要船型/用途、客户与经营环节、控制关系和真实差异等有助认识公司的内容，按资料和重要性选择。
- 两篇均需修正的方法问题：扣非接近归母仅说明非经常性损益的净影响较小，不证明增长来自主营、可持续或现金质量；不得正文引用结算说法而文末承认未取得原文；收入份额或毛利份额不能单独证明动态变化的主因。
- 首段优先核心生意，必要控制关系次之；更名、家族成员名单等不挤占核心介绍。内部字段、异常计算、失败链接进入工作记录；正文只保留影响理解的真实口径和未知。表格每列有清楚表头，正文解读最重要的差异，不逐行重复数字。
- 内容厚度由读者问题与证据决定，不强制“五问达标”、字数或同行数量；也不能把可补证的核心问题当成可省略项。

## 2. 主动取得资料的规则

先判断缺口是否会改变读者对生意、盈利来源、可比口径或重要事件的认识。对核心缺口主动补证，已获本任务授权，无需逐次向用户请求搜索许可。普通身份附属信息可以省略；核心业务仍不明才不能称文章完成。

本地备料是起点，列数/最近公告条数/接口功能不限定研究问题。先读最新可用定期报告对应章节，缺正文就去 WEB。已有链接 404 后改用同一官方文档的静态入口、交易所披露、公司投资者关系页面或官方公开检索/API；浏览工具不能下载时可用现有 HTTP 工具或浏览器；PDF 提取失败可换提取器或必要页 OCR。只读公开资料，不绕过权限限制，不购置服务，不建立采集系统。

不规定“只聚焦补读一次”，也不要求机械尝试固定数量渠道。有新定位线索且重要问题未解决就继续换方法；同一失效请求重复执行没有价值。原文和时间核实后停止该项；合理官方路径已查仍无结果，或访问确需额外权限时，准确留下具体缺口。检索与失败原因放临时工作记录，不塞进读者正文。

核对代码、公司名称、报告期、标题/公告身份和文档版本；公告备料可能混有其他公司，不能因为同块就引用。不能猜公告编号或编造可用时间。取得时间可以晚于研究截止，作为事实依据的版本必须在原截止已公开；首次公开时间只有日期且跨越截止不确定时不能假定零点。无法证明历史版本则该事实不用。

官方原文可补充本地没有的数值、调整后同期和解释，也可纠正错误自动计算；以 official_document 来源记录，不伪装成 warehouse 行，不改原 facts-file。金额、占比、毛利率由临时 Python/既有计算核对，保留关键原值和公式；不增加永久事实仓。

## 3. 运行层的必要小修复

当前分区查询可返回 gaps，但事实仓构造器失败会让整个 prepare 抛错；Prompt 还规定备料命令失败就全部缺项。这会在正式身份已经可核对时提前放弃 WEB 补证。

保留正式 trace 完成、身份、时间校验在前。只对已知本地读盘/数据库访问错误（OSError、FactRecoveryError、明确的 DuckDB IOException/ConnectionException/PermissionException）处理：返回真实 formal context/scope，受影响股票 blocks 为空并记录 warehouse_unavailable 或 query_failed。不伪造本地数据，不自动维护或恢复事实仓。必要时将相同已知读取错误按股票隔离；其他意外程序错误仍明确报错。复用原 facts-file 形状和现有 official_document 保存能力，不增加 CLI 模式、schema、校验豁免或后台重试。

Prompt 按问题区分错误：有有效身份和 scope、但本地事实缺失，可从官方原文形成足够事实并按原 record 保存；缺原 trace、身份矛盾或研究未完成，不能靠 WEB 建造正式身份。若命令本身异常，先检查调用参数和已有环境、完成可恢复修正；不手造 formal facts-file。仍失败才报告具体失败，保留已完成研究与原 Web 收尾。
