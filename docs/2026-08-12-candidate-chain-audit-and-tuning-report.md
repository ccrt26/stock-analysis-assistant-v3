# 候选链追溯审计与 Skill 调优报告

## 一句话结论

本轮应当**保留修改**。

修改只做了一件事：要求总控把四个专业 Skill 提出的每条线索、去重后的每只候选和最终去向保留下来。它解决的是“为什么这只股票没入选，当时到底有没有审过”，不是放宽选股标准。

两个未见日期中，新旧版入选结果完全一致；新版没有多造一只候选，但把所有线索和淘汰原因都补齐了。

## 这次到底优化了什么

原版总控要求最终输出“入选股票”和“代表性未入选”，但没有强制输出：

- 四个 Skill 实际提交了哪些原始线索；
- 方向、板块和问题线索最后转成了哪些股票；
- 同一只股票同时来自哪些 Skill；
- 每只候选的市场、板块、公司、价格四视角支持、反证和未知；
- 每只候选是入选、淘汰还是未决，最主要的原因是什么。

所以旧版常出现这种情况：专业 Skill 实际提过一只股票，总控也可能看过，但它既没入选，又没被选成“代表性未入选”，最终答卷里就完全看不见它。事后只能猜它是“没发现”、“交接丢了”还是“审过但判断错了”。

新版总控补了一份轻量 `candidate_chain`：

1. `skill_leads`：保留四个 Skill 实际输出的线索；
2. `non_stock_lead_fates`：方向、板块、问题线索都有去向；
3. `candidate_ledger`：每只去重候选保留所有来源、四视角审查和最终原因；
4. `candidate_conservation`：核对候选数是否等于入选、淘汰和未决之和，以及是否有线索无声消失。

这不是新评分器、新 Gate 或新候选池，也不会因为记录完整就给股票加分。

## 把几类问题分开

本轮得到的最重要分层是：

| 问题 | 含义 | 本轮结果 |
|---|---|---|
| 记录缺失 | 实际提过或审过，但最终答卷看不见 | 已修复，新合同应保留 |
| 交接丢失 | Skill 提了股票，去重后却没进候选 | 5 个日期均为 0 |
| 发现漏掉 | 形成日已有足以进候选的公司或价格信号，却未提交 | 存在，是下一轮主问题 |
| 判断错误 | 已审查且证据较完整，但取舍失衡 | 001309.SZ 是较清楚案例，样本仍少 |
| 合理未入选 | 后来涨了，但当时因果、可持续性或剩余路径证据不足 | 在达标的淘汰候选中很常见 |

这也就是“有些值得看的股票没有留下完整审查记录”的准确含义：它首先是一个可追溯性问题，不能直接推导出“后来涨的当时都该买”。只有把记录补齐，事后才能知道应该改发现、交接还是最终判断。

## 最终决定

**保留修改。**

理由是：

1. 同一结构问题在三个开发日期重复出现；
2. 原版总控确实没有要求候选链完整输出；
3. 修改只补输出合同，没有改研究逻辑；
4. 两个未见日期的入选结果不变；
5. 两个未见日期中，线索追溯、去重来源、四视角审查、最终去向和守恒检查全部通过；
6. 没有出现无来源的候选扩张。

## 下一轮应该做什么

下一轮建议只针对**发现召回率**，不再动候选记账合同，也不放宽最终买入条件。具体要验证两个问题：

1. **公司发现是否过度依赖“当期新鲜业绩预告”**：603629.SH 和 301520.SZ 显示，仍有传导力的旧事件、并购进展或非预告公告可能没有被提交；
2. **价格发现是否只看了最极端尾部**：001259.SZ、300540.SZ、603221.SH、000779.SZ 显示，“中等短窗口超额 + 成交放大 + 价格位置不同”的股票应先作为原因问题进候选，然后再由公司和板块视角淘汰。

这里的优化目标仍然只是“该审的股票不要没进审查”，不是“价格有异动就入选”。

## 局限与证据状态

- 本线程之前已读过邻近历史日期，因此本轮不能被称为完全独立的盲测。
- 历史 `security_master` 在 2026-07-13 前无可用版本，所以报告使用股票代码，不用当前名称倒填形成日身份。这使部分公司真实业务联系无法确认。
- 结构化业绩快报中 `yoy_net_profit` 与净利润绝对金额存在语义冲突，本轮没有把该字段当作同比增长判断使用。
- 形成日账没有为每只入选股写出可机械复现的精确行动日条件，所以事后评价中该项统一为 `unknown`。
- 只有 5 个日期、10 只入选股，不足以宣称收益规律已经泛化。
- 入选与错误归因包含专业判断，不是程序评分器的回测。
- 未见日期只验证了结构合同是否稳定，不证明本轮形成日入选策略有超额收益。
