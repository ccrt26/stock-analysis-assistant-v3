# 股票知识库与 Skill 优化复盘 V1

本文是 Obsidian 股票知识子库、优化数据导出与批量复盘三者分工的正式说明。它不改变五个选股 Skill、V4 合同、Forward 口径或任何正式研究产物；冲突时以 `AGENTS.md` 与现有正式合同为准。

## 1. 分层与流转

```text
本地正式记录与事实仓：当时的事实、原判断、之后的路径，保留原貌
              ↓ 只读提取
优化数据包（local_archive/skill_optimization/ 与 research/skill-optimization/）：
              程序统一计算、按批次比较、可复现核对
              ↓ 解释、讨论、确认
Obsidian 股票知识子库：个股经历、写作范例、批量认识、优化决定
              ├→ 已认可范文与适用边界 → 日常推荐/复盘表达（只读学习写法）
              └→ 用户明确批准的方法修改 → 以后版本的 Skill / 运行合同
绝不把范文结论当作本次事实，绝不回改旧推荐和旧结案
```

两条铁律：

1. **事实记录不从知识库回写。**知识库只引用正式记录，永远不是第二套数据源。
2. **方法改进须经明确批准进入未来版本。**知识库笔记是提议与记录，不是对 Skill 的修改；这不与第一条矛盾。

## 2. 三类消费方，三个存放位置

| 数据 | 消费方 | 位置 |
|---|---|---|
| 逐日路径、固定 20 日指标、相对市场收益、归因结构化字段 | 程序与批量分析 | 仓库：正式归档 + 优化数据包 |
| 当时的事实与原判断（理由、反证、thesis、决策证据） | 复盘与导出 | 仓库：冻结 trace、Forward CSV、账本 |
| 个股经历、范文与教训、批量认识、优化决定 | 用户与 AI 写作 | Obsidian 知识子库 |

判定口诀：**拿来算的进仓库，拿来读的进知识库**；既算又读的，仓库存本体，知识库存引用和结论。

## 3. 计算口径（导出器 v3）

- 交易日编号来自 `local_warehouse/facts/trade_calendar` 的实际开市日，第 1 日就是原行动日；整日行情缺失不前移编号。
- 当前观察最多 30 个交易日；`fixed_d20_*` 只取原第 1—20 个交易日，`outcome_*` 表示截至观察终点，两者不互相冒充。
- 收盘触达 20% 的容差与正式 Forward 一致（`0.20 - 1e-12`），不使用盘中最高价。
- 沪深300对照是 `action_open_to_same_close` 的描述性比较，不是等权收益，也不是风险调整后的证明。
- `context_origin` 区分 `frozen_used`（有原输入引用证明）与 `retrospective_reconstruction`（按旧日期从现有数据重算），后者不能冒充当时选股输入。
- 条件事件只认人工提供且观测不晚于导出截止的判定；无输入、无匹配或过晚都记 `unknown` 并注明原因，`formal_return_started` 恒为 false。
- 每次导出记录三个时点：`selection_as_of`（当时研究截止）、`outcome_through_date`（行情终点）、`exported_at`（读取归档时间），不可互换。
- 导出包是一次分析的副本：新批次或新截止另存新目录，不覆盖旧包；旧 v1/v2 包继续可读，不迁移。

## 4. 知识子库结构与状态

结构见子库 `AGENTS.md`；要点：

- `10_方法与范文/`：范文、改稿对照、经验教训。方法合同（文风基准、Skill）只在仓库；知识库存实例与教训，按当天类型、节点和实际问题读 `approved` 范例，同次已读材料复用。首次推荐至多一篇适用稿；复盘没有跨类型合计两篇上限，不为凑范文而跨类型套用。
- `20_个股档案/<名称代码>/`：一股一夹，一条推荐一篇记录；原判断区只摘录当时内容，事后认识单列。同股多次推荐是多条记录。
- `30_批量复盘/`、`31_优化史.md`：批量对照的认识与每次方法修改的记录（依据、改动、验证、效果）。
- `90_专题/`：板块、反例等横向页面。
- `99_模板/`：四类笔记的固定模板。

笔记状态四种：`source_excerpt`（资料摘录，可直接落盘）、`draft`（AI 起草待确认）、`approved`（用户已确认）、`superseded`（已被替代，不删除）。原 `as_of` 与笔记 `updated` 不互相覆盖。

## 5. 批量复盘方法（要点）

- 按原行动日期固定连续批次，正式结果统计只用正式记录；legacy、conditional、rejected、unresolved 分列，不混入正式胜率。
- 同股重复推荐是多条 episode，不是独立样本；不做伪造精度的置信区间。
- 五个环节各查自己的问题，归因使用现有结构化字段（`weak_or_failed_link`、`decision_review`、`best_supported_explanation`），是分析意见，不是价格事实。
- 每个值得改的问题必须同时给出：原判断及原值、程序结果、支持例、反例、其他解释、仍缺证据；样本不足可以只提出问题。
- 修改与验证分开：一批最多一项优先修改假设；下一批尚未用于设计该修改的记录用于观察是否成立；一次改善只是支持，不是证明。

## 6. 与正式流程的接入

- 首次推荐说明已有定向入口：`ops/forward-selection-prompt.md` 读取 `selection-writing-calibration.md`，再按知识库推荐说明指南选一篇适用采用稿；合法空名单跳过，无适用稿按仓库教学写。
- 每晚复盘写作前必须实际打开子库 `00_已确认写作要点.md`、当天出现类型的 `00_阅读指南.md` 与按类型/节点阶段选出的 `approved` 范文全文（见 ops Prompt 的分类入口段；无跨类型两篇上限）；公司介绍入口保持原行为。合同与文风基准始终优先，读取失败按现行规则降级一次并如实说明，不阻断正式研究。
- 三类复盘的共同目的自 current-opportunity-v1 起是当前机会判断（未来5—10日方向、参与意见、改变条件），原推荐固定20日结案独立保留；详见 `docs/architecture/current-opportunity-review-v1.md`。
- `ops/stock-knowledge-prompt.md` 是知识子库的唯一整理入口，仅人工触发。用户认可的新写法优先合并到对应范文/指南；只有真正改变研究方法、证据或运行合同时才改 Skill/Prompt。这里的“学习”是执行时读取范文，不是训练模型或自动改规则。
- 新研究自 `research-run-context-<action_date>.json` 起记录方法版本辅助信息；历史运行不补造，导出时按 `version_status=unknown` 处理。
