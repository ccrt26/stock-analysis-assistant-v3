# 选出股票后的跟踪与走势复盘 V1

正式复盘与新推荐共用前晚18:45任务、18:30固定截止；明天非交易日时不生成报告。周日分析周五收盘，为周一提供报告；长假在下个交易日前一自然日晚间运行。所有交易日路径与D1—D20、D21—D30评价口径不变。18:00和21:30仅在今天或明天交易时补事实；21:30不覆盖18:32形成的正式健康JSON和Markdown，晚完成的record-trace仍沿用18:30冻结能力。增减持、解禁、回购按公开日期补到研究自然日，仍遵守原available_at、不提前日期型事实。08:45只做昨晚名单安全提醒，若交易日09:30及之后才启动，只报错过检查时点，不请求公告、停牌或声称无变化；均不改写正式报告。20:30是交付目标，不新增守护服务。分钟仍可选，融资融券仅补形成日前已达T+1可用时点的历史缺口。

## 设计目的

每天的 V4 结果保存后，程序继续记录真实价格路径。当天所有需更新判断的正式推荐 episode 都由 AI 形成结构化判断；四个专业 Skill 提供事实，复盘 Skill 回到当初判断并解释后续变化，总控检查一致性。该能力是个人助手的一部分，不是股票池平台、持仓系统或实时交易系统。

当天需更新判断的正式推荐按三路互斥生成：节点股（D1/D3/D5/D10/D20及待补D20）全部节点详评，共用同一份六项必备对账清单（每项按“事实—含义—边界”小单元覆盖，缺项明示），节点只决定侧重，不生成简评、不占名额；剔除节点后按优先级最多8只普通详评（0只允许），完整覆盖入选原因、原推荐理由变化、目标余程与下一观察点四项信息；剩余只写简评。账本 `DailyFormalReviewV1` 保存全部结构化判断及仅简评类正文（`review_kind` 标注三路，简评600字符上限）；两类详评正文只存 `monitor-report`。record 校验互斥、覆盖、普通详评上限与结构化一致性。Markdown 分三区（关键节点复盘／今日深入复盘／今日简评）；网页长正文读详评、标题/摘要按类型取唯一正文，账本空正文不覆盖报告。snapshot episode 另含带固定口径的 `review_context`（沪深300基准、行动日开盘入口、分析日复权归一、61日窗口内的逐日路径、近5日量价、基准窗口、入口/当前/前高/ATR20/目标价与剩余距离），供复盘直接引用。

## 三个时间阶段

| 阶段 | 交易日 | 处理方式 |
|---|---:|---|
| 主要评价期 | 推荐后的第1—20个交易日 | 每天记录全部路径；第1、3、5、10、20个交易日做完整复盘，第20个交易日按现有 Forward 口径固定评价原目标 |
| 后续观察期 | 推荐后的第21—30个交易日 | 低成本记录；普通日期不详细展示，只有新事件、突破、相对表现或价格情形变化等才提醒 |
| 已结束 | D30 之后 | 旧记录关闭；新变化必须通过新的每日 V4 结果建立新记录 |

后续观察期的上涨不能修改 D20 结果，也不能把旧记录延长到 D30 以后。

## 三层内容

1. 全量记录：程序保存各选择记录的确定性路径；正式推荐按 episode 保存结构化判断与上轮观点，比较记录只保留内部评价。
2. 正文分配：先形成全部结构化判断草稿，再确定节点K、非节点普通详评D和其余简评B；三类各写唯一正文，核对后先保存账本、后保存报告。
3. 用户报告：节点股全部详评，普通详评0—8只，其余简评；同股合并显示，各episode分别对账，不展示非正式对象和内部比较数量。

## 专业事实、复盘综合与总控检查

- 市场 Skill 每天只分析一次，同时服务已有股票复盘和当天新选股；它提供市场共同变化的参照。
- 板块 Skill 只看需复盘正式股票真实涉及的板块，并区分行业共同变化和个股自身变化。
- 公司 Skill 只看新公告、事件型股票、固定复盘日或可能推翻原判断的事实，事实判断和价格表现分开写。
- 价格 Skill 解释需复盘正式记录的价格变化，包括当前价格、从阶段高点回撤、相对表现和原行动条件是否可用。
- `reviewing-stock-recommendations` 回到原推荐理由、实际引用的决定和上轮判断，对每条正式记录做跨时间综合，按三路分配正文。
- 总控 Skill 检查记录、推荐日期、证据和结构化结论一致性，不重复维护复盘方法，也不重新推荐股票。

四个专业 Skill 的 review 阶段与复盘 Skill 只处理已正式推荐的记录，不扩展候选范围，不改变历史推荐。原理由、风险、决定和成对比较保留内部追溯；用户正文只使用可核对事实，不能加入后来信息改写当初理由。成对比较仅在身份、研究日期、观察窗口及双方价格路径均可靠时用于内部评价，不公开替代股名称或表现。

## 数据路径

`prepare` 只读取 V4 正式记录、手工注册的 V4 replay、本地交易日、日线、复权因子、市场/板块/价格派生数据、公告元数据、当时选股日有效的申万 2021 二级行业成员、上一份跟踪快照，以及分析日前已经保存的日评账本和最终日报；上轮详评正文从其对应的报告恢复到本 episode 历史上下文。待保存日报不参与上次状态判断。所有事实必须满足 `available_at <= as_of`，行情不得晚于分析日。

同一次 `prepare` 只读取实际需要的日期分区；每个日期的日线和复权因子各读取一次后在内存中供全部跟踪记录复用，不做全库扫描，也不建立持久缓存。

## 价格与提醒口径

- 买入参考价只取原定行动日的复权开盘价；当天缺失时保持未知，不得借用后一天开盘价。后续完整行情仍可用于判断首次可观察日期和当前变化。
- snapshot 同时保存固定前20个交易日的 `d20_*` 和截至当前、最多 D30 的 `current_*`。D20 收盘达到 20% 的判断使用与正式 Forward 相同的浮点容差。到 D20 及以后，只有前20个计划交易日的价格完整且日期逐一相同时才固定计算 `d20_*`；路径不完整时结果保持未知，不能记成未达到。D21—D30 的路径不能改写任何 `d20_*`，首次达到 20% 的原目标提醒也只看 `d20_*`。
- snapshot 保留原推荐理由和完整 `research_thesis`，包括短期推动因素、信息新鲜度、价格确认、剩余路径、经营依据、公司风险、最强反证、关键未知、原行动条件和最近替代股。旧记录缺少完整研究结论时保持缺失并在日报中说明，程序不猜测、不倒填。
- 当前路径和固定前20个交易日路径都记录三种不同数字：相对最初参考价的期间最深跌幅、历史最高收盘到其后某个收盘的最大回撤，以及当前收盘相对期间最高收盘的回落，三者不能混用。
- snapshot 带入已有的1、3、5、20个交易日相对市场和相对行业数字；日报按当前所处交易日选择最近1、3、5或20个交易日窗口，缺失时明确未知，不把固定窗口说成“从推荐以来”。
- 同一次 snapshot 的全部记录生成后，程序才附加紧凑的推荐股与备选股配对数据。只有两边股票身份、研究日期、原计划观察日期、交易日窗口和价格路径全部一致时，才把双方涨跌、期间最深跌幅和最大收盘回撤交给内部评价，不公开替代股表现。
- 读取上一份旧快照时，仅在新的首次达到日期字段不存在时兼容读取旧字段，不迁移或回写旧字段。
- `breakout_vs_prior60` 只有大于 0 才表示突破；负数和 0 都不是突破。
- 新事件等待首次价格反应的股票，只在行动日起首个完整可观察交易日提醒一次，D 数仍按真实市场交易日计算。
- 数据问题只在问题首次出现、内容发生变化或 D1、D3、D5、D10、D20、D25、D30 固定检查日提醒。
- V2/V3 每条记录按自己的记录编号带入最近一份最终日报中的上一轮复盘；历史 V1 只保留原有股票级上次状态兼容，不伪装成记录级复盘。

本地产物位于 `local_archive/forward_monitor/`，包括注册记录、每日 snapshot、日评账本和最终 JSON/Markdown；该目录不提交 GitHub。`tools/render_monitor_web.py` 与 `tools/render_prism_web.py` 将冻结结果渲染为本地 HTML，后者调用 Prism 的 `render_html()` 并写独立页面；`tools/update_monitor_web.py` 提供已有的本地更新入口，不创作正文、不增加研究任务。

## CLI

```bash
./.venv/bin/python -m stock_analyzer.ops.forward_monitor register --trace-file <V4 trace> --label <唯一标签>
./.venv/bin/python -m stock_analyzer.ops.forward_monitor prepare --analysis-date <已收盘交易日> --as-of <带时区截止时间>
./.venv/bin/python -m stock_analyzer.ops.forward_monitor record-daily-formal-reviews --snapshot-file <snapshot> --review-file <pending daily reviews>
./.venv/bin/python -m stock_analyzer.ops.forward_monitor record --snapshot-file <snapshot> --report-file <pending report>
```

正式 `research-trace-*.json` 由 `prepare` 自动发现；`register` 只用于需要观察的非正式 V4 replay。四个命令不改写 Forward CSV；`prepare` 会写本地快照，不能因名称将它当作只读命令。

## 日报

新生成的待保存日报使用修正后的 `DailyForwardMonitorReportV2`；两类详评使用现有 V2，日评账本保存全部结构化判断及仅简评正文，不增加报告版本。历史 `DailyForwardMonitorReportV1` 仍可读取，不迁移、不改写。V2 中一只股票仍只有一个大标题，但 `episode_reviews` 与当天两类详评中全部正式 episode 一一对应。正式推荐第1—19个交易日没有最终评价，第20个交易日首次形成并冻结前20天最终评价；未成功保存时每天以最高优先级继续提醒并强制进入详细日报。比较记录始终不形成荐股最终评价。第21—30个交易日可以改变当前观察，但必须原样保留正式推荐已经冻结的最终评价。第20天漏跑时，之后首次形成的最终评价仍只能依据前20个交易日的固定路径和当时有效事实。

每日合并报告使用“今天的市场情况”“正式推荐股票的今日复盘”“目前仍开放的正式推荐股票数量”“今天明确推荐的股票”。复盘分为“关键节点复盘”“今日深入复盘”“今日简评”。详评正文读取报告，简评正文读取账本，观点变化和展望读取当天结构化字段；不重新摘要已保存正文。具体呈现以 `ops/forward-selection-prompt.md` 为准。

保存前，程序严格核对 V4 六种市场状态、数量汇总、三路互斥和覆盖、普通详评上限，以及每只详评股票当天全部合格正式记录。`episode_ids` 必须完整；`episode_reviews` 的记录编号必须与它完全一致，所有待结案正式推荐也必须出现，不得缺少、重复或多出。正式报告不混入比较和条件事件；内部保留原角色供追溯。同一股票同时有多条记录时仍只显示一个股票大标题，当天共同的市场、行业、公司和个股变化只显示一次；下面按原计划观察日分别说明每条记录，观察条件最后只显示一次。正式推荐的前20天固定数字和最终结论单独显示，第21—30天当前走势不能改写它；比较对象不显示荐股最终结论。Markdown 只用每条记录专门生成的通俗理由和风险，不直接展示冻结的原始内部表述。可靠配对数字只用于内部核对股票选择，正式报告不展示替代股名称或表现；配对不完整时不作自由比较。

同一天第一次保存返回 `recorded`；相同内容重跑返回 `already_recorded`，不覆盖最终 JSON；如果对应 Markdown 缺失，则从已核对内容原子补回后再删除待保存日报。不同内容返回 `report_conflict`，保留原最终日报和新的待保存日报供人工检查。

## D20 与 D30 边界

提前判断失效后，股票退出普通详细提醒，但程序仍记录到第20个交易日。提前达到目标只标记已经达到，仍记录到第20个交易日，不自动生成新的买入建议。第21—30个交易日的迟到上涨必须注明“不改变推荐后前20个交易日的结果”，并且只能更新当前走势评价，不能覆盖该条记录已经冻结的前20天最终复盘。第30个交易日后旧记录关闭。

## 不做事项

不新增数据源、数据库表、服务、消息推送、Skill、Scheduled Task、评分、权重、概率模型、自动交易、仓位、止盈止损、盘中实时监控、新闻社交采集或公告全文库；不修改 V4 七种内部分类、V4 规则、Forward CSV、D20 口径或11个价格情形。自 current-opportunity-v1 起的唯一兼容性新增：日评账本 `DailyFormalReviewV1` 增加可选 `current_opportunity` 对象（旧文件缺字段可原样读取，不迁移不回写），新 prepare 的 snapshot 带 `current_opportunity_required` 标志；这不授权任何其他新报告模型或 schema。现有本地 Markdown、静态 HTML 与 Prism 只呈现冻结结果，不属于云端发布。
