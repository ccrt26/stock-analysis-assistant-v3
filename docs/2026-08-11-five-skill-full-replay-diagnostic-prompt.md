# 2026-08-11 五 Skill 完整复跑诊断 Prompt

## 任务性质

这是一次只读、形成日时点冻结的全流程复跑与候选漏斗诊断。独立审查通过后，由主智能体在当前工作区连续执行到验证和汇报。除非缺少会实质改变结论的核心数据，或需要用户新增授权，否则不中途请求介入。

## 唯一目标

使用当前工作区尚未提交的五个股票研究 Skill，完整重跑一次 `2026-08-11` 的历史形成日选股流程，记录：

- 市场方向、板块、问题线索如何交给其他 Skill 并转化为具体股票；
- 每条具体股票线索从发现、合并、共同验证、同类比较到最终入选、淘汰或未决的去向；
- 每只未入选候选最先在哪个研究环节被阻断，以及该阻断属于合理淘汰、数据缺口还是 Skill 间语义冲突。

据此确认当前系统是否仍存在已产生的方向或股票线索在某一层无明确理由地丢失。

本轮是整体流程诊断，不以任何已知股票必须进入候选池或最终入选为目标，也不使用后来涨跌反推形成日结论。对“发现覆盖”的判断只依据完整合格股票范围是否实际进入各专业 Skill 的轻量发现，以及已产生方向和问题线索是否完成交接；不得把从未被任何 Skill 发现的股票事后认定为“已丢失候选”。

## 冻结研究边界

```yaml
task_type: historical_simulation
research_objective: "未来约20个交易日形成可操作显著上涨路径，重点观察约20%涨幅"
formation_date: 2026-08-11
action_date: 2026-08-12
as_of: "2026-08-11T23:59:59+08:00"
selection_universe: "上海主板、深圳主板和创业板"
exclusions:
  - "科创板、北交所和场内基金"
  - "ST/*ST、退市整理、停牌、无可靠报价"
  - "依据形成日截止时间前已知事实，行动日明确无法正常参与的股票"
```

所有研究事实必须满足 `available_at <= as_of`。形成日研究阶段不得读取或使用 `2026-08-12` 及之后的价格、公告、交易状态或结果；本轮也不做未来 20 日收益评价。

## 五个 Skill 的使用方式

严格使用当前版本：

1. `orchestrating-stock-research`
2. `interpreting-market-macro`
3. `researching-sectors-industries`
4. `researching-company-events`
5. `analyzing-price-trading`

`orchestrating-stock-research` 贯穿全程，负责冻结边界、组织发现、维护线索交接和候选台账、发起共同验证、比较同类并作最终选择。

发现阶段向市场、板块、公司和价格 Skill 提供相同的形成日、截止时间、目标和合格股票范围。市场 Skill 只提交 `direction`、`group` 或 `question`；板块、公司和价格 Skill 可以独立提交具体 `stock` 线索。

总控建立候选池后，仅对少量候选发起一轮定向共同验证。五个 Skill 的职责、证据边界和原生输出合同保持不变。市场、板块、公司和价格不是四道固定 Gate，也不进行投票、打分或固定阈值排序。

## 执行顺序

### 1. 冻结输入

- 记录五个 Skill 的当前 SHA-256 和复跑开始时的 `git status --short`，保留所有已有修改及未跟踪文件。
- SHA-256 仅作为本次复跑所用 Skill 版本清单，不扩张为状态文件或新系统。
- 核对交易日历、2026-08-11 数据健康摘要、核心行情、形成日有效的股票身份、合格范围和时点边界。
- 记录完整合格股票范围的规模、生成依据和数据来源。
- 写出简短研究简报：市场、板块、公司和价格各自需要回答什么，哪些关键事实缺失会阻断正式选择。

核心行情、交易日、股票身份或时间边界不可靠时，停止正式选择并报告阻碍；次要数据不足时继续，但必须保留未知。

### 2. 全范围轻量发现

- 候选边界必须是形成日当时的完整合格股票范围，不得以新公告名单、旧候选、已有叙事或已知股票替代全范围。
- 板块、公司和价格 Skill 必须分别以同一完整合格股票范围实际执行横截面轻量发现。允许输出零条股票线索，但必须说明实际使用的数据、覆盖范围和为何没有足够线索。
- 使用现有结构化市场、板块、公司事件和价格事实做轻量发现；不得逐股深读全市场公告正文。
- 市场 Skill 只提交搜索方向、板块或问题；板块、公司和价格 Skill 可以分别独立提交具体股票线索。
- 各 Skill 按各自原生输出合同返回线索，不要求公司 Skill 代替板块 Skill 完成行业同类比较，也不要求市场 Skill 直接生成股票。
- 每条股票线索至少保留其原生输出中要求的股票身份、形成日前变化或异常、目标相关性或可能传导、现有支持、最强反证以及待验证问题。某项属于其他 Skill 职责时，将其登记为待验证问题，不得补猜。
- 没有足够内容的线索不为凑数提交。

### 3. 建立方向交接表

总控对市场以及其他 Skill 提交的 `direction`、`group` 和 `question` 线索建立简短交接表：

```yaml
lead_id: ""
lead_type: "direction | group | question"
name: ""
origin_skill: ""
rationale: ""
handoff_to: []
handoff_outcome: "converted_to_stock | no_stock_with_reason | unresolved"
resulting_ts_codes: []
outcome_reason: ""
```

要求：

- 每条非股票线索都必须有交接结果；
- 转化为股票时记录对应代码和负责补出具体成员的 Skill；
- 没有转化时说明是无有效成员、证据不足、数据缺口、职责不匹配还是仍未解决；
- 不得由总控仅凭方向或概念标签直接猜出股票；
- 交接表只用于诊断发现链路，不建设长期状态机或候选系统。

### 4. 建立候选漏斗台账

总控对板块、公司和价格 Skill 已提交的所有具体股票线索去重并纳入候选池。合并同一股票的多来源线索不算消失，但必须保留全部来源及原始命题。

每只股票至少记录：

```yaml
ts_code: ""
name: ""
discovered_by: []
source_leads: []
discovery_reason: ""
entered_candidate_pool: true
entered_joint_validation: false
company_validation: "sufficient | partial | insufficient | not_yet_checked"
sector_validation: "supportive | mixed | adverse | unknown | not_yet_checked"
price_validation: "stock_specific | sector_or_market_following | overextended | mixed | unknown | not_yet_checked"
strongest_counter_evidence: ""
key_unknowns: []
final_fate: "selected | rejected | unresolved"
fate_stage: "pre_validation_comparison | company_transmission | sector_comparison | price_attribution | joint_validation | final_comparison | selected | unresolved"
fate_class: "reasonable_rejection | data_gap | semantic_conflict | selected | unresolved"
fate_reason: ""
```

要求：

- 任何已由板块、公司或价格 Skill 提交的股票，都不能在后续步骤中无说明地消失；
- 未进入共同验证的候选也必须填写 `final_fate`、`fate_stage`、`fate_class` 和具体理由；
- `fate_stage` 记录最先实质阻断该候选继续推进的环节，不以最后写报告的环节代替；
- 多个反证同时存在时，记录主导阻断环节，并在理由中保留其他反证；
- 仍因关键未知无法定夺时使用 `unresolved`，不得伪装成合理淘汰。

### 5. 共同验证与同类比较

- 总控先根据发现结果、因果链和同类关系选择少量候选进入共同验证；未进入者必须在台账中记录预验证比较理由。
- 只对进入共同验证的同一批少量候选做一轮定向补证，不借机重新扫描全市场。
- 公司验证必须区分公司自身新事件与总控提交的外部变化命题。没有当日新公司公告不能单独判为 `insufficient`；但真实业务联系、核心传导或材料性无法确认时仍可判为 `insufficient`。
- 板块验证必须使用形成日有效的成员关系，并比较最接近同类；板块标签、少数龙头或一次普涨不能替代候选自身优势。
- 价格验证必须先拆分大盘共同变化、板块或同类共同变化和个股增量。前期跌幅、20 日负收益或低位置不能单独证明启动或剩余空间。
- 市场验证只判断候选所需市场条件及市场级反证，不直接删除股票。
- 在同一因果链内比较最接近的替代股票，明确为什么保留其中一只、淘汰另一只。
- 不得按证据条数、多 Skill 赞成票、总分、权重或固定阈值排序。

### 6. 最终取舍

- 按总控 Skill 输出 `0—5` 只股票，允许空名单，不以低质量候选补位。
- 同时输出具有代表性的未入选股票及具体原因。
- 最终名单必须说明形成日前的新变化、目标命题、因果链、相对同类优势、已反映程度、剩余路径、最强反证、关键未知以及行动日可观察的参与和放弃条件。
- 最终名单、理由、反证、未知和行动日条件只依据形成日事实；不查看行动日实际表现。

### 7. 诊断方向交接和候选漏斗

汇总：

- 合格股票范围规模；
- 市场提交的方向、板块和问题线索数，以及转化为股票、无有效股票和未决的数量；
- 板块、公司、价格各自提交的股票线索数；
- 去重后的候选池规模；
- 进入共同验证、最终入选、明确淘汰和关键未知未决的数量；
- 按 `fate_stage` 和 `fate_class` 汇总的数量；
- 每条非股票线索的交接结果；
- 每只候选的最终去向、最先阻断环节和主导原因。

最后只根据方向交接表和候选台账回答：

1. 当前是否仍有已产生的方向、问题或股票线索无明确理由地消失；
2. 主要阻断发生在方向转股票的发现交接、预验证比较、公司传导、板块比较、价格归因、共同验证还是总控最终比较；
3. 各项阻断属于合理淘汰、数据缺口，还是 Skill 之间的真实语义冲突；
4. 是否已有足够证据支持下一轮只改一个 Skill；若有，只指出一个最应修改的 Skill 和具体语义问题，不在本轮实施修改；
5. 若证据不足，明确写“暂不继续调 Skill”。

不得把零线索、少线索或某只股票未被发现本身直接解释为 Skill 缺陷；只有发现输入未覆盖完整合格范围、已产生线索未完成交接，或职责和输出语义发生可复现冲突时，才能诊断相应流程问题。

## 验收标准

本轮同时满足以下条件才算完成：

1. 全流程严格使用同一形成日、截止时间和合格股票范围。
2. 完整合格股票范围的规模、来源和形成日身份边界可核查。
3. 板块、公司和价格都实际执行独立发现，而不是只分析预先给定股票；零线索输出也有覆盖和原因说明。
4. 每条市场方向、板块和问题线索都有交接结果。
5. 每条具体股票线索都有可追踪去向，不发生“无声消失”。
6. 每只未入选或未决候选都有最先阻断环节、归因类别和具体理由。
7. 没有新公司公告不被当作自动淘汰理由；纯概念、无业务传导的候选仍被拦截。
8. 大盘或板块跟涨与个股增量确认被明确区分，低位或前期下跌不被写成启动证据。
9. 最终 `0—5` 只结论体现同类比较、剩余路径、最强反证和行动日可观察条件。
10. 诊断结论来自方向交接表和完整候选台账，不从任何一只股票的后来表现倒推。
11. 对下一轮 Skill 修改的建议至多一个；证据不足时不继续调 Skill。
